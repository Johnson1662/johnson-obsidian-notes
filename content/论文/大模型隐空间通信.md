## 2 混合架构模型的两种内部状态对模型行为的影响

### 2.1 基本信息

名称：What Attention Recalls and Recurrence Controls in Hybrid Language Models  
链接：https://arxiv.org/abs/2609.04434  
仓库：https://github.com/kirillTerra/split-prefill

解决的问题：Hybrid LLM 同时具有 Attention KV Cache 和 Recurrent State，但两类状态各自在上下文利用和生成行为中承担什么作用并不清楚；该工作通过拆分 Prefill 状态研究二者的因果功能。

作者：
- Kirill Afendulev（AIRI、YSDA）           
- Alexey Dontsov（AIRI、HSE University） 
- Elena Tutubalina（AIRI、HSE University）
- Anton Korznikov（HSE University、AIRI）

### 2.2 实验

#### 2.2.1 设计

- 正常——K,V,R
- KV-only——K,V
- Rec-only——R

#### 2.2.2 模型

- Qwen3.5-4B
- Falcon-H1-3B-Instruct
- Qwen3.5-9B
- Qwen3.5-27B
- Falcon-H1-7B
- Falcon-H1-34B
- Kimi-Linear-48B
- Olmo-Hybrid-7B
- Jamba2-3B

#### 2.2.3 结论

$$ KV\ Cache \approx \text{可寻址的精确记忆} $$

$$Recurrent\ State\approx\text{压缩的上下文状态 / 控制下一步行为}$$

## 3 C2C：融合两个模型的理解来提升回答

### 3.1 基本信息

名称：Cache-to-Cache: Direct Semantic Communication Between Large Language Models  
链接：https://proceedings.iclr.cc/paper_files/paper/2026/hash/474ada926b331d78f06d95e8913111cc-Abstract-Conference.html  
仓库：https://github.com/thu-nics/C2C

解决的问题：模型之间通过文本通信需要先生成中间文本，再由另一个模型重新理解，存在信息瓶颈和额外 Decode 延迟；C2C 研究能否直接通过内部 KV 表示进行语义通信。

作者：
- Tianyu Fu
- Zihan Min
- Hanling Zhang
- Jichao Yan
- Guohao Dai
- Wanli Ouyang
- Yu Wang

### 3.2 实验

#### 3.2.1 设计

- Sharer 和 Receiver 分别计算自己的 KV Cache
- 使用可学习的 Fuser 将 Sharer KV 投影并融合到 Receiver KV 中
- Receiver 自己的 KV 保留，融合采用残差形式

$$KV_B^{fused}=KV_B+F(KV_B,KV_A)$$

- 使用 learnable gate 决定哪些 Receiver Layer 接收 Sharer 的信息
- 两个 LLM 参数冻结，只训练中间的 Fuser
- 对比单模型和 Text-to-Text 模型间通信

#### 3.2.2 模型

- Receiver：Qwen3-0.6B
- Sharer：Qwen2.5-0.5B-Instruct
- Sharer：Llama-3.2-1B-Instruct
- Sharer：Qwen3-4B-Base
- 另外测试 Qwen、Llama、Gemma 等不同系列和不同规模的组合

#### 3.2.3 结论

- C2C 直接通过内部 KV 表示传递信息，不需要 Sharer 先生成中间文本
- 相比单模型，平均准确率提高 6.4%–14.2%
- 相比 Text-to-Text 通信，平均准确率提高 3.1%–5.4%
- 相比 Text-to-Text 通信，平均通信延迟加速约 2.5×

## 4 Models Take Notes at Prefill：KV Cache 可以编辑和组合

### 4.1 基本信息

名称：Models Take Notes at Prefill: KV Cache Can Be Editable and Composable  
链接：https://arxiv.org/abs/2606.17107  
仓库：https://github.com/19PINE-AI/programmable-kv

解决的问题：现有 Prefix Cache 通常把 KV Cache 当作只读的输入缓存，但模型在 Prefill 中已经把部分推理结果写入后续 KV；该工作研究这些内部“笔记”能否被定位、编辑和组合复用。

作者：
- Bojie Li

### 4.2 实验

#### 4.2.1 设计

- 构造包含 policy rule 和 mutable field 的上下文，最终答案由 mutable field 决定
- 对比 Stale、Field-only、Full-downstream、Oracle 四种 Cache 状态
- 通过 locality、suffix concentration、linear decodability、knockout / dose-response 实验定位决策信息被写到了哪里
- 进一步测试 KV Cache 的编辑和组合：修改上下文后局部更新 Cache，以及把预计算好的 Skill KV 拼接进新的上下文

#### 4.2.2 模型

- Qwen3-0.6B / 1.7B / 4B / 8B / 14B / 32B / 30B-A3B
- Llama-3.1-8B / 70B
- Mistral-7B
- Gemma-2-9B
- Gemma-3-27B
- 论文还扩展测试了 DeepSeek MLA、Falcon-H1 / Mamba 和 Qwen-VL 等架构

#### 4.2.3 结论

- 模型在 Prefill 阶段就已经把“根据这个字段应该得出什么结论”算出来，并写到了后面的 Token 上
- Mutable field 自己对应的 KV 对最终决策贡献很小，决策信息主要集中在其后的 downstream KV 中
- 因此 KV Cache 不只是原始上下文的缓存，还包含模型在 Prefill 阶段已经计算出的中间结论
- 预计算的 KV 片段可以经过位置处理后组合进新的上下文，用于复用已经计算过的 Skill / Context

## 5 Marconi：混合架构模型的 Prefix Cache 管理

### 5.1 基本信息

名称：MARCONI: PREFIX CACHING FOR THE ERA OF HYBRID LLMS  
链接：https://arxiv.org/abs/2411.19379  
仓库：https://github.com/ruipeterpan/marconi

解决的问题：传统 Prefix Caching 只需管理 Attention KV，而 Hybrid LLM 还包含会被原地更新的 recurrent state，直接套用传统缓存会造成高昂的状态存储开销；Marconi 研究如何高效选择和管理 recurrent-state checkpoint。

作者：
- Rui Pan
- Zhuang Wang
- Zhen Jia
- Can Karakus
- Luca Zancato
- Tri Dao
- Yida Wang
- Ravi Netravali

### 5.2 实验

#### 5.2.1 设计

- Hybrid LLM 同时具有 Attention KV Cache 和 recurrent layer state
- recurrent state 会被原地更新，不能像 Attention KV 一样从一个更长 Cache 中直接回退到较短前缀
- 因此 Prefix Cache 需要在部分前缀位置额外保存 recurrent state checkpoint
- Marconi 根据前缀未来被复用的可能性决定哪些 checkpoint 值得进入 Cache
- Eviction 同时考虑 recency、重算节省的 FLOPs 和占用的显存

#### 5.2.2 模型 / 工作负载

- Jamba-1.5-Mini
- 7B Hybrid LLM 配置
- LMSys
- ShareGPT
- SWE-Agent / SWE-Bench

#### 5.2.3 结论

- 相比直接把传统 Prefix Caching 用在 Hybrid LLM 上，Marconi 能显著提高有效 Cache Hit
- 在 LMSys、ShareGPT、SWE-Bench 工作负载上，Cache Hit 分别平均提高 4.5×、7.3×、34.4×
- P95 TTFT 最高降低 71.1%（617 ms）
- 核心问题不是如何改变 recurrent state，而是如何在有限显存下选择值得保存的 state checkpoint

## 6 Sparse Prefix Caching：稀疏保存 Recurrent State Checkpoint

### 6.1 基本信息

名称：Sparse Prefix Caching for Hybrid and Recurrent LLM Serving  
链接：https://arxiv.org/abs/2605.05219  
仓库：原文未给出

解决的问题：Hybrid / Recurrent LLM 若在所有位置保存精确 recurrent state，会产生过高的缓存开销；该工作研究在有限存储下只保留少量 checkpoint，同时通过局部 Replay 精确恢复状态。

作者：
- Mikhail Shirokikh
- Sergey Nikolenko

### 6.2 实验

#### 6.2.1 设计

- Attention KV Cache 正常保存
- Recurrent state 不在每个位置保存，只在少量 checkpoint 位置保存精确状态
- 新请求命中共享前缀时，找到不超过共享前缀长度的最深 checkpoint
- 从这个 checkpoint 恢复 recurrent state，再精确 Replay checkpoint 到共享前缀末尾之间的 Token
- 根据真实前缀命中分布，用动态规划选择有限 checkpoint 应该放在哪些位置

#### 6.2.2 模型

- 使用 Qwen3.5-0.8B 的代表性 Hybrid layer group：1 个 Full Attention Layer + 3 个 Gated DeltaNet Layer

#### 6.2.3 结论

- Sparse checkpoint 可以在较低显存占用下支持 Hybrid / Recurrent LLM 的 Prefix Reuse
- 因为从精确 checkpoint 开始重新执行剩余 Token，所以恢复后的 recurrent state 与完整执行一致，不引入近似误差
- 根据请求分布选择 checkpoint，相比固定间隔放置能获得更好的存储—重算 Pareto trade-off
- 对完全 append-only、始终复用最长前缀的场景，只保存最近 checkpoint 已经足够；该方法主要针对共享前缀长度变化较大的工作负载

## 7 Tail-Replay：用前缀尾部重放重建 Recurrent State

### 7.1 基本信息

名称：Tail-Replay: Escaping the Curse of Linear Attention in Prefix Caching for Hybrid LLMs  
链接：https://arxiv.org/abs/2608.30310  
仓库：原文未给出

解决的问题：Hybrid LLM 的 recurrent state 难以像 KV Cache 一样直接做 Prefix Reuse，而保存大量 state checkpoint 又很昂贵；Tail-Replay 研究能否只重放共享前缀尾部来近似重建状态。

作者：
- Yirui Liu
- Ruoling Qi
- Xuaner Wu
- Penghang Liu
- Jian Chen

### 7.2 实验

#### 7.2.1 设计

- Full Attention Layer 的 KV Cache 正常缓存并直接复用
- 不保存 Linear Attention / Gated DeltaNet 的 recurrent state checkpoint
- Prefix Cache 命中后，只 Replay 共享前缀末尾的一小段 Token 来重建 recurrent state
- 利用 Gated DeltaNet recurrent update 会逐渐衰减早期 Token 影响这一性质，把 Tail Replay 作为完整 state 的近似恢复

#### 7.2.2 模型

- 3 个基于 Gated DeltaNet 的 Hybrid LLM

#### 7.2.3 结论

- 只 Replay 共享前缀最后约 5%–10%，即可在 LongBench / RULER 上保留 Full Prefill 的 92.8%–99.9% 质量
- 在 32K 上下文下，TTFT 加速 9.1×–14.3×
- 与 Sparse Prefix Caching 不同，Tail-Replay 不追求精确恢复 recurrent state，而是利用 recurrent state 对远期历史的遗忘进行近似重建
