## 一、选择题（每题 2 分，共 16 分）

> [!question] 选择题 1
> 主机 A 向 B 发送 TCP 报文段，seq=199，ack=200，数据部分有 2 字节。主机 B 对该报文的确认报文段中（）。
> - A. seq = 201, ack = 200
> - B. seq = 200, ack = 201
> - C. seq = 200, ack = 200
> - D. seq = 202, ack = 201

> [!check]- 答案与解析（点击展开）
> **参考答案**：B
> 
> **解析**：A 发送了序号为 199 和 200 的两个字节，B 期望收到的下一字节为 $199+2=201$，因此确认号 $ack = 201$。B 的发送序号取自 A 先前的期待值 $ack=200$，故 $seq = 200$。

> [!question] 选择题 2
> 下列关于 TCP 和 UDP 的说法，错误的是（）。
> - A. TCP 是面向连接的服务，在数据传输前要进行三次握手
> - B. UDP 提供一种不可靠数据传送服务，是无连接的
> - C. UDP 报文字段中的确认号，用于接收方向发送方确认报文接收
> - D. TCP 拥塞控制主要包括慢启动、拥塞避免、快速恢复等技术

> [!check]- 答案与解析（点击展开）
> **参考答案**：C
> 
> **解析**：UDP 首部只有源端口、目的端口、长度和校验和共 8 字节，根本没有确认号字段。

> [!question] 选择题 3
> 考虑通过固定的路由从源主机发送数据包到目标主机，下面哪个延迟可能会动态发生变化（）。
> - A. 节点处理延迟
> - B. 传输延迟
> - C. 传播延迟
> - D. 排队延迟

> [!check]- 答案与解析（点击展开）
> **参考答案**：D
> 
> **解析**：固定路由下，传播时延（距离固定）、传输时延（包长与带宽固定）、处理时延相对恒定，只有排队时延会随着网络各节点的实时拥塞与并发流量动态变化。

> [!question] 选择题 4
> 给定子网 `20.1.24.0/24`，该子网能支持的可用用户主机数量和子网掩码是多少（）。
> - A. 246；255.255.255.0
> - B. 254；255.255.255.0
> - C. 128；255.255.255.0
> - D. 126；255.255.248.0

> [!check]- 答案与解析（点击展开）
> **参考答案**：B
> 
> **解析**：`/24` 掩码为 `255.255.255.0`，主机位数 8 位，可用主机数 $= 2^8 - 2 = 254$。

> [!question] 选择题 5
> Persistent HTTP 与 Non-persistent HTTP 的核心区别在于（）。
> - A. Persistent HTTP 不需要建立传输层的 TCP 连接
> - B. Persistent HTTP 在应用层与传输层之间采用 Socket 通信
> - C. Persistent HTTP 可以通过一个 TCP 连接请求和接收多个对象
> - D. Persistent HTTP 在两个 RTT 时间内只能传输一个对象

> [!check]- 答案与解析（点击展开）
> **参考答案**：C
> 
> **解析**：持久连接允许在同一条建立好的 TCP 连接上连续发送和接收多个 Web 对象请求，消除了每个对象的重复握手开销。

> [!question] 选择题 6
> 关于 P2P 和 C/S 架构，下列说法正确的是（）。
> - A. P2P 应用系统中的节点只能是客户端或者是服务器
> - B. P2P 应用架构需要在 TCP/IP 协议栈增加功能来进行支持
> - C. 在 P2P 架构下，每个 peer 既可以提供服务也可以请求服务
> - D. P2P 架构总比 C/S 架构性能优越

> [!check]- 答案与解析（点击展开）
> **参考答案**：C
> 
> **解析**：P2P（对等网络）核心特点是具备自扩展性（Self-scalability），每个节点兼具 Client 与 Server 功能。

> [!question] 选择题 7
> 下列关于 CSMA/CA 协议的说法错误的是（）。
> - A. 在数据帧发送过程中能够检测到信道冲突
> - B. 在发送数据帧前要先侦听信道的状态
> - C. 监测到信道忙时，随机等待一段时间再继续监测信道
> - D. 使用停-等可靠传输（ACK）来应对冲突产生的丢包

> [!check]- 答案与解析（点击展开）
> **参考答案**：A
> 
> **解析**：无线网络无法实现硬件级的冲突检测（CD），因此采用冲突避免（CA）。

> [!question] 选择题 8
> 下列关于 IP 层的说法中错误的是（）。
> - A. IP 层可以屏蔽各个物理网络的差异
> - B. IP 层可以代替各个物理网络和数据链路层工作
> - C. IP 层可以隐藏各个物理网络的实现细节
> - D. IP 层可以提供转发和路由的功能

> [!check]- 答案与解析（点击展开）
> **参考答案**：B
> 
> **解析**：IP 层作为互联协议运行在数据链路层之上，不能代替底层物理网卡和链路介质的工作。

## 二、大题部分（共 84 分）

> [!question] 大题 1：跨网段通信与 MAC 地址变化机制（10分）
> 主机 A 向不同网段的主机 B 发送数据，从网络层和链路层描述数据发送过程，并说明在此过程中数据帧头部的源和目的 MAC 地址变化规律。

> [!check]- 答案与解析（点击展开）
> **解析与核心考点**：
> 1. 主机 A 判断目的 IP 跨网段，通过 ARP 获得默认网关（路由器接口）的 MAC 地址。
> 2. A 发送数据帧：源 MAC = A 的 MAC，目的 MAC = 路由器入接口 MAC；源 IP = A 的 IP，目的 IP = B 的 IP。
> 3. 路由器解帧查路由表确定出接口，通过 ARP 获得下一跳/目的主机 B 的 MAC 地址。
> 4. 路由器重新封装出新帧：源 MAC = 路由器出接口 MAC，目的 MAC = B 的 MAC。
> **核心规律**：端到端传输中，源目 IP 始终不变，源目 MAC 每一跳都在更新。

> [!question] 大题 2：校园网三路由器与 NAT 转换表（12分）
> 某校园网有两个局域网通过路由器 R1、R2、R3 互联后接入 Internet，写出私网主机访问公网 Web 服务时 NAT 转换表的表项结构以及转换前后 IP 与端口的变化。

> [!check]- 答案与解析（点击展开）
> **NAT 转换表项核心设计**：
> - 结构：`(WAN IP, WAN Port) <===> (LAN IP, LAN Port)`
> - 出站报文：源 IP 被替换为路由器的公网 IP，源端口被替换为 NAT 分配的空闲临时端口；
> - 入站响应报文：目的 IP 和端口被替换回内网主机的实际 IP 和原始客户端端口。

> [!question] 大题 3：DV 距离向量路由算法推导（15分）
> 给定拓扑图与链路开销，计算从节点 X 到各节点的最短距离向量表更新过程，并写出算法收敛时节点 X 的最终路由表项（Destination, Nexthop, Cost）。

> [!check]- 答案与解析（点击展开）
> **Bellman-Ford 方程**：$D_x(y) = \min_v \{ c(x,v) + D_v(y) \}$，逐轮与邻居交换向量直至不再更新，得出收敛路由表。

> [!question] 大题 4：电路交换 vs 分组交换容量与概率分析（12分）
> 100Mbps 共享链路，每用户需 1Mbps 带宽，用户活跃概率为 10%。
> 1. 电路交换最多支持多少用户？
> 2. 分组交换有 N 个用户，给出多于 M 个用户同时传输的概率表达式。
> 3. 解释 Internet 采用分组交换的原因。

> [!check]- 答案与解析（点击展开）
> 1. 电路交换独占带宽：$100\text{M} / 1\text{M} = 100$ 个用户。
> 2. 二项分布概率：$P(X > M) = \sum_{k=M+1}^{N} \binom{N}{k} (0.1)^k (0.9)^{N-k}$。
> 3. 原因：统计复用提高链路利用率、无呼叫建立开销、抗单点失效鲁棒性强。

> [!question] 大题 5：时延公式推导与 32GB 数据交付决策（15分）
> $t_0$ 首 bit 进入，$t_1$ 首 bit 离开，$t_2$ 尾 bit 离开链路。
> 1. 表示传播时延、传输时延和吞吐量；
> 2. 链路带宽 1Mbps，传播时延 500ms，求 4Kb 邮件的端到端总时延；
> 3. 紧急情况下把 32Gb 数据从天津交付给北京的朋友，选网络还是物理运送（高铁）？计算说明。

> [!check]- 答案与解析（点击展开）
> 1. 传播时延 $= t_1 - t_0$；传输时延 $= t_2 - t_1$；吞吐量 $= L / (t_2 - t_0)$。
> 2. $4\text{Kb} / 1\text{Mbps} = 4\text{ms}$，总延时 $= 4\text{ms} + 500\text{ms} = 504\text{ms}$。
> 3. **坚决选高铁物理运输**。1Mbps 下网络传输 32Gb 需要 $32 \times 10^9 / 10^6 = 32,000\text{秒} \approx 8.89\text{小时}$；而京津城际高铁仅需 30 分钟，总耗时远小于网络下载。

> [!question] 大题 6：TCP Tahoe 拥塞控制 6 大事件分析（12分）
> 分析 TCP Tahoe 拥塞控制曲线中 1~6 号事件所处的状态（慢启动还是拥塞避免），解释丢包后 Tahoe 协议的窗口重置特点。

> [!check]- 答案与解析（点击展开）
> Tahoe 协议不区分 3-ACK 还是超时，遇丢包一律将 $ssthresh$ 减半并将 $cwnd$ 强行置 1，重新进入慢启动。

> [!question] 大题 7：CSMA/CD 二进制指数退避算法（8分）
> 简述 CSMA/CD 二进制指数退避算法思想并解释其能有效减少冲突的原因。

> [!check]- 答案与解析（点击展开）
> 冲突 $k$ 次后从 $[0, 2^k-1]$ 中随机抽取退避时间。当碰撞加剧时随机区间呈指数放大，迅速将并发站点的等待时间错开，防止雪崩再次冲突。
