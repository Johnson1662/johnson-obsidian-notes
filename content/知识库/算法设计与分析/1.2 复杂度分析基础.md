### **4. 复杂度分析基础**

**性能评价的重要性**

程序的性能指程序运行时所需的内存空间量和计算时间。在算法分析中，我们区分出算法的性能，忽略系统开销。为什么要研究性能？设计满足要求的算法需要某种度量指标。

**问题实例与实例特征**

- **问题实例（instance）**：算法的具体输入
- **实例长度（size）**：表示实例的数据结构的长度
- **实例特征**：描述问题实例长度的参数，例如矩阵的阶数n是反映实例长度(n²)的参数
- 算法分析建立算法执行时间或空间占用与实例特征的函数关系

**空间复杂度（Space Complexity）**

程序p的空间复杂度指程序运行时所需的内存空间大小和实例特征的函数关系，记为$S_p(n)$。

程序运行时所需空间包括：

- **指令空间**：与实例特征无关的常数
- **数据空间**：
  - 常量和简单变量：实例无关
  - 复合变量（数组、链表、树和图等）：常常和问题实例特征有关
  - 环境栈空间（函数调用）：是否递归？

> [!tip] 💡
> 程序p的空间需求量包括两部分：
> $S(n) = c + S_p(n)(\text{instance characteristics})$
> 其中c为常量（实例无关部分，所有变量默认2字节），$S_p$为可变部分。

**空间复杂度分析要点**

- 对非递归算法：分析与实例特征有关的数据结构的大小
- 对递归算法：还要分析递归调用的深度和实例特征的关系

**时间复杂度（Time Complexity）**

时间复杂度指程序执行时所用的时间。

在使用解析法时，程序p的时间复杂度表示为输入量的函数T。

机器独立的分析方法使用以下两种时间单位：

- **操作计数（operation count）**：算法的基本操作
- **步计数（step count）**：分析全部程序

要点：基本操作或程序步的执行时间必须是常数。

**最好、最坏、平均情况分析**

当长度相同的不同输入有不同的计算时间时，时间复杂度分析分别考虑三种情形：

- **最好情形**：给出算法计算时间的下界
- **最坏情形**：给出算法计算时间的上界，当特定应用对计算时间有严格要求时应做最坏情形分析
- **平均情形**：假设输入数据为所有可能的排列，计算平均执行时间

### **5. 渐近分析**

### **大O记号（Big O Notation）**

$f(n) = O(g(n))$ 当且仅当存在常数c和$n_0$使得对所有$n > n_0$有$f(n) \leq cg(n)$成立。

等价定义：$\lim_{n \to \infty} |f(n)/g(n)| = c$，$0 \leq c < \infty$，则$f(n) = O(g(n))$。

称g(n)为f(n)的**渐近上界（Asymptotic Upper Bound）**。

**示例**：

- $10n^2 + 3n + 100 = O(n^2)$，$\lim = 10$
- $1000n^2 = O(n^{2.1})$，$\lim = 0$

### **大Ω记号（Big Omega Notation）**

$f(n) = \Omega(g(n))$ 当且仅当存在常数c和$n_0$使得对所有$n > n_0$有$f(n) \geq cg(n)$成立。

等价定义：$\lim_{n \to \infty} |f(n)/g(n)| = c$，$0 < c \leq \infty$，则$f(n) = \Omega(g(n))$。

称g(n)为f(n)的**渐近下界**。

### **大Θ记号（Big Theta Notation）**

如果$f(n) = O(g(n))$同时$f(n) = \Omega(g(n))$则$f(n) = \Theta(g(n))$，并称f(n)与g(n)同阶。

等价定义：$\lim_{n \to \infty} f(n)/g(n) = c$，$0 < c < \infty$，则$f(n) = \Theta(g(n))$。

当$f(n)$为算法的时间复杂度函数时，称$g(n)$为该算法的复杂度的阶。

**渐近分析的应用**

常见复杂度函数的增长率比较：
$O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$

**算法分类**：

- 如果一算法的最坏情形时间复杂度$t(n) = O(n^k)$，则称该算法为**多项式复杂度的算法**或**有多项式界的算法**
- 如果一算法的最坏情形时间复杂度$t(n)$不能用多项式限界，则称该算法为**指数复杂度的算法**，这类算法可认为计算上不可行的算法

**问题分类**：

- 如果一个问题有多项式界的算法称该问题属于**多项式类P**
- 有很多实际上有意义的问题找不到有多项式界的算法称这些问题是**NP-hard问题**，即问题本身难
- 上述难问题只能通过近似算法或启发式算法求解
