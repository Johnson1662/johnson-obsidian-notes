\begin{aligned}
&\text{证明：设 } n \text{ 个任务的某种执行序列中，各个任务所需的执行时间依次为 } t_1, t_2, \dots, t_n \text{。} \\
&\text{根据定义，第 } k \text{ 个任务的完成时间为 } c_k = \sum_{m=1}^{k} t_m \text{。总完成时间为：} \\
&n\text{ACT} = \sum_{k=1}^{n} (n - k + 1)t_k = \sum_{k \neq i, j} (n - k + 1)t_k + (n - j + 1)t_j + (n - i + 1)t_i \\
\\
&\text{假设当前序列中存在一对逆序任务 } j \text{ 和 } i \text{，满足位置下标 } i > j \text{ 且执行时间 } t_i < t_j \text{（即 } t_j - t_i > 0 \text{）。} \\
&\text{保持其他任务位置不动，仅交换作业 } i \text{ 和 } j \text{ 的位置，交换后的新总完成时间 } n\text{ACT}' \text{ 为：} \\
&n\text{ACT}' = \sum_{k \neq i, j} (n - k + 1)t_k + (n - j + 1)t_i + (n - i + 1)t_j \\
\\
&\text{将两式相减以计算总时间变化量，非交换项在作差时全部抵消：} \\
&n\text{ACT} - n\text{ACT}' = \left[ (n - j + 1)t_j + (n - i + 1)t_i \right] - \left[ (n - j + 1)t_i + (n - i + 1)t_j \right] \\
&\phantom{n\text{ACT} - n\text{ACT}'} = (n - j + 1)t_j - (n - i + 1)t_j + (n - i + 1)t_i - (n - j + 1)t_i \\
&\phantom{n\text{ACT} - n\text{ACT}'} = \left[ (n - j + 1) - (n - i + 1) \right]t_j + \left[ (n - i + 1) - (n - j + 1) \right]t_i \\
&\phantom{n\text{ACT} - n\text{ACT}'} = (i - j)t_j + (j - i)t_i \\
&\phantom{n\text{ACT} - n\text{ACT}'} = (i - j)(t_j - t_i) \\
\\
&\text{因 } i > j \implies i - j > 0 \text{ 且 } t_i < t_j \implies t_j - t_i > 0 \text{，故：} \\
&(i - j)(t_j - t_i) > 0 \implies n\text{ACT} - n\text{ACT}' > 0 \implies \text{ACT}' < \text{ACT} \\
\\
&\text{结论：每消除一个逆序对，平均完成时间都会严格减小。} \\
&\text{因此，当且仅当所有任务完全按照执行时间 } t_k \text{ 从小到大升序排列时，}\text{ACT}\text{ 达到全局最小值。}
\end{aligned}

10. 若有两个工人执行练习9中的n个任务，需将任务分配给他们，同时他们具有自己的任务执行顺序。任务完成时间及ACT的定义同练习9。使ACT最小化的一种可行的贪婪算法是：两个工人轮流选择任务，每次从剩余的任务中选择时间最小的任务。每个人按照自己所选任务的顺序执行任务。对于练习9中的例子，假定工人1首先选择任务4，然后工人2选择任务2，工人1选择任务1，最后工人2选择任务3。
1) 利用伪代码实现这种策略，其时间复杂性为多少？取$ACT=max(ACT1,ACT2)$
2) 上述的贪婪策略总能获得最小的ACT吗？证明结论。

1)

```
Algorithm TwoWorkerScheduling(T, n)
    Input: T - 包含 n 个任务的数组，每个任务包含 ID 和所需时间 time
    Output: 整体的 ACT 值

    // 1. 将任务按所需时间从小到大进行排序（核心：短作业优先）
    Sort T in non-decreasing order based on T[i].time 

    Initialize Worker1_Tasks as an empty list
    Initialize Worker2_Tasks as an empty list

    // 2. 轮流分配任务
    For i from 1 to n do
        If i is odd then
            Append T[i] to Worker1_Tasks
        Else
            Append T[i] to Worker2_Tasks
        EndIf
    EndFor

    // 3. 分别计算两个工人的 ACT
    ACT1 = CalculateIndividualACT(Worker1_Tasks)
    ACT2 = CalculateIndividualACT(Worker2_Tasks)

    // 4. 根据题目定义，取两者中的较大值
    Return max(ACT1, ACT2)
EndAlgorithm

Function CalculateIndividualACT(Tasks)
    Let m = length of Tasks
    If m == 0 Return 0
    
    current_time = 0
    sum_completion_time = 0
    
    For i from 1 to m do
        current_time = current_time + Tasks[i].time
        sum_completion_time = sum_completion_time + current_time
    EndFor
    
    Return sum_completion_time / m
EndFunction
```

时间复杂度分析：
- 排序任务的时间复杂度为 O(n log n)。
- 轮流分配任务的时间复杂度为 O(n)。
- 计算每个工人的 ACT 的时间复杂度为 O(n)。
因此，整体时间复杂度为 O(n log n)。

2) 该贪婪策略不总能获得最小的 ACT。以下是一个反例：
假设有 4 个任务，执行时间分别为 $\{1, 2, 5, 6\}$。

* **贪心策略（按 $1, 2, 5, 6$ 轮流分配）：**
工人 1 分得 $\{1, 5\}$，完成时间分别为 $1, 6$，则 $\text{ACT}_1 = \frac{1+6}{2} = 3.5$
工人 2 分得 $\{2, 6\}$，完成时间分别为 $2, 8$，则 $\text{ACT}_2 = \frac{2+8}{2} = 5$
$\text{ACT} = \max(3.5, 5) = 5$

* **更优策略（非轮流分配）：**
工人 1 分得 $\{1, 6\}$，完成时间分别为 $1, 7$，则 $\text{ACT}_1 = \frac{1+7}{2} = 4$
工人 2 分得 $\{2, 5\}$，完成时间分别为 $2, 7$，则 $\text{ACT}_2 = \frac{2+7}{2} = 4.5$
$\text{ACT} = \max(4, 4.5) = 4.5$

因为 $4.5 < 5$，说明该贪心策略无法总能获得最小 ACT。

\begin{aligned}
&\text{设 } x=(x_1, \dots, x_n) \text{ 为贪心法产生的解，其形式为 } (1, 1, \dots, x_j, 0, \dots, 0) \text{，其中 } 0 < x_j < 1 \text{。} \\
&\text{设 } y=(y_1, \dots, y_n) \text{ 是一个优化解。} \\
\\
&\text{设 } k \text{ 是满足 } x_i \neq y_i \text{ 的最小下标，则显然有 } k \le j \text{ 且 } y_k < x_k \text{。} \\
&\text{将 } y_k \text{ 增加到 } x_k \text{，并从后面的项中扣除等额重量，即从 } \sum_{k < i \le n} y_i w_i \text{ 中减去 } (x_k - y_k)w_k \text{，} \\
&\text{得到新序列 } (z_k, z_{k+1}, \dots, z_n) \text{，其中 } z_k = x_k \text{，且满足重量守恒：} \sum_{k < i \le n} (y_i - z_i)w_i = (x_k - y_k)w_k \text{。} \\
\\
&\text{下面通过作差法证明新解 } (y_1, \dots, y_{k-1}, z_k, \dots, z_n) \text{ 的总价值不低于原优化解，即证：} \sum_{k \le i \le n} (y_i - z_i)p_i \le 0 \\
\\
&\text{将第 } k \text{ 项拆出，并将其余项的价值转换为重量与密度的乘积：} \\
&\sum_{k \le i \le n} (y_i - z_i)p_i = (y_k - z_k)p_k + \sum_{k < i \le n} (y_i - z_i)p_i \\
&\phantom{\sum_{k \le i \le n} (y_i - z_i)p_i} = (y_k - x_k)p_k + \sum_{k < i \le n} (y_i - z_i)w_i \cdot \frac{p_i}{w_i} \\
\\
&\text{利用物品按价值密度非递增排序的性质，对所有 } i > k \text{，均有 } \frac{p_i}{w_i} \le \frac{p_k}{w_k} \text{。由于 } y_i - z_i \ge 0 \text{，进行放大缩放：} \\
&\le (y_k - x_k)p_k + \sum_{k < i \le n} (y_i - z_i)w_i \cdot \frac{p_k}{w_k} \\
&\phantom{\le} = (y_k - x_k)p_k + \frac{p_k}{w_k} \sum_{k < i \le n} (y_i - z_i)w_i \\
\\
&\text{代入重量守恒方程 } \sum_{k < i \le n} (y_i - z_i)w_i = (x_k - y_k)w_k \text{：} \\
&\phantom{\le} = (y_k - x_k)p_k + \frac{p_k}{w_k} \cdot (x_k - y_k)w_k \\
&\phantom{\le} = (y_k - x_k)p_k + (x_k - y_k)p_k \\
&\phantom{\le} = 0 \\
\\
&\text{由此可得 } \sum_{k \le i \le n} y_i p_i \le \sum_{k \le i \le n} z_i p_i \text{，即新构造的解仍是优化解。} \\

\end{aligned}
$$

（1）可以采用最大度优先的贪婪算法，每次选择当前图中度数最大的顶点加入集合$S$，然后每次从未加入 $S$ 的顶点中，挑选一个与当前 $S$ 中所有顶点都有边相连、且在剩余可用顶点中度数最大的顶点加入 $S$。当找不到任何一个能与当前 $S$ 内所有顶点保持全连接的顶点时，算法结束,伪代码如下：
```
Algorithm GreedyMaxClique(G)
    Input: 无向图 G = (V, E)
    Output: 完备子图的顶点集合 S

    Initialize S as an empty set
    
    // 1. 挑选全图度数最大的顶点作为起点
    Sort vertices in V in non-increasing order of their degrees
    Let v_start be the vertex with the maximum degree in V
    Add v_start to S
    
    // 2. 依次考察其他顶点是否能并入完备子图
    For each vertex u in V \ {v_start} (按照度数从大到小的顺序) do
        Let can_add = true
        
        // 检查 u 是否与当前 S 中的所有顶点都相连
        For each vertex s in S do
            If (u, s) is not in E then
                can_add = false
                break
            EndIf
        EndFor
        
        // 如果全连接，则将 u 加入完备子图 S
        If can_add is true then
            Add u to S
        EndIf
    EndFor

    Return S
EndAlgorithm
```
