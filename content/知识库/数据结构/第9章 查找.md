# 第9章 查找

## 基本概念

| 概念                   | 含义                                                   | 备注                                                             |
| :--------------------- | :----------------------------------------------------- | :--------------------------------------------------------------- |
| **查找表**             | 由同一类型的数据元素（或记录）构成的集合               | 静态查找表：仅查找<br>动态查找表：含增删操作                     |
| **查找**               | 根据给定的值，在查找表中确定一个其关键字等于该值的记录 |                                                                  |
| **关键字**             | 记录中某个数据项的值，用以标识该记录                   | **主关键字**：唯一标识记录<br>**次关键字**：识别若干记录         |
| **平均查找长度 (ASL)** | $ASL = \sum_{i=1}^n P_i C_i$                           | $n$：表长；$P_i$：查找概率；$C_i$：找到第 $i$ 个记录时的比较次数 |

## 9.1 静态查找表

### 9.1.1 顺序表的查找

1. **要求**：线性表结构，顺序或链式存储均可。
2. **基本思想**：从表的一端开始，逐个进行记录的关键字与给定值的比较。
3. **平均查找长度**：
   在等概率情况下（$P_i = 1/n$）：
   $$ASL = \sum_{i=1}^n \frac{1}{n} \times i = \frac{n+1}{2} = O(n)$$
4. **评价**：算法简单但效率较低，适用于小规模查找表。
5. **算法实现**：通常在顺序表或单链表类中实现 `search` 成员函数。

### 9.1.2 有序表的查找 (折半查找)

1. **前提条件**：
   - 必须采用**顺序存储**结构。
   - 记录必须按关键字**有序排列**。
     ![image](assets/image_t-20260104152051-oeu5gn6.png)

2. **查找逻辑**：
   - 设置 `low`、`high` 指针。
   - 若 `low > high`，说明查找失败，返回 -1。
     ![image 1](assets/image-1-20260104152051-zl10s8j.png)

3. **代码实现**：

```cpp
// 循环实现（效率更高）
template <typename T>
int BinSearch(T A[], int low, int high, T key) {
    while(low <= high) {
        int mid = (low + high) / 2;
        if(key == A[mid]) return mid;
        if(key < A[mid]) high = mid - 1;
        else low = mid + 1;
    }
    return -1;
}

// 递归实现
template <typename T>
int BinSearchRecursive(T A[], int low, int high, T key) {
    if(low > high) return -1;
    int mid = (low + high) / 2;
    if(key == A[mid]) return mid;
    return (key < A[mid]) ? BinSearchRecursive(A, low, mid - 1, key) : BinSearchRecursive(A, mid + 1, high, key);
}
```

4. **查找效率**：$ASL \approx \log_2 n$。

### 9.1.3 静态树的查找 (次优二叉树)

当查找概率不均等时，折半查找并非最优。此时需构造**次优二叉树 (Sub-optimal Binary Search Tree)**。

1. **构造原则 (PH原则)**：
   使得左右子树的权值之和尽可能相等。
2. **构造方法**：
   设权值序列为 $w_l \dots w_h$，选择根节点 $i$ 使得 $\Delta w = |\sum_{j=i+1}^h w_j - \sum_{j=l}^{i-1} w_j|$ 最小。
3. **性能**：次优二叉树的 $WPL$ 接近最优二叉树（差别仅 1%~2%），但构造复杂度更低 ($O(n \log n)$)。

### 9.1.4 索引顺序表的查找 (分块查找)

1. **结构**：
   - **主表**：分 $b$ 块。**块间有序**（前块最大值 < 后块所有值），块内可无序。
   - **索引表**：存储每块的`(最大关键字, 起始地址)`，索引表有序。
2. **过程**：
   - 先在索引表中找块（顺序或折半）。
   - 再在块内顺序查找。
3. **ASL 计算**：
   设 $n$ 为记录总数，$b$ 为块数，$s$ 为块内记录数：
   $$ASL = L_{index} + L_{block} \approx \frac{b+1}{2} + \frac{s+1}{2}$$
   当 $s = \sqrt{n}$ 时，$ASL$ 取得最小值 $\sqrt{n} + 1$。

## 9.2 动态查找表

### 9.2.1 二叉排序树 (BST) 和平衡二叉树 (AVL)

1. **二叉排序树定义**：
   - 若左子树非空，则左子树所有节点值 < 根节点值。
   - 若右子树非空，则右子树所有节点值 > 根节点值。
   - 左右子树本身也是二叉排序树。
   - **特性**：中序遍历结果是一个有序递增序列。
     ![image 2](assets/image-2-20260104152051-6fdzrzs.png)

2. **操作逻辑**：
   - **插入**：新记录总是作为叶子节点插入，保证 BST 性质。
   - **删除**：
     - 叶子节点：直接删除。
     - 单孩子节点：孩子替换该节点。
     - 双孩子节点：用中序前驱（左子树最大）或后继（右子树最小）替代，再删除该替代节点。

3. **平均查找长度**：
   - 平衡状态：$ASL = O(\log_2 n)$。
   - 退化状态（单支树）：$ASL = O(n)$。

4. **平衡二叉树 (AVL)**：
   - 性质：左右子树深度差不超过 1。
   - 调整：通过 LL、RR、LR、RL 四种平衡旋转维持平衡。

### 9.2.2 B-树 和 B+ 树

1. **B-树 (平衡多路查找树)**：
   - 阶为 $m$ 的 B-树：每个节点至多有 $m$ 棵子树；根节点外，非叶节点至少有 $\lceil m/2 \rceil$ 棵子树。
   - 所有叶子节点在同一层（失败节点）。
   - 插入时若溢出则**分裂**，删除时若不足则**借位**或**合并**。

2. **B+ 树**：
   - 主要区别：分支节点仅作为索引（不存数据），所有数据存储在叶子节点。
   - 所有叶子节点通过指针链接成**有序双向链表**，非常适合范围查询。

### 9.2.3 键树 (Digital Search Tree)

1. **定义**：关键字通过字符或数字位拆分，节点代表字符。
2. **分类**：
   - **双链树**：采用二叉链表存储（孩子-兄弟法）。
   - **多重链表树 (Trie 树)**：每个节点是一个指针数组，查找效率仅取决于关键字长度 $k$。

## 9.3 哈希表 (Hash Table)

### 9.3.1 什么是哈希表

通过哈希函数 $H(key)$ 将关键字直接映射到存储地址，实现 $O(1)$ 级别的查找。

### 9.3.2 哈希函数的构造方法

1. **直接定址法**：$H(k) = a \cdot k + b$。
2. **除留余数法**：$H(k) = k \mod p$（$p$ 取不大于表长的最大质数）。
3. **数字分析法**、**平方取中法**等。

### 9.3.3 处理冲突的方法

**同义词冲突**：不同关键字映射到同一地址。

1. **开地址法**：
   - **线性探测**：发生冲突时地址加 1 循环寻找空位。
   - **二次探测**：地址按 $1^2, -1^2, 2^2, -2^2 \dots$ 步长探测。

**线性探测示例分析**：
设 $H(key) = key \mod 7$，输入：33, 52, 41, 12, 88, 66

| 地址         | 0                                                       | 1      | 2      | 3      | 4      | 5   | 6      |
| :----------- | :------------------------------------------------------ | :----- | :----- | :----- | :----- | :-- | :----- |
| **关键字**   | **66**                                                  | **12** | **52** | **88** | **33** |     | **41** |
| **映射逻辑** | (33 mod 7=5); (12 mod 7=5 $\to$ 找地址 $6 \to 0 \to 1$) |        |        |        |        |     |        |

2. **链地址法 (拉链法)**：
   发生冲突的记录链接在同一单链表中。

---

### 9.3.4 哈希表的查找及其分析

1. **装填因子 ($\alpha$)**：
   $$\alpha = \frac{\text{表中记录数 } n}{\text{表长 } m}$$
2. **性能结论**：
   - 哈希表的 $ASL$ 取决于 $\alpha$ 和冲突处理方法，与 $n$ 无关。
   - 链地址法：$ASL_{succ} \approx 1 + \alpha/2$。
   - 线性探测：$ASL_{succ} \approx \frac{1}{2}(1 + \frac{1}{1-\alpha})$。
3. **优化**：通常控制 $\alpha < 0.75$ 以获得最优性能。
