## 一、并行计算基本概念

### 1.1 什么是并行计算？

**定义**：并行计算（Parallel Computing）是指同时使用多种计算资源来解决计算问题的过程。

> 💡 **通俗理解**：一个人做100道题需要100分钟，但10个人同时各做10道题可能只需要10分钟。并行计算就是"人多力量大"的计算方式。

**核心思想**：
- 将一个大问题分解为多个小问题
- 使用多个处理器同时处理这些小问题
- 最终合并结果得到完整解答

**三个关键步骤**：
1. **分解（Decomposition）**：把大任务拆成小任务
2. **分配（Mapping）**：把小任务分配给不同处理器
3. **协调（Coordination）**：处理器之间同步和通信

### 1.2 为什么需要并行计算？

**根本原因**：单处理器性能提升遇到瓶颈

| 时期 | 性能提升速度 | 说明 |
|------|-------------|------|
| 1986–2002 | 50%/年 | 每10年增长60倍（黄金期）|
| 2002以后 | 20%/年 | 每10年增长6倍（瓶颈期）|

**三大瓶颈（常考）**：

| 瓶颈 | 英文 | 说明 |
|------|------|------|
| **功耗墙** | Power Wall | 主频越高，功耗和散热问题越严重 |
| **存储墙** | Memory Wall | 内存速度远落后于CPU速度 |
| **指令级并行墙** | ILP Wall | 单核内可挖掘的并行度有限 |

> 💡 **存储墙解释**：CPU处理速度很快，但等数据从内存传来要很久，就像"巧妇难为无米之炊"。缓存占据了芯片70%以上的面积！

**应用需求推动**：
- 天气预报：精度提高1倍，计算量提高16倍
- 人工智能：GPT-4训练成本约7800万美元
- 互联网：双11峰值54.4万笔/秒、12306日点击量1577.8亿次

### 1.3 性能度量

**FLOPS（Floating-point Operations Per Second）**：每秒浮点运算次数

> 💡 **通俗理解**：衡量计算机"算得有多快"的单位，就像汽车用"公里/小时"衡量速度。

| 单位 | 数值 | 读法 |
|------|------|------|
| K | 10³ | 千 |
| M | 10⁶ | 百万 |
| G | 10⁹ | 十亿 |
| T | 10¹² | 万亿 |
| P | 10¹⁵ | 千万亿 |

**性能计算公式**（理论峰值）：

$$\text{峰值性能} = \text{主频(GHz)} \times \text{每时钟周期浮点指令数} \times \text{核心数}$$

**实例**：

| 设备 | 性能 | 说明 |
|------|------|------|
| ENIAC (1946) | 300 FLOPS | 第一台通用电子计算机 |
| Intel Xeon D-2146NT | 73.6 GFLOPS | 8核，2.3GHz |
| NV Tesla V100 | 7 TFLOPS（双精度）| GPU |
| 现代手机 | 数百GFLOPS | 8CPU+12GPU+NPU |

## 二、并行化方法

> ⚠️ **重要概念**：这是PPT 01的重点内容，原笔记缺失！

将问题并行化的三种主要策略：

### 2.1 域分解（Domain Decomposition）

**定义**：首先将**数据**划分到各处理器，然后确定每个处理器要执行的操作。

> 💡 **通俗理解**：先把任务（数据）切分，再安排每人负责一块。就像把一摞试卷分成几份，每人批改一份。

**示例：求数组最大值**

```
原数组：[3, 7, 2, 9, 1, 5, 8, 4]

Step 1: 数据划分
  CPU0: [3, 7]    → 本地最大值 = 7
  CPU1: [2, 9]    → 本地最大值 = 9
  CPU2: [1, 5]    → 本地最大值 = 5
  CPU3: [8, 4]    → 本地最大值 = 8

Step 2: 汇总比较
  max(7, 9, 5, 8) = 9
```

**适用场景**：矩阵运算、图像处理、科学仿真等数据密集型计算。

### 2.2 任务分解（Task Decomposition）

**定义**：首先将**任务/功能**划分到各处理器，然后确定每个处理器需要处理的数据。

> 💡 **通俗理解**：按"工种"分工。就像做饭时，一个人切菜、一个人炒菜、一个人摆盘，各自做不同的事。

**示例：GUI事件处理**
- 处理器A：处理鼠标事件
- 处理器B：处理键盘事件
- 处理器C：处理网络请求

**适用场景**：功能独立的系统、流水线式处理。

### 2.3 流水线（Pipelining）

**定义**：一种特殊的任务分解方式，将任务分成若干阶段，不同处理器负责不同阶段，数据像流水一样依次通过各阶段。

> 💡 **通俗理解**：汽车装配线——焊接、喷漆、组装依次进行，第一辆车在喷漆时，第二辆车在焊接，以此类推。

**示例：四人洗衣**

| 阶段 | 操作 | 时间 |
|------|------|------|
| 阶段1 | 洗衣 | 30分钟 |
| 阶段2 | 烘干 | 40分钟 |
| 阶段3 | 叠衣 | 20分钟 |

- **串行方式**：每人90分钟，4人共需 6小时
- **流水线方式**：4人共需 3.5小时

**指令流水线**（CPU内部）：

| IF | ID | EX | MA | WB |
|----|----|----|----|----|
| 取指 | 译码 | 执行 | 访存 | 写回 |

- **IF** (Instruction Fetch)：取指令
- **ID** (Instruction Decode)：译码
- **EX** (Execute)：执行
- **MA** (Memory Access)：访存
- **WB** (Write Back)：写回

> 💡 流水线提高了硬件利用率，但不能减少单条指令的执行时间。

## 三、并行计算硬件架构

### 3.1 Flynn分类法

根据**指令流**和**数据流**的数量，将计算机体系结构分为四类：

| 类型 | 指令流 | 数据流 | 典型例子 | 实际应用 |
|------|--------|--------|----------|----------|
| **SISD** | 单 | 单 | 传统单核CPU | 早期计算机 |
| **SIMD** | 单 | 多 | GPU、向量处理器 | 图像处理、AI推理 |
| **MISD** | 多 | 单 | 容错系统 | 极少见（考试几乎不考）|
| **MIMD** | 多 | 多 | 多核CPU、集群 | 最常见的并行架构 |

> 🎯 **重点**：SIMD和MIMD是最常见且最重要的并行架构。
> 
> 💡 **记忆技巧**：S=Single(单)，M=Multiple(多)，I=Instruction(指令)，D=Data(数据)。按顺序读就行：SIMD = 单指令多数据。

**SIMD执行示例**：

```c
// 一条指令同时处理4个数据
for (i = 0; i < n; i++)
    if (u[i] > 0)
        w[i] = u[i] - v[i];
    else
        w[i] = u[i] + v[i];
```

在SIMD架构中，同一条if/else指令会同时作用于多个数据元素。

### 3.2 PRAM模型（并行随机访问机）

**PRAM（Parallel Random Access Machine）**：一种理想的并行计算模型，假设所有处理器可以同时访问共享内存。

> 💡 **通俗理解**：PRAM是一个"理想国"——所有人可以同时读写同一个白板，没有冲突、没有延迟。实际做不到，但便于理论分析。

**三个阶段**：
1. **Read phase**：每个处理器同时从共享内存读取数据到本地寄存器
2. **Compute phase**：每个处理器独立执行计算
3. **Write phase**：每个处理器同时将结果写入共享内存（可能有冲突）

**PRAM衍生模型**（按读写权限分类）：

| 模型 | 全称 | 并发读 | 并发写 | 灵活性 |
|------|------|--------|--------|--------|
| **EREW** | Exclusive Read Exclusive Write | ❌ | ❌ | 最严格 |
| **CREW** | Concurrent Read Exclusive Write | ✅ | ❌ | 中等 |
| **CRCW** | Concurrent Read Concurrent Write | ✅ | ✅ | 最灵活 |

**CRCW写冲突处理策略**：
- **Common CRCW**：只有所有处理器写入相同值才允许并发写
- **Arbitrary CRCW**：随机选择一个处理器的值写入
- **Priority CRCW**：优先级最高的处理器写入

> ⚠️ **考试重点**：理解三种PRAM模型的区别。EREW最安全但限制最多，CRCW最灵活但需要处理写冲突。

**PRAM算法示例：前缀求和（Prefix Sum）**

```
串行算法：
for (i = 1; i < n; i++)
    A[i] = A[i] + A[i-1]    // 时间复杂度 O(n)

PRAM并行算法：
外循环：i = 0 到 ceil(log₂(n)) - 1    // 共 log₂(n) 轮
  内循环：j = 2^i 到 n-1，并行执行
    A[j] += A[j - 2^i]                 // 时间复杂度 O(log n)
```

> 💡 原理：每一轮让间隔为 2^i 的元素相加，类似"两两配对→四四配对→八八配对"的过程。

**PRAM算法示例：数组压缩**

将满足条件的元素提取出来组成新数组：
1. 先对标志数组做前缀求和，得到每个元素在新数组中的位置
2. 根据位置信息将元素写入新数组

### 3.3 SIMD指令集扩展

**为什么需要**：现代CPU通过SIMD指令扩展，在单核内实现数据级并行。

**Intel SIMD发展历史**：

| 版本 | 年份 | 寄存器宽度 | 说明 |
|------|------|------------|------|
| SSE | 1999 | 128位(XMM) | 4个单精度浮点数 |
| SSE4.1 | 2007 | 128位 | 支持点积等操作 |
| AVX | 2011 | 256位(YMM) | 仅支持浮点 |
| AVX2 | 2013 | 256位 | 支持整数运算 |
| AVX-512 | 2016 | 512位(ZMM) | 性能最强 |

**AoS vs SoA数据布局**（⭐常考）：

```c
// AoS: Array of Structure（结构体数组）❌ 不利于SIMD
struct Point { float x, y, z; };
Point points[N];  // 内存布局: x0 y0 z0 x1 y1 z1 x2 y2 z2...
// 同类型数据不连续，无法一次加载多个x值

// SoA: Structure of Array（数组结构体）✅ 利于SIMD
struct Points { float x[N], y[N], z[N]; };
// 内存布局: x0 x1 x2... y0 y1 y2... z0 z1 z2...
// 同类型数据连续，可以一次加载多个x值
```

> 📖 **记忆技巧**：SIMD需要连续相同类型的数据做运算，SoA满足这个特点。
> 
> 💡 **为什么SoA更好**：SIMD一条指令要同时处理多个同类型数据（如4个x坐标），SoA中x是连续存储的，可以一次性加载到SIMD寄存器中。

**AVX2编程示例**：

```c
#include <immintrin.h>

__m256 a, b, c;        // 声明256位AVX寄存器
// 初始化 a 和 b
c = _mm256_add_ps(a, b); // c[0:8] = a[0:8] + b[0:8]，一次处理8个float
```

**向量内积优化对比**：

| 方式 | 每次处理 | 编译选项 |
|------|----------|----------|
| 标量 | 1个乘加 | 默认 |
| SSE | 4个乘加 | `-msse4.1` |
| AVX | 8个乘加 | `-mavx` |

## 四、处理器技术

### 4.1 多核处理器

**为什么转向多核**：
- 单核频率提升遇到功耗墙
- 多个中等性能核心 > 一个超高频核心
- 时钟频率基本不变，但"宽度"增加

**双核 vs 超线程（HT）**：

| 特性 | 超线程(HT) | 双核(Dual Core) |
|------|-----------|-----------------|
| 物理核心 | 1个 | 2个 |
| 线程数 | 2个 | 2个（可支持HT则4个）|
| 资源冲突 | 可能发生（如两个浮点线程）| 不会发生 |
| 缓存/寄存器 | 共享 | 各自独立 |
| 性能提升 | 约1/3 | 接近2倍 |

> 💡 **关键理解**：超线程是"假装"有两个处理器，双核是"真的"有两个处理器。两个浮点线程在HT上会争抢资源，在双核上不会。

### 4.2 GPU（图形处理器）

**GPU的设计哲学**：
- 将更多晶体管用于**数据处理**，而非控制和存储
- 适合大规模**数据并行**任务
- 单个GPU核心简单，但数量极多（数千个）

**CPU vs GPU对比**：

| 特性 | CPU | GPU |
|------|-----|-----|
| 核心数 | 少（几到几十个）| 多（数千个）|
| 单核性能 | 强 | 弱 |
| 控制逻辑 | 复杂 | 简单 |
| 适合任务 | 串行、逻辑复杂 | 大规模并行、数据密集 |
| 缓存 | 大 | 小 |

**GPU编程模型**：
- **SPMD**（Single Program Multiple Data）：同一程序在不同数据上执行
- 典型框架：**CUDA**（NVIDIA）、OpenCL

**CUDA架构简介**：

```
CPU (Host)                  GPU (Device)
┌─────────┐                ┌─────────────────┐
│ C/C++   │ ──Kernel──→   │ Grid            │
│ Host    │                │ ┌───┐ ┌───┐     │
│ Code    │                │ │Blk│ │Blk│ ... │
└─────────┘                │ │0,0│ │1,0│     │
                           │ └───┘ └───┘     │
                           │ ┌───┐ ┌───┐     │
                           │ │Blk│ │Blk│ ... │
                           │ │0,1│ │1,1│     │
                           │ └───┘ └───┘     │
                           └─────────────────┘
```

每个Block包含多个Thread，同一Block内的Thread可以共享内存和同步。

### 4.3 APU与MIC

**APU（Accelerated Processing Unit）**：
- CPU + GPU集成在同一芯片上
- AMD提出，兼顾串行和并行处理能力

**MIC（Many Integrated Core）/ Intel Phi**：
- Intel的众核架构
- 典型产品：Xeon Phi
  - 57个核心，1.1GHz主频
  - 28.5MB缓存
  - 8GB内存，12通道
- 2013年天河二号使用了大量Xeon Phi协处理器

## 五、互连网络

> ⚠️ **PPT 02重要考点**：互连网络的分类和拓扑结构

互连网络决定处理器之间如何通信，分为两大类：

### 5.1 静态互连网络

处理单元之间有**固定连接**，程序执行期间连接不变。

| 拓扑 | 特点 | 节点度 | 直径 | 对剖宽度 |
|------|------|--------|------|----------|
| **一维线性阵列** | 首尾不相连 | 2 | N-1 | 1 |
| **环** | 首尾相连 | 2 | N/2 | 2 |
| **2D网孔(Mesh)** | 每个节点连上下左右 | 4 | 2(√N-1) | √N |
| **2D环绕(Torus)** | Mesh + 环绕 | 4 | √N | 2√N |
| **二叉树** | 父子节点连接 | 3 | 2logN | 1 |
| **胖树(Fat Tree)** | 向根方向通路变宽 | — | 2logN | N/2 |
| **超立方(Hypercube)** | d维有2^d个节点 | d | d | 2^(d-1) |

> 💡 **节点度**：一个节点连接的邻居数。**直径**：任意两点间最短路径的最大值。**对剖宽度**：将网络分成两半需要切断的最少边数。

**常见拓扑图示**：

```
一维线性阵列:    [0]─[1]─[2]─[3]

环:              [0]─[1]
                  │   │
                 [3]─[2]

2D Mesh:         [0]─[1]
                  │   │
                 [2]─[3]

超立方(3D):      [000]──[001]       4维：2^4=16个节点
                  │  ╲  │  ╲        每个节点度=4
                 [010]──[011]
```

### 5.2 动态互连网络

用**交换开关**构成，可根据程序需要动态改变连接。

| 类型 | 说明 | 应用 |
|------|------|------|
| **总线(Bus)** | 共享介质，简单但带宽有限 | SMP、小型多处理器 |
| **交叉开关(Crossbar)** | NxN全连接，无阻塞 | 高端服务器 |
| **多级互连网络(MIN)** | 多级交叉开关级联 | Omega网络等 |

```
总线:     CPU0 ─┐
               ├──[共享总线]── 内存
         CPU1 ─┘

交叉开关:        输出
              0  1  2  3
         0  [ ╲│  │  │ ]    任意输入可连接任意输出
输入     1  [ ─╳──│──│  ]    (不冲突时)
         2  [ │╲─╳──│  ]
         3  [ │──│╲─╳  ]
```

## 六、内存架构与访问模式

### 6.1 共享存储 vs 分布式存储

**共享存储模型**：

| 类型 | 全称 | 特点 |
|------|------|------|
| **UMA** | Uniform Memory Access | 所有处理器访问内存时间相同，扩展性有限 |
| **NUMA** | Non-Uniform Memory Access | 访问本地内存快，远程内存慢，扩展性好 |

```
UMA架构：                    NUMA架构：
┌─────────────────┐         ┌────────┐  ┌────────┐
│   CPU1    CPU2  │         │CPU  MEM│  │CPU  MEM│
│      \  /      │         │  \    /│  │  \    /│
│    共享内存     │         │  本地   │──│  本地   │
│      /  \      │         │  可访问远│  │  可访问远│
│   CPU3    CPU4  │         └────────┘  └────────┘
└─────────────────┘
```

**分布式存储模型**：
- 每个物理节点有**私有存储空间**
- 节点之间通过**高速网络**连接
- 不能直接访问其他节点的内存，需要通过**消息传递**（如MPI）

> 🎯 **必考概念**：UMA和NUMA的核心区别——访问延迟是否均匀

### 6.2 存储器层次结构

```
        ┌─────────┐
        │ 寄存器  │  ← 最快(~0.5ns)，容量最小(字节级)
        ├─────────┤
        │ L1 Cache│  ← ~1ns，~64KB
        ├─────────┤
        │ L2 Cache│  ← ~10ns，~256KB-1MB
        ├─────────┤
        │ L3 Cache│  ← ~40ns，~数MB-数十MB
        ├─────────┤
        │  主存   │  ← ~100ns，GB级
        ├─────────┤
        │  磁盘   │  ← 最慢(ms级)，TB级
        └─────────┘
```

### 6.3 缓存优化原则

**时间局部性（Temporal Locality）**：
- 最近访问的数据很可能再次被访问
- 循环变量、频繁使用的变量应保持在缓存中

**空间局部性（Spatial Locality）**：
- 访问某数据后，很可能访问其相邻数据
- C语言中数组按行访问比按列访问更高效

**矩阵乘法优化示例**：

```c
// ❌ 差：按列访问，缓存命中率低
for (j = 0; j < n; j++)
    for (i = 0; i < n; i++)
        C[i][j] += A[i][k] * B[k][j];

// ✅ 好：按行访问，缓存命中率高
for (i = 0; i < n; i++)
    for (j = 0; j < n; j++)
        C[i][j] += A[i][k] * B[k][j];
```

### 6.4 多层混合并行计算

现代超算系统的典型架构：
- **节点内**：OpenMP/多线程 + GPU加速
- **节点间**：MPI消息传递

```
┌───────节点0─────────┐     ┌───────节点1─────────┐
│  CPU     CPU        │     │  CPU     CPU        │
│ Thread Thread       │     │ Thread Thread       │
│    GPU加速          │     │    GPU加速          │
│                     │←───→│                     │
│      OpenMP共享内存  │ MPI │      OpenMP共享内存  │
└─────────────────────┘     └─────────────────────┘
```

## 七、并行计算系统体系结构

### 7.1 系统分类

| 类型 | 全称 | 存储 | 通信方式 | 代表 |
|------|------|------|----------|------|
| **PVP** | Parallel Vector Processor | 共享 | 专用向量单元 | 银河I、NEC地球模拟器 |
| **SMP** | Symmetric Multiprocessor | 共享(UMA) | 总线/交叉开关 | 多核服务器 |
| **MPP** | Massively Parallel Processor | 分布式 | 专用互连网络 | 天河系列、Cray |
| **Cluster** | 集群 | 分布式 | 商用网络 | Google集群 |

### 7.2 SMP（对称多处理器）

- 多个处理器通过**总线或交叉开关**连接到共享存储器
- 每个处理器等同地访问共享内存和I/O设备
- **扩展性有限**（总线带宽限制）
- 多核CPU本质上可视为SMP

### 7.3 MPP（大规模并行处理器）

- 采用商品微处理器
- **物理上的分布式存储器**
- 使用高带宽低延迟的**专用互连网络**
- 可扩展至成千上万个处理器
- 异步MIMD，进程间通过消息传递通信

### 7.4 集群（Cluster）

**定义**：由高速网络连接的高性能工作站/PC组成，作为一个统一的资源对外服务。

**优点**：
- 投资风险小（使用商用硬件）
- 系统结构灵活
- 性能/价格比高
- 可扩展性好

**缺点**：
- 通信性能受限于商用网络
- 并行编程环境复杂

**集群分类**：

| 类型 | 特点 | 优化目标 |
|------|------|----------|
| **HPC集群** | 科学计算、并行计算 | 计算性能 |
| **大数据集群** | 分布式数据处理 | IO与存储性能 |
| **HA集群** | 在线服务、负载均衡 | 可靠性、低延迟 |

**集群管理系统**：
- **PBS（Portable Batch System）**：历史悠久，包含openPBS、PBS Pro、Torque
- **Slurm**：TOP500超算中约60%使用，大规模集群首选

## 八、名词解释汇总

| 术语 | 英文 | 定义 |
|------|------|------|
| **并行计算** | Parallel Computing | 同时使用多个计算资源解决问题 |
| **UMA** | Uniform Memory Access | 统一内存访问，所有处理器访问时间相同 |
| **NUMA** | Non-Uniform Memory Access | 非统一内存访问，本地/远程访问时间不同 |
| **SIMD** | Single Instruction Multiple Data | 单指令多数据，一条指令处理多个数据 |
| **MIMD** | Multiple Instruction Multiple Data | 多指令多数据，多处理器独立执行 |
| **PRAM** | Parallel Random Access Machine | 并行随机访问机，理想并行模型 |
| **EREW** | Exclusive Read Exclusive Write | PRAM模型，不能并发读写 |
| **CREW** | Concurrent Read Exclusive Write | PRAM模型，可并发读 |
| **CRCW** | Concurrent Read Concurrent Write | PRAM模型，可并发读写 |
| **FLOPS** | Floating-point Operations Per Second | 每秒浮点运算次数 |
| **集群** | Cluster | 多台计算机通过网络连接组成的并行系统 |
| **MPP** | Massively Parallel Processor | 大规模并行处理器 |
| **SMP** | Symmetric Multiprocessor | 对称多处理器 |
| **AoS** | Array of Structure | 结构体数组，不利于SIMD |
| **SoA** | Structure of Array | 数组结构体，利于SIMD |
| **缓存** | Cache | 处理器与主存之间的高速存储器 |
| **局部性** | Locality | 程序访问内存的规律性（时间/空间） |
| **域分解** | Domain Decomposition | 先划分数据再确定操作 |
| **任务分解** | Task Decomposition | 先划分任务再确定数据 |
| **流水线** | Pipelining | 任务分阶段并行处理 |
| **功耗墙** | Power Wall | 主频提升受限于功耗和散热 |
| **存储墙** | Memory Wall | 内存速度落后于CPU速度 |
| **超线程** | Hyper-Threading | 单核模拟多线程的技术 |
| **CUDA** | Compute Unified Device Architecture | NVIDIA的GPU编程框架 |
