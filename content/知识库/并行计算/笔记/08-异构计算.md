## 1 指令集基础

### 1.1 什么是指令集？

> [!tip] 通俗理解
> 指令集就像CPU的"词汇表"——CPU能理解和执行的所有指令的集合。不同架构的CPU有不同的指令集（如x86、ARM、RISC-V），就像不同国家说不同语言。

![指令集概览](/知识库/并行计算/assets/08_instruction_set.jpg)

### 1.2 程序语言的层次

从高级语言到硬件执行，代码经历多层转换：

![程序语言层次](/知识库/并行计算/assets/08_program_levels.jpg)

```
高级语言(C/C++/Python)
    ↓ 编译器
汇编语言
    ↓ 汇编器
机器码（二进制指令）
    ↓ CPU执行
```

### 1.3 指令格式

典型指令包含：
- **opcode**：操作码（做什么操作）
- **Rs/Rt/Rd**：源/目标寄存器
- **displacement/immediate**：偏移量或立即数

常见指令格式：
- `LW Rt, displacement(Rs)` — 加载字
- `SW Rt, displacement(Rs)` — 存储字
- `ADD Rd, Rs, Rt` — 加法
- `BEQ Rs, Rt, offset` — 分支跳转

## 2 异构并行计算平台

### 2.1 什么是异构并行计算？

> [!tip] 通俗理解
> **异构** = 计算系统中包含多种不同架构的处理器（如CPU+GPU、CPU+FPGA）
> **并行** = 这些处理器都支持并行计算

**为什么要异构？**
- 不同处理器擅长不同任务：
  - **CPU**：复杂逻辑判断、控制流
  - **GPU**：大规模并行向量计算
  - **FPGA**：定制化高效计算
- 将合适的任务交给合适的处理器 → 获得更好的性能和能耗比

### 2.2 协处理器类型

| 类型 | 代表 | 特点 |
|-----|------|------|
| **GPU** | NVIDIA Tesla、AMD MI系列 | 大规模并行，SIMT模式 |
| **FPGA** | Xilinx Virtex、Intel Stratix | 半定制电路，可重配 |
| **ASIC** | Google TPU、华为昇腾 | 专用芯片，极致效率 |
| **NPU** | 各家神经网络处理器 | 专为AI/深度学习设计 |
| **DCU** | 海光DCU | 深度计算单元 |

### 2.5 FPGA（现场可编程门阵列）

> [!tip] 通俗理解
> FPGA就像一个"可以重新连线的电路板"——你可以通过编程改变芯片内部的电路连接，实现不同的硬件功能。

![FPGA结构](/知识库/并行计算/assets/08_fpga_structure.jpg)

**优点**：
- 可无限重新编程，加载新设计只需几百毫秒
- 支持深度可变的流水线
- 内置存储器，存储器和运算逻辑紧密结合

**缺点**：
- 所有功能依靠硬件实现，不能直接做浮点运算
- 需要硬件描述语言（Verilog/VHDL），开发门槛高

### 2.6 ASIC（专用集成电路）

> [!tip] 通俗理解
> ASIC是为某个特定算法"量身定做"的芯片，就像定制的工具——只能做一件事，但做得极致高效。

![ASIC芯片](/知识库/并行计算/assets/08_asic_chip.jpg)

### 2.7 各平台对比

| 平台 | 上市速度 | 性能 | 可配置性 | 适用场景 |
|-----|---------|------|---------|---------|
| **CPU** | — | 通用 | 完全 | 复杂逻辑控制 |
| **GPU** | — | 高 | 软件可编程 | 大规模并行计算 |
| **FPGA** | 快 | 中等(1x) | 完全 | 企业/军工定制 |
| **ASIC** | 慢 | 最优(10x) | 有限 | 消费电子量产 |

## 3 编程环境与编程模型

### 3.1 OpenCL

> [!tip] 通俗理解
> OpenCL是一个"通用翻译器"——它让你可以用同一套代码在CPU、GPU、FPGA等各种设备上运行，实现跨平台的异构并行编程。

**特点**：
- Apple设计，Khronos Group维护（2008年）
- 基于纯C语言的API
- 支持数据并行与任务并行

#### OpenCL平台模型

![OpenCL平台模型](/知识库/并行计算/assets/08_opencl_platform.jpg)

```
主机(Host)  →  设备(Device)  →  计算单元(Compute Unit)  →  处理单元(Processing Element)
```

#### OpenCL内存模型

![OpenCL内存模型](/知识库/并行计算/assets/08_opencl_memory.jpg)

| 内存类型 | 范围 | 速度 |
|---------|------|------|
| Global Memory | 所有设备可访问 | 慢 |
| Constant Memory | 只读，所有设备 | 中 |
| Local Memory | 工作组内共享 | 快 |
| Private Memory | 单个工作项私有 | 最快 |

## 4 GPU/DCU并行编程

### 4.1 CUDA 简介

CUDA是NVIDIA推出的GPU通用计算平台（2006年），采用**SIMT**（单指令多线程）模式。

**软件栈**：
```
GPU计算应用（科学计算、深度学习...）
    ↓
库与中间件（cuBLAS、cuDNN、cuFFT...）
    ↓
编程语言（C/C++/Fortran/Python）
    ↓
CUDA运行时/驱动
    ↓
NVIDIA GPU硬件
```

### 4.2 DCU软件栈（HIP）

DCU使用HIP编程模型，API与CUDA高度兼容：

![DCU软件栈](/知识库/并行计算/assets/08_dcu_software_stack.jpg)

### 4.3 Host-Device 模型

> [!tip] 通俗理解
> **Host**（CPU）是"指挥官"，负责控制流程和调度；
> **Device**（GPU）是"工人"，负责大规模并行计算。

![Host-Device模型](/知识库/并行计算/assets/08_host_device.jpg)

**CUDA程序基本流程**：
```
1. Host分配内存 → malloc()
2. Device分配显存 → cudaMalloc()
3. 数据拷贝 Host→Device → cudaMemcpy()
4. 启动Kernel（GPU计算）→ kernel<<<grid, block>>>()
5. 结果拷贝 Device→Host → cudaMemcpy()
6. 释放内存 → cudaFree() / free()
```

### 4.4 CUDA Hello World

```c
// 最简单的kernel（空函数）
__global__ void mykernel(void) { }

int main(void) {
    mykernel<<<1, 1>>>();  // 在GPU上执行1次
    printf("Hello World!\n");
    return 0;
}
```

> `__global__` 表示此函数在Device上执行，从Host调用。

### 4.5 GPU求和计算

**Kernel（Device端）**：
```c
__global__ void add(int *a, int *b, int *c) {
    *c = *a + *b;
}
```

**Main（Host端）**：
```c
int main(void) {
    int a = 2, b = 7, c;
    int *d_a, *d_b, *d_c;

    // 1. Device分配内存
    cudaMalloc((void**)&d_a, sizeof(int));
    cudaMalloc((void**)&d_b, sizeof(int));
    cudaMalloc((void**)&d_c, sizeof(int));

    // 2. 拷贝数据 Host→Device
    cudaMemcpy(d_a, &a, sizeof(int), cudaMemcpyHostToDevice);
    cudaMemcpy(d_b, &b, sizeof(int), cudaMemcpyHostToDevice);

    // 3. 启动Kernel
    add<<<1, 1>>>(d_a, d_b, d_c);

    // 4. 拷贝结果 Device→Host
    cudaMemcpy(&c, d_c, sizeof(int), cudaMemcpyDeviceToHost);

    // 5. 释放
    cudaFree(d_a); cudaFree(d_b); cudaFree(d_c);
    return 0;
}
```

### 4.6 并行向量加法

#### 使用并行Block

每个Block处理一个元素：
```c
__global__ void add(int *a, int *b, int *c) {
    c[blockIdx.x] = a[blockIdx.x] + b[blockIdx.x];
}

// 调用：add<<<N, 1>>>(d_a, d_b, d_c);  // N个Block，每个1个Thread
```

#### 使用并行Thread

每个Thread处理一个元素：
```c
__global__ void add(int *a, int *b, int *c) {
    c[threadIdx.x] = a[threadIdx.x] + b[threadIdx.x];
}

// 调用：add<<<1, N>>>(d_a, d_b, d_c);  // 1个Block，N个Thread
```

#### Block + Thread 组合

```c
__global__ void add(int *a, int *b, int *c) {
    int index = threadIdx.x + blockIdx.x * blockDim.x;
    c[index] = a[index] + b[index];
}

// 调用：add<<<N/512, 512>>>(d_a, d_b, d_c);
```

![Block+Thread索引](/知识库/并行计算/assets/08_block_thread_index.jpg)

> [!warning] 数组越界保护
> 当向量长度不是 `blockDim.x` 的整数倍时，最后一个Block可能越界：
> ```c
> int index = threadIdx.x + blockIdx.x * blockDim.x;
> if (index < n)  // 边界检查
>     c[index] = a[index] + b[index];
> ```

### 4.7 HIP/DCU 版向量加

DCU使用HIP编程，API与CUDA类似：

```c
#include "hip/hip_runtime.h"

__global__ void add(float *d_A, float *d_B, float *d_C) {
    int tid = threadIdx.x + blockIdx.x * blockDim.x;
    if (tid < N)
        d_C[tid] = d_A[tid] + d_B[tid];
}

int main() {
    // 申请空间
    hipMalloc((void**)&d_A, N * sizeof(float));
    hipMalloc((void**)&d_B, N * sizeof(float));
    hipMalloc((void**)&d_C, N * sizeof(float));

    // 拷贝数据
    hipMemcpy(d_A, A, sizeof(float) * N, hipMemcpyHostToDevice);
    hipMemcpy(d_B, B, sizeof(float) * N, hipMemcpyHostToDevice);

    // 执行Kernel
    dim3 blocksize(256, 1);
    dim3 gridsize(N / 256 + 1, 1);
    add<<<gridsize, blocksize>>>(d_A, d_B, d_C);

    // 拷回结果
    hipMemcpy(C, d_C, sizeof(float) * N, hipMemcpyDeviceToHost);
}
```

### 4.8 线程层次结构

![线程层次](/知识库/并行计算/assets/08_thread_hierarchy.jpg)

```
Grid（整个任务）
 ├── Block(0,0)    → Thread(0,0), Thread(0,1), ...
 ├── Block(0,1)    → Thread(0,0), Thread(0,1), ...
 ├── Block(1,0)    → Thread(0,0), Thread(0,1), ...
 └── ...
```

**内置变量**：
| 变量 | 含义 |
|-----|------|
| `gridDim` | Grid的维度 |
| `blockIdx` | Block在Grid中的坐标 |
| `blockDim` | Block的维度（每Block的Thread数） |
| `threadIdx` | Thread在Block中的坐标 |
| `warpSize` | Warp大小（固定为32） |

**矩阵加法示例（多Block）**：
```c
__global__ void MatAdd(float A[N][N], float B[N][N], float C[N][N]) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    int j = blockIdx.y * blockDim.y + threadIdx.y;
    if (i < N && j < N)
        C[i][j] = A[i][j] + B[i][j];
}

// 调用
dim3 threadsPerBlock(16, 16);
dim3 numBlocks(N/16, N/16);
MatAdd<<<numBlocks, threadsPerBlock>>>(A, B, C);
```

### 4.9 CUDA存储器层次

![内存层次](/知识库/并行计算/assets/08_memory_hierarchy.jpg)

| 存储器 | 位置 | 容量 | 速度 | 访问范围 |
|-------|------|------|------|---------|
| **Register** | 芯片内 | KB级 | 最快 | 线程私有 |
| **Shared Memory** | 芯片内 | 几十KB | 快 | Block内共享 |
| **Global Memory** | 显存 | GB级 | 慢 | Grid内所有线程 |
| **Constant Memory** | 显存 | KB级 | 只读 | Grid内所有线程 |

#### CUDA函数类型修饰符

| 修饰符 | 执行位置 | 调用位置 |
|-------|---------|---------|
| `__global__` | GPU | Host调用 |
| `__device__` | GPU | GPU调用 |
| `__host__`（默认） | CPU | CPU调用 |

#### CUDA变量类型修饰符

| 修饰符 | 存储位置 | 访问范围 |
|-------|---------|---------|
| `__device__` | Global Memory | Grid所有线程 |
| `__constant__` | Constant Memory | Grid所有线程（只读） |
| `__shared__` | Shared Memory | Block内线程 |

### 4.10 共享内存与同步

**Shared Memory**：片上高速存储，Block内线程可共享

```c
__shared__ int temp[BLOCK_SIZE + 2 * RADIUS];  // 声明共享内存
```

**同步函数**：
```c
__syncthreads();  // Block内所有线程同步（路障）
```

> [!warning] 竞态条件
> 当多个线程同时读写共享内存中的同一位置时，可能产生错误结果。必须使用 `__syncthreads()` 确保所有线程完成写操作后再进行读操作。

#### 示例：1D Stencil

对数组每个元素，计算其邻域内元素的和：

```c
__global__ void stencil_1d(int *in, int *out) {
    __shared__ int temp[BLOCK_SIZE + 2 * RADIUS];
    int gindex = threadIdx.x + blockIdx.x * blockDim.x;
    int lindex = threadIdx.x + RADIUS;

    // 读入数据到共享内存
    temp[lindex] = in[gindex];
    if (threadIdx.x < RADIUS) {
        temp[lindex - RADIUS] = in[gindex - RADIUS];
        temp[lindex + BLOCK_SIZE] = in[gindex + BLOCK_SIZE];
    }

    __syncthreads();  // 确保所有数据就绪

    // 计算stencil
    int result = 0;
    for (int offset = -RADIUS; offset <= RADIUS; offset++)
        result += temp[lindex + offset];

    out[gindex] = result;
}
```

### 4.11 性能优化原则

| 优化方向 | 要点 |
|---------|------|
| **算法选择** | 并行性是首要因素，时间复杂度低未必合适 |
| **并行度** | GPU线程切换效率高，使用尽可能多的线程 |
| **数据传输** | 次数少、量少、异步传输 |
| **存储访问** | 利用Shared Memory减少Global Memory访问 |
| **避免分支** | 同一个Warp内的线程应尽量走相同分支 |

## 小结

| 主题 | 核心要点 |
|-----|---------|
| **异构计算** | 不同架构处理器协作，各取所长 |
| **平台类型** | GPU（并行）、FPGA（可配）、ASIC（专用）、NPU（AI） |
| **CUDA/HIP** | Host-Device模型，SIMT并行 |
| **线程层次** | Grid → Block → Thread，内置变量管理 |
| **存储层次** | Register → Shared → Global，速度递减容量递增 |
| **同步** | `__syncthreads()` 避免竞态条件 |
