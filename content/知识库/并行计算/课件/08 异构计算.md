# 异构计算

## 什么异构并行计算？

### 异构
计算系统中同时包括多种不同架构的处理器：
- **X86 + GPU**、**X86 + FPGA**、**ARM/Power + GPU** 等
- 不同架构处理器对应不同的指令集

### 并行
- 异构计算环境本身要求应用程序支持并行计算
- 无论是X86、ARM、GPU还是DSP，都是多核向量处理器
- 要发挥混合平台性能，必须采用并行编程方式

---

## 为什么需要异构并行计算？

### 不同处理器适合不同计算
- 将逻辑判别、调度分配到X86通用CPU
- 将大规模向量计算分配到GPU
- 为特定应用设计定制架构（如NPU处理神经网络）

### 性能、功耗与通用性难以兼得
| 类型 | 架构特点 | 开发成本 | 量产成本 | 可配置性 | 目标市场 |
|------|---------|---------|---------|---------|---------|
| FPGA | 可重构逻辑，开发周期短 | 低 | 高（100×） | 完全 | 企业军工 |
| ASIC | 算法固定，无冗余 | 高 | 低（1×） | 有限 | 消费电子 |

## 异构并行计算平台

### 异构处理器类型

| 类型 | 说明 | 代表产品 |
|------|------|---------|
| GPU | 大规模数据并行，SIMT模式 | NVIDIA Tesla, AMD Radeon |
| DPU（Deep Computing Unit） | CPU+GPU集成，能效优化 | AMD APU |
| FPGA | 半定制电路，可重构 | Xilinx, Altera(Intel) |
| ASIC | 全定制，最优能效比 | DianNao（神经网络芯片） |
| NPU | 神经网络专用，非冯·诺伊曼结构 | Google TPU, 华为昇腾 |

### GPU vs CPU

| 对比项 | CPU | GPU |
|--------|-----|-----|
| 晶体管用途 | 70%缓存，少量计算单元 | 大部分计算单元，少量缓存 |
| 设计目标 | 低延迟、复杂逻辑 | 高吞吐、简单计算 |
| 适用场景 | 通用计算、复杂逻辑 | 大规模并行计算 |
| 性能示例 | E5-2690: 1.33 TFLOPS, 145W | Tesla K80: 8.74 TFLOPS, 300W |

### FPGA 特点

**优点**：
- 支持深度可变的流水线结构，一个时钟周期完成复杂功能
- 通过Verilog/VHDL编程，可无限次重配置
- 内置存储器，带宽不受I/O引脚限制
- 工作频率可根据设计调整

**缺点**：
- 无法实现复杂分支跳转
- 不能直接实现浮点运算（需IP核）
- 开发难度高，需了解底层硬件特性

### ASIC 特点

**优点**：体积小、功耗低、计算性能高、量产成本低
**缺点**：算法固定，一旦变化无法使用；开发风险大，研发到市场周期长

### NPU（神经网络处理器）

- 专为神经网络计算设计
- 非冯·诺伊曼结构（存储与计算分离）
- 适于处理视频、图像等海量多媒体数据

**基本神经网络计算**：
- 卷积层（Convolution）→ 特征提取
- 池化层（Pooling）→ 降维
- 分类层（Classifier）→ 输出结果

## 编程环境与编程模型

### OpenCL（Open Computing Language）

- Apple设计，Khronos Group维护（2008年推出）
- 异构平台并行编程的开放标准/框架
- 支持CPU、GPU和其他加速器
- 支持数据并行与任务并行
- API基于纯C语言编写
- NVIDIA、AMD、Intel的OpenCL实现仅支持自家产品

#### OpenCL平台模型
```
Host（主机）
  ├── Platform（平台，如NVIDIA CUDA/AMD OpenCL）
  │     ├── Device 0（如GPU 0）
  │     │     ├── Compute Unit 0 → Processing Element ...
  │     │     ├── Compute Unit 1 → Processing Element ...
  │     │     └── ...
  │     └── Device 1（如GPU 1）
  └── Context（上下文，管理所有对象）
```

#### OpenCL执行模型
- **主机端程序**：控制整个并行执行流程
- **设备端内核（Kernel）**：在设备上执行的并行函数
- **原生内核**：OpenCL之外创建的函数（通过函数指针访问）
- **内建内核**：绑定到特定设备，无需再编译

#### OpenCL内存模型

| 内存类型 | 说明 |
|---------|------|
| 主机内存（Host Memory） | 主机可直接访问 |
| 全局内存（Global Memory） | 所有计算单元共享访问 |
| 常量内存（Constant Memory） | 只读，所有计算单元可访问 |
| 局部内存（Local Memory） | 计算单元内共享，工作组内可见 |
| 私有内存（Private Memory） | 单个处理单元私有 |

### CUDA（NVIDIA）

- 2006年推出，支持C/C++/Fortran
- SIMT模式（Single Instruction, Multiple Threads）
- 参考文档：https://docs.nvidia.com/cuda/

#### CUDA程序基本结构
```c
int main(int argc, char** argv) {
    // 1. 在主机分配内存
    malloc() → host数据

    // 2. 在设备分配内存
    cudaMalloc() → device数据

    // 3. 拷贝输入数据到设备
    cudaMemcpy(host → device)

    // 4. 设置网格和块维度
    dim3 dimGrid, dimBlock;

    // 5. 启动kernel
    kernel_name<<dimGrid, dimBlock>>>(args);

    // 6. 拷贝结果回主机
    cudaMemcpy(device → host)

    // 7. 释放内存
    cudaFree(), free()
}
```

#### Hello World!
```c
__global__ void mykernel(void) { }

int main(void) {
    mykernel<<<1,1>>>();
    printf("Hello World!\n");
    return 0;
}
// 编译：nvcc hello.cu
```

#### 向量加示例
```c
// kernel定义
__global__ void add(int *a, int *b, int *c) {
    c[blockIdx.x] = a[blockIdx.x] + b[blockIdx.x];
}

int main(void) {
    int a=2, b=7, c;
    int *d_a, *d_b, *d_c;
    int size = sizeof(int);

    cudaMalloc((void**)&d_a, size);
    cudaMalloc((void**)&d_b, size);
    cudaMalloc((void**)&d_c, size);

    cudaMemcpy(d_a, &a, size, cudaMemcpyHostToDevice);
    cudaMemcpy(d_b, &b, size, cudaMemcpyHostToDevice);

    add<<<1,1>>>(d_a, d_b, d_c);

    cudaMemcpy(&c, d_c, size, cudaMemcpyDeviceToHost);

    cudaFree(d_a); cudaFree(d_b); cudaFree(d_c);
    printf("Result: %d\n", c);  // 输出9
    return 0;
}
```

#### CUDA线程层次

```
Grid（网格）
  ├── Block 0
  │     ├── Thread 0
  │     ├── Thread 1
  │     └── ...
  ├── Block 1
  │     └── ...
  └── Block N-1
```

- **Grid**：对应一个Kernel，由多个Block组成
- **Block**：包含多个Thread，可同步、可共享局部内存
- **Thread**：最基本执行单元

#### 内置变量

| 变量 | 类型 | 说明 |
|------|------|------|
| `gridDim` | `dim3` | Grid的维度 |
| `blockIdx` | `uint3` | Block在Grid中的坐标 |
| `blockDim` | `dim3` | Block的维度 |
| `threadIdx` | `uint3` | Thread在Block中的坐标 |
| `warpSize` | `int` | Warp大小（固定32） |

#### 内存层次

| 内存类型 | 说明 | 速度 | 容量 |
|---------|------|------|------|
| Register | 线程私有 | 最快 | KB级 |
| Local Memory | 线程私有（实际在设备内存） | 慢 | KB级 |
| Shared Memory | Block内共享 | 快 | 几十KB |
| Global Memory | 所有线程可访问 | 慢 | GB级 |
| Constant Memory | 只读，所有线程可访问 | 快（有缓存） | KB级 |
| Texture Memory | 只读，有缓存 | 快 | KB级 |

#### 内存分配

| 函数 | 说明 |
|------|------|
| `cudaMalloc()` | 一维数组，数据连续存储 |
| `cudaMallocPitch()` | 二维数组，自动对齐 |
| `cudaMalloc3D()` | 三维数组 |

#### 统一寻址（Unified Memory，CUDA 6.0+）

- 在Host内存与Device显存之间根据访问需要自动迁移数据
- Host和Device都可访问同一指针
- 需要进行显式同步（保证前一步骤完成）

```c
// 方法1：cudaMallocManaged
__device__ __managed__ int ret[1000];

__global__ void AplusB(int a, int b) {
    ret[threadIdx.x] = a + b + threadIdx.x;
}

int main() {
    AplusB<<<1,1000>>>(10, 100);
    cudaDeviceSynchronize();  // 同步
    for (int i=0; i<1000; i++)
        printf("%d: 10+100+%d = %d\n", i, i, ret[i]);
    return 0;
}
```

## GPU/DCU 并行编程

### DCU（Deep Computing Unit）

- 与GPU类似，采用SIMT模式
- 编程模型类似CUDA，使用HIP（Heterogeneous-compute Interface for Portability）
- 软件栈：类似CUDA，支持C/C++/Fortran

#### DCU向量加示例（HIP）
```c
#include <hip/hip_runtime.h>

__global__ void add(float *d_A, float *d_B, float *d_C, int n) {
    int tid = threadIdx.x + blockIdx.x * blockDim.x;
    if (tid < n)
        d_C[tid] = d_A[tid] + d_B[tid];
}

int main() {
    const int N = 10000;
    float *A = (float*)malloc(N * sizeof(float));
    float *B = (float*)malloc(N * sizeof(float));
    float *C = (float*)malloc(N * sizeof(float));
    float *d_A, *d_B, *d_C;

    hipMalloc((void**)&d_A, N * sizeof(float));
    hipMalloc((void**)&d_B, N * sizeof(float));
    hipMalloc((void**)&d_C, N * sizeof(float));

    // 初始化数据
    for (int i=0; i<N; i++) { A[i]=1; B[i]=1; }

    hipMemcpy(d_A, A, N*sizeof(float), hipMemcpyHostToDevice);
    hipMemcpy(d_B, B, N*sizeof(float), hipMemcpyHostToDevice);

    dim3 blockSize(256);
    dim3 gridSize(N/256 + 1);
    add<<<gridSize, blockSize>>>(d_A, d_B, d_C, N);

    hipMemcpy(C, d_C, N*sizeof(float), hipMemcpyDeviceToHost);

    free(A); free(B); free(C);
    hipFree(d_A); hipFree(d_B); hipFree(d_C);
    return 0;
}
```

### 线程管理

#### Warp执行
- GPU线程以Warp（32个线程）为单位调度执行
- 同一Warp内线程执行相同指令（SIMT）
- 分支发散（Branch Divergence）会导致性能下降

#### 块内同步
```c
__syncthreads();  // 同步同一个Block内的所有线程
// 用于避免RAW/WAR/WAW风险
// 所有线程必须都运行到barrier
```

### 共享内存优化

**用途**：Block内线程共享数据，速度远快于全局内存。

**示例：1D Stencil（卷积）**
```c
__global__ void stencil_1d(int *in, int *out, int radius) {
    __shared__ int temp[BLOCK_SIZE + 2*RADIUS];
    int gindex = threadIdx.x + blockIdx.x * blockDim.x;
    int lindex = threadIdx.x + RADIUS;

    // 读数据到共享内存
    temp[lindex] = in[gindex];
    if (threadIdx.x < RADIUS) {
        temp[lindex - RADIUS] = in[gindex - RADIUS];
        temp[lindex + BLOCK_SIZE] = in[gindex + BLOCK_SIZE];
    }

    __syncthreads();  // 等待所有数据就绪

    // 计算stencil
    int result = 0;
    for (int offset = -RADIUS; offset <= RADIUS; offset++)
        result += temp[lindex + offset];

    out[gindex] = result;
}
```

**避免伪共享（False Sharing）**：
- Cache行大小64B，多个线程修改同一Cache行会导致性能下降
- 通过填充（Padding）使每个数据独占Cache行

## 异构计算性能优化

### 算法选择
- 算法并行性是首要因素
- 时间复杂度低未必适合并行

### 并行度
- GPU环境中线程切换效率很高，使用尽可能多的线程数
- 每个Block的线程数建议是32的倍数（Warp大小）

### 数据传输
- 次数尽可能少（合并传输）
- 传输量尽可能少
- 使用异步传输，与计算重叠

### GPUDirect（NVIDIA）

| 技术 | 说明 |
|------|------|
| P2P（Peer-to-Peer） | 同一节点内GPU直接拷贝，无需经过主存 |
| RDMA（Remote Direct Memory Access） | GPU内存直接推送到网卡，无需CPU参与 |
| Unified Memory | 自动数据迁移，简化编程 |

### CPU/GPU异构计算模型

```
┌─────────────────────────────────┐
│            Host (CPU)                │
│  ┌──────────────┐  ┌──────────────┐  │
│  │   Input Data  │  │  Output Data │  │
│  └──────┬───────┘  └──────┬───────┘  │
│         │ Copy              │ Copy        │
│         ▼                  ▼            │
│  ┌─────────────────────────────┐  │
│  │      Device (GPU)            │  │
│  │  ┌──────────────────────┐ │  │
│  │  │   Kernel执行          │ │  │
│  │  │   (SIMT并行)        │ │  │
│  │  └──────────────────────┘ │  │
│  └─────────────────────────────┘  │
└─────────────────────────────────┘
```
