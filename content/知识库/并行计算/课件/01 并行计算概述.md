# 并行计算概述

## 为什么需要并行计算？

- 为满足不断增长的计算力需求
  - 用速度更快的硬件（减少每指令时间）
  - 优化算法或编译
  - **用多个处理器同时解决一个问题 → 并行计算**
- 单处理器性能提升受限：
  - 1986–2002：每年提升50%（每10年增长60倍）
  - 2002以后：每年提升20%（每10年增长6倍）
- 并行计算环境无处不在，应用程序必须支持并行执行才能充分利用计算能力

## 性能衡量

- **FLOPS**：浮点运算数/秒

| 单位 | 数值 |
|------|------|
| K | $10^3$ |
| M | $10^6$ |
| G | $10^9$（10亿） |
| T | $10^{12}$（万亿） |
| P | $10^{15}$（千万亿） |

- 处理器浮点计算能力 = 主频 × 每时钟周期浮点指令数（理论值）
- 示例：Xeon D-2146NT 8核 2.3GHz → 73.6 GFLOPS；NV Tesla V100 → 112 TFLOPS（Tensor）

| 系统 | 年份 | 配置 | 性能 |
|------|------|------|------|
| 深蓝 | 1997 | 32×Power2 CPU + 480 VLSI象棋芯片 | 11.38 GFLOPS，每秒2亿步 |
| 沃森 | 2011 | 90台服务器，2800个Power7处理器，15TB存储 | 80 TFLOPS |
| AlphaGo | 2016-2017 | GPU集群 + Policy/Value网络 | 击败人类顶尖棋手 |
| 大模型（GPT-4/Gemini） | 2023-2024 | 超大规模参数（$\gt 10^9$）、GPU集群 | 训练成本数千万至上亿美元 |

## 超级计算机面临的主要问题

### 应用与研发
- 并行程序编制、调试复杂
- 同步、数据交换困难
- GPU加速模式复杂
- 工具及集成开发环境支持不足
- 商业软件价格昂贵

### 能源消耗
- 算力与数据：国家推动"东数西算"工程，优化算力资源布局

## 并行化方法

| 方法 | 说明 |
|------|------|
| 域分解（Domain Decomposition） | 将数据空间划分到各处理器，每个处理器处理一部分数据 |
| 任务分解（Task Decomposition） | 将计算任务划分到各处理器，每个处理器处理一类任务 |
| 流水线（Pipelining） | 将任务分成多个阶段，各处理器依次处理不同阶段 |

### 指令级流水线示例
经典五级流水线：IF（取指）→ ID（译码）→ EX（执行）→ MA（访存）→ WB（写回）

### 避免流水线冲突
- **结构冲突**：多个指令同时使用同一硬件资源
- **数据冲突**：指令间存在数据依赖
- **控制冲突**：分支跳转导致流水线清空

## 并行计算技术层次

```
应用问题
    ↓
并行算法设计
    ↓
并行程序设计
    ↓
编译/运行时
    ↓
硬件体系结构
```

关键：了解底层硬件特性和并行编程模型，才能写出高效的并行程序。
