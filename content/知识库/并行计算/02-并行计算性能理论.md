## 一、性能基本概念

### 1.1 性能定义

**Performance（性能）**：机器速度的度量，是程序执行时间的**倒数**

$$\text{Performance} = \frac{1}{\text{Execution Time}}$$

> 💡 **通俗理解**：执行时间越短，性能越高。就像赛跑——跑完越快，速度越好。

**程序执行时间的组成**：

| 组成部分 | 说明 |
|----------|------|
| 访问磁盘时间 | 读写硬盘的等待时间 |
| 访问存储器时间 | 从内存读取数据的时间 |
| CPU时间 | CPU实际计算的时间 |
| I/O时间 | 输入输出等待时间 |
| 操作系统开销 | 任务调度、上下文切换等 |

**CPU时间**：CPU实际工作时间，**不包括**I/O等待和其他任务的时间。这是衡量程序本身效率的关键指标。

### 1.2 为什么要进行性能评测？

| 角色 | 目的 |
|------|------|
| **管理员** | 提高并行机使用效率 |
| **用户** | 减少购机盲目性，降低投资风险 |
| **架构师** | 改进系统结构设计，优化"结构-算法-应用"组合 |
| **市场人员** | 提供客观公正的评价标准 |

### 1.3 计算量度量

| 度量方式 | 说明 |
|----------|------|
| 执行时间 (t) | 真实世界时间，最直观 |
| 浮点运算数 (FLOPS) | 理论计算量 |
| 指令数目 (MIPS) | 百万条指令/秒 |

## 二、并行计算性能指标

### 2.1 并行执行时间

并行执行时间由三部分组成：

$$T_p = T_{comp} + T_{paro} + T_{comm}$$

| 符号 | 含义 | 说明 |
|------|------|------|
| $T_{comp}$ | 计算时间 | 实际做有用计算的时间 |
| $T_{paro}$ | 并行开销时间 | 同步、空闲等待等额外开销 |
| $T_{comm}$ | 通信时间 | 处理器间数据交换时间 |

> 💡 **理解**：串行程序只有计算时间。并行程序除了计算，还要花时间在"协调"和"通信"上，这些都是额外的代价。

### 2.2 核心指标定义

**加速比（Speedup）**：速度提升的倍数

$$S(n) = \frac{T_s}{T_p} = \frac{\text{串行执行时间}}{\text{并行执行时间}}$$

> 💡 **通俗理解**：1个人做要100秒，4个人做只要20秒，加速比 = 100/20 = 5倍。

**效率（Efficiency）**：处理器的利用率

$$E = \frac{S(n)}{n} = \frac{T_s}{n \times T_p}$$

其中 $n$ 为处理器数量。

> 💡 **通俗理解**：4个人干活，如果加速比正好是4（每人贡献100%），效率=1。如果加速比只有2，说明很多人在"摸鱼"，效率=0.5。

**理想情况**：

| 指标 | 理想值 | 含义 |
|------|--------|------|
| 加速比 S | = n | n个处理器快n倍 |
| 效率 E | = 1 (100%) | 每个处理器都在全力工作 |
| 效率 E | = 0.5 (50%) | 一半时间在等待/通信 |

**代价（Cost）**：

$$\text{Cost} = T_p \times n = \text{执行时间} \times \text{处理器数}$$

> 💡 **理解**：代价衡量的是"总共投入了多少计算资源"。一个程序用10个处理器跑10秒，代价 = 100处理器·秒。

**代价的另一种表达**：

$$\text{Cost} = T_p \times n = \frac{T_s}{S(n)} \times n = \frac{T_s}{E}$$

### 2.3 计算/通信比

$$\text{计算通信比} = \frac{T_{comp}}{T_{comm}}$$

| 比值 | 结果 |
|------|------|
| 大 | 并行效率高（通信开销小）|
| 小 | 通信成为瓶颈（花太多时间在传数据）|

> 💡 **理解**：就像快递——真正花在"干活"上的时间越多越好，花在"交接"上的时间越少越好。

### 2.4 并行开销的来源

| 开销类型 | 说明 |
|----------|------|
| 处理器空闲 | 部分处理器在等待数据或同步 |
| 额外计算 | 并行版本中串行版本不需要的计算（如重复计算边界）|
| 通信时间 | 发送/接收消息的延迟和带宽限制 |

## 三、内存系统对性能的影响

> 💡 **为什么单独讲内存**：对很多应用来说，瓶颈不在CPU算得不够快，而在数据供给跟不上。

### 3.1 延迟与带宽

**延迟（Latency）**：
- 处理器发起访问到获取数据所需的时间
- 单位：纳秒(ns)

**带宽（Bandwidth）**：
- 数据传输的速率
- 单位：字节/秒(GB/s)

> 💡 **消防龙头类比**：
> - 打开水龙头后2秒水才流出 → 延迟 = 2秒
> - 水流速5加仑/秒 → 带宽 = 5加仑/秒
> - 想扑灭小火 → 需要低延迟（立即出水）
> - 想扑灭大火 → 需要高带宽（出水量大）

### 3.2 内存延迟的影响

**示例计算**：

假设：
- 处理器主频：1GHz（时钟周期1ns）
- DRAM延迟：100ns（无缓存时）
- 处理器能力：每周期4条指令 → 峰值 4 GFLOPS

计算向量点积：
- 每次浮点运算需要取1个数据
- 每取一次数据需等待100ns
- 实际速度：每100ns一次浮点运算 = **10 MFLOPS**
- 只有峰值的 **0.25%**！

> 💡 **结论**：没有缓存时，内存延迟严重限制了实际性能。

### 3.3 高速缓存的作用

**缓存命中率（Hit Ratio）**：由缓存提供数据的比例。

**示例**：

在上述系统中加入32KB缓存（1ns延迟），计算32×32矩阵乘法：

| 步骤 | 计算 |
|------|------|
| 加载矩阵到缓存 | 2K个字 × 100ns ≈ 200μs |
| 计算量 | 2×32³ = 64K步 |
| 计算时间 | 64K ÷ 4指令/周期 ÷ 1GHz = 16μs |
| 总时间 | 200 + 16 = 216μs |
| **实际速度** | **64K/216μs = 303 MFLOPS** |

对比无缓存的10MFLOPS，性能提升**30倍**！

### 3.4 时间局部性与空间局部性

**时间局部性（Temporal Locality）**：
- 最近访问的数据很可能再次被访问
- 缓存的价值在于**数据的重复使用**

**空间局部性（Spatial Locality）**：
- 访问某数据后，很可能访问其相邻数据
- 连续数据字被连续指令使用

> 💡 **提高性能的关键**：计算次数/内存访问次数 的比值越大越好。即"少访问内存，多做计算"。

**内存带宽的影响示例**：

| 块大小 | 每次访问 | 执行FLOPs | 实际速度 |
|--------|----------|-----------|----------|
| 1个字 | 取1个数据 | 1次 | 10 MFLOPS |
| 4个字 | 取4个数据 | 4次 | 40 MFLOPS |

> 💡 **结论**：增加块大小（提高带宽）可以提升性能，但不改变延迟。

## 四、加速比定律（⭐⭐⭐ 必考！）

### 4.1 基本参数定义

| 符号 | 含义 |
|------|------|
| $P$ 或 $n$ | 处理器数量 |
| $W$ | 问题规模（总计算量/工作负载）|
| $W_s$ | 串行分量 |
| $W_p$ | 可并行化部分 |
| $f$ | 串行分量比例，$f = W_s / W$ |
| $1-f$ | 并行分量比例 |
| $T_s$ | 串行执行时间 |
| $T_p$ | 并行执行时间 |
| $S$ | 加速比 |
| $E$ | 效率 |
| $W_o$ | 并行引起的额外开销 |

$$W_s + W_p = W$$

### 4.2 Amdahl定律（阿姆达尔定律）⭐⭐⭐

**核心思想**：**固定问题规模**，增加处理器来加快执行速度。

**假设**：
- 问题规模固定不变
- 串行比例 $f$ 固定
- 只增加处理器数量

> 💡 **通俗理解**：100道题，其中5道必须串行做（1个人做），剩下95道可以并行分给多人做。

**公式推导**：

$$S = \frac{W_s + W_p}{W_s + \frac{W_p}{P}} = \frac{1}{f + \frac{1-f}{P}}$$

或等价地：

$$S = \frac{P}{1 + f(P-1)}$$

**极限情况**（$P \to \infty$）：

$$\boxed{S_{max} = \frac{1}{f}}$$

> 🎯 **Amdahl定律的核心结论**：
> - 加速比受限于程序中的串行部分
> - 即使有无限多处理器，加速比也不会超过 $1/f$
> - 串行比例5%时，最大加速比只有20倍
> - 这是一个**悲观**的结论

**数值示例表**：

| 串行比例 $f$ | 最大加速比 $S_{max}$ | 含义 |
|--------------|----------------------|------|
| 1% | 100 | 99%可并行，上限高 |
| 5% | 20 | 95%可并行 |
| 10% | 10 | 90%可并行 |
| 20% | 5 | 80%可并行 |
| 50% | 2 | 一半可并行，上限很低 |

**例题**：一个串行程序94%的执行时间花费在可以并行化的函数中，求在20个处理器上的加速比。

**解答**：
- 可并行化比例 = 94%，所以 $f = 1 - 0.94 = 0.06$
- $S = \frac{1}{0.06 + \frac{0.94}{20}} = \frac{1}{0.06 + 0.047} = \frac{1}{0.107} \approx 9.35$
- 最大加速比 = $\frac{1}{0.06} \approx 16.67$

**考虑额外开销的Amdahl定律**：

$$S = \frac{P}{1 + f(P-1) + \frac{W_o \cdot P}{W}}$$

> 💡 开销项 $W_o$ 使得实际加速比更低。

### 4.3 Gustafson定律（古斯塔夫森定律）⭐⭐⭐

**核心思想**：**固定执行时间**，问题规模随处理器增加而扩大。

**假设**：
- 执行时间固定
- 串行部分的绝对时间不变
- 增加处理器来处理更多工作

> 💡 **通俗理解**：给1小时做完的考试。1个人只能做100道题，但4个人可以在1小时内做更多题。串行部分（如写名字）花的时间不变，但题目变多了。

**公式推导**：

$$S = \frac{W_s + P \cdot W_p}{W_s + W_p} = P - (1-f)(P-1)$$

或写成：

$$S = n - f(n-1)$$

**考虑额外开销的Gustafson定律**：

$$S = \frac{f + P(1-f)}{1 + W_o/W}$$

**特点**：
- 强调大规模问题的处理能力
- 加速比可以随处理器数**线性增长**
- 更符合实际大规模计算场景
- 这是一个**乐观**的结论

**图示理解**：

```
Amdahl（固定负载）:           Gustafson（固定时间）:
┌─────┬─────┬─────┐          ┌───────┬───────┬───────┐
│串行 │可并行│     │          │ 串行  │  并行1 │ 并行2 │
│  f  │1-f  │     │          │  f    │ P*(1-f)│       │
└─────┴─────┴─────┘          └───────┴───────┴───────┘
 ↑规模不变，加处理器           ↑时间不变，规模扩大
```

### 4.4 Sun-Ni定律（孙贤和-倪明选定律）⭐⭐

**核心思想**：**内存受限**，在不超过内存限制的前提下最大化计算规模。

> 💡 **通俗理解**：Amdahl说"活就这么多"，Gustafson说"时间就这么多"，Sun-Ni说"内存就这么多"。实际中内存容量常常是限制因素。

**存储受限的加速公式**：

$$S = \frac{f + (1-f)G(P)}{f + (1-f)G(P)/P}$$

其中 $G(P)$ 是存储容量增加 $P$ 倍时并行工作负载的增加因子。

**特殊情况**：
- $G(P) = 1$ → 退化为 **Amdahl定律**
- $G(P) = P$ → 退化为 **Gustafson定律**
- $G(P) > P$ → 比两者都乐观

**考虑额外开销**：

$$S = \frac{f + (1-f)G(P)}{f + (1-f)G(P)/P + W_o/W}$$

## 五、三种定律对比总结

| 特性 | Amdahl定律 | Gustafson定律 | Sun-Ni定律 |
|------|------------|---------------|------------|
| **核心限制** | 计算负载 | 执行时间 | 内存容量 |
| **问题规模** | 固定 | 可扩展 | 受限扩展 |
| **出发点** | 固定负载求加速 | 固定时间求吞吐 | 受限内存求规模 |
| **加速比公式** | $\frac{1}{f + \frac{1-f}{P}}$ | $P - f(P-1)$ | $\frac{f+(1-f)G(P)}{f+(1-f)G(P)/P}$ |
| **应用特点** | 强调串行瓶颈 | 强调大规模计算 | 强调内存优化 |
| **乐观程度** | 😟 悲观 | 😊 乐观 | 😐 中间 |
| **加速比上限** | $1/f$（有限）| 随P线性增长 | 取决于G(P) |

> 🎯 **考试重点**：
> 1. 理解三种定律的不同假设和出发点
> 2. 能够运用Amdahl和Gustafson定律进行计算
> 3. 知道加速比的理论上限
> 4. 理解三个定律之间的关系（Sun-Ni是推广形式）

**三者关系图**：

```
                    Sun-Ni定律（推广形式）
                   /                    \
          G(P)=1 ↓                      ↓ G(P)=P
              Amdahl定律            Gustafson定律
```

## 六、可扩放性评测

### 6.1 可扩放性的定义

**可扩放性（Scalability）**：并行系统（算法/程序）的性能随处理器数增加而**按比例**提高的能力。

> 💡 **通俗理解**：给更多处理器，效率不能降太多。好算法应该"越大越好"。

**影响加速比的因素**：
1. 求解问题中的串行分量
2. 并行处理引起的额外开销（通信、等待、竞争、同步等）
3. 处理器数超过了算法的并发度

**增加规模有利于提高加速比的因素**：
- 较大问题规模 → 更高的并发度
- 额外开销增长可能慢于有效计算增长
- 串行分量比例可能随问题规模增大而缩小

### 6.2 等效率度量标准

**基本思想**：为了维持一定的效率，当处理器数 $P$ 增大时，需要相应增大问题规模 $W$。

**效率公式**：

$$E = \frac{1}{1 + \frac{T_o}{W}}$$

其中 $T_o$ 是总开销。

**等效率曲线**：

```
问题规模 W
    ↑
    │        曲线3: 不可扩放
    │       ╱ (W增长太快才能维持效率)
    │      ╱
    │     ╱ 曲线2: 可扩放
    │    ╱╱ (W适度增长)
    │   ╱╱ 曲线1: 扩放性好
    │  ╱╱ (W增长很慢)
    │ ╱╱
    └──────────────→ 处理器数 P
```

| 曲线 | 特点 | 评价 |
|------|------|------|
| 曲线1 | W随P增长很慢 | 扩放性好 |
| 曲线2 | W随P适度增长 | 可扩放 |
| 曲线3 | W随P增长很快 | 不可扩放 |

**可扩放性研究的主要目的**：
1. 确定何种并行算法与体系结构的组合能有效利用大量处理器
2. 评估算法从小规模移植到大规模系统的性能
3. 确定固定问题规模的最优处理器数和最大加速比
4. 指导改进并行算法和体系结构

## 七、计算题型总结

### 题型1：给定并行化比例求加速比（⭐最常见）

**模板**：
```
已知：串行程序中 P% 可并行化
求：N个处理器的加速比

解答：
f = 1 - P/100                    // 串行比例
S = 1 / (f + (1-f)/N)            // Amdahl定律
S_max = 1/f                      // 理论最大加速比
E = S/N                          // 效率
```

**例题**：程序90%可并行化，使用4个处理器。
- $f = 0.10$
- $S = 1 / (0.1 + 0.9/4) = 1 / (0.1 + 0.225) = 1/0.325 \approx 3.08$
- $E = 3.08/4 = 0.77 = 77\%$

### 题型2：给定目标加速比求处理器数

**模板**：
```
已知：串行比例为 f，目标加速比为 S
求：需要多少处理器

解答：
S = 1 / (f + (1-f)/N)
解方程：N = (1-f) / (1/S - f)

注意：若 f ≥ 1/S，无解（目标不可达）
```

### 题型3：Gustafson定律计算

**模板**：
```
已知：串行比例为 f，使用 P 个处理器
求：Gustafson定律下的加速比

解答：
S = P - f(P-1) = f + P(1-f)
```

**例题**：程序串行比例10%，使用16个处理器。
- Amdahl: $S = 1/(0.1 + 0.9/16) = 1/0.15625 = 6.4$
- Gustafson: $S = 16 - 0.1 \times 15 = 16 - 1.5 = 14.5$

### 题型4：缓存性能计算

**模板**：
```
已知：缓存延迟L1，主存延迟L2，命中率h
求：平均访问时间

解答：
T_avg = h × L1 + (1-h) × L2
```
