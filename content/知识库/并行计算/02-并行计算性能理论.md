## 一、性能基本概念

### 1.1 性能定义

**Performance**：通常指机器的速度，是程序执行时间的倒数

$$\text{Performance} = \frac{1}{\text{Execution Time}}$$

**程序执行时间组成**：
- 访问磁盘时间
- 访问存储器时间
- CPU时间
- I/O时间
- 操作系统开销

**CPU时间**：CPU实际工作时间，不包括I/O等待和其他任务时间

### 1.2 为什么要进行性能评测？

| 角色 | 目的 |
|------|------|
| **管理员** | 提高并行机使用效率 |
| **用户** | 减少购机盲目性，降低投资风险 |
| **架构师** | 改进系统结构设计 |
| **市场人员** | 提供客观公正的评价标准 |

## 二、并行计算性能指标

### 2.1 核心指标定义

**并行执行时间**：

$$T_p = T_{comp} + T_{paro} + T_{comm}$$

其中：
- $T_{comp}$：计算时间
- $T_{paro}$：并行开销时间
- $T_{comm}$：通信时间

**加速比（Speedup）**：

$$S(n) = \frac{T_s}{T_p} = \frac{\text{串行执行时间}}{\text{并行执行时间}}$$

**效率（Efficiency）**：

$$E = \frac{S(n)}{n} = \frac{T_s}{n \times T_p}$$

其中 $n$ 为处理器数量

**代价（Cost）**：

$$\text{Cost} = T_p \times n = \text{执行时间} \times \text{处理器数}$$

> 🎯 **关键理解**：
> - 加速比：速度提升倍数（越大越好）
> - 效率：处理器利用率（0~1之间，越大越好）
> - 理想情况：$S = n$，$E = 1$

### 2.2 计算/通信比

$$\text{计算通信比} = \frac{T_{comp}}{T_{comm}}$$

- 比值越大，并行效率越高
- 比值越小，通信开销越成为瓶颈

## 三、加速比定律（⭐⭐⭐ 必考！）

### 3.1 基本参数定义

| 符号 | 含义 |
|------|------|
| $P$ | 处理器数量 |
| $W$ | 问题规模（总计算量） |
| $W_s$ | 串行分量 |
| $W_p$ | 可并行化部分 |
| $f$ | 串行分量比例，$f = W_s / W$ |
| $1-f$ | 并行分量比例 |
| $T_s$ | 串行执行时间 |
| $T_p$ | 并行执行时间 |

$$W_s + W_p = W$$

---

### 3.2 Amdahl定律（阿姆达尔定律）⭐⭐⭐

**核心思想**：**固定问题规模**，增加处理器加快执行速度

**假设**：
- 问题规模固定不变
- 串行比例 $f$ 固定
- 增加处理器数量

**公式推导**：

$$S = \frac{W_s + W_p}{W_s + \frac{W_p}{P}} = \frac{1}{f + \frac{1-f}{P}}$$

**极限情况**（$P \to \infty$）：

$$\boxed{S_{max} = \frac{1}{f}}$$

> 🎯 **Amdahl定律的核心结论**：
> - 加速比受限于程序中的串行部分
> - 即使有无限多处理器，加速比也不会超过 $1/f$
> - 串行部分比例为5%时，最大加速比只有20倍

**数值示例**：

| 串行比例 $f$ | 最大加速比 $S_{max}$ |
|--------------|---------------------|
| 1% | 100 |
| 5% | 20 |
| 10% | 10 |
| 20% | 5 |
| 50% | 2 |

**示例计算**：

> **例题**：一个串行程序94%的执行时间花费在可以并行化的函数中，求在20个处理器上的加速比。

**解答**：
- 可并行化比例 = 94%，所以 $f = 1 - 0.94 = 0.06$
- $S = \frac{1}{0.06 + \frac{0.94}{20}} = \frac{1}{0.06 + 0.047} = \frac{1}{0.107} \approx 9.35$
- 最大加速比 = $\frac{1}{0.06} \approx 16.67$

---

### 3.3 Gustafson定律（古斯塔夫森定律）⭐⭐⭐

**核心思想**：**固定执行时间**，问题规模可随处理器增加而扩大

**假设**：
- 执行时间固定
- 串行部分的绝对时间不变
- 增加处理器处理更多工作

**公式推导**：

$$S = \frac{W_s + P \cdot W_p}{W_s + W_p} = P - (1-f)(P-1)$$

或写成：

$$S = n - (1-f)(n-1)$$

**特点**：
- 强调大规模问题的处理能力
- 加速比可以随处理器数线性增长
- 更符合实际大规模计算场景

**与Amdahl对比**：

| 定律 | 出发点 | 问题规模 | 加速比上限 |
|------|--------|----------|------------|
| Amdahl | 固定负载 | 固定 | $1/f$ |
| Gustafson | 固定时间 | 可扩展 | 随 $P$ 线性增长 |

---

### 3.4 Sun-Ni定律（孙贤和-倪明选定律）⭐⭐

**核心思想**：**内存受限**，在不超过内存限制的前提下最大化计算规模

**公式**：

$$S = \frac{P + (1-P) \cdot \frac{W_1}{W_G}}{1}$$

或简化为：

$$S = \frac{N}{1 + (N-1) \cdot \frac{W_1}{W_G}}$$

其中：
- $W_1$：串行部分
- $W_G$：内存能容纳的最大问题规模

**适用场景**：
- 内存容量有限
- 问题规模受存储限制

---

## 四、三种定律对比总结

| 特性 | Amdahl定律 | Gustafson定律 | Sun-Ni定律 |
|------|------------|---------------|------------|
| **核心限制** | 计算负载 | 执行时间 | 内存容量 |
| **问题规模** | 固定 | 可扩展 | 受限扩展 |
| **加速比公式** | $\frac{1}{f + \frac{1-f}{P}}$ | $P - (1-f)(P-1)$ | $\frac{P}{1+(P-1)W_1/W_G}$ |
| **应用特点** | 强调串行瓶颈 | 强调大规模计算 | 强调内存优化 |
| **乐观程度** | 悲观 | 乐观 | 中间 |

> 🎯 **考试重点**：
> 1. 理解三种定律的不同假设和出发点
> 2. 能够运用Amdahl定律进行计算
> 3. 知道加速比的理论上限

## 五、内存系统对性能的影响

### 5.1 延迟与带宽

**延迟（Latency）**：
- 处理器发起访问到获取数据所需的时间
- 例：打开水龙头后2秒水才流出 → 延迟2秒

**带宽（Bandwidth）**：
- 数据传输的速率
- 例：水管每秒流出5加仑水 → 带宽5加仑/秒

**类比理解**：
- 想立即扑灭小火 → 减少延迟
- 想扑灭大火 → 提高带宽

### 5.2 高速缓存的作用

**缓存命中率（Hit Ratio）**：由缓存提供数据的比例

**示例计算**：

| 场景 | 计算速度 |
|------|----------|
| 无缓存（100ns延迟） | 10 MFLOPS |
| 有缓存（命中率99%） | 303 MFLOPS |

**关键概念**：
- **时间局部性**：重复访问相同数据
- **空间局部性**：访问相邻数据

## 六、计算题型总结

### 题型1：给定并行化比例求加速比

**模板**：
```
已知：串行程序中 P% 可并行化
求：N个处理器的加速比

解答：
f = 1 - P/100
S = 1 / (f + (1-f)/N)
最大加速比 = 1/f
```

### 题型2：给定目标加速比求处理器数

**模板**：
```
已知：串行比例为 f，目标加速比为 S
求：需要多少处理器

解答：
S = 1 / (f + (1-f)/N)
解方程：N = (1-f) / (1/S - f)
```
