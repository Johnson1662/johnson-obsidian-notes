## 1.1 什么是互联网（What is the Internet）

### 1.1.1 课程目标与概述

本章作为计算机网络的入门介绍，有两个核心目标：
1. 提供计算机网络的整体概览，建立全局视野。
2. 介绍大量专业术语和词汇，为后续深入学习奠定基础。

本章内容对应教材第一章，涵盖以下主题：什么是互联网、什么是协议、网络边缘、网络核心、网络结构、性能指标、协议分层与封装、网络安全、以及计算机网络的历史。

### 1.1.2 互联网的工程视角

互联网是一个工程人工制品（engineering artefact），类似于道路系统或电话网络。作为工程师，应从组件和结构的角度来理解互联网，而非将其视为某种抽象的"思考实体"。

### 1.1.3 互联网的组成——从细节角度

从组成部件的角度，互联网可以分解为以下几个层次：

**网络边缘（Network Edge）**
- 位于网络边缘的是互联网用户用来连接互联网的设备，统称为"主机"（host）或"端系统"（end system）。
- 目前已有数十亿台设备连接到互联网。
- 设备类型极其多样，包括：
  - 传统计算设备：个人电脑、计算机、数据中心服务器、智能手机。
  - 家用联网设备：游戏机、媒体流媒体设备、数字个人助理、安全摄像头、能源监测器。
  - 家用电器：冰箱、洗衣机、烘干机、相框，甚至床垫。
  - 可穿戴设备：个人健康与健身设备、VR眼镜等人体增强设备。
  - 交通工具：汽车（如特斯拉）、卡车、滑板车、自行车。
  - 其他创意设备：如能下载天气预报并将其"烤"到吐司上的面包机（2000年初英国某大学的大师项目）。
- 互联网连接使新型使用方式成为可能，即使是传统模拟设备（如自行车、滑板车）也可以通过获得数字足迹而发挥新价值。

**网络核心（Network Core）**
- 深入网络内部，使网络真正成为"网络"的设备称为"分组交换机"（packet switch）。
- 分组交换机负责转发数据块（分组），有两种主要类型：路由器（router）和交换机（switch）。
- 大量的通信链路（communication link）将路由器、交换机、主机和端系统互相连接。

**网络的网络**
- 上述链路、路由器、交换机和主机被组装成一个个网络，每个网络由某个实体拥有和运营。
- 例如，UMass校园运营自己的校园网络，该校园网络通过骨干网连接到其他校园网络。
- 正是这种多重网络的存在，使得互联网本质上是一个"网络的网络"（network of networks）。

### 1.1.4 协议（Protocol）

- 路由器、交换机、主机和端系统之间信息的发送和接收均由协议控制。
- 网络中发生的一切都由协议控制，协议在网络中无处不在。
- 本课程既是一门关于网络原理与实践的课程，也是一门关于协议的课程。
- 协议定义了一种标准的做事方式，描述了网络中实体之间通信的规则和格式。

## 1.2 网络边缘（The Network Edge）

> 注：本节字幕文件存在内容错误（被其他视频内容替换），以下基于课程知识体系补充核心概念。

### 1.2.1 网络边缘的定义

网络边缘指互联网的末端，即主机（端系统）所在的区域。主机是运行应用程序的设备，是用户直接接触互联网的入口。

### 1.2.2 接入网（Access Network）

接入网是将主机连接到其"边缘路由器"（edge router）的物理链路和网络设施。边缘路由器是主机到任何其他远程主机路径上的第一台路由器。

主要接入方式包括：
- 家庭接入：DSL（数字用户线）、电缆（Cable）、FTTH（光纤到户）、拨号和卫星。
- 企业接入：以太网（Ethernet）、WiFi（无线局域网）。
- 广域无线接入：4G/5G蜂窝网络、卫星。

### 1.2.3 物理媒体（Physical Media）

物理媒体是数据实际传输的介质，分为两类：
- 导向媒体（guided media）：如双绞线（twisted pair）、同轴电缆（coaxial cable）、光纤（fiber optic cable）。
- 非导向媒体（unguided media）：如无线电波（radio waves），用于WiFi、蜂窝网络和卫星通信。

## 1.3 网络核心（The Network Core）

> 注：本节字幕文件存在内容错误（被其他视频内容替换），以下基于课程知识体系补充核心概念。

### 1.3.1 网络核心的功能

网络核心是由路由器和通信链路构成的网状结构，其核心功能是将数据从源主机传输到目的主机。

### 1.3.2 两种交换技术

**电路交换（Circuit Switching）**
- 电话网络传统上使用的技术。
- 在通信开始前，需要在源和目的之间建立一条专用通路（电路），该通路在整个通信过程中被独占。
- 电路交换将链路带宽划分为"片"（slice），分配方式有频分复用（FDM）和时分复用（TDM）。
- 适合语音等恒定速率传输的场景，但对计算机通信的突发流量效率低下。

**分组交换（Packet Switching）**
- 互联网的技术基础。
- 数据被分割为小的"分组"（packet），每个分组独立地在网络中传输。
- 分组在路由器中经历"存储-转发"（store-and-forward）过程：路由器必须接收完整的分组后才能开始转发。
- 分组交换允许多个通信会话共享链路带宽，适合计算机通信的突发特性。

### 1.3.3 分组交换网络中的关键概念

- **存储转发传输（Store-and-Forward Transmission）**：交换机在转发分组之前必须先接收并存储整个分组。
- **排队延迟与丢包（Queuing Delay and Loss）**：当分组到达路由器的速率超过输出链路容量时，分组在输出缓冲区中排队等待。若缓冲区已满，则发生丢包（packet loss）。
- **转发表（Forwarding Table）**：路由器根据分组头部的目的地址查找转发表，确定输出链路。
- **路由选择协议（Routing Protocol）**：用于自动设置和更新转发表。

### 1.3.4 网络结构（Network Structure）

互联网是一个分层的网络结构：
- 第一层：接入ISP（Access ISP），直接面向终端用户。
- 第二层：区域ISP，连接多个接入ISP。
- 第三层：骨干ISP（Tier-1 ISP），通过互联网交换点（IXP）互相连接。
- 内容提供商（如Google）可能构建自己的专用网络，直接与低层ISP互联。

## 1.4 网络性能（Performance）

### 1.4.1 时延（Delay/Latency）

当分组的到达速率（暂时地）超过输出链路的容量时，分组需要在路由器中排队等待传输。时延的四个组成部分如下：

**1. 处理延迟（Processing Delay）**
- 与转发表查找和相关的完整性检查相关的延迟。
- 量级通常在微秒或更短。

**2. 排队延迟（Queuing Delay）**
- 分组在输出链路排队等待传输所花费的时间。
- 取决于传出链路的拥塞级别。
- 定量分析：设比特到达率为 $l \times a$（$a$ 为分组到达率，$l$ 为分组长度），链路带宽（传输速率）为 $r$。
- 定义"交通强度"（traffic intensity）为 $l \times a / r$：
  - 当交通强度较低时，排队延迟很小。
  - 当交通强度接近1时，排队延迟变得非常大。
  - 当交通强度大于1时，到达的工作量超过系统处理能力，队列无限增长，延迟趋于无穷。

**3. 传输延迟（Transmission Delay）**
- 将分组的所有比特推送到链路上所需的时间。
- 计算公式：$L / r$，其中 $L$ 为分组长度（比特），$r$ 为链路传输速率（bps）。
- 传输延迟取决于分组长度和链路带宽。

**4. 传播延迟（Propagation Delay）**
- 比特从链路发送端传播到接收端所需的时间。
- 比特通常以接近光速的速度在介质中传播。
- 计算公式：$d / s$，其中 $d$ 为链路距离，$s$ 为传播速度。
- 实际例子：
  - 从地球到地球同步卫星再返回的延迟约为270毫秒。
  - 从美国东海岸到欧洲的跨大西洋传播延迟约为30毫秒。

**传输延迟与传播延迟的区别（收费站类比）**

用一个车队通过收费站的类比来区分这两个概念：
- 收费站服务一辆车需要12秒（类比传输延迟）。
- 汽车以100公里/小时的速度在收费站之间行驶（类比传播延迟）。
- 收费站相距100公里。
- 车队有10辆车。

计算：
- 传输时间（车队全部通过第一个收费站）：12秒 × 10辆 = 120秒 = 2分钟。
- 传播时间（最后一辆车从第一个收费站到第二个收费站）：100公里 ÷ 100公里/小时 = 1小时 = 60分钟。
- 总时间：2分钟 + 60分钟 = 62分钟。

由此可见，传播延迟在长距离通信中往往占主导地位。

### 1.4.2 traceroute 工具

traceroute 是一个运行在笔记本电脑或计算机上的程序，用于测量和查看从源到目的地路径上各路由器的实时延迟。

**工作原理：**
- traceroute 向目的地发送一系列特殊的分组。
- 它测量从发送消息到收到回复的往返时间（RTT, Round-Trip Time）。
- 显示到第一跳路由器的三个RTT测量值，然后到第二跳，依此类推，直到到达最终目的地。

**实际示例：**
从马萨诸塞州阿默斯特的 gaia.cs.umass.edu 到法国 Eurocom FR 的追踪结果：
- 第一跳路由器在计算机科学系网络中，RTT延迟约1-2毫秒。
- 第二跳路由器仍在UMass网络内，RTT延迟约1-2毫秒。
- 后续到达华盛顿特区的路由器，RTT延迟约2毫秒。
- 到达法国研究网络的路由器时，RTT延迟超过100毫秒。

### 1.4.3 吞吐量（Throughput）

吞吐量是另一个重要的性能指标，表示比特从源转发到目的地的速率。
- 吞吐量受路径上所有链路中带宽最小的那条链路（瓶颈链路，bottleneck link）的限制。
- 吞吐量不仅取决于链路带宽，还受到网络拥塞程度的影响。

## 1.5 分层与封装（Layering and Encapsulation）

### 1.5.1 为什么需要分层

互联网是一个极其复杂的系统，拥有数十亿个相互作用的部件：边缘的应用设备、核心的路由器和交换机、各种通信链路、硬件和软件。如何设计、讨论、教授和学习这样一个系统？

分层（layering）是处理复杂系统的一种核心方法。

### 1.5.2 分层思维的类比——航空系统

航空旅行是一个非常复杂的系统，包含飞机、跑道、塔楼、行李认领处、售票柜台、安保、旅行者等。

**按步骤思考：** 买票 → 安检 → 登机 → 飞行 → 到达 → 取行李。这有助于将旅程分解为更小的部分。

**按层次思考：** 起飞侧的功能与着陆侧的对应功能共同提供从源头到目的地的服务。每一层使用下层提供的服务，同时向上层提供服务。

### 1.5.3 分层架构的优势

1. **明确的参考模型：** 分层结构清晰地展示了系统的不同部分及其相互关系，为讨论系统提供了明确的参考框架。
2. **模块化设计：** 每一层使用下层的服务来实现自身的服务。当某层服务的实现方式改变时，只要服务接口保持不变，变化就被局部化了。这有助于系统的维护和演进。

### 1.5.4 互联网的五层架构

互联网协议栈（Internet protocol stack）从顶到底分为五层：

**1. 应用层（Application Layer）**
- 应用程序的分布式部分在此层相互交换消息。
- 协议数据单元（PDU）称为"消息"（message）。
- 典型协议：HTTP、SMTP、DNS。

**2. 传输层（Transport Layer）**
- 将应用层消息从一个进程传输到另一个进程。
- 协议数据单元称为"段"（segment）。
- 两种典型服务：
  - TCP：提供可靠的数据传输服务（reliability guaranteed）。
  - UDP：不提供可靠性保证。
- 注意区分：网络层提供"主机到主机"（host-to-host）传输，传输层提供"进程到进程"（process-to-process）传输。

**3. 网络层（Network Layer）**
- 将数据从一个终端设备（主机）传输到另一个终端设备。
- 协议数据单元称为"数据报"（datagram）。
- 服务模型称为"最大努力服务"（best-effort service）——网络会尽力而为，但不保证传输的可靠性。
- 核心协议：IP（Internet Protocol）。

**4. 链路层（Link Layer）**
- 在位于同一通信链路两端的两个网络设备之间传输数据。
- 协议数据单元称为"帧"（frame）。

**5. 物理层（Physical Layer）**
- 控制向通信链路发送比特。

### 1.5.5 封装（Encapsulation）

封装是互联网中无处不在的核心概念。每一层从上层获取数据单元，添加本层的头部信息（header），创建新的协议数据单元，然后传递给下层。

封装过程（从顶到底）：
1. 应用层生成"消息"（message）。
2. 传输层获取消息，添加传输层头部（如TCP头部 $h_t$），创建"段"（segment）。
3. 网络层获取段，添加网络层头部（如IP头部 $h_n$），创建"数据报"（datagram）。
4. 链路层获取数据报，添加链路层头部，创建"帧"（frame）。
5. 物理层将帧转换为比特流在链路上传输。

每一层的协议数据单元（PDU）都包含两部分：头部（header）和有效载荷（payload，即上层传来的数据单元）。

## 1.6 网络安全（Networks Under Attack）

> 注：本节字幕文件仅包含音乐标记，无实际课程内容。以下基于课程知识体系补充核心概念。

### 1.6.1 网络安全概述

互联网在设计之初并未将安全性作为核心考量，随着互联网的普及，网络安全问题日益突出。网络安全涉及保护网络及其数据免受各种攻击。

### 1.6.2 主要攻击类型

**恶意软件（Malware）**
- 病毒（Virus）：需要用户交互才能传播的恶意软件。
- 蠕虫（Worm）：无需用户交互即可自动传播的恶意软件。
- 僵尸网络（Botnet）：被恶意软件感染并受控的大量主机。

**拒绝服务攻击（Denial of Service, DoS）**
- 攻击者通过向目标发送大量流量，使其无法为合法用户提供服务。
- 分布式拒绝服务攻击（DDoS）：利用僵尸网络中的大量主机同时发起攻击。

**分组嗅探（Packet Sniffing）**
- 在无线环境中，攻击者可以截获传输中的分组，获取敏感信息。

**IP欺骗（IP Spoofing）**
- 攻击者伪造分组的源IP地址，冒充其他主机。

**中间人攻击（Man-in-the-Middle Attack）**
- 攻击者插入到通信双方之间，截获或篡改通信内容。

### 1.6.3 安全机制

- 加密（Encryption）：保护数据的机密性。
- 认证（Authentication）：验证通信双方的身份。
- 完整性检查（Integrity Check）：确保数据未被篡改。
- 防火墙（Firewall）：控制进出网络的流量。
- 入侵检测系统（IDS）：监控网络中的可疑活动。

## 1.7 计算机网络的历史（History of Computer Networking）

### 1.7.1 前言

本课程关注原则与实践。在这段历史概述中，有些原则和实践是相对较新的，但其基础研究在60年前就已开始。有些网络思想甚至更加古老——电话网络已有一百多年历史，早在1879年就必须处理交换和路由问题。

更古老的网络例子包括信号量信令网络（Semaphore signaling network），用于端到端中继加密消息。信号量中继节点的实例收藏于巴黎的艺术与工艺博物馆（Musée des Arts et Métiers）。

### 1.7.2 历史分期

**第一幕：分组交换的诞生（1961-1967）**

- 1961年，电话网络是世界上占主导地位的通信网络，使用电路交换技术。
- 语音以恒定速率产生和传输，电路交换是合适的选择。
- 但计算机产生的流量具有突发性（bursty），在活动期和不活动期之间交替。
- 1961年，MIT研究生 Len Kleinrock 发表了第一篇关于分组交换（packet switching）的论文，用排队论证明了分组交换网络处理突发流量的有效性。
- 1964年，兰德研究所（RAND Institute）的 Paul Baran 开始研究在军事网络中使用分组交换。
- 同时，英国国家物理实验室（NPL）的研究人员也在独立发展分组交换的思想。
- 这三个研究小组当时互不知情，却共同成为分组交换的发明者。
- 1967年，高级研究计划局（ARPA）发布了 Arpanet 网络计划，这将成为世界上第一个分组交换计算机网络，是今天互联网最古老的直系祖先。

**第二幕：Arpanet 与早期网络扩展（1969-1975）**

- 1972年，Ray Tomlinson 编写了第一个电子邮件程序。Arpanet 已发展到15个节点。
- 1970年代初至中期：
  - ALOHAnet 是一个微波网络，将夏威夷群岛上的大学连接在一起。
  - DARPA 正在建立第二个分组交换网络——卫星网络（SATNET）以及分组无线网络（PRNET），后者是当今蜂窝数据网络的祖先。
  - Cyclades 是一个法国分组交换网络。
- 网络数量在增长，时机已经成熟。
- DARPA 再次承担了网络互连（internetworking）的开创性工作。
- 1974年，Vint Cerf 和 Bob Kahn 发表了关于互联网（internetworking）原则的论文，阐述了如何建立一个"网络的网络"。这些原则定义了当今互联网架构的基础，包括四个关键点：
  1. 极简主义与自主性（Minimalism and Autonomy）：在没有内部变化的情况下轻松互连网络的能力。
  2. 最大努力服务模型（Best-Effort Service Model）的概念。
  3. 无状态路由（Stateless Routing）。
  4. 其他架构原则。

**第三幕：以太网发明与网络商业化萌芽（1976-1979）**

- 1976年，以太网（Ethernet）由 Bob Metcalfe 在其博士论文中发明。
- 到1970年代末，专有的商业网络正在建立。
- Arpanet 已发展到200个节点。

**第四幕：协议标准化与网络扩张（1980s）**

- 1980年代以 Arpanet 协议标准化为标志，这些协议至今仍在使用。
- Arpanet 社区网络持续爆炸性增长。
- TCP 和 IP 在1980年代早期标准化。
- 1982年，SMTP（Simple Mail Transfer Protocol）电子邮件协议被开发。SMTP 至今仍是电子邮件的定义协议。
- 1983年，域名系统（DNS, Domain Name System）被开发，用于在人类可读的互联网名称（如 gaia.cs.umass.edu）和32位IP地址之间进行映射。
- SMTP 和 DNS 都是应用层协议。
- 1980年代末，TCP 进行了重要扩展，实现了基于主机的拥塞控制（congestion control），允许主机在网络拥塞时降低发送速率。
- 1980年代的其他网络：
  - Bitnet：提供电子邮件和文件传输，主要在东北地区的大学中。
  - CSNET（计算机科学网络）：为无法访问 Arpanet 的大学研究人员建立。
- 1986年，国家科学基金会（NSF）创建了 NSFnet，提供对 NSF 赞助的超级计算中心的访问。
- 到1980年代末，NSFnet 的作用扩大，成为连接区域网络并与其他网络互联的主要骨干网。
- 到1980年代末，连接到这个"网络网络"的主机数量达到约10万台，已初具今天互联网的雏形。

**第五幕：互联网商业化与万维网时代（1990s）**

- 1990年代初，许多事件象征着网络的持续发展和即将到来的互联网商业化。
- Arpanet（互联网的前身）于1991年退役。
- 1989年，Tim Berners-Lee 在瑞士日内瓦的 CERN 开发了万维网（World Wide Web）。
- 1991年12月，Tim 发布了万维网，起初几乎无人注意。
- 国家超级计算应用中心（NCSA）的 Marc Andreessen 和 Eric Bina 开发了 Mosaic 浏览器，使互联网看起来像一本杂志，包含格式化文本和图像，最终还有音频和视频。
- 万维网的引入对互联网的可及性和实用性产生了深远影响。
- 互联网基础设施的可扩展性非常好，设计被免费公开，没有专利或其他限制，故意刺激采用和使用。
- 随着大量内容的涌入，搜索引擎变得必要：AltaVista、Yahoo，最终 Google、Bing 等。
- 2007年智能手机的出现进一步推动了互联网的普及。

### 1.7.3 Vint Cerf 访谈要点

互联网之父之一 Vint Cerf 在访谈中提到：
- 在阿帕网项目之前就已出现电子邮件。Ray Tomlinson 在 BBN 公司实现了网络电子邮件，他使用 @ 符号来区分主机名和用户名（@ 是键盘上唯一未被操作系统使用的字符）。
- 电子邮件在互联网工作开始之前就已经存在。
- 互联网架构师对技术的作用有一定认识，支持了电子邮件、文件传输、远程分时机访问等应用。
- 最重要的变化是1983年初互联网投入使用，以及1989年万维网的发展。
- 互联网设计被免费赠送，没有专利限制，以刺激采用和使用。

## 核心概念总结

| 概念 | 英文 | 说明 |
|------|------|------|
| 主机/端系统 | Host / End System | 连接到互联网的设备，运行应用程序 |
| 分组交换机 | Packet Switch | 在网络核心转发分组的设备，包括路由器和交换机 |
| 通信链路 | Communication Link | 连接网络设备的物理介质 |
| 协议 | Protocol | 定义网络通信规则的标准化方法 |
| 电路交换 | Circuit Switching | 建立专用通路的交换方式，用于电话网络 |
| 分组交换 | Packet Switching | 将数据分割为分组独立传输，互联网的基础技术 |
| 封装 | Encapsulation | 每层添加头部信息创建新PDU的过程 |
| 处理延迟 | Processing Delay | 路由器查找转发表的延迟 |
| 排队延迟 | Queuing Delay | 分组在输出缓冲区排队等待的延迟 |
| 传输延迟 | Transmission Delay | 将分组比特推送到链路上的延迟 |
| 传播延迟 | Propagation Delay | 比特在物理介质中传播的延迟 |
| 交通强度 | Traffic Intensity | 比特到达率与传输速率的比值 |
| 吞吐量 | Throughput | 比特从源到目的地的实际传输速率 |
| traceroute | traceroute | 测量路径上各跳RTT的工具 |
| 最大努力服务 | Best-Effort Service | 网络层不保证可靠传输的服务模型 |
| 网络的网络 | Network of Networks | 互联网的本质——多个网络的互联 |
