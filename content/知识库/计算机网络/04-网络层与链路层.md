# 第4章 网络层（Network Layer）

## 4.1 网络层概述

### 网络层的核心功能

网络层负责将数据报（datagram）从源主机传输到目的主机。这是互联网架构中实现"主机到主机"通信的关键层。

网络层提供的服务模型称为"尽力而为"（best-effort）服务：网络会尽力传输数据报，但不保证可靠性、顺序或时延。

### 网络层的两个核心功能

**转发（Forwarding）**：
- 数据报到达路由器的输入端口后，路由器需要确定将其从哪个输出端口转发出去
- 这是一个路由器本地的数据平面功能
- 通过查找转发表（forwarding table）完成

**路由（Routing）**：
- 确定数据报从源到目的地所经过的路径
- 这是一个网络范围的控制平面功能
- 通过路由算法计算路由表（routing table）

转发和路由的区别：转发是"微观"的本地操作，路由是"宏观"的全局决策。

### 网络层服务模型

互联网网络层（IP协议）提供的服务：
- 尽力而为交付：不保证数据报一定到达
- 不保证交付顺序
- 不保证端到端时延
- 不保证最小带宽

## 4.2 路由器内部结构（What's Inside a Router）

### 路由器架构概述

路由器的主要组件：

**输入端口（Input Port）**：
- 实现物理层和链路层功能
- 进行网络层处理：查找转发表，确定输出端口
- 可能形成分组队列
- 使用"匹配加动作"（match+action）行为确定转发

**交换结构（Switching Fabric）**：
- 路由器的核心，连接输入端口和输出端口
- 三种主要类型：
  1. 通过内存交换（Memory）：早期路由器使用，CPU控制
  2. 通过总线交换（Bus）：所有分组共享一条总线
  3. 通过互联网络交换（Interconnection Network）：如交叉开关（crossbar），现代路由器使用

**输出端口（Output Port）**：
- 存储从交换结构接收的分组
- 在输出链路上传输分组
- 进行链路层和物理层处理

**路由处理器（Routing Processor）**：
- 执行控制平面功能
- 运行路由协议，维护路由表
- 在SDN架构中，还可能与远程控制器通信

### 最长前缀匹配（Longest Prefix Match）

转发表使用地址前缀而非完整地址范围来聚合路由条目。

**为什么需要最长前缀匹配**：
- IPv4有近40亿个可能地址，不可能为每个地址设置表项
- 使用地址前缀可以聚合路由
- 当多个前缀匹配时，选择最长的前缀（最具体的匹配）

**示例**：
```
前缀1: 10001000 010101xx xxxxxxxx xxxxxxxx (21位) → 接口0
前缀2: 11001000 01010101 xxxxxxxx xxxxxxxx (24位) → 接口1
```
地址 11001000 01010101 00000000 00000001 同时匹配两个前缀，但选择更长的前缀2（接口1）。

**TCAM（Ternary Content Addressable Memory）**：
- 用于硬件加速最长前缀匹配
- 在一个时钟周期内完成查找，无论表大小
- 支持三值匹配（0、1、通配符）

### 分组调度与缓冲

当多个分组竞争同一输出端口时，需要分组调度：
- **FIFO（First In First Out）**：最简单的调度策略
- **优先级调度（Priority Scheduling）**：高优先级分组优先传输
- **轮询调度（Round Robin）**：轮流服务各队列
- **加权公平队列（WFQ）**：按权重分配带宽

当缓冲区满时，发生丢包：
- **尾部丢弃（Tail Drop）**：丢弃新到达的分组
- **随机早期检测（RED）**：在缓冲区满之前随机丢弃分组

## 4.3 IP协议（Internet Protocol）

### IPv4 数据报格式

IPv4数据报头部包含以下关键字段：

| 字段 | 说明 |
|------|------|
| 版本（4位） | IP版本号，IPv4为4 |
| 头部长度（4位） | 以32位字为单位，通常为5（20字节） |
| 服务类型（8位） | 区分不同类型的数据报 |
| 总长度（16位） | 数据报总长度（头部+数据），最大65535字节 |
| 标识、标志、片偏移（32位） | 用于分片和重组 |
| TTL（8位） | 生存时间，每经过一个路由器减1，防止无限循环 |
| 协议（8位） | 指示上层协议（TCP=6, UDP=17） |
| 头部校验和（16位） | 仅校验头部 |
| 源IP地址（32位） | 发送方IP地址 |
| 目的IP地址（32位） | 接收方IP地址 |
| 选项（可变） | 很少使用 |

### IP分片

当IP数据报的大小超过链路的MTU（Maximum Transmission Unit）时，需要分片：
- 路由器将大数据报分割为多个较小的片段
- 每个片段独立传输
- 目的主机负责重组
- 分片通过标识、标志和偏移字段管理

### IPv4 编址

**分类编址（Classful Addressing）**：
- A类：1.0.0.0 ~ 126.255.255.255（/8）
- B类：128.0.0.0 ~ 191.255.255.255（/16）
- C类：192.0.0.0 ~ 223.255.255.255（/24）

**无类别域间路由（CIDR）**：
- 使用任意长度的前缀，如 a.b.c.d/x
- x 表示前缀的位数
- 提高了地址分配效率

**子网（Subnet）**：
- 将一个IP网络划分为多个较小的网络
- 子网掩码用于区分网络部分和主机部分

**DHCP（Dynamic Host Configuration Protocol）**：
- 自动为主机分配IP地址
- 即插即用协议
- 工作过程：DHCP发现 → DHCP提供 → DHCP请求 → DHCP确认

### NAT（Network Address Translation）

NAT允许局域网内的多台设备共享一个公网IP地址。

**NAT的工作原理**：
1. 局域网内设备使用私有IP地址（如10.0.0.x）
2. NAT路由器维护一个转换表
3. 传出数据报：替换源IP地址和端口号为NAT公网IP和新端口号
4. 传入数据报：根据转换表替换目的IP地址和端口号

**NAT的优势**：
- 节省IPv4地址空间
- 局域网内部地址变更不影响外部
- 安全：外部无法直接访问内部设备

**NAT的争议**：
- 网络层设备处理端口号，违反分层原则
- NAT遍历（NAT Traversal）问题：外部主机难以主动发起连接
- 被认为是IPv4地址短缺的临时解决方案

### IPv6

IPv6的主要改进：

**128位地址空间**：解决了IPv4地址耗尽问题

**简化的头部**：
- 固定40字节头部（IPv4头部可变，通常20字节）
- 移除分片字段（由端系统处理）
- 移除头部校验和（依赖上层协议校验）
- 移除选项字段（通过扩展头部实现）

**其他改进**：
- 流标签（Flow Label）：支持特定流的特殊处理
- 更好的扩展性：通过扩展头部链实现

**IPv4到IPv6的过渡**：
- 双栈（Dual Stack）：设备同时支持IPv4和IPv6
- 隧道（Tunneling）：将IPv6数据报封装在IPv4数据报中传输

## 4.4 通用转发（Generalized Forwarding）

### 从基于目的地的转发到通用转发

传统路由器只根据目的IP地址进行转发。通用转发（Generalized Forwarding）扩展了这一概念：

**匹配可以在多个头字段上进行**：
- 链路层：MAC地址
- 网络层：源/目的IP地址、协议类型
- 传输层：源/目的端口号

**动作空间更广**：
- 转发到指定端口
- 丢弃（防火墙功能）
- 修改头部字段（NAT功能）
- 重定向到SDN控制器

### OpenFlow 协议

OpenFlow是通用转发的标准化实现，是SDN（Software Defined Networking）的基础。

**OpenFlow的匹配字段**（OpenFlow 1.0支持12个字段）：
- 入端口、源/目的MAC地址
- 以太网类型、VLAN ID
- 源/目的IP地址、IP协议、IP TOS
- 源/目的TCP/UDP端口号

**OpenFlow的动作**：
- 转发到指定端口
- 转发到一组端口
- 丢弃
- 修改头部字段
- 封装并转发到SDN控制器

**流表（Flow Table）**：
OpenFlow交换机维护流表，每个表项包含：
- 匹配字段
- 动作
- 优先级（解决多条规则匹配的冲突）
- 计数器（统计匹配的分组数）

**通用转发的应用**：
- 基于目的地的转发（传统路由）
- 防火墙（丢弃特定流量）
- NAT（修改IP和端口）
- 负载均衡
- 链路层交换

## 4.5 中间件与互联网架构

### 中间件（Middlebox）

中间件是部署在网络中、执行超出简单IP转发功能的设备：
- NAT：地址转换
- 防火墙：流量过滤
- 入侵检测系统（IDS）：监控可疑流量
- 负载均衡器：分配流量
- 深度包检测（DPI）：检查分组内容

中间件的存在与互联网端到端原则（end-to-end principle）存在张力，但实际部署中不可或缺。

# 第5章 网络层控制平面（Network Layer Control Plane）

## 5.1 控制平面概述

### 数据平面 vs 控制平面

**数据平面（Data Plane）**：
- 本地操作：将数据报从输入端口转发到输出端口
- 由转发表驱动
- 通常以硬件实现，高速运行

**控制平面（Control Plane）**：
- 网络范围的操作：确定数据报从源到目的地的路径
- 由路由算法驱动
- 通常以软件实现

### 两种路由方法

**每路由器控制（Per-Router Control）**：
- 每个路由器独立运行路由算法
- 路由器之间通过路由协议交换信息
- 分布式实现

**SDN控制（Software Defined Networking）**：
- 逻辑集中的控制器计算路由
- 控制器将流表推送到各路由器
- 路由器只负责转发，不参与路由计算

## 5.2 路由算法

### 路由算法的分类

路由算法可以根据以下维度分类：

**集中式 vs 分布式**：
- 集中式：所有路由器拥有完整的网络拓扑信息（如链路状态算法）
- 分布式：路由器只与邻居交换信息（如距离向量算法）

**静态 vs 动态**：
- 静态：路由变化缓慢，手动配置
- 动态：路由随网络状态变化自动更新

### 链路状态路由（Link State Routing）

链路状态路由算法的代表是Dijkstra算法。

**基本思想**：
1. 每个路由器发现其直接连接的链路及其代价
2. 将链路状态信息广播给网络中所有其他路由器
3. 每个路由器拥有完整的网络拓扑图
4. 使用Dijkstra算法计算到所有目的地的最短路径

**Dijkstra算法**：
- 维护一个已知最短路径的节点集合
- 每次选择距离源最近的未加入集合的节点
- 更新该节点邻居的距离
- 重复直到所有节点都加入集合

**链路状态广播（LSA, Link State Advertisement）**：
- 使用洪泛（flooding）机制传播链路状态信息
- 每个路由器将收到的LSA转发给所有邻居（除了来源方向）
- 使用序列号和年龄字段防止循环和过期信息

### 距离向量路由（Distance Vector Routing）

距离向量路由算法的代表是Bellman-Ford算法。

**基本思想**：
1. 每个路由器维护一个距离向量：到所有目的地的估计代价
2. 路由器定期与邻居交换距离向量
3. 收到邻居的距离向量后，使用Bellman-Ford方程更新自己的距离向量

**Bellman-Ford方程**：
```
D_x(y) = min_v {c(x,v) + D_v(y)}
```
其中 D_x(y) 是x到y的最小代价，c(x,v) 是x到邻居v的链路代价，D_v(y) 是v到y的代价。

**距离向量算法的特点**：
- 分布式：每个路由器只与直接邻居通信
- 异步：路由器独立运行
- 迭代：通过多次交换逐步收敛

**好消息传播快，坏消息传播慢**：
- 当链路代价降低时，信息快速传播
- 当链路代价升高时，信息传播缓慢，可能导致路由环路

**计数到无穷（Count to Infinity）问题**：
- 当一条链路断开时，路由器可能通过其他路由器"绕路"
- 导致距离值不断增加直到达到最大值
- 解决方案：水平分割（Split Horizon）、毒性逆转（Poison Reverse）

## 5.3 OSPF（Open Shortest Path First）

### OSPF 概述

OSPF是一种链路状态路由协议，用于在自治系统（AS, Autonomous System）内部进行路由，也称为域内路由（intra-domain routing）。

**OSPF的特点**：
- 使用Dijkstra算法计算最短路径
- 支持等代价多路径（ECMP）
- 支持分层路由：将大型网络划分为区域（area）
- 区域0为骨干区域，其他区域通过骨干区域互联
- 支持认证，提高安全性

**OSPF的工作过程**：
1. 发现邻居：通过Hello消息
2. 建立邻接关系：交换数据库描述消息
3. 同步链路状态数据库
4. 运行Dijkstra算法计算路由

## 5.4 BGP（Border Gateway Protocol）

### BGP 概述

BGP是互联网的核心路由协议，用于在自治系统之间进行路由，也称为域间路由（inter-domain routing）。BGP有时被称为"将互联网粘合在一起的胶水"。

**BGP的特点**：
- 路径向量协议（Path Vector Protocol）
- 基于策略的路由：路由选择不仅基于距离，还基于商业关系
- 使用TCP连接（端口179）交换路由信息
- 增量更新：只传播变化的路由信息

### BGP 路由

**自治系统（AS）**：
- 由单一组织管理的一组路由器和IP网络
- 每个AS有一个唯一的AS号（ASN）
- AS内部使用域内路由协议（如OSPF、EIGRP）
- AS之间使用BGP

**BGP路由通告**：
- BGP路由器通过eBGP（外部BGP）从其他AS学习路由
- 通过iBGP（内部BGP）在AS内部传播路由
- 路由通告包含AS路径（AS Path）：经过的AS序列

**BGP路由选择**：
BGP路由器可能收到多条到达同一目的地的路由，选择策略包括：
1. 本地偏好（Local Preference）：管理员配置的优先级
2. 最短AS路径
3. 最近下一跳（Hot Potato Routing）
4. 其他规则

### BGP路由类型

**eBGP（External BGP）**：
- 在不同AS的路由器之间运行
- 学习到达其他AS的路由

**iBGP（Internal BGP）**：
- 在同一AS内的路由器之间运行
- 在AS内部传播从eBGP学到的路由

## 5.5 SDN（Software Defined Networking）

### SDN 的核心思想

SDN将网络的控制平面与数据平面分离，通过逻辑集中的控制器管理网络。

**SDN架构的三层**：
1. 应用层：网络应用（如负载均衡、防火墙）
2. 控制层：SDN控制器，维护网络全局视图
3. 基础设施层：网络设备（交换机、路由器），只负责转发

**SDN的优势**：
- 集中式管理，全局优化
- 快速创新：通过软件更新实现新功能
- 可编程性：开发者可以通过API控制网络行为

### SDN控制器

**OpenDaylight（ODL）**：
- 开源SDN控制器平台
- 支持多种南向协议（如OpenFlow）
- 提供北向API供应用程序使用

**ONOS（Open Network Operating System）**：
- 另一个开源SDN控制器
- 专注于运营商网络场景
- 强调高可用性和可扩展性

## 5.6 ICMP（Internet Control Message Protocol）

ICMP是网络层协议，用于在主机和路由器之间传递控制消息。

**常见的ICMP消息**：
- Echo Request/Reply：ping工具使用
- Destination Unreachable：目的不可达
- Time Exceeded：TTL超时，traceroute使用
- Redirect：路由器通知主机有更好的路径

**ping工具**：
- 发送ICMP Echo Request，等待Echo Reply
- 测量往返时间（RTT）

**traceroute工具**：
- 发送TTL递增的分组
- 每跳路由器返回ICMP Time Exceeded消息
- 从而发现从源到目的地的路径

# 第6章 链路层（Link Layer）

## 6.1 链路层概述

### 链路层的基本概念

链路层负责在相邻网络节点之间传输数据。"相邻"指通过同一条通信链路直接相连的两个节点。

**链路层的服务**：
- 成帧（Framing）：将比特流组织为帧
- 链路接入（Link Access）：多路访问控制
- 可靠交付（可选）：有些链路层协议提供可靠传输
- 差错检测与纠正：检测传输中的比特错误

### 两种类型的链路

**点对点链路（Point-to-Point Link）**：
- 单个发送者和单个接收者
- 如PPP（Point-to-Point Protocol）

**广播链路（Broadcast Link）**：
- 多个发送者和多个接收者共享同一链路
- 如以太网、WiFi
- 需要多路访问协议协调传输

### 链路层实现

链路层功能通常在网络适配器（Network Interface Card, NIC）中实现，部分在硬件中，部分在固件/软件中。

## 6.2 差错检测与纠正

### 奇偶校验

**简单奇偶校验**：
- 添加一个奇偶校验位，使总位数为偶数（偶校验）或奇数（奇校验）
- 只能检测奇数个比特错误
- 无法纠正错误

**二维奇偶校验**：
- 将比特排列成网格
- 为每行和每列计算奇偶校验位
- 可以检测所有单比特和双比特错误
- 可以纠正单比特错误（通过行和列的交叉定位错误位置）

### 互联网校验和（Internet Checksum）

UDP和TCP使用的差错检测方法：
- 将数据视为16位整数序列
- 计算16位反码和
- 接收端重新计算并比较
- 校验和较弱，不能检测所有错误

### CRC（Cyclic Redundancy Check）

CRC是链路层广泛使用的强大差错检测技术，用于以太网和WiFi。

**CRC的工作原理**：
1. 发送方和接收方约定一个生成多项式G（r位）
2. 发送方在数据位D后面附加r个0
3. 用模2除法除以G，得到余数R
4. 将R附加到D后面发送（D+R能被G整除）
5. 接收方用收到的数据除以G，余数为0则无错误

**CRC的能力**：
- 可以检测所有单比特错误
- 可以检测所有双比特错误
- 可以检测任何奇数个错误
- 可以检测长度小于等于r的突发错误
- 广泛用于以太网（CRC-32）和WiFi

### 前向纠错（Forward Error Correction, FEC）

前向纠错技术允许接收方在不请求重传的情况下纠正错误：
- 通过添加冗余信息实现
- 应用于DVD、光盘、DSL接入网、深空通信
- 在延迟大的场景中特别有用（如深空通信，重传代价极高）

## 6.3 多路访问协议

### 多路访问问题

当多个节点共享同一广播信道时，需要多路访问协议来协调传输。核心挑战是：任何关于如何共享信道的协调通信都必须通过该信道本身进行。

### 三类多路访问协议

**1. 信道划分协议（Channel Partitioning Protocols）**

将信道划分为小的"片"，分配给各节点：

- **TDMA（Time Division Multiple Access）**：
  - 将时间划分为时隙
  - 每个节点在分配的时隙内传输
  - 没有碰撞，但可能有时隙浪费

- **FDMA（Frequency Division Multiple Access）**：
  - 将频谱划分为频带
  - 每个节点在分配的频带上传输
  - 如FM广播、电视频道

- **CDMA（Code Division Multiple Access）**：
  - 每个节点使用唯一的编码
  - 多个节点可以同时传输
  - 接收方通过解码分离信号

**2. 随机访问协议（Random Access Protocols）**

节点在有数据时立即发送，碰撞后通过重传解决：

- **ALOHA**：
  - 纯ALOHA：有数据就发送，碰撞后随机等待重传
  - 时隙ALOHA：只能在时隙开始时发送，效率翻倍
  - 最大效率：纯ALOHA约18%，时隙ALOHA约37%

- **CSMA（Carrier Sense Multiple Access）**：
  - 发送前先监听信道
  - 信道空闲才发送
  - 仍可能碰撞（因为传播延迟）

- **CSMA/CD（CSMA with Collision Detection）**：
  - 发送时持续监听
  - 检测到碰撞立即停止发送
  - 使用二进制指数退避算法选择重传时间
  - 用于传统以太网

- **CSMA/CA（CSMA with Collision Avoidance）**：
  - 发送前等待随机时间
  - 使用RTS/CTS机制预留信道
  - 用于WiFi（802.11）

**3. 轮流协议（Taking-Turns Protocols）**

节点轮流获得传输机会：

- **轮询（Polling）**：
  - 主节点依次询问各从节点是否有数据发送
  - 有单点故障问题（主节点失效）

- **令牌传递（Token Passing）**：
  - 令牌（特殊帧）在节点间传递
  - 持有令牌的节点才能发送
  - 如令牌环网络、FDDI

### 有线接入网

**DOCSIS（Data Over Cable Service Interface Specification）**：
- 有线电视网络的数据传输标准
- 使用FDM划分上下行信道
- 下行：广播方式
- 上行：使用TDMA或CSMA

**FTTH（Fiber To The Home）**：
- 光纤到户
- 使用PON（Passive Optical Network）
- 上下行使用不同波长（WDM）
