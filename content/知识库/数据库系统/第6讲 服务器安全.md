## 6.1 服务器安全概述

### 6.1.1 安全的差异

| 类型 | 对应的安全领域 | 保护对象 |
|--------|--------|--------|
| **物理安全** | 机房安全、设备防护 | 硬件、中间件、应用程序 |
| **操作系统安全** | 身份认证、权限管理 | 系统资源、文件、内存 |
| **应用程序安全** | 输入验证、会话管理 | 应用程序及其数据 |
| **数据库安全** | 访问控制、加密存储 | 数据库中的数据 |

### 6.1.2 服务器安全技术

**核心目标**：
1. **机密性**：防止未授权访问者获取密密信息
2. **完整性**：防止未授权访问者破坏或修改数据
3. **可用性**：确保许可实体能够访问和使用数据
4. **可审计性**：描述安全闯入的时间、方式、结果

## 6.2 身份认证

### 6.2.1 身份认证机制

**身份认证**（Authentication）是系统确认用户身份的过程。

**常见身份认证方式**：

| 方式 | 原理 | 优点 | 缺点 |
|--------|--------|--------|--------|
| 密码认证 | 比对密码 | 简单易用 | 易被猜解 |
| 智能卡 | 卡片存储密钥 | 安全性高 | 成本高 |
| 生物认证 | 指纹、面部 | 难伪造 | 需特殊设备 |
| 动态密码 | 时变密码 | 随机性强 | 需额外设备 |

### 6.2.2 数据库身份认证

**Oracle身份认证**：
```sql
-- 操作系统身份认证
CONNECT username/password

-- 数据库身份认证
CONNECT username/password@database

-- 强制密码策略
ALTER PROFILE default LIMIT
    PASSWORD_LIFE_TIME 90
    FAILED_LOGIN_ATTEMPTS 3;
```

**SQL Server身份认证**：
```sql
-- Windows身份认证
CREATE LOGIN [domain\user] FROM WINDOWS;

-- SQL Server身份认证
CREATE LOGIN username WITH PASSWORD = 'StrongPassword';

-- 用户映射
CREATE USER username FOR LOGIN username;
```

**MySQL身份认证**：
```sql
-- 创建用户
CREATE USER 'username'@'host' IDENTIFIED BY 'password';

-- 密码策略
CREATE PROFILE strong_password LIMIT
    PASSWORD_LIFE_TIME 90
    PASSWORD_REUSE_MAX 5
    PASSWORD_VERIFY_FUNCTION verify_function;
```

### 6.2.3 多因素身份认证（MFA）

**原理**：
- 你所知的东西（密码）
- 你所有的东西（智能卡）
- 你所是的人（生物特征）

**实现**：
```sql
-- 启用MFA
ALTER USER username 
    IDENTIFIED BY password
    REQUIRE MOBILE_AUTHENTICATION;
```

## 6.3 权限控制

### 6.3.1 访问控制矩阵

| | 对象类型 | |
|------|---------|---------|---------|
| | | 表、视图 | 存储过程、函数 |
| **操作类型** | 查询 | SELECT | EXECUTE |
| | 插入 | INSERT | - |
| | 更新 | UPDATE | - |
| | 删除 | DELETE | - |
| **权限组合** | 所有权限 | ALL PRIVILEGES | - |

### 6.3.2 列级权限

```sql
-- 授予对特定列的更新权限
GRANT UPDATE(phone, email) ON employees TO hr_dept;

-- 查询列级权限信息
SELECT grantee, table_name, column_name, privilege
FROM column_privileges
WHERE table_name = 'EMPLOYEES';
```

### 6.3.3 行级权限（RLS）

**行级安全策略**：
```sql
-- Oracle RLS
BEGIN
    DBMS_RLS.ADD_POLICY(
        object_schema => 'HR',
        object_name => 'EMPLOYEES',
        policy_name => 'EMP_SALARY_POLICY',
        function_schema => 'SEC_MGR',
        policy_function => 'CHECK_DEPT',
        statement_types => 'SELECT, INSERT, UPDATE, DELETE'
    );
END;

-- SQL Server RLS
CREATE SECURITY POLICY DepartmentPolicy
    ADD FILTER PREDICATE dbo.fn_securitypredicate(department_id) 
    ON dbo.Employees;
```

**动态数据掩蔽**：
```sql
-- 基于角色的数据掩蔽
GRANT SELECT ON employees TO manager_role
    WITH COLUMN MASKING ON salary;
```

## 6.4 密码策略

### 6.4.1 密码复杂度

**密码要求**：
1. 长度：最小12位（建议16位）
2. 组合：大小写字母 + 数字 + 特殊符号
3. 规则：禁止常用单词、生日、递增序号
4. 保密：每90天强制更换

### 6.4.2 密码策略配置

```sql
-- Oracle密码策略
CREATE PROFILE secure_profile LIMIT
    SESSIONS_PER_USER 3
    CPU_PER_SESSION 3600
    CPU_PER_CALL 600
    CONNECT_TIME 180
    IDLE_TIME 30
    LOGICAL_READS_PER_SESSION 10000
    LOGICAL_READS_PER_CALL 1000
    COMPOSITE_LIMIT 5000000
    PRIVATE_SGA 15K
    FAILED_LOGIN_ATTEMPTS 5
    PASSWORD_LOCK_TIME 1
    PASSWORD_LIFE_TIME 90
    PASSWORD_GRACE_TIME 7
    PASSWORD_REUSE_MAX 5
    PASSWORD_REUSE_TIME 365
    PASSWORD_VERIFY_FUNCTION ora12c_verify_function;

ALTER USER username PROFILE secure_profile;

-- SQL Server密码策略
ALTER LOGIN username 
    WITH 
    PASSWORD = 'StrongP@ssw0rd!' MUST_CHANGE,
    CHECK_EXPIRATION = ON,
    CHECK_POLICY = ON;
```

### 6.4.3 密码管理

**密码存储**：
- 直接存储：仍然存在的危险
- 哈希存储：MD5、SHA-256
- 加盐哈希：PBKDF2、bcrypt

**密码识别**：
```sql
-- Oracle密码版本
SELECT password_versions FROM dba_users WHERE username = 'USERNAME';
-- 支持10g/11g/12c多版本

-- SQL Server密码加密
SELECT LOGINPROPERTY('username', 'PasswordHash');
```

## 6.5 审计监控

### 6.5.1 审计的目标

**安全审计**（Security Audit）的目标：
1. 检测安全违反行为
2. 评估安全控制的有效性
3. 满足合规性要求的证明
4. 促进安全意识的提高

### 6.5.2 审计分类

| 类型 | 内容 | 频率 |
|--------|--------|--------|
| **基础审计** | 系统登录、退出 | 实时 |
| **用户审计** | 权限变化、访问行为 | 日志 |
| **操作审计** | DDL、DML操作 | 实时 |
| **安全审计** | 异常访问、攻击 | 即时 |
| **合规审计** | 满足SOX、GDPR等 | 按期 |

### 6.5.3 审计日志

**审计事件**：
- 登录成功/失败
- 权限变化
- 数据访问
- 系统配置变化
- 数据导出/导入

```sql
-- 启用审计功能
-- Oracle
AUDIT SELECT TABLE, UPDATE TABLE, INSERT TABLE BY username;

-- SQL Server
CREATE SERVER AUDIT ServerAudit
TO FILE (FILEPATH = '/var/audit/')
WITH (ON_FAILURE = SHUTDOWN);

-- 查看审计记录
SELECT * FROM dba_audit_trail
WHERE timestamp > SYSDATE - 30;

-- 分析异常登录
SELECT username, os_username, terminal, timestamp
FROM dba_audit_session
WHERE returncode != 0
ORDER BY timestamp DESC;
```

### 6.5.4 实时监控

```sql
-- 当前活跃连接
SELECT sid, serial#, username, program, status
FROM v$session
WHERE username IS NOT NULL;

-- 长时运行查询
SELECT sid, sql_text, elapsed_time
FROM v$session s
JOIN v$sqlarea a ON s.sql_id = a.sql_id
WHERE status = 'ACTIVE'
    AND elapsed_time > 300000;  -- 5分钟

-- 锁竞争监控
SELECT l.session_id, l.oracle_username, l.locked_mode,
       s.serial#, s.username, s.osuser
FROM v$locked_object l
JOIN v$session s ON l.session_id = s.sid;
```

## 6.6 异常访问防护

### 6.6.1 SQL注入攻击

**原理**：
攻击者将恶意SQL代码插入到输入字段，绕过认证或执行非授权操作。

**示例**：
```sql
-- 正常登录
SELECT * FROM users WHERE username = 'admin' AND password = 'password';

-- SQL注入攻击
SELECT * FROM users 
WHERE username = 'admin' OR '1'='1' 
  AND password = 'anything' OR '1'='1';
-- 结果：绕过认证，登录成功
```

### 6.6.2 防护措施

**1. 参数化查询**
```sql
-- 使用参数化查询，避免字符串拼接
PREPARE stmt FROM 'SELECT * FROM users WHERE username = ? AND password = ?';
EXECUTE stmt USING @username, @password;
```

**2. 输入验证**
```sql
-- 验证用户名格式
IF username NOT REGEXP '^[a-zA-Z0-9_]{3,20}$' THEN
    SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Invalid username';
END IF;

-- 输入过滤
SET username = REPLACE(username, '\'', '\'\'');
SET username = REPLACE(username, ';', '');
SET username = REPLACE(username, '--', '');
```

**3. 最小权限原则**
```sql
-- 不使用管理员账号
-- 给应用账号分配最小权限
GRANT SELECT, INSERT, UPDATE ON app_db.* TO 'app_user'@'localhost';
```

**4. 使用预编译语句**
```sql
-- 每个DBMS都支持预编译
stmt = connection.prepareStatement(
    "SELECT * FROM users WHERE username = ? AND password = ?"
);
stmt.setString(1, username);
stmt.setString(2, password);
ResultSet rs = stmt.executeQuery();
```

### 6.6.3 其他攻击防护

**拖库攻击**：
- 使用完整的事务
- 采用行级锁

**拒绝服务攻击（DoS）**：
```sql
-- Oracle连接限制
ALTER PROFILE default LIMIT
    SESSIONS_PER_USER 5
    CONNECT_TIME 180;

-- SQL Server连接限制
CREATE LOGIN limited_user WITH PASSWORD = 'password';
ALTER LOGIN limited_user 
    WITH DEFAULT_DATABASE = [AdventureWorks]
    CHECK_EXPIRATION = ON;
```

## 6.7 加密技术

### 6.7.1 数据加密

**加密目标**：
- 防止数据泄露
- 满足合规要求
- 保护敏感数据

**加密算法**：
| 算法 | 类型 | 适用场景 |
|--------|--------|--------|
| AES | 对称加密 | 数据库存储 |
| RSA | 非对称加密 | 密钥传输 |
| SHA-256 | 哈希函数 | 密码存储 |

**加密策略**：
1. **存储加密**：数据在磁盘上的加密存储
2. **传输加密**：数据在网络中的加密传输
3. **列级加密**：对特定敏感列进行加密

```sql
-- Oracle TDE（透明数据加密）
CREATE TABLESPACE encrypted_ts
ENCRYPTION USING 'AES256'
DEFAULT STORAGE(ENCRYPT);

CREATE TABLE credit_cards (
    card_id NUMBER,
    card_number VARCHAR2(19)
) TABLESPACE encrypted_ts;

-- SQL Server TDE
CREATE MASTER KEY ENCRYPTION BY PASSWORD = 'StrongPassword';
CREATE CERTIFICATE MyServerCert WITH SUBJECT = 'TDE Certificate';
CREATE DATABASE ENCRYPTION KEY
WITH ALGORITHM = AES_256
ENCRYPTION BY SERVER CERTIFICATE MyServerCert;
ALTER DATABASE MyDatabase SET ENCRYPTION ON;
```

### 6.7.2 列级加密

```sql
-- 对敏感列加密
CREATE TABLE customers (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(200) ENCRYPTED WITH (COLUMN_ENCRYPTION_KEY = CEK1),
    ssn VARCHAR(11) ENCRYPTED WITH (COLUMN_ENCRYPTION_KEY = CEK1)
);
```

## 6.8 权限审计

### 6.8.1 定期审查

**权限审计检查项**：

| 检查项 | 检查内容 | 频率 |
|--------|--------|--------|
| 不活跃账户 | 超过90天未登录的账户 | 月度 |
| 过期权限 | 未及时更新的权限 | 月度 |
| 多余权限 | 飘亮于工作的权限 | 季度 |
| 密码周期 | 未按规定更换的密码 | 周度 |
| 并发登录 | 同一账户多地登录 | 实时 |

```sql
-- 查找不活跃账户
SELECT username, last_login
FROM dba_users
WHERE last_login < SYSDATE - 90
    AND account_status = 'OPEN';

-- 查找过期权限
SELECT grantee, privilege, admin_option
FROM dba_sys_privs
WHERE grantee NOT IN (
    SELECT username FROM dba_users 
    WHERE expiry_date > SYSDATE
);

-- 查找多余主顾责人
SELECT table_name, grantee
FROM dba_tab_privs
WHERE privilege = 'ALL'
    AND grantee NOT IN ('DBA', 'ADMIN');
```

### 6.8.2 移除权限

```sql
-- 恢复默认权限
ALTER USER username DEFAULT ROLE ALL;

-- 暂停账户
ALTER USER username ACCOUNT LOCK;

-- 强制密码变更
ALTER USER username PASSWORD EXPIRE;

-- 删除多余权限
REVOKE SELECT ANY TABLE FROM username;
REVOKE CREATE ANY TABLE FROM username;
```
