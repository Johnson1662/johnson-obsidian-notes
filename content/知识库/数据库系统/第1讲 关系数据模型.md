## 1.1 数据库系统概述

### 1.1.1 数据库系统的定义

**数据库**（Database, DB）是长期存储在计算机内有组织的、可共享的大量数据的集合。数据库中的数据按一定的数据模型组织、描述和储存，具有较小的冗余度、较高的数据独立性和易扩展性，并可为各种用户共享。

**数据库管理系统**（Database Management System, DBMS）是位于用户与操作系统之间的一层数据管理软件。用于科学地组织和存储数据、高效地获取和维护数据。

**数据库系统**（Database System, DBS）是由数据库、数据库管理系统（及其开发工具）、应用程序、数据库管理员组成的存储、管理、处理和维护数据的系统。

### 1.1.2 数据管理技术的发展阶段

| 阶段 | 时间 | 特征 | 代表系统 |
|------|------|------|----------|
| 人工管理 | 1950年代中期前 | 无专门软件，数据不保存、不共享、不独立 | 纸质记录，穿孔卡片 |
| 文件系统 | 1950年代后期-1960年代中期 | 文件系统管理，数据可长期保存，共享性差 | IBM的IMS系统 |
| 数据库系统 | 1960年代后期至今 | 数据结构化，共享性高，独立性高 | Oracle, MySQL, SQL Server |

### 1.1.3 数据模型的三要素

数据模型是现实世界数据特征的抽象，用于描述数据、组织数据和对数据进行操作。

数据模型 = **数据结构** + **数据操作** + **完整性约束**

#### 1. 数据结构
描述数据的组织形式，包括：
- 数据类型
- 内容
- 性质
- 数据间的联系

#### 2. 数据操作
对数据库中各种对象（型）的实例（值）允许执行的操作集合：
- 检索（查询）
- 插入
- 修改
- 删除

#### 3. 完整性约束
一组完整性规则的集合，保证数据的正确性、有效性和相容性：
- 实体完整性
- 参照完整性
- 用户自定义完整性

## 1.2 概念模型

### 1.2.1 基本概念

**实体（Entity）**：客观存在并可相互区别的事物。如：学生、课程、教师。

**实体集（Entity Set）**：同一类型实体的集合。如：所有学生的集合。

**属性（Attribute）**：实体所具有的某一特性。如：学生的学号、姓名、年龄。

**码（Key）**：唯一标识实体的属性集。如：学号是学生的码。

**域（Domain）**：属性的取值范围。如：年龄的域是正整数。

**实体-联系模型（E-R Model）**：用E-R图来描述现实世界的概念模型。

### 1.2.2 E-R图的表示方法

| 图形元素 | 形状 | 说明 |
|----------|------|------|
| 实体集 | 矩形 | 表示实体集集合 |
| 属性 | 椭圆 | 表示实体的属性 |
| 联系 | 菱形 | 表示实体集之间的联系 |
| 边 | 直线 | 连接实体集到其属性，或连接联系到其实体集 |

**联系的元数（Degree）**：
- 一元联系：同一实体集内部实体间的联系
- 二元联系：两个实体集之间的联系（最常见）
- 三元联系：三个实体集之间的联系
- 多元联系：多个实体集之间的联系

**联系的类型**：
- 一对一（1:1）
- 一对多（1:N）
- 多对多（M:N）

### 1.2.3 概念模型的表示

E-R图示例（学生-课程）：
```
[学生] ———(选课)——— [课程]
  |学号                |课程号
  |姓名                |课程名
  |年龄                |学分
```

## 1.3 关系数据模型

### 1.3.1 关系数据模型的基本概念

关系模型是建立在严格的数学理论（集合论）基础上的数据模型。

#### 基本术语对应关系

| 关系模型术语 | 表格术语 | 数学术语 |
|-------------|---------|---------|
| 关系 | 表 | 集合 |
| 元组 | 行 | 元素 |
| 属性 | 列 | 域 |
| 域 | 列的取值范围 | 集合 |
| 码 | 主键 | 能唯一标识元组的属性集 |
| 分量 | 列的值 | 元组在域上的映射 |
| 关系模式 | 表结构 | R(U, D, DOM, F) |

### 1.3.2 关系的性质

1. **列是同质的**：每一列中的分量是同一类型的数据，来自同一个域。

2. **不同的列可出自同一个域**：不同的列称为不同的属性，必须给予不同的属性名。

3. **列的顺序无所谓**：理论上列的顺序可以任意交换。

4. **任意两个元组不能完全相同**：关系中不允许有重复元组。

5. **行的顺序无所谓**：理论上行的顺序可以任意交换。

6. **分量必须取原子值**：每一个分量都必须是不可分的数据项。

### 1.3.3 关系的键（码）

#### 1. 超码（Superkey）
能唯一标识关系中一个元组的属性集。

#### 2. 候选码（Candidate Key）
- 能唯一标识关系中一个元组
- 不含有冗余的属性
- 一个关系可能有多个候选码

#### 3. 主码（Primary Key）
- 从候选码中选择一个作为主码
- 主属性：包含在任何一个候选码中的属性
- 非主属性：不包含在任何候选码中的属性

#### 4. 外码（Foreign Key）
- 设F是基本关系R的一个或一组属性，但不是R的主码
- 如果F与基本关系S的主码Ks相对应
- 则称F是R的外码，R是参照关系，S是被参照关系

### 1.3.4 关系模式

关系的描述称为关系模式：
```
R(U, D, DOM, F)
```
其中：
- R：关系名
- U：组成该关系的属性名集合
- D：属性组U中属性所来自的域
- DOM：属性向域的映射集合
- F：属性间的数据依赖关系集合

**简化表示**：R(A1, A2, ..., An)

## 1.4 关系完整性

### 1.4.1 实体完整性（Entity Integrity）

**定义**：若属性A是基本关系R的主属性，则A不能取空值。

**说明**：
- 主属性是主码的组成部分
- 空值（NULL）表示"不知道"或"无意义"
- 实体完整性规则保证了每个实体的唯一性

### 1.4.2 参照完整性（Referential Integrity）

**定义**：若属性（或属性组）F是基本关系R的外码，它与基本关系S的主码Ks相对应，则对于R中每个元组在F上的值必须：
- 或者取空值（F的每个属性值均为空值）
- 或者等于S中某个元组的主码值

**示例**：
```
学生表(学号, 姓名, 专业号)      -- 学号是主码
专业表(专业号, 专业名)         -- 专业号是主码

-- 学生表中的专业号是外码，参照专业表的主码专业号
-- 学生表中的专业号要么为空，要么必须是专业表中存在的专业号
```

### 1.4.3 用户定义的完整性（User-defined Integrity）

针对某一具体关系数据库的约束条件，反映某一具体应用所涉及的数据必须满足的语义要求：

- 属性值范围：年龄在0-150之间
- 字符串长度：姓名不超过20个字符
- 数据格式：邮箱地址必须包含@
- 业务规则：考试成绩在0-100分之间

## 1.5 关系代数

关系代数是一种抽象的查询语言，用对关系的运算来表达查询。

### 1.5.1 传统的集合运算

#### 1. 并（Union）
```
R ∪ S = { t | t ∈ R ∨ t ∈ S }
```
关系R和S具有相同的目n，且相应的属性取自同一个域。

#### 2. 差（Difference）
```
R - S = { t | t ∈ R ∧ t ∉ S }
```
属于R但不属于S的元组构成的集合。

#### 3. 交（Intersection）
```
R ∩ S = { t | t ∈ R ∧ t ∈ S }
```
既属于R又属于S的元组构成的集合。

等价表示：R ∩ S = R - (R - S)

#### 4. 笛卡尔积（Cartesian Product）
```
R × S = { tr ⋈ ts | tr ∈ R ∧ ts ∈ S }
```
- R有k1个元组，S有k2个元组
- R × S有k1 × k2个元组

### 1.5.2 专门的关系运算

#### 1. 选择（Selection）
```
σF(R) = { t | t ∈ R ∧ F(t) = 真 }
```
- 从关系R中选择使逻辑表达式F为真的元组
- 是行的运算
- F由逻辑运算符（∧, ∨, ¬）和比较运算符（>, ≥, <, ≤, =, ≠）组成

**示例**：
```
σ年龄>20(学生)        -- 选择年龄大于20的学生
σ性别='女'∧年龄<20(学生)  -- 选择年龄小于20岁的女生
```

#### 2. 投影（Projection）
```
πA(R) = { t[A] | t ∈ R }
```
- 从R中选出若干属性列组成新的关系
- 是列的运算
- 会取消重复元组

**示例**：
```
π学号,姓名(学生)      -- 选出学生的学号和姓名
```

#### 3. 连接（Join）
```
R ⋈AθB S = { tr ⋈ ts | tr ∈ R ∧ ts ∈ S ∧ tr[A] θ ts[B] }
```
- 从R和S的笛卡尔积中选取属性间满足条件的元组
- θ是比较运算符（=, >, <, ≥, ≤, ≠）

**等值连接**：θ为"="的连接

**自然连接**：
- 特殊的等值连接
- 要求两个关系中进行比较的分量必须是相同的属性组
- 在结果中取消重复的属性列

**示例**：
```
学生 ⋈ 课程      -- 自然连接：基于相同的属性（课程号）连接
```

#### 4. 除法（Division）

给定关系R(X,Y)和S(Y,Z)，其中X、Y、Z为属性组：
- R中的Y与S中的Y可以有不同的属性名
- 但必须出自相同的域集

R ÷ S = { tr[X] | tr ∈ R ∧ πY(S) ⊆ YX(tr) }

**直观理解**：
- 象集YX(tr)：给定一个X值，找到它对应的所有Y值
- R ÷ S的结果是所有在R中，其Y值包含S中所有Y值的X值

**示例**：查询选修了所有课程的学生
```
π学号,课程号(选课) ÷ π课程号(课程)
```

## 1.6 关系演算

关系演算是以数理逻辑中的谓词演算为基础的。

### 1.6.1 元组关系演算

以元组变量作为谓词变元的基本对象。

**原子公式**：
1. R(t)：t是关系R的一个元组
2. t[i] θ u[j]：元组t的第i个分量与元组u的第j个分量满足比较关系θ
3. t[i] θ C 或 C θ t[i]：元组t的第i个分量与常量C满足比较关系θ

**公式**：
- 原子公式是公式
- 若φ₁和φ₂是公式，则φ₁ ∧ φ₂、φ₁ ∨ φ₂、¬φ₁也是公式
- 若φ是公式，则∃t(φ)和∀t(φ)也是公式

**查询表达式**：
{t | φ(t)}

### 1.6.2 域关系演算

以域变量作为谓词变元的基本对象。

**原子公式**：
1. R(x₁, x₂, ..., xₙ)：域变量组(x₁, x₂, ..., xₙ)是关系R的一个元组
2. xᵢ θ yᵢ：域变量满足比较关系θ
3. xᵢ θ C：域变量与常量满足比较关系θ

**查询表达式**：
{x₁, x₂, ..., xₖ | φ(x₁, x₂, ..., xₙ)}

## 1.7 关系模型的存储结构

### 1.7.1 关系数据库的组织

关系数据库包含多个关系（表），每个关系对应一个或多个文件：

- **堆文件**：元组无序存储
- **排序文件**：元组按某个属性值排序存储
- **聚簇文件**：将不同关系的元组存储在同一文件中
- **散列文件**：使用散列函数确定存储位置
- **索引文件**：建立索引以加速访问

### 1.7.2 关系视图

**视图（View）**：从一个或几个基本表（或视图）导出的表。视图本身不存储数据，只存储定义。

**作用**：
- 简化用户操作
- 多角度看待同一数据
- 提供逻辑独立性
- 安全保护
