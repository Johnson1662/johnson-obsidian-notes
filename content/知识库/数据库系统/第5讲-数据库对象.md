## 完整性约束概述

### 什么是完整性约束？

**完整性约束**是数据库中数据必须满足的规则，用于保证数据的正确性和一致性。

### 约束的分类

1. **域约束**：限制属性的取值范围
2. **实体完整性**：主键不能为空
3. **参照完整性**：外键必须引用存在的值
4. **用户定义约束**：业务规则约束

## 关系代数作为约束语言

### 两种约束表达方式

#### 1. 空结果约束

$$R = \emptyset$$

- **含义**：$R$ 的值必须为空
- **解释**：$R$ 表达式的结果中没有元组

**示例：** 约束"没有1900年以前的电影"

$$\pi_{title}(\sigma_{year<1900}(Movies)) = \emptyset$$

**验证：** 查询 Movies 表中 year < 1900 的记录，结果应该为空

#### 2. 包含约束

$$R \subseteq S$$

- **含义**：$R$ 中的每个元组也必须在 $S$ 中
- **解释**：$R$ 的结果是 $S$ 的结果的子集

**示例：** 参照完整性约束

$$\pi_{deptID}(Student) \subseteq \pi_{deptID}(Department)$$

**含义：** 每个学生的系别必须在 Department 表中存在

**验证：**

Student 表中的 deptID：{D01, D02, D03}
Department 表中的 deptID：{D01, D02, D03}

{D01, D02, D03} ⊆ {D01, D02, D03} ✓

## 主键约束

### 什么是主键？

**主键**是关系中唯一标识元组的属性或属性集。

### 主键的形式化定义

设 $K$ 是关系模式 $R$ 的属性集，$K$ 是 $R$ 的**主键**，当且仅当：

1. **唯一性**：$\forall t_1, t_2 \in r: t_1[K] = t_2[K] \Rightarrow t_1 = t_2$
2. **非空性**：$\forall t \in r: t[K] \neq \text{NULL}$
3. **最小性**：不存在 $K' \subset K$ 满足上述条件

### 示例

#### 单属性主键

Student 表的主键是 studentID：

| studentID | name | age |
|-----------|------|-----|
| S001 | 张三 | 20 |
| S002 | 李四 | 21 |

- 唯一性：S001 ≠ S002，所以对应的元组不同
- 非空性：studentID 不能为空
- 最小性：studentID 是最小的唯一标识

#### 复合主键

Enroll 表的主键是 (studentID, courseID)：

| studentID | courseID | grade |
|-----------|----------|-------|
| S001 | C01 | 90 |
| S001 | C02 | 85 |
| S002 | C01 | 88 |

- 唯一性：(S001, C01) ≠ (S001, C02) ≠ (S002, C01)
- 非空性：studentID 和 courseID 都不能为空
- 最小性：单独的 studentID 或 courseID 都不能唯一标识

### SQL中的主键定义

```sql
-- 单属性主键
CREATE TABLE Student (
    studentID CHAR(10) PRIMARY KEY,
    name VARCHAR(50),
    age INT
);

-- 复合主键
CREATE TABLE Enroll (
    studentID CHAR(10),
    courseID CHAR(10),
    grade INT,
    PRIMARY KEY (studentID, courseID)
);
```

## 外键约束

### 什么是外键？

**外键**是引用另一个关系主键的属性或属性集。

### 外键的形式化定义

设 $R$ 和 $S$ 是两个关系模式，$FK \subseteq R$ 是 $R$ 的属性集，$PK \subseteq S$ 是 $S$ 的主键。如果 $FK$ 引用 $PK$，则：

$$\pi_{FK}(R) \subseteq \pi_{PK}(S)$$

### 示例

#### 示例1：学生-系别外键

Student 表的 deptID 引用 Department 表的 deptID：

$$\pi_{deptID}(Student) \subseteq \pi_{deptID}(Department)$$

**验证：**

Student 表中的 deptID：

| deptID |
|--------|
| D01 |
| D01 |
| D02 |
| D03 |

Department 表中的 deptID：

| deptID |
|--------|
| D01 |
| D02 |
| D03 |

{D01, D02, D03} ⊆ {D01, D02, D03} ✓

#### 示例2：选课-学生外键

Enroll 表的 studentID 引用 Student 表的 studentID：

$$\pi_{studentID}(Enroll) \subseteq \pi_{studentID}(Student)$$

**验证：**

Enroll 表中的 studentID：{S001, S002, S003, S004}
Student 表中的 studentID：{S001, S002, S003, S004}

{S001, S002, S003, S004} ⊆ {S001, S002, S003, S004} ✓

### SQL中的外键定义

```sql
CREATE TABLE Student (
    studentID CHAR(10) PRIMARY KEY,
    name VARCHAR(50),
    deptID CHAR(10),
    FOREIGN KEY (deptID) REFERENCES Department(deptID)
);

CREATE TABLE Enroll (
    studentID CHAR(10),
    courseID CHAR(10),
    grade INT,
    PRIMARY KEY (studentID, courseID),
    FOREIGN KEY (studentID) REFERENCES Student(studentID),
    FOREIGN KEY (courseID) REFERENCES Course(courseID)
);
```

### 外键约束的违反

#### 插入违反

```sql
-- 尝试插入一个不存在的系别
INSERT INTO Student VALUES ('S005', '钱七', 20, 'M', 'D99', 3.0);
-- 错误：D99 在 Department 表中不存在
```

**当前 Department 表：**

| deptID | deptName |
|--------|----------|
| D01 | 计算机系 |
| D02 | 数学系 |
| D03 | 物理系 |

D99 不在 {D01, D02, D03} 中，违反了外键约束

#### 删除违反

```sql
-- 尝试删除一个被引用的系别
DELETE FROM Department WHERE deptID = 'D01';
-- 错误：D01 被 Student 表中的 S001 和 S002 引用
```

**Student 表中引用 D01 的记录：**

| studentID | name | deptID |
|-----------|------|--------|
| S001 | 张三 | D01 |
| S002 | 李四 | D01 |

删除 D01 会导致这些记录的外键失效

## 属性约束

### NOT NULL 约束

**含义：** 属性不能为空

$$\forall t \in r: t[A] \neq \text{NULL}$$

**示例：**

```sql
CREATE TABLE Student (
    studentID CHAR(10) NOT NULL,
    name VARCHAR(50) NOT NULL,
    age INT,
    gpa DECIMAL(3,2)
);
```

**违反示例：**

```sql
INSERT INTO Student (studentID, name) VALUES (NULL, '张三');
-- 错误：studentID 不能为空
```

### CHECK 约束

**含义：** 属性值必须满足条件

$$\forall t \in r: \text{condition}(t[A]) = \text{TRUE}$$

**示例：**

```sql
CREATE TABLE Student (
    studentID CHAR(10) PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    age INT CHECK (age >= 0 AND age <= 150),
    gender CHAR(1) CHECK (gender IN ('M', 'F')),
    gpa DECIMAL(3,2) CHECK (gpa >= 0 AND gpa <= 4.0)
);
```

**验证：**

Student 表中的数据：

| studentID | name | age | gender | gpa |
|-----------|------|-----|--------|-----|
| S001 | 张三 | 20 | M | 3.5 |
| S002 | 李四 | 21 | F | 3.8 |

- age = 20, 21：都在 0-150 范围内 ✓
- gender = 'M', 'F'：都在 ('M', 'F') 集合中 ✓
- gpa = 3.5, 3.8：都在 0-4.0 范围内 ✓

**违反示例：**

```sql
INSERT INTO Student VALUES ('S005', '钱七', 200, 'M', 3.0);
-- 错误：age = 200 不满足 CHECK (age >= 0 AND age <= 150)

INSERT INTO Student VALUES ('S006', '孙八', 20, 'X', 3.0);
-- 错误：gender = 'X' 不满足 CHECK (gender IN ('M', 'F'))

INSERT INTO Student VALUES ('S007', '周九', 20, 'M', 5.0);
-- 错误：gpa = 5.0 不满足 CHECK (gpa >= 0 AND gpa <= 4.0)
```

### DEFAULT 约束

**含义：** 属性的默认值

**示例：**

```sql
CREATE TABLE Student (
    studentID CHAR(10) PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    gender CHAR(1) DEFAULT 'M',
    enrollDate DATE DEFAULT CURRENT_DATE
);
```

**使用示例：**

```sql
-- 使用默认值
INSERT INTO Student (studentID, name) VALUES ('S001', '张三');
-- 等价于
INSERT INTO Student VALUES ('S001', '张三', 'M', '2024-04-15');
```

## 元组约束

### 什么是元组约束？

**元组约束**限制元组中多个属性之间的关系。

### 形式化表示

$$\forall t \in r: \text{condition}(t[A_1], t[A_2], \ldots, t[A_n]) = \text{TRUE}$$

### 示例

#### 示例1：日期约束

```sql
CREATE TABLE Enroll (
    studentID CHAR(10),
    courseID CHAR(10),
    enrollDate DATE,
    dropDate DATE,
    CHECK (dropDate IS NULL OR dropDate > enrollDate)
);
```

**含义：** 退课日期必须晚于选课日期，或者为空

**验证：**

| studentID | courseID | enrollDate | dropDate |
|-----------|----------|------------|----------|
| S001 | C01 | 2024-02-20 | NULL |
| S001 | C02 | 2024-02-20 | 2024-03-15 |

- S001, C01：dropDate = NULL ✓
- S001, C02：dropDate (2024-03-15) > enrollDate (2024-02-20) ✓

**违反示例：**

```sql
INSERT INTO Enroll VALUES ('S002', 'C01', '2024-02-20', '2024-02-15');
-- 错误：dropDate (2024-02-15) < enrollDate (2024-02-20)
```

#### 示例2：年龄-年级约束

```sql
CREATE TABLE Student (
    studentID CHAR(10) PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    grade INT,
    CHECK (age >= grade + 15)
);
```

**含义：** 年龄至少比年级大15岁

## 断言

### 什么是断言？

**断言**是一个谓词，表达了我们希望数据库总能满足的条件。

### 断言的形式化表示

$$\text{Assertion}: \forall \text{ 定量}: \text{条件}$$

### 示例

#### 示例1：总学分限制

```sql
CREATE ASSERTION total_credit_check
CHECK (
    (SELECT SUM(credit) FROM Course) <= 100
);
```

**含义：** 所有课程的总学分不能超过100

**验证：**

Course 表中的 credit：

| courseID | credit |
|----------|--------|
| C01 | 3 |
| C02 | 4 |
| C03 | 3 |
| C04 | 4 |

SUM(credit) = 3 + 4 + 3 + 4 = 14 ≤ 100 ✓

#### 示例2：学生选课数量限制

```sql
CREATE ASSERTION max_enrollment_check
CHECK (
    NOT EXISTS (
        SELECT studentID
        FROM Enroll
        GROUP BY studentID
        HAVING COUNT(*) > 10
    )
);
```

**含义：** 每个学生最多选修10门课程

**验证：**

Enroll 表中的数据：

| studentID | courseID |
|-----------|----------|
| S001 | C01 |
| S001 | C02 |
| S002 | C01 |
| S002 | C03 |
| S003 | C02 |
| S004 | C04 |

每个学生的选课数量：
- S001：2 门 ≤ 10 ✓
- S002：2 门 ≤ 10 ✓
- S003：1 门 ≤ 10 ✓
- S004：1 门 ≤ 10 ✓

## 触发器

### 什么是触发器？

**触发器**是一段程序，当特定事件发生时自动执行。

### 触发器的组成

1. **事件**：触发器执行的条件（如 INSERT、UPDATE、DELETE）
2. **条件**：触发器执行的额外条件
3. **动作**：触发器执行的操作

### 触发器的形式化表示

$$\text{Trigger}: E \wedge C \rightarrow A$$

### 示例

#### 示例1：成绩更新日志

```sql
CREATE TRIGGER grade_update_log
AFTER UPDATE OF grade ON Enroll
FOR EACH ROW
WHEN (NEW.grade <> OLD.grade)
BEGIN
    INSERT INTO GradeLog (studentID, courseID, oldGrade, newGrade, updateTime)
    VALUES (NEW.studentID, NEW.courseID, OLD.grade, NEW.grade, CURRENT_TIMESTAMP);
END;
```

**触发条件：** Enroll 表的 grade 字段被更新

**执行动作：** 将旧成绩和新成绩记录到 GradeLog 表

**示例数据：**

初始 Enroll 表：

| studentID | courseID | grade |
|-----------|----------|-------|
| S001 | C01 | 90 |

执行更新：
```sql
UPDATE Enroll SET grade = 95 WHERE studentID = 'S001' AND courseID = 'C01';
```

触发器执行后，GradeLog 表：

| studentID | courseID | oldGrade | newGrade | updateTime |
|-----------|----------|----------|----------|------------|
| S001 | C01 | 90 | 95 | 2024-04-15 10:30:00 |

#### 示例2：自动更新平均分

```sql
CREATE TRIGGER update_gpa
AFTER INSERT OR UPDATE OR DELETE ON Enroll
FOR EACH ROW
BEGIN
    UPDATE Student
    SET gpa = (
        SELECT AVG(grade) / 25
        FROM Enroll
        WHERE studentID = NEW.studentID
    )
    WHERE studentID = NEW.studentID;
END;
```

**触发条件：** Enroll 表发生插入、更新或删除

**执行动作：** 重新计算该学生的 GPA

**示例数据：**

初始 Student 表：

| studentID | name | gpa |
|-----------|------|-----|
| S001 | 张三 | NULL |

初始 Enroll 表：

| studentID | courseID | grade |
|-----------|----------|-------|
| S001 | C01 | 90 |
| S001 | C02 | 85 |

执行插入：
```sql
INSERT INTO Enroll VALUES ('S001', 'C03', 88, '2024-02-20');
```

触发器计算：AVG(grade) = (90 + 85 + 88) / 3 = 87.67
GPA = 87.67 / 25 = 3.51

更新后的 Student 表：

| studentID | name | gpa |
|-----------|------|-----|
| S001 | 张三 | 3.51 |

## 约束与触发器的比较

| 特性 | 约束 | 触发器 |
|------|------|--------|
| 声明式 | ✓ | ✗ |
| 简单性 | 简单 | 复杂 |
| 表达能力 | 有限 | 强大 |
| 性能影响 | 小 | 可能大 |
| 调试难度 | 低 | 高 |

### 选择建议

- **简单约束**使用声明式约束（NOT NULL, CHECK, FOREIGN KEY）
- **复杂业务规则**使用触发器
- **避免过度使用触发器**，可能影响性能

## 学习建议

对于初学者，建议：
1. **理解约束的重要性**：这是数据完整性的基础
2. **掌握主键和外键**：这是关系数据库的核心
3. **学习简单的约束语法**：NOT NULL、CHECK等
4. **了解触发器的基本概念**：知道它的作用和应用场景

> [!tip] 实践建议
> 建议在数据库系统中创建包含各种约束的表，然后尝试插入违反约束的数据，观察数据库的响应，这样能更好地理解约束的作用。

## 关键概念总结

1. **主键**：唯一标识元组，不能为空
2. **外键**：$\pi_{FK}(R) \subseteq \pi_{PK}(S)$，引用完整性
3. **CHECK 约束**：$\forall t: \text{condition}(t) = \text{TRUE}$
4. **断言**：全局性的业务规则
5. **触发器**：$\text{Event} \wedge \text{Condition} \rightarrow \text{Action}$
