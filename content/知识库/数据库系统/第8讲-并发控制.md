## 并发控制概述

### 为什么需要并发控制？

#### 并发执行的问题示例

**场景：丢失更新（Lost Update）**

两个事务同时对 A001 账户进行操作：
- $T_1$：从 A001 取款 100
- $T_2$：向 A001 存款 50

**没有并发控制的执行：**

| 时刻 | $T_1$ | $T_2$ | A001.balance |
|------|-------|-------|--------------|
| 0 | - | - | 1000 |
| 1 | read(A001) | - | 1000 |
| 2 | - | read(A001) | 1000 |
| 3 | write(900) | - | 900 |
| 4 | - | write(1050) | 1050 |

**问题：** $T_1$ 的取款操作丢失了！正确结果应该是 950

## 调度的形式化定义

### 操作的形式化表示

设事务 $T_i$ 的操作：
- $r_i(X)$：事务 $T_i$ 读取数据项 $X$
- $w_i(X)$：事务 $T_i$ 写入数据项 $X$

### 调度的定义

**调度** $S$ 是所有事务操作的一个序列。

**示例：**

事务 $T_1$：$r_1(A), w_1(A), r_1(B), w_1(B)$
事务 $T_2$：$r_2(A), w_2(A), r_2(B), w_2(B)$

**调度 $S$：** $r_1(A), r_2(A), w_1(A), w_2(A), r_1(B), w_1(B), r_2(B), w_2(B)$

## 串行调度

### 什么是串行调度？

**串行调度**是指事务一个接一个地执行，没有交叉执行。

#### 示例

**串行调度 $S_1 = T_1 \cdot T_2$：**

| 时刻 | 操作 | 数据库状态 |
|------|------|------------|
| 1 | $r_1(A001)$ | A001=1000 |
| 2 | $w_1(A001)$ | A001=900 |
| 3 | $r_1(A002)$ | A002=2000 |
| 4 | $w_1(A002)$ | A002=2100 |
| 5 | $r_2(A003)$ | A003=1500 |
| 6 | $w_2(A003)$ | A003=1400 |
| 7 | $r_2(A001)$ | A001=900 |
| 8 | $w_2(A001)$ | A001=950 |

**最终状态：** A001=950, A002=2100, A003=1400

**串行调度 $S_2 = T_2 \cdot T_1$：**

| 时刻 | 操作 | 数据库状态 |
|------|------|------------|
| 1 | $r_2(A003)$ | A003=1500 |
| 2 | $w_2(A003)$ | A003=1400 |
| 3 | $r_2(A001)$ | A001=1000 |
| 4 | $w_2(A001)$ | A001=1050 |
| 5 | $r_1(A001)$ | A001=1050 |
| 6 | $w_1(A001)$ | A001=950 |
| 7 | $r_1(A002)$ | A002=2000 |
| 8 | $w_1(A002)$ | A002=2100 |

**最终状态：** A001=950, A002=2100, A003=1400

## 冲突可串行化

### 什么是冲突？

**冲突**是指两个操作满足以下条件：
1. 来自不同事务
2. 访问同一数据项
3. 至少有一个是写操作

#### 冲突的类型

| 类型 | 示例 | 问题 |
|------|------|------|
| 读-写冲突 | $r_1(A), w_2(A)$ | 不可重复读 |
| 写-读冲突 | $w_1(A), r_2(A)$ | 脏读 |
| 写-写冲突 | $w_1(A), w_2(A)$ | 丢失更新 |

### 优先图示例

**调度 $S$：** $r_1(A), w_2(A), r_1(A), w_1(A)$

**冲突分析：**

| 操作对 | 是否冲突 | 原因 |
|--------|----------|------|
| $r_1(A)$ 和 $w_2(A)$ | 是 | 读-写冲突 |
| $w_2(A)$ 和 $r_1(A)$ | 是 | 写-读冲突 |
| $r_1(A)$ 和 $w_1(A)$ | 否 | 同一事务 |
| $w_2(A)$ 和 $w_1(A)$ | 是 | 写-写冲突 |

**优先图：**

```
T2 → T1（因为 w2(A) 在 r1(A) 之前）
```

图无环，所以冲突可串行化，等价于串行调度 $T_2 \cdot T_1$

### 非冲突可串行化的示例

**调度 $S$：** $r_1(A), w_2(A), r_2(A), w_1(A)$

**优先图：**

```
T1 → T2（因为 r1(A) 在 w2(A) 之前）
T2 → T1（因为 w2(A) 在 w1(A) 之前）
```

图有环，所以不是冲突可串行化

## 锁机制

### 锁的类型

#### 共享锁（S锁）

- **作用**：允许读取，禁止写入
- **兼容性**：多个事务可以同时持有共享锁

**示例：**

| 时刻 | $T_1$ | $T_2$ | A001 的锁 |
|------|-------|-------|-----------|
| 1 | $SL_1(A001)$ | - | S锁 |
| 2 | $r_1(A001)$ | - | S锁 |
| 3 | - | $SL_2(A001)$ | S锁+S锁 |
| 4 | - | $r_2(A001)$ | S锁+S锁 |
| 5 | $UL_1(A001)$ | - | S锁 |
| 6 | - | $UL_2(A001)$ | 无锁 |

#### 排他锁（X锁）

- **作用**：禁止读取和写入
- **兼容性**：只能有一个事务持有排他锁

**示例：**

| 时刻 | $T_1$ | $T_2$ | A001 的锁 |
|------|-------|-------|-----------|
| 1 | $XL_1(A001)$ | - | X锁 |
| 2 | $r_1(A001)$ | - | X锁 |
| 3 | - | $SL_2(A001)$ | 阻塞（等待） |
| 4 | $w_1(A001)$ | 等待 | X锁 |
| 5 | $UL_1(A001)$ | 等待 | 无锁 |
| 6 | - | $SL_2(A001)$ | S锁 |

### 锁的兼容性矩阵

| 持有锁 \ 请求锁 | S锁 | X锁 |
|----------------|-----|-----|
| S锁 | ✓ | ✗ |
| X锁 | ✗ | ✗ |

## 两阶段锁

### 什么是两阶段锁？

**两阶段锁**（Two-Phase Locking，2PL）是保证冲突可串行化的锁协议。

### 两阶段示例

**事务 $T_1$：从 A001 转 100 到 A002**

**遵守两阶段锁的执行：**

| 时刻 | 操作 | 阶段 |
|------|------|------|
| 1 | $XL_1(A001)$ | 增长阶段 |
| 2 | $r_1(A001)$ | 增长阶段 |
| 3 | $w_1(A001)$ | 增长阶段 |
| 4 | $XL_1(A002)$ | 增长阶段 |
| 5 | $r_1(A002)$ | 增长阶段 |
| 6 | $w_1(A002)$ | 增长阶段 |
| 7 | $UL_1(A001)$ | 收缩阶段 |
| 8 | $UL_1(A002)$ | 收缩阶段 |

**违反两阶段锁的执行：**

| 时刻 | 操作 | 阶段 |
|------|------|------|
| 1 | $XL_1(A001)$ | - |
| 2 | $r_1(A001)$ | - |
| 3 | $w_1(A001)$ | - |
| 4 | $UL_1(A001)$ | ❌ 违反（释放锁后又获取锁） |
| 5 | $XL_1(A002)$ | - |
| 6 | $r_1(A002)$ | - |
| 7 | $w_1(A002)$ | - |
| 8 | $UL_1(A002)$ | - |

### 两阶段锁的正确性

**定理：** 如果所有事务都遵守两阶段锁协议，则任何调度都是冲突可串行化的。

## 死锁

### 死锁示例

**事务 $T_1$：从 A001 转到 A002**
**事务 $T_2$：从 A002 转到 A001**

**死锁发生：**

| 时刻 | $T_1$ | $T_2$ | 状态 |
|------|-------|-------|------|
| 1 | $XL_1(A001)$ | - | $T_1$ 持有 A001 的 X锁 |
| 2 | - | $XL_2(A002)$ | $T_2$ 持有 A002 的 X锁 |
| 3 | $XL_1(A002)$ | - | $T_1$ 等待 $T_2$ 释放 A002 |
| 4 | - | $XL_2(A001)$ | $T_2$ 等待 $T_1$ 释放 A001 |

**等待图：**

```
T1 → T2（$T_1$ 等待 $T_2$）
T2 → T1（$T_2$ 等待 $T_1$）
```

图有环，发生死锁！

### 死锁的处理

#### 预防：顺序封锁法

规定所有事务必须按固定顺序获取锁（如按 accountID 排序）：

| 事务 | 正确顺序 |
|------|----------|
| $T_1$ | 先锁 A001，再锁 A002 |
| $T_2$ | 先锁 A001，再锁 A002 |

**这样就不会发生死锁**

#### 检测：等待图

定期检查等待图是否有环

#### 恢复：选择牺牲者

选择一个事务回滚，释放其所有锁

## 时间戳排序示例

### 基本思想

每个事务分配唯一时间戳，按时间戳顺序执行操作。

**示例：**

| 事务 | 时间戳 |
|------|--------|
| $T_1$ | 10 |
| $T_2$ | 20 |

**规则：** 如果 $TS(T_1) < TS(T_2)$，则 $T_1$ 的操作应该在 $T_2$ 的对应操作之前执行

## MVCC 示例

### 多版本并发控制

保留数据的多个版本，读操作不阻塞写操作。

**示例：**

A001 的多个版本：

| 版本 | 值 | 创建时间 | 删除时间 |
|------|-----|----------|----------|
| V1 | 1000 | 10 | - |
| V2 | 900 | 20 | - |

**读操作：** 根据事务的时间戳选择合适的版本

- $T_1$（时间戳 15）读 A001：选择 V1（值=1000）
- $T_2$（时间戳 25）读 A001：选择 V2（值=900）

对于初学者，建议：
1. **理解并发控制的重要性**：知道为什么需要并发控制

3. **理解两阶段锁**：这是保证可串行化的重要方法

> [!tip] 实践建议

## 关键概念总结

1. **并发控制**：确保事务并发执行时保持一致性
2. **可串行化**：$\text{Result}(S) = \text{Result}(S')$，其中 $S'$ 是串行调度
3. **冲突可串行化**：优先图无环
4. **锁机制**：$SL_i(X)$（共享锁）、$XL_i(X)$（排他锁）
5. **两阶段锁**：增长阶段和收缩阶段
6. **死锁**：循环等待 $T_1 \rightarrow T_2 \rightarrow \ldots \rightarrow T_1$
