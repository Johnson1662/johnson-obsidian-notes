## 数据库设计阶段

### 数据库建模与实现过程

数据库设计是一个从概念到实现的过程：

```
想法 → 高层设计 → 关系数据库模式 → 关系DBMS
```

1. **想法**：业务需求和概念
2. **高层设计**：概念模型设计
3. **关系数据库模式**：逻辑结构设计
4. **关系DBMS**：物理实现

## 实体/联系模型

### 什么是E/R模型？

**E/R模型**（实体/联系模型）是由**陈品山博士**（Dr. Peter Chen）于1976年发明的概念模型。

### E/R模型的组成
- **实体集**（Entity Sets）
- **联系**（Relationships）
- **属性**（Attributes）

### E/R图
- **E/R图**是E/R模型的图形化表示
- 用于可视化数据库的概念结构

## 实体集

### 什么是实体集？

**实体集**是具有相同属性的实体的集合。例如：
- 学生实体集
- 课程实体集
- 教师实体集

### 实体的属性

每个实体都有一组**属性**，描述实体的特征。例如学生实体的属性：
- 学号
- 姓名
- 年龄
- 性别

## 联系

### 什么是联系？

**联系**描述实体集之间的关联关系。例如：
- 学生**选修**课程
- 教师**讲授**课程

### 联系的类型

1. **一对一联系（1:1）**
   - 例如：系主任与系别

2. **一对多联系（1:N）**
   - 例如：系别与学生

3. **多对多联系（M:N）**
   - 例如：学生与课程

## E/R图的基本符号

### 实体集
- 用**矩形**表示
- 实体名写在矩形内

### 属性
- 用**椭圆**表示
- 属性名写在椭圆内
- 用线连接到实体集

### 联系
- 用**菱形**表示
- 联系名写在菱形内
- 用线连接相关的实体集

### 示例：学生选课系统

```
[学生] ---<选修>--- [课程]
  |                    |
学号                 课程号
姓名                 课程名
年龄                 学分
```

## 设计原则

### 1. 避免冗余
- 同一信息不要存储多次
- 例如：不要在每个学生记录中都存储系主任信息

### 2. 简单性原则
- 尽量使用简单的实体和联系
- 避免不必要的复杂性

### 3. 选择正确的联系类型
- 准确判断1:1、1:N、M:N联系
- 这影响数据库的结构和性能

### 4. 使用弱实体集
- 当实体不能独立存在时使用弱实体集
- 例如：家属实体依赖于员工实体

## E/R模型中的约束

### 键约束

**键约束**确保实体集中的每个实体都能被唯一标识。

#### 主键
- 每个实体集都应该有主键
- 主键值必须唯一

#### 示例
- 学生实体集：学号是主键
- 课程实体集：课程号是主键

### 参照完整性约束

**参照完整性约束**确保联系中的实体必须存在。

#### 示例
- 如果学生选修了某门课程，那么该课程必须存在
- 如果课程被某学生选修，那么该学生必须存在

### 基数约束

**基数约束**限制实体参与联系的次数。

#### 示例
- 一个学生最多选修10门课程
- 一门课程最多有200名学生选修

## 弱实体集

### 什么是弱实体集？

**弱实体集**是不能独立存在的实体集，它依赖于另一个实体集（强实体集）。

### 弱实体集的特点
1. **依赖性强**：必须与强实体集关联
2. **部分键**：只能用部分键，需要结合强实体集的键才能唯一标识
3. **存在依赖**：弱实体的存在依赖于强实体

### 示例：员工与家属

```
[员工] ---<拥有>--- [家属]
  |                   |
员工号              姓名
姓名                关系
部门                出生日期
```

在这个例子中：
- **员工**是强实体集
- **家属**是弱实体集
- 家属不能独立于员工存在

### 弱实体集的标识

弱实体集的标识需要：
1. **部分键**：弱实体集自身的属性
2. **强实体集的键**：关联的强实体集的主键

例如：家属的标识 = 员工号 + 家属姓名

## E/R图绘制规范

### 1. 实体集表示
- 矩形框
- 实体名首字母大写
- 属性用椭圆表示

### 2. 联系表示
- 菱形框
- 联系名通常用动词
- 标明联系类型（1:1、1:N、M:N）

### 3. 弱实体集表示
- 双线矩形表示弱实体集
- 双线菱形表示标识性联系
- 部分键属性用下划虚线表示

## 学习建议

对于初学者，建议：
1. **理解实体和联系的概念**：这是E/R模型的基础
2. **通过具体例子学习**：设计一个简单的E/R图
3. **掌握约束类型**：理解各种约束的作用
4. **练习绘制E/R图**：这是数据库设计的重要技能

> [!tip] 实践建议
> 建议选择一个熟悉的应用场景（如图书馆管理、学生成绩管理），然后绘制其E/R图，这样能更好地理解E/R模型。

## 关键概念总结

1. **E/R模型**：实体/联系模型，用于概念设计
2. **实体集**：具有相同属性的实体的集合
3. **联系**：实体集之间的关联关系
4. **约束**：键约束、参照完整性约束、基数约束
5. **弱实体集**：不能独立存在的实体集
