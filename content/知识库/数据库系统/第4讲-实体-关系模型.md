## 数据库设计阶段

### 数据库建模与实现过程

数据库设计是一个从概念到实现的过程：

```
想法 → 高层设计（E/R图） → 关系数据库模式 → 关系DBMS
```

1. **想法**：业务需求和概念
2. **高层设计**：概念模型设计（E/R图）
3. **关系数据库模式**：逻辑结构设计
4. **关系DBMS**：物理实现

## 实体/联系模型

### 什么是E/R模型？

**E/R模型**（实体/联系模型）是由**陈品山博士**（Dr. Peter Chen）于1976年发明的概念模型。

### E/R模型的组成
- **实体集**（Entity Sets）
- **联系**（Relationships）
- **属性**（Attributes）

### E/R图
- **E/R图**是E/R模型的图形化表示
- 用于可视化数据库的概念结构

## 实体集

### 什么是实体集？

**实体集**是具有相同属性的实体的集合。

#### 示例：学生实体集

```
┌─────────────────┐
│     Student     │
├─────────────────┤
│ ○ studentID (PK)│
│   name          │
│   age           │
│   gender        │
│   enrollDate    │
└─────────────────┘
```

**数据示例：**

| studentID | name | age | gender | enrollDate |
|-----------|------|-----|--------|------------|
| S001 | 张三 | 20 | M | 2022-09-01 |
| S002 | 李四 | 21 | F | 2022-09-01 |
| S003 | 王五 | 19 | M | 2023-09-01 |

#### 示例：课程实体集

```
┌─────────────────┐
│     Course      │
├─────────────────┤
│ ○ courseID (PK) │
│   courseName    │
│   credit        │
│   hours         │
└─────────────────┘
```

**数据示例：**

| courseID | courseName | credit | hours |
|----------|------------|--------|-------|
| C01 | 数据库系统 | 3 | 48 |
| C02 | 操作系统 | 4 | 64 |
| C03 | 计算机网络 | 3 | 48 |

## 联系

### 什么是联系？

**联系**描述实体集之间的关联关系。

### 联系的类型

#### 1. 一对一联系（1:1）

**示例：系主任与系别**

```
┌─────────────────┐      ┌─────────────────┐
│    Department   │      │      Dean       │
├─────────────────┤  1:1 ├─────────────────┤
│ ○ deptID (PK)   │──────│ ○ deanID (PK)   │
│   deptName      │      │   deanName      │
│   location      │      │   title         │
└─────────────────┘      └─────────────────┘
```

**含义：** 一个系只有一个系主任，一个系主任只管理一个系

#### 2. 一对多联系（1:N）

**示例：系别与学生**

```
┌─────────────────┐      ┌─────────────────┐
│   Department    │      │     Student     │
├─────────────────┤  1:N ├─────────────────┤
│ ○ deptID (PK)   │──────│ ○ studentID (PK)│
│   deptName      │      │   name          │
│   location      │      │   deptID (FK)   │
└─────────────────┘      └─────────────────┘
```

**含义：** 一个系有多个学生，一个学生只属于一个系

**数据示例：**

Department 表：

| deptID | deptName | location |
|--------|----------|----------|
| D01 | 计算机系 | 楼A |
| D02 | 数学系 | 楼B |

Student 表：

| studentID | name | deptID |
|-----------|------|--------|
| S001 | 张三 | D01 |
| S002 | 李四 | D01 |
| S003 | 王五 | D02 |

#### 3. 多对多联系（M:N）

**示例：学生与课程（选课）**

```
┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐
│     Student     │      │      Enroll     │      │     Course      │
├─────────────────┤  M:N ├─────────────────┤      ├─────────────────┤
│ ○ studentID (PK)│──────│   studentID (FK)│──────│ ○ courseID (PK) │
│   name          │      │   courseID (FK) │      │   courseName    │
│   age           │      │   grade         │      │   credit        │
└─────────────────┘      │   enrollDate    │      └─────────────────┘
                         └─────────────────┘
```

**含义：** 一个学生可以选多门课，一门课可以有多个学生选

**数据示例：**

Student 表：

| studentID | name |
|-----------|------|
| S001 | 张三 |
| S002 | 李四 |
| S003 | 王五 |

Course 表：

| courseID | courseName | credit |
|----------|------------|--------|
| C01 | 数据库系统 | 3 |
| C02 | 操作系统 | 4 |

Enroll 表：

| studentID | courseID | grade | enrollDate |
|-----------|----------|-------|------------|
| S001 | C01 | 90 | 2024-02-20 |
| S001 | C02 | 85 | 2024-02-20 |
| S002 | C01 | 88 | 2024-02-21 |
| S003 | C02 | 92 | 2024-02-21 |

## E/R图的基本符号

### 符号说明

| 符号 | 含义 |
|------|------|
| ▭（矩形） | 实体集 |
| ◇（菱形） | 联系 |
| ○（椭圆） | 属性 |
| ○ 下划线 | 主键属性 |
| ▭▭（双线矩形） | 弱实体集 |
| ◇◇（双线菱形） | 标识性联系 |

### 完整E/R图示例：学生选课系统

```
                           ┌─────────────┐
                           │   Student   │
                           ├─────────────┤
                        ┌──│○ studentID  │
                        │  │  name       │
                        │  │  age        │
                        │  └─────────────┘
                        │
                      M │        ┌─────────────┐
                        │        │   Enroll    │
                        ├────────├─────────────┤
                        │        │  grade      │
                        │        │  enrollDate │
                        │        └─────────────┘
                        │
                      N │        ┌─────────────┐
                        │        │   Course    │
                        └────────├─────────────┤
                                 │○ courseID   │
                                 │  courseName │
                                 │  credit     │
                                 └─────────────┘
```

## 设计原则

### 1. 避免冗余
- 同一信息不要存储多次
- 例如：不要在每个学生记录中都存储系主任信息

### 2. 简单性原则
- 尽量使用简单的实体和联系
- 避免不必要的复杂性

### 3. 选择正确的联系类型
- 准确判断1:1、1:N、M:N联系
- 这影响数据库的结构和性能

### 4. 使用弱实体集
- 当实体不能独立存在时使用弱实体集
- 例如：家属实体依赖于员工实体

## E/R模型中的约束

### 键约束

**键约束**确保实体集中的每个实体都能被唯一标识。

#### 主键
- 每个实体集都应该有主键
- 主键值必须唯一

#### 示例
- Student 实体集：studentID 是主键
- Course 实体集：courseID 是主键

### 参照完整性约束

**参照完整性约束**确保联系中的实体必须存在。

#### 示例

在 Enroll 联系中：
- 如果学生选修了某门课程，那么该课程必须存在
- 如果课程被某学生选修，那么该学生必须存在

**形式化表示：**

$$\pi_{studentID}(Enroll) \subseteq \pi_{studentID}(Student)$$
$$\pi_{courseID}(Enroll) \subseteq \pi_{courseID}(Course)$$

### 基数约束

**基数约束**限制实体参与联系的次数。

#### 示例

```
Student ──(0,10)── Enroll ──(1,200)── Course
```

**含义：**
- 一个学生最多选修10门课程（0到10）
- 一门课程至少有1名学生，最多200名学生（1到200）

## 弱实体集

### 什么是弱实体集？

**弱实体集**是不能独立存在的实体集，它依赖于另一个实体集（强实体集）。

### 弱实体集的特点
1. **依赖性强**：必须与强实体集关联
2. **部分键**：只能用部分键，需要结合强实体集的键才能唯一标识
3. **存在依赖**：弱实体的存在依赖于强实体

### 示例：员工与家属

```
┌─────────────────┐          ┌─────────────────┐
│    Employee     │          │    Dependent    │
├─────────────────┤    1:N   ├─────────────────┤
│ ○ empID (PK)    │──────────│ ○ name (部分键) │
│   name          │  拥有    │   relationship  │
│   dept          │          │   birthdate     │
│   salary        │          │   empID (FK)    │
└─────────────────┘          └─────────────────┘
```

**数据示例：**

Employee 表（强实体集）：

| empID | name | dept | salary |
|-------|------|------|--------|
| E001 | 张三 | IT | 10000 |
| E002 | 李四 | HR | 8000 |

Dependent 表（弱实体集）：

| empID | name | relationship | birthdate |
|-------|------|--------------|-----------|
| E001 | 张小明 | 儿子 | 2010-05-01 |
| E001 | 李红 | 配偶 | 1985-03-15 |
| E002 | 李小花 | 女儿 | 2015-08-20 |

### 弱实体集的标识

弱实体集的标识需要：
1. **部分键**：弱实体集自身的属性（如 Dependent.name）
2. **强实体集的键**：关联的强实体集的主键（如 Employee.empID）

例如：家属的标识 = empID + name（"E001"+"张小明" 唯一确定一个家属）

### 弱实体集的表示

在E/R图中：
- 双线矩形表示弱实体集
- 双线菱形表示标识性联系
- 部分键属性用下划虚线表示

## E/R图到关系模式的转换

### 转换规则

1. **实体集** → 关系表
2. **联系** → 关系表（M:N）或外键（1:1, 1:N）
3. **弱实体集** → 关系表，包含强实体集的主键

### 示例转换

#### E/R图

```
┌─────────────┐         ┌─────────────┐         ┌─────────────┐
│  Department │    1:N  │   Student   │    M:N  │   Course    │
├─────────────┤─────────├─────────────┤─────────├─────────────┤
│○ deptID     │         │○ studentID  │         │○ courseID   │
│  deptName   │         │  name       │         │  courseName │
│  location   │         │  deptID(FK) │         │  credit     │
└─────────────┘         └─────────────┘         └─────────────┘
```

#### 转换结果

```sql
-- Department 实体集
CREATE TABLE Department (
    deptID CHAR(10) PRIMARY KEY,
    deptName VARCHAR(50),
    location VARCHAR(50)
);

-- Student 实体集
CREATE TABLE Student (
    studentID CHAR(10) PRIMARY KEY,
    name VARCHAR(50),
    deptID CHAR(10),
    FOREIGN KEY (deptID) REFERENCES Department(deptID)
);

-- Course 实体集
CREATE TABLE Course (
    courseID CHAR(10) PRIMARY KEY,
    courseName VARCHAR(50),
    credit INT
);

-- Enroll 联系（M:N 联系需要单独的表）
CREATE TABLE Enroll (
    studentID CHAR(10),
    courseID CHAR(10),
    grade INT,
    enrollDate DATE,
    PRIMARY KEY (studentID, courseID),
    FOREIGN KEY (studentID) REFERENCES Student(studentID),
    FOREIGN KEY (courseID) REFERENCES Course(courseID)
);
```

## 综合示例：图书馆管理系统

### 需求分析

1. 图书馆有多种图书
2. 读者可以借阅图书
3. 一本书可以被多个读者借阅（不同时间）
4. 记录借阅日期和归还日期

### E/R图设计

```
┌─────────────────┐          ┌─────────────────┐
│      Book       │          │     Reader      │
├─────────────────┤          ├─────────────────┤
│○ bookID (PK)    │          │○ readerID (PK)  │
│  title          │          │  name           │
│  author         │          │  phone          │
│  publisher      │          │  address        │
│  publishYear    │          └─────────────────┘
└─────────────────┘                  │
         │                           │
         │        ┌─────────────────┐│
         │        │     Borrow      ││
         └────────├─────────────────┤│
                  │  bookID (FK)    ├┘
                  │  readerID (FK)  │
                  │  borrowDate     │
                  │  returnDate     │
                  └─────────────────┘
```

### 转换为关系模式

```sql
-- 图书表
CREATE TABLE Book (
    bookID CHAR(20) PRIMARY KEY,
    title VARCHAR(100),
    author VARCHAR(50),
    publisher VARCHAR(50),
    publishYear INT
);

-- 读者表
CREATE TABLE Reader (
    readerID CHAR(20) PRIMARY KEY,
    name VARCHAR(50),
    phone CHAR(20),
    address VARCHAR(100)
);

-- 借阅表
CREATE TABLE Borrow (
    bookID CHAR(20),
    readerID CHAR(20),
    borrowDate DATE,
    returnDate DATE,
    PRIMARY KEY (bookID, readerID, borrowDate),
    FOREIGN KEY (bookID) REFERENCES Book(bookID),
    FOREIGN KEY (readerID) REFERENCES Reader(readerID)
);
```

## 学习建议

对于初学者，建议：
1. **理解实体和联系的概念**：这是E/R模型的基础
2. **通过具体例子学习**：设计一个简单的E/R图
3. **掌握约束类型**：理解各种约束的作用
4. **练习绘制E/R图**：这是数据库设计的重要技能

> [!tip] 实践建议
> 建议选择一个熟悉的应用场景（如图书馆管理、学生成绩管理），然后绘制其E/R图，这样能更好地理解E/R模型。

## 关键概念总结

1. **E/R模型**：实体/联系模型，用于概念设计
2. **实体集**：具有相同属性的实体的集合
3. **联系**：实体集之间的关联关系（1:1, 1:N, M:N）
4. **约束**：键约束、参照完整性约束、基数约束
5. **弱实体集**：不能独立存在的实体集
