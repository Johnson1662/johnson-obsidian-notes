## 5.1 外观概念视图（View）

### 5.1.1 视图的基本概念

**视图（View）**是从一个或几个基本表（或视图）导出的虚拟表。

**特点**：
- 视图本身不存储数据，只存储定义
- 基于视图的查询被转换为对基本表的查询
- 对于简单视图，更新操作可以转换为对基本表的更新
- 定义视图的数据存在数据字典中

### 5.1.2 创建视图

```sql
CREATE [OR REPLACE] [FORCE | NOFORCE] VIEW 视图名 [(列名列表)]
AS SELECT 语句
[WITH CHECK OPTION [CONSTRAINT 约束名]]
[WITH READ ONLY];
```

**参数说明**：
- `OR REPLACE`：如果视图已存在，则更新
- `FORCE`：无论基本表是否存在，都创建视图
- `NOFORCE`：只有在基本表存在时才创建视图（默认）
- `WITH CHECK OPTION`：确保通过视图进行的DML操作结果要保持在视图可见区内
- `WITH READ ONLY`：确保这个视图只能查询，不能进行DML操作

**示例**：

```sql
-- 创建学生和课程信息的视图
CREATE VIEW StudentCourse AS
SELECT S.Sno, S.Sname, S.Sdept, C.Cno, C.Cname, SC.Grade
FROM Student S
JOIN SC ON S.Sno = SC.Sno
JOIN Course C ON SC.Cno = C.Cno;

-- 创建计算机系学生的视图（带条件）
CREATE VIEW CS_Student AS
SELECT Sno, Sname, Sage
FROM Student
WHERE Sdept = 'CS'
WITH CHECK OPTION;

-- 创建带列别名的视图
CREATE VIEW StudentInfo (StuID, Name, Department)
AS SELECT Sno, Sname, Sdept
FROM Student;

-- 创建只读视图
CREATE VIEW DeptSummary AS
SELECT Sdept, COUNT(*) NumStudents, AVG(Sage) AvgAge
FROM Student
GROUP BY Sdept
WITH READ ONLY;
```

### 5.1.3 删除视图

```sql
DROP VIEW 视图名 [CASCADE];
```

## 5.2 关系数据库的存储结构

### 5.2.1 物理存储器与文件组织

**存储器层次**：
1. 主存存储器（Main Memory）
2. 磁盘存储器（Magnetic Disk）
3. 磁带存储器（Magnetic Tape）

**主存存储器**：
- 访问速度快（纳秒级）
- 容量小（通常为GB级）
- 比较贵
- 提供给DBMS使用

**磁盘存储器**：
- 访问速度较慢（毫秒级）
- 容量大（TB级）
- 价格低
- 是数据永久存储的主要位置

**文件组织**：
- 一个关系对应一个或多个文件
- 文件由固定长度的记录组成
- 记录按顺序存储在磁盘上

### 5.2.2 存储结构类型

#### 1. 堆文件（Heap File）
元组无序存储在文件中，新插入的记录存储在文件的最后

#### 2. 排序文件（Sorted File）
元组按某个属性值排序存储

#### 3. 聚簇文件（Clustered File）
将不同关系的记录存储在同一个文件中

#### 4. 散列文件（Hashed File）
使用散列函数确定存储位置

#### 5. 索引文件（Index File）
建立索引来加速访问

### 5.2.3 索引技术

**索引的作用**：
- 加速查询速度
- 保证数据唯一性
- 支持排序

**索引结构**：

#### 1. 顺序索引（Sequential Index）
按索引值顺序存储，适合范围查询

#### 2. 二叉搜索树索引（B-Tree Index）
使用B树结构，支持快速查找、插入、删除

#### 3. 散列索引（Hash Index）
使用散列函数映射到存储位置，适合等值查询

**聚簇与非聚簇索引**：
- 聚簇索引：数据物理上按索引排序
- 非聚簇索引：索引项指向数据位置

### 5.2.4 视图的更新操作

**可更新视图的条件**：
1. 从单个基本表导出
2. 包含基本表的主键
3. 不包含聚合函数
4. 不包含DISTINCT
5. 不包含GROUP BY或HAVING

**更新示例**：
```sql
-- 更新可更新视图
UPDATE CS_Student
SET Sage = 22
WHERE Sno = '201215121';

-- 向可更新视图插入数据
INSERT INTO CS_Student (Sno, Sname, Sage)
VALUES ('201215125', '赵四', 20);
```

## 5.3 触发器（Trigger）

### 5.3.1 触发器的概念

**触发器**（Trigger）是一种特殊的存储过程，由事件启动，自动执行。

**组成**：
- 触发事件：对表的INSERT、UPDATE、DELETE操作
- 触发时机：AFTER、BEFORE、INSTEAD OF
- 触发体：触发器执行的操作

### 5.3.2 触发器的作用

1. **实时监测**：对关键数据的变化进行监控
2. **自动处理**：自动完成某些业务规则
3. **完整性检查**：比CHECK约束更强大的完整性检查
4. **审计和监控**：记录操作日志

### 5.3.3 触发器的类型

| 按触发时机 |按表操作 |按表当前行数 |
|------|------|------|------|
| BEFORE | NEW.cno | OLD.cno | - |
| AFTER | - | - | FOR EACH ROW |

**1. 按触发时机**：
- **BEFORE**：在触发事件前执行
- **AFTER**：在触发事件后执行
- **INSTEAD OF**：代替触发事件执行（主要用于视图）

**2. 按表操作**：
- **INSERT**：插入操作
- **UPDATE**：更新操作
- **DELETE**：删除操作

### 5.3.4 触发器的创建

```sql
CREATE TRIGGER 触发器名
{BEFORE | AFTER | INSTEAD OF}
{INSERT | UPDATE | DELETE} [OR ...]
ON 表名
[REFERENCING NEW|OLD ROW AS 别名]
[FOR EACH ROW | FOR EACH STATEMENT]
[WHEN 触发条件]
触发体;
```

**示例1：记录操作日志**
```sql
CREATE TRIGGER LogStudentChanges
AFTER UPDATE OR DELETE ON Student
FOR EACH ROW
BEGIN
    IF UPDATING THEN
        INSERT INTO StudentLog (Sno, Action, ChangeTime)
        VALUES (:OLD.Sno, 'UPDATE', SYSDATE);
    ELSIF DELETING THEN
        INSERT INTO StudentLog (Sno, Action, ChangeTime)
        VALUES (:OLD.Sno, 'DELETE', SYSDATE);
    END IF;
END;
```

**示例2：自动更新学分**
```sql
CREATE TRIGGER UpdateStudentGrade
AFTER INSERT OR UPDATE OF Grade ON SC
FOR EACH ROW
BEGIN
    UPDATE Student
    SET TotalCredits = TotalCredits + :NEW.Credits
    WHERE Sno = :NEW.Sno;
END;
```

**示例3：BEFORE触发器**
```sql
CREATE TRIGGER CheckStudentAge
BEFORE INSERT OR UPDATE OF Sage ON Student
FOR EACH ROW
BEGIN
    IF :NEW.Sage < 15 OR :NEW.Sage > 45 THEN
        RAISE_APPLICATION_ERROR(-20001, '年龄必须在15-45之间');
    END IF;
END;
```

### 5.3.5 触发器的管理

```sql
-- 显示触发器信息
SELECT TRIGGER_NAME, TABLE_NAME, TRIGGERING_EVENT, TRIGGER_TYPE
FROM USER_TRIGGERS;

-- 禁用触发器
ALTER TRIGGER 触发器名 DISABLE;

-- 启用触发器
ALTER TRIGGER 触发器名 ENABLE;

-- 删除触发器
DROP TRIGGER 触发器名;
```

## 5.4 安全控制与权限

### 5.4.1 安全级别

**数据库安全的两个层次**：
1. **系统级别**：用户身份验证、密码保护
2. **数据库级别**：在数据库内部的访问控制

### 5.4.2 权限系统

**权限的类型**：
1. **系统权限**权限：创建模式、创建表、创建视图、创建索引等
2. **对象权限**：对特定应用对象的操作权限

**常见权限**：
- SELECT：查询权限
- INSERT：插入权限
- UPDATE：修改权限
- DELETE：删除权限
- ALL PRIVILEGES：所有权限

### 5.4.3 权限的授予与斥回

```sql
-- 授予权限
GRANT 权限列表
ON 对象名
TO 用户列表
[WITH GRANT OPTION];

-- 示例：授予查询权限
GRANT SELECT ON Student TO U1;

-- 示例：授予多个权限
GRANT SELECT, UPDATE(Sage) ON Student TO U2;

-- 示例：授予所有权限
GRANT ALL PRIVILEGES ON Student TO U3;

-- 示例：授予权限并允许传递
GRANT SELECT ON Student TO U4 WITH GRANT OPTION;

-- 斥回权限
REVOKE 权限列表
ON 对象名
FROM 用户列表;

-- 示例：斥回查询权限
REVOKE SELECT ON Student FROM U1;

-- 示例：斥回所有权限
REVOKE ALL PRIVILEGES ON Student FROM U3;

-- 示例：级联斥回
REVOKE SELECT ON Student FROM U1 CASCADE;
```

**权限传递**：
- 授予权限时加上 WITH GRANT OPTION，获得权限的用户可以再次授予其他用户
- REVOKE 斥回权限时，自动回收由 WITH GRANT OPTION 授予的权限

### 5.4.4 角色管理

```sql
-- 创建角色
CREATE ROLE 角色名;

-- 给角色授予权限
GRANT SELECT, INSERT ON Student TO R1;

-- 把角色赋予用户
GRANT R1 TO U1;

-- 删除角色
DROP ROLE R1;
```

## 5.5 数据库安全实例

### 5.5.1 多层安全机制

| 层次 | 安全措施 |
|--------|--------|
| 物理层 | 机房安全、设备防护 |
| 操作系统层 | 身份认证、权限控制 |
| 数据库系统层 | 用户验证、角色管理 |
| 应用程序层 | 业务逻辑控制 |

### 5.5.2 安全策略

1. **最小权限原则**：只授予用户完成工作所必须的最小权限
2. **职责分离**：不同岗位分配不同权限
3. **审计督制**：定期审查权限使用情况
4. **数据加密**：对敏感数据进行加密存储
