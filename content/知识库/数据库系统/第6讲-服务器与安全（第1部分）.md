## 三层架构

### 什么是三层架构？

**三层架构**是一种常见的数据库应用环境，将系统分为三个处理层次：

### 三层架构的组成

#### 1. Web服务器层
- **功能**：与用户交互
- **职责**：
  - 处理用户请求
  - 返回网页内容
  - 管理用户会话

#### 2. 应用服务器层
- **功能**：执行业务逻辑
- **职责**：
  - 处理业务规则
  - 执行应用程序
  - 协调数据处理

#### 3. 数据库服务器层
- **功能**：从数据库获取数据
- **职责**：
  - 执行SQL查询
  - 管理数据存储
  - 保证数据完整性

### 三层架构的优势

#### 1. 分离关注点
- 每层专注于特定功能
- 便于维护和修改

#### 2. 可扩展性
- 可以独立扩展每一层
- 根据负载情况调整资源

#### 3. 安全性
- 数据库服务器不直接暴露给用户
- 可以实施多层安全控制

#### 4. 复用性
- 业务逻辑可以在多个应用中复用
- 减少代码重复

### 三层架构的示例

```
用户 → Web服务器 → 应用服务器 → 数据库服务器
      ↓           ↓           ↓
    界面交互    业务处理    数据存储
```

### 三层架构与两层架构的比较

#### 两层架构（客户端-服务器）
```
客户端 → 数据库服务器
```
- **优点**：简单、直接
- **缺点**：业务逻辑与界面混合，难以维护

#### 三层架构
```
客户端 → 应用服务器 → 数据库服务器
```
- **优点**：结构清晰、可维护性好
- **缺点**：相对复杂

## 存储过程

### 什么是存储过程？

**存储过程**是一组预编译的SQL语句，存储在数据库服务器上，可以被应用程序调用。

### 存储过程的特点

#### 1. 预编译
- SQL语句在创建时编译
- 执行时不需要再次编译
- 提高性能

#### 2. 存储在服务器
- 减少网络传输
- 集中管理业务逻辑

#### 3. 可重复使用
- 多个应用程序可以调用
- 减少代码重复

### 存储过程的优点

#### 1. 性能提升
- 减少网络流量
- 预编译提高执行速度
- 优化器可以优化执行计划

#### 2. 安全性
- 可以限制直接访问表
- 通过存储过程控制数据访问
- 减少SQL注入风险

#### 3. 维护性
- 业务逻辑集中管理
- 修改存储过程不影响客户端
- 便于版本控制

#### 4. 一致性
- 确保所有应用使用相同的业务逻辑
- 减少数据不一致的风险

### 存储过程的语法

#### 创建存储过程
```sql
CREATE PROCEDURE GetStudentInfo(IN student_id INT)
BEGIN
    SELECT student_id, name, major, gpa
    FROM Student
    WHERE student_id = student_id;
END;
```

#### 调用存储过程
```sql
CALL GetStudentInfo(1001);
```

#### 带输出参数的存储过程
```sql
CREATE PROCEDURE GetStudentCount(OUT count INT)
BEGIN
    SELECT COUNT(*) INTO count
    FROM Student;
END;

-- 调用
CALL GetStudentCount(@student_count);
SELECT @student_count;
```

### 存储过程的控制结构

#### 条件语句
```sql
IF condition THEN
    -- statements
ELSEIF condition THEN
    -- statements
ELSE
    -- statements
END IF;
```

#### 循环语句
```sql
-- WHILE循环
WHILE condition DO
    -- statements
END WHILE;

-- LOOP循环
LOOP
    -- statements
    IF condition THEN
        LEAVE;
    END IF;
END LOOP;
```

### 存储过程的示例

#### 示例1：计算学生平均成绩
```sql
CREATE PROCEDURE CalculateAverageGPA()
BEGIN
    DECLARE avg_gpa DECIMAL(3,2);
    
    SELECT AVG(gpa) INTO avg_gpa
    FROM Student;
    
    SELECT avg_gpa AS '平均GPA';
END;
```

#### 示例2：更新员工工资
```sql
CREATE PROCEDURE UpdateSalary(
    IN emp_id INT,
    IN new_salary DECIMAL(10,2)
)
BEGIN
    DECLARE old_salary DECIMAL(10,2);
    
    -- 获取原工资
    SELECT salary INTO old_salary
    FROM Employee
    WHERE employee_id = emp_id;
    
    -- 更新工资
    UPDATE Employee
    SET salary = new_salary
    WHERE employee_id = emp_id;
    
    -- 记录变更
    INSERT INTO SalaryHistory (employee_id, old_salary, new_salary, change_date)
    VALUES (emp_id, old_salary, new_salary, NOW());
END;
```

### 存储过程的优缺点

#### 优点
1. **性能好**：预编译，执行快
2. **安全性高**：可以控制访问权限
3. **维护方便**：业务逻辑集中
4. **减少网络流量**：只需传递参数

#### 缺点
1. **可移植性差**：不同数据库语法不同
2. **调试困难**：错误信息不直观
3. **版本控制复杂**：需要专门工具
4. **资源消耗**：占用数据库服务器资源

### 存储过程的应用场景

#### 适合使用存储过程的场景
1. **复杂的业务逻辑**
2. **频繁执行的操作**
3. **需要高性能的查询**
4. **安全敏感的操作**

#### 不适合使用存储过程的场景
1. **简单的CRUD操作**
2. **需要频繁变更的业务逻辑**
3. **跨数据库平台的应用**

## 安全性考虑

### 数据库安全的重要性

数据库安全是信息系统安全的核心，包括：
1. **数据保密性**：防止未授权访问
2. **数据完整性**：防止数据被篡改
3. **数据可用性**：保证数据可访问

### 常见的安全威胁

#### 1. SQL注入攻击
- **原理**：通过输入恶意SQL代码
- **防范**：使用参数化查询、存储过程

#### 2. 未授权访问
- **原理**：绕过权限控制
- **防范**：实施最小权限原则

#### 3. 数据泄露
- **原理**：敏感数据被非法获取
- **防范**：加密、访问控制

### 安全最佳实践

1. **使用强密码策略**
2. **实施最小权限原则**
3. **定期备份数据**
4. **使用加密技术**
5. **监控数据库活动**
6. **及时更新补丁**

## 学习建议

对于初学者，建议：
1. **理解三层架构的概念**：这是现代应用的基础架构
2. **掌握存储过程的基本语法**：学会创建和调用存储过程
3. **了解安全性的基本概念**：知道常见的安全威胁和防范措施
4. **实践存储过程的编写**：通过实际例子加深理解

> [!tip] 实践建议
> 建议在数据库系统中创建几个简单的存储过程，然后测试它们的性能和安全性，这样能更好地理解存储过程的作用。

## 关键概念总结

1. **三层架构**：Web服务器、应用服务器、数据库服务器
2. **存储过程**：预编译的SQL语句集合
3. **安全性**：数据保密性、完整性、可用性
4. **SQL注入**：常见的安全攻击方式
5. **最小权限原则**：安全设计的基本原则
