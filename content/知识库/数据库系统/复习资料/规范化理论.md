## 1 范式判定（1NF、2NF、3NF、BCNF）

范式是衡量关系模式规范化程度的标准，旨在消除数据冗余、更新异常、插入异常和删除异常。

### 1.1 第一范式（1NF）—— 属性原子性

**判定：**
1. 所有属性值必须是原子的，即不可再分。
2. 必须有一个键。

**例子：**
- 不符合：表中某列值为"数据库、操作系统"（可进一步拆分）。
- 符合：拆分为多行，每行只对应一个值，如 (张三, 数据库)、(张三, 操作系统)。

### 1.2 第二范式（2NF）—— 消除部分函数依赖

**判定：**
1. 满足 1NF。
2. 所有**非主属性**必须**完全函数依赖**于每一个候选键（不能仅依赖键的一部分）。
3. 若 1NF 关系的键是单属性，则自动满足 2NF。

**例子：**
- 不符合：`Employees_Skills(Employee, Skill, WorkLocation)`，键为 `{Employee, Skill}`，`WorkLocation` 只依赖于 `Employee`，存在**部分函数依赖**。
- 符合：拆分为 `Employees(Employee, WorkLocation)` 和 `Skills(Employee, Skill)`。

### 1.3 第三范式（3NF）—— 消除传递函数依赖

**判定（Zaniolo 定义）：** 满足 2NF，且对每个非平凡函数依赖 $X \to A$，至少满足以下条件之一：
- $X$ 是一个**超键**；
- 或 $A$ 是一个**主属性**（包含在某个候选键中）。

**例子：**
- 不符合：`Tournament_Winners(Tournament, Year, Winner, Winner_DOB)`，键为 `{Tournament, Year}`，存在传递依赖 `Winner → Winner_DOB`，且 `Winner_DOB` 非主属性。
- 符合：拆分为 `Winners(Winner, Winner_DOB)` 和 `Tournament(Tournament, Year, Winner)`。

### 1.4 BC 范式（BCNF）—— 决定因素必须是键

**判定：** 对每个**非平凡**函数依赖 $X \to A$，$X$ 必须是**超键**。即每个决定因子都必须是键。

> 判定技巧：先找候选键，再看每个 FD 的左边是不是键。只要有一个 FD 的决定因子不是键，就违反 BCNF。

**例子：**
- 不符合：`Bookings(title, theater, city)`，规则：一个剧院只在一个城市；某城市某电影只在某剧院放。候选键为 `{title, city}` 和 `{theater, title}`，存在依赖 `theater → city`，但 `theater` 不是键。
- 符合：拆分为 `(theater, city)` 和 `(theater, title)`。

### 1.5 总结口诀

| 范式 | 核心要求 | 消除什么 |
|------|---------|---------|
| 1NF | 属性值原子性，必须有键 | 非原子属性 |
| 2NF | 非主属性依赖于**整个键** | 部分函数依赖 |
| 3NF | 非主属性依赖于**且仅依赖于键** | 传递函数依赖 |
| BCNF | **每一个**决定因素都必须是**键** | 所有非键决定因子 |

> 任何只有两个属性的关系都必然符合 BCNF。

## 2 候选键计算

候选键是规范化理论的核心概念。求候选键的本质是：找到满足**函数决定性**（能决定所有属性）且**最小性**（去掉任一属性就不行）的属性集。

### 2.1 基本概念

| 概念                        | 定义                                    |
| ------------------------- | ------------------------------------- |
| **超键 (Superkey)**         | 能函数决定所有其他属性的属性集，即"键的超集"               |
| **候选键 (Candidate Key)**   | 满足**函数决定性** + **最小性**（任何真子集都不是超键）的属性集 |
| **主属性 (Prime Attribute)** | 包含在**任一**候选键中的属性                      |
| **属性闭包 $X^+$**            | 在给定 FD 集下，由 $X$ 能推导出的所有属性的集合          |

### 2.2 求候选键的步骤

**第一步：初步分类（辅助技巧）**

通过观察 FD 集 $F$ 的左右两侧快速缩小范围：

| 类别       | 特征                       | 结论         |
| -------- | ------------------------ | ---------- |
| **必选属性** | 只出现在 FD 左侧，或从未出现在任何 FD 中 | 一定属于每个候选键  |
| **待定属性** | 既出现在左侧又出现在右侧             | 可能是键的一部分   |
| **非键属性** | 只出现在右侧                   | 通常不属于最小候选键 |

**第二步：计算属性闭包**

对选定的属性集 $X$，反复迭代：查找形如 $B \to C$ 的 FD，若 $B \subseteq X$ 且 $C \not\subseteq X$，则将 $C$ 加入 $X$。直到 $X$ 不再增大，此时的 $X$ 即为 $X^+$。

**第三步：判定与验证**

1. **判定超键**：若 $X^+$ 包含所有属性，则 $X$ 是超键。
2. **验证最小性**：尝试从 $X$ 中逐个去掉一个属性，计算剩余部分的闭包：
   - 若**没有任何**真子集的闭包能包含所有属性，则 $X$ 是**候选键**。
   - 若存在真子集也能包含所有属性，则 $X$ 只是超键，需继续对子集测试。

### 2.3 典型例题

**例题 1（基础判定）**：$R(A, B, C, D)$，$F = \{B \to C, B \to D\}$，求候选键。

- $A$ 未出现在 FD 右侧，必含在键中。
- 计算 $\{A, B\}^+ = \{A, B, C, D\}$，是超键。
- 验证最小性：$\{A\}^+ = \{A\}$，$\{B\}^+ = \{B, C, D\}$，均不含全集。
- **结论：** $\{A, B\}$ 是唯一候选键。

**例题 2（多候选键）**：$R(A, B, C, D)$，$F = \{AB \to C, C \to D, D \to A\}$，求候选键。

- $B$ 只在左侧出现，必在键中。
- 分别测试：
  - $\{A, B\}^+ = \{A, B, C, D\}$
  - $\{D, B\}^+ = \{D, B, A, C\}$（$D \to A$）
  - $\{C, B\}^+ = \{C, B, D, A\}$（$C \to D \to A$）
- 去掉 $B$ 均不行，去掉 $A/C/D$ 也不行。
- **结论：** 三个候选键 $\{AB, BC, BD\}$。

**例题 3（非键判定）**：$R(A, B, C, D, E, F)$，$F = \{AB \to C, BC \to AD, D \to E, CF \to B\}$，判断 $\{A, B\}$ 是否为键。

- 计算 $\{A, B\}^+ = \{A, B, C, D, E\}$（见 §3.3 中闭包计算例题）。
- 不含 $F$，连超键都不是。
- 若要构成键，必须加入 $F$。

## 3 属性闭包与函数依赖推导

**核心思想**：利用 Armstrong 公理及其推论，通过计算属性闭包来验证函数依赖是否成立。

### 3.1 计算属性闭包 $X^+$ 的步骤

1. **初始化**：令结果集 $X = \{A, B\}$（即要求的起始属性）。
2. **分解复合依赖**：将右侧含多个属性的依赖分解为单属性，如 $BC \to AD$ 分解为 $BC \to A$ 和 $BC \to D$。
3. **迭代增长**：遍历函数依赖集 $S$，若某个依赖的左部包含在当前 $X$ 中，则将其右部属性加入 $X$。
4. **停止条件**：直到 $X$ 不再增大为止。

### 3.2 判断函数依赖 $Y \to Z$ 是否成立

- 计算左部属性 $Y$ 的闭包 $Y^+$。
- 检查右部属性 $Z$ 是否包含在 $Y^+$ 中：
  - 若 $Z \subseteq Y^+$，则成立；
  - 若 $Z \nsubseteq Y^+$，则不成立。

### 3.3 典型例题

**题目**：有关系 $R(A, B, C, D, E, F)$，函数依赖集 $S = \{AB \to C, BC \to AD, D \to E, CF \to B\}$。

**a) 求 $\{A, B\}^+$**

- $X = \{A, B\}$
- $AB \to C$ → $X = \{A, B, C\}$
- $BC \to A, BC \to D$ → $X = \{A, B, C, D\}$
- $D \to E$ → $X = \{A, B, C, D, E\}$

$\therefore \{A, B\}^+ = \{A, B, C, D, E\}$

**b) $AB \to D$ 是否成立？**

$D \in \{A, B\}^+$，成立。

**c) $D \to A$ 是否成立？**

计算 $\{D\}^+ = \{D, E\}$，$A \notin \{D\}^+$，不成立。

## 4 最小函数依赖集（Minimal Cover）

### 4.1 求解步骤

1. **右部分解**：将所有函数依赖的右部化为单属性。
2. **消除左部冗余属性**：对每个左部含多属性的依赖，逐一检查每个属性是否冗余。
3. **消除冗余函数依赖**：逐一检查每个依赖是否可由其他依赖推导。

### 3.2 典型例题

**题目**：有关系 $R(A, B, C, D, E, F, G, H, I)$，函数依赖集 $F = \{AB \to CD, A \to E, B \to FH, C \to G, D \to B, G \to C, H \to I\}$。

**第一步：右部分解**

$F = \{AB \to C, AB \to D, A \to E, B \to F, B \to H, C \to G, D \to B, G \to C, H \to I\}$

**第二步：消除左部冗余属性**

检查 $AB \to C$ 和 $AB \to D$：
- $A^+ = \{A, E\}$（不含 $C, D$），故 $A$ 不冗余。
- $B^+ = \{B, F, H, I\}$（不含 $C, D$），故 $B$ 不冗余。

其他依赖左部均为单属性，无需检查。

**第三步：消除冗余函数依赖**

逐一检查每个依赖是否可由其他依赖推导（在去掉该依赖后的 $F$ 中计算左部闭包）：

| 依赖 | 去掉后计算闭包 | 结果 |
|------|---------------|------|
| $AB \to C$ | $(AB)^+ = \{A,B,D,E,F,H,I\}$ | 不含 $C$，保留 |
| $AB \to D$ | $(AB)^+ = \{A,B,C,E,F,G,H,I\}$ | 不含 $D$，保留 |
| $C \to G$ | 无其他路径推出 $G$ | 保留 |
| $G \to C$ | 无其他路径推出 $C$ | 保留 |
| $D \to B$ | 无其他路径推出 $B$ | 保留 |

全部不可移除。

**最终最小集：**

$F_{min} = \{AB \to C, AB \to D, A \to E, B \to F, B \to H, C \to G, D \to B, G \to C, H \to I\}$

## 5 3NF 保持函数依赖的合成算法

### 5.1 算法步骤

1. **求最小函数依赖集**：确保所有依赖右部为单属性，消除左部冗余属性和冗余依赖。
2. **构造关系模式**：为最小集中每个函数依赖创建一个关系模式（左部相同的依赖合并）。
3. **消除包含关系**：若一个模式的属性集是另一个的子集，则删除前者。
4. **添加候选码**：检查已有模式是否包含原关系的候选码，若不包含则添加一个候选码作为独立模式。

### 5.2 典型例题 1

**题目**：有关系 $R(A, B, C, D, E)$，函数依赖 $AB \to C, C \to B, A \to D$，分解为 3NF。

- 给定的 FD 已是最小集。
- 为每个 FD 创建模式：$S_1(A, B, C), S_2(B, C), S_3(A, D)$。
- 消除包含：$S_2(B, C) \subset S_1(A, B, C)$，丢弃 $S_2$。
- 候选码为 $\{A, B, E\}$ 或 $\{A, C, E\}$，均未出现在 $S_1, S_3$ 中，需添加 $S_4$。

**最终结果：**
- $\{S_1(A, B, C), S_3(A, D), S_4(A, B, E)\}$ 或
- $\{S_1(A, B, C), S_3(A, D), S_4(A, C, E)\}$

### 5.3 典型例题 2（含无损连接性保证）

**题目**：有关系 $R(A, B, C, D, E, F, G, H, I)$，$F_{min}$ 已求得（如第 4 节所示，$F_{min} = \{AB \to C, AB \to D, A \to E, B \to F, B \to H, C \to G, D \to B, G \to C, H \to I\}$）。

**分解 3NF：**

将左部相同的依赖合并，每个左部作为一个关系模式：

| 模式 | 属性 | 依赖 |
|------|------|------|
| $R_1$ | $A, B, C, D$ | $AB \to C, AB \to D$ |
| $R_2$ | $A, E$ | $A \to E$ |
| $R_3$ | $B, F, H$ | $B \to F, B \to H$ |
| $R_4$ | $C, G$ | $C \to G$ |
| $R_5$ | $D, B$ | $D \to B$ |
| $R_6$ | $G, C$ | $G \to C$ |
| $R_7$ | $H, I$ | $H \to I$ |

**合并：** $C \to G$ 和 $G \to C$ 互为依赖，合并 $R_4, R_6$ 为 $R_{46}(C, G)$。

**检查候选码：** $(AB)^+ = \{A, B, C, D, E, F, G, H, I\}$，$AB$ 为候选码。$R_1$ 已包含 $AB$，无需添加。

**最终结果：**
$$\rho = \{R_1(A,B,C,D), R_2(A,E), R_3(B,F,H), R_{46}(C,G), R_5(D,B), R_7(H,I)\}$$

## 6 BC 范式（BCNF）分解算法

BCNF 要求每个非平凡 FD 的左侧都必须是**超键**。BCNF 分解的核心思路是：找到违例 FD，以它为界拆分关系，然后递归处理子模式。

### 6.1 分解步骤

1. **计算候选键**：利用属性闭包确定关系的所有键。
2. **识别违例项**：检查 FD 集，寻找左侧不是超键的非平凡 FD $X \to Y$。
3. **执行拆分**：将 $R$ 分解为 $R_1(X \cup Y)$ 和 $R_2(X \cup (R - Y))$。
4. **递归处理**：对分解出的子模式重复上述过程，直到所有子模式都符合 BCNF。

### 6.2 典型例题 1（基础）

**题目**：有关系 $R(A, B, C, D)$，函数依赖集 $F = \{B \to C, B \to D\}$，将其分解为 BCNF。

**解题过程：**

- **候选键**：$A$ 没有任何入度，必须含在键中。计算 $\{A, B\}^+ = \{A, B, C, D\}$，候选键为 $\{A, B\}$。
- **违例**：$B \to C$ 的左侧 $B$ 不是超键，违反 BCNF。
- **分解**：用 $B \to C$ 拆分：
  - $R_1(B, C, D)$（包含 $B$ 及其决定的所有项）
  - $R_2(A, B)$（包含 $B$ 和剩余项 $A$）
- **检查**：
  - $R_2$ 只有两个属性，必符合 BCNF。
  - $R_1$ 的键是 $B$，其内部依赖 $B \to C$ 和 $B \to D$ 的左侧均为键，符合 BCNF。

**答案：** $\{(A, B), (B, C, D)\}$

### 6.3 典型例题 2（复杂）

**题目**：有关系 $R(A, B, C, D)$，函数依赖集 $F = \{AB \to C, C \to D, D \to A\}$，将其分解为 BCNF。

**解题过程：**

- **候选键**：通过闭包计算得到候选键集合为 $\{AB, BC, BD\}$。
- **违例**：$C \to D$ 和 $D \to A$ 的左侧都不是超键，均违反 BCNF。
- **第一次分解**：选择 $C \to D$ 分解：
  - $R_1(C, D)$
  - $R_2(A, B, C)$
- **二次分解**：在 $R_2(A, B, C)$ 中，继承的依赖有 $AB \to C$，以及通过传递律（$C \to D$ 且 $D \to A$）得到的 $C \to A$。由于 $C$ 在 $R_2$ 中不是键，违反 BCNF。继续分解：
  - $R_3(A, C)$
  - $R_4(B, C)$
- **检查**：所有最终子模式均为二元关系，必符合 BCNF。

**答案：** $\{(C, D), (A, C), (B, C)\}$

## 7 Armstrong 公理与伪传递律证明

该定理在学术上称为**伪传递律（Pseudo-transitive Rule）**，是 Armstrong 公理的重要推论。

### 7.1 基础知识：Armstrong 三条核心公理

| 公理 | 定义 | 说明 |
|-----|------|------|
| **自反律 (Reflexivity)** | 若 $Y \subseteq X$，则 $X \to Y$ | 已知全集必然已知子集 |
| **增广律 (Augmentation)** | 若 $X \to Y$，则对任意 $W$ 有 $XW \to YW$ | 两边可同时增加相同属性 |
| **传递律 (Transitivity)** | 若 $X \to Y$ 且 $Y \to Z$，则 $X \to Z$ | 推导间接依赖的基本工具 |

### 7.2 定理

有关系模式 $R$，$X, Y, W$ 是 $R$ 的属性子集。若 $X \to Y$，$YW \to Z$ 成立，则 $XW \to Z$ 也成立。

### 7.3 证明

1. **已知** $X \to Y$
2. **增广律**：对 $X \to Y$ 两边增加 $W$，得 $XW \to YW$（记为结论 A）
3. **已知** $YW \to Z$
4. **传递律**：由结论 A（$XW \to YW$）和已知（$YW \to Z$），得 $XW \to Z$

**证毕。**

### 7.4 解题思路

观察已知条件的**接口**是关键：$YW \to Z$ 需要一个左侧为 $YW$ 的前提，而已知 $X \to Y$ 缺少 $W$，因此第一步自然地使用**增广律**补全 $W$。

该推导出的伪传递律在**计算属性闭包**和**求最小函数依赖集**时非常有用，可简化推导过程，帮助识别和消除冗余依赖。

## 8 解题核心技巧总结

| 任务 | 核心工具 | 关键注意点 |
|-----|---------|-----------|
| **求闭包** | 迭代扫描法 | 别漏掉隐含属性，如 $A \to B, B \to C \implies A \to C$ |
| **验证依赖** | $Y \to Z \iff Z \subseteq Y^+$ | 只需要算左边的闭包即可判断 |
| **3NF 合成** | 最小集 + 合并 + 补码 | 补码步骤最容易丢分，必须确保分解后的关系集能代表原关系的键 |
