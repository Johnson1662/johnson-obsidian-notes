# 第三章 程序的机器级表示

## 1. 本章概述

计算机无法直接执行 C、C++ 等高级语言编写的程序，需要将其编译为机器指令（机器码）后才能运行。本章讲解 x86-64 架构下，高级语言中的变量、表达式、条件判断、循环、函数调用等结构是如何被翻译为汇编指令和机器级表示的，帮助读者建立"程序在计算机中到底如何执行"的微观理解。

---

## 2. 知识点讲解

### 2.1 x86-64 寄存器

**通俗定义**：寄存器是 CPU 内部容量极小但速度极快的小型存储单元（类似"CPU 的工作台面"），用于存放正在处理的数据或地址。x86-64 有 16 个通用寄存器，每个 64 位宽。

**标准表示**：

x86-64 的通用寄存器及用途：

| 寄存器 | 64 位 | 32 位 | 16 位 | 8 位 | 用途 |
|--------|-------|-------|-------|------|------|
| 返回值 | %rax | %eax | %ax | %al | 存放函数返回值 |
| 参数 1 | %rdi | %edi | %di | %dil | 第 1 个参数 |
| 参数 2 | %rsi | %esi | %si | %sil | 第 2 个参数 |
| 参数 3 | %rdx | %edx | %dx | %dl | 第 3 个参数 |
| 参数 4 | %rcx | %ecx | %cx | %cl | 第 4 个参数 |
| 参数 5 | %r8 | %r8d | %r8w | %r8b | 第 5 个参数 |
| 参数 6 | %r9 | %r9d | %r9w | %r9b | 第 6 个参数 |
| 栈指针 | %rsp | %esp | %sp | %spl | 指向栈顶 |
| 基指针 | %rbp | %ebp | %bp | %bpl | 指向栈帧基址（可选） |

**寄存器后缀与数据宽度**：指令的后缀表示操作数宽度。
- `b` = byte（8 位，1 字节）
- `w` = word（16 位，2 字节）
- `l` = long / double word（32 位，4 字节）
- `q` = quad word（64 位，8 字节）

例如：`movb` 传送 1 字节，`movw` 传送 2 字节，`movl` 传送 4 字节，`movq` 传送 8 字节。

**举例**：

```asm
movb $70, %al    ; 将数值 70 存入 %al（8 位寄存器）
movb $80, %bl    ; 将数值 80 存入 %bl（8 位寄存器）
addb %al, %bl   ; %bl = %bl + %al   →  %bl = 80 + 70 = 150 = 0x96
```

**初学易错点**：

1. **不同宽度寄存器的关系**：`%al` 是 `%rax` 的最低 8 位，`%ax` 是最低 16 位，`%eax` 是最低 32 位。修改 `%al` 只会影响最低 8 位，高 56 位不变；但修改 `%eax` 时会自动将高 32 位清零（x86-64 的约定）。
2. **`movl` 的特殊行为**：`movl` 传送到 32 位寄存器时，会自动将高 32 位清零。
3. **AT&T 格式 vs Intel 格式**：本课程使用 AT&T 格式，源操作数在左，目的操作数在右，如 `movq %rax, %rdx`（将 `%rax` 的值复制到 `%rdx`）。寄存器名前加 `%`，立即数前加 `$`。

### 2.2 数据传送指令（mov）

**通俗定义**：`mov` 指令用于在寄存器之间、寄存器和内存之间、或向寄存器写入立即数（常量）。它是汇编程序中最常用的指令。

**标准形式**：

```
mov<后缀> <源操作数>, <目的操作数>
```

操作数类型：
- **立即数**：`$xxx`，如 `$70`
- **寄存器**：`%rax`、`%al` 等
- **内存引用**：`(%rax)` 表示以 `%rax` 中的值作为地址去访问内存

**举例**：

```asm
movq %rax, %rdx      ; 将 %rax 的值复制到 %rdx（寄存器→寄存器）
movq (%rax), %rdx    ; 从内存地址 %rax 处读取 8 字节存入 %rdx
movq $0x100, %rdx    ; 将立即数 0x100 存入 %rdx
```

**初学易错点**：

1. **`movq (%rax), %rdx` 与 `movq %rax, %rdx` 的区别**：前者是"从 `%rax` 指向的内存地址取值"，后者是"把 `%rax` 本身的数值（地址值）传过去"。初学者常混淆这两个意义完全不同的指令。
2. **x86-64 不允许两个操作数都是内存地址**，如 `movq (%rax), (%rdx)` 是非法指令。必须经过寄存器中转。
3. **`lea` 与 `mov` 的区别**：`lea`（Load Effective Address）不访问内存，它只计算地址。例如 `lea 8(%rax), %rdx` 将 `%rax+8` 这个值（而不是该地址的内容）存入 `%rdx`。

---

### 2.3 寻址模式

**通俗定义**：寻址模式是指令如何指定它要操作的内存地址的方式。x86-64 提供了灵活的寻址方式，可以用基址寄存器、变址寄存器、偏移量和比例因子的组合来计算出最终的内存地址。

**标准公式**：

```
Imm(%base, %index, scale)  →  有效地址 = base + index × scale + Imm
```

其中各部分：
- `Imm`：常量偏移量（立即数）
- `%base`：基址寄存器
- `%index`：变址寄存器
- `scale`：比例因子（1、2、4、8）

几种常用形式：

| 寻址模式 | 格式 | 有效地址 |
|----------|------|----------|
| 立即数寻址 | `$Imm` | `Imm`（立即数本身） |
| 寄存器寻址 | `%reg` | `%reg`（寄存器的值） |
| 间接寻址 | `(%reg)` | `%reg` 中存放的地址 |
| 基址+偏移 | `Imm(%reg)` | `%reg + Imm` |
| 基址+变址×比例 | `(%base, %index, s)` | `base + index × s` |
| 完整形式 | `Imm(%base, %index, s)` | `base + index × s + Imm` |

**举例**（基于 Q0022 的数据）：

```asm
movq (%rax), %rdx          ; 从 %rax=0x100 指向的地址取 8 字节
                            ; 地址 0x100~0x107 的数据: 06 03 00 00 0C 08 00 00
                            ; 小端格式: 0x0000080C00000306 → %rdx = 0x0000080C00000306

movw 12(%rax), %dx         ; 从 0x100+12 = 0x10C 取 2 字节
                            ; 偏移量 12 = 0xC, 从 0x10C 开始: FF FF
                            ; 小端: 0xFFFF → %dx = 0xFFFF

movq (%rax, %rcx, 4), %rdx ; %rcx=4, scale=4 → 4×4 = 16, 地址 = 0x100+16 = 0x110
                            ; 从 0x110 取 8 字节: 00 00 00 00 04 00 00 00
                            ; 小端: 0x0000000400000000 → %rdx = 0x0000000400000000
```

**初学易错点**：

1. **小端字节序（Little-Endian）**：x86 架构使用小端格式——低位字节存储在低地址。例如 4 字节整数 `0x00000306` 在内存中存放顺序是 `06 03 00 00`（低位 `06` 在最低地址）。读写多字节数据时必须按小端解析。
2. **比例因子只能是 1、2、4、8**，对应 byte、word、long、quad 的大小。
3. **变址寄存器不能是 `%rsp`**（栈指针寄存器不能作为变址寄存器使用）。

### 2.4 算术与逻辑运算指令

**通俗定义**：这部分指令完成加减乘除、位运算（与、或、异或、移位）等操作，是程序实现计算的"算盘"。

**常用指令**：

| 指令 | 效果 | 说明 |
|------|------|------|
| `add<后缀> S, D` | `D = D + S` | 加法 |
| `sub<后缀> S, D` | `D = D - S` | 减法 |
| `imul<后缀> S, D` | `D = D × S` | 乘法 |
| `and<后缀> S, D` | `D = D & S` | 按位与 |
| `or<后缀> S, D` | `D = D \| S` | 按位或 |
| `xor<后缀> S, D` | `D = D ^ S` | 按位异或 |
| `shl<后缀> k, D` | `D = D << k` | 左移 |
| `shr<后缀> k, D` | `D = D >> k` | 逻辑右移 |
| `sar<后缀> k, D` | `D = D >> k`（算术） | 算术右移 |

**举例**：

```asm
; 计算 t = a + b
movq a, %rax      ; %rax = a
addq b, %rax      ; %rax = %rax + b = a + b

; 循环右移 1 位（Q0021 中用于计算 1 的个数）
shrq $1, %rdi     ; %rdi = %rdi >> 1（每次右移 1 位）
```

**初学易错点**：

1. **AT&T 格式的加法和减法**：`addq S, D` 表示 `D += S`，而 `subq S, D` 表示 `D -= S`。初学者容易记反方向——AT&T 格式是"逗号左边的操作数对右边的操作数运算"。
2. **移位指令 `shl` 和 `shr` 的区别**：算术右移 `sar` 会在高位补符号位（正数补 0，负数补 1）；逻辑右移 `shr` 高位永远补 0。对于无符号数两者等价，对于有符号数则不同。
3. **条件码由算术指令自动设置**：加减乘除等运算后，CPU 自动更新条件码寄存器（ZF、SF、OF、CF），供后续条件跳转指令使用。

---

### 2.5 条件码与条件跳转

**通俗定义**：条件码是 CPU 中一组 1 位寄存器（标志位），记录了最近一次算术或逻辑运算的结果特征。条件跳转指令根据条件码决定是否改变程序的执行顺序，实现了高级语言中的 `if`、`while`、`for` 等控制结构。

**标准表示**：

四个主要条件码：
- **ZF**（零标志）：最近运算结果为 0 时置 1
- **SF**（符号标志）：最近运算结果为负数（最高位为 1）时置 1
- **OF**（溢出标志）：有符号运算发生溢出时置 1
- **CF**（进位标志）：无符号运算发生进位/借位时置 1

**比较指令 `cmp`**：

```
cmpq S2, S1      ; 计算 S1 - S2，设置条件码但不保存结果
```

**测试指令 `test`**：

```
testq S2, S1     ; 计算 S1 & S2（按位与），设置条件码但不保存结果
                  ; 常用于检查寄存器是否为 0 或判断特定比特位
```

**常用条件跳转指令**：

| 指令 | 条件 | 含义 |
|------|------|------|
| `je` / `jz` | ZF=1 | 相等/为零时跳转 |
| `jne` / `jnz` | ZF=0 | 不相等/不为零时跳转 |
| `js` | SF=1 | 负数时跳转 |
| `jns` | SF=0 | 非负数时跳转 |
| `jg` / `jnle` | ZF=0且SF=OF | 有符号大于 |
| `jge` / `jnl` | SF=OF | 有符号大于等于 |
| `jl` / `jnge` | SF≠OF | 有符号小于 |
| `jle` / `jng` | ZF=1或SF≠OF | 有符号小于等于 |
| `ja` / `jnbe` | CF=0且ZF=0 | 无符号大于 |
| `jb` / `jnae` | CF=1 | 无符号小于 |

**举例**（分析 Q0012 的汇编）：

```asm
cond:
    testq   %rsi, %rsi      ; 测试 p（%rsi）是否为 0
    je      .L1             ; 如果 p == 0（ZF=1），跳转到 .L1（跳过赋值）
    cmpq    %rdi, (%rsi)    ; 比较 *p 与 a：计算 *p - a
    jge     .L1             ; 如果 *p >= a（SF=OF 或 ZF=1），跳转
    movq    %rdi, (%rsi)    ; 否则 *p = a
.L1:
    ret
```

对应 C 代码：`if (p && *p < a) { *p = a; }`（当 p 不为空且 p 指向的值小于 a 时，将 a 写入 p 指向的位置）。

**初学易错点**：

1. **`cmpq` 的 operand 顺序**：`cmpq S2, S1` 计算 `S1 - S2`，而不是 `S2 - S1`。`cmpq %rdi, (%rsi)` 计算的是 `*p - a`。
2. **`je` 和 `jne` 是测试 ZF**：`testq %rsi, %rsi` 后 `je .L1` 的含义是"如果 `%rsi` 为 0 则跳转"——因为 `%rsi & %rsi = %rsi`，结果为 0 时 ZF=1。
3. **有符号比较和无符号比较使用不同的跳转指令**：`jg`（有符号大于）和 `ja`（无符号大于）内部判断条件码的逻辑不同，不能混用。

### 2.6 循环的机器级表示

**通俗定义**：高级语言中的 `while`、`for`、`do-while` 循环在机器级都通过条件判断 + 跳转指令实现。本质上就是"判断条件→不满足则跳到循环体后→执行循环体→跳回条件判断处"的模式。

**标准模式**：

`do-while` 模式（先执行一次再判断）：
```asm
loop:                   ; 循环开始标签
    ... 循环体 ...
    <条件检测>
    jne loop            ; 条件满足则跳回
```

`while` 模式（先判断再执行）：
```asm
    jmp check           ; 先跳到条件检测
loop:                   ; 循环开始标签
    ... 循环体 ...
check:                  ; 条件检测标签
    <条件检测>
    jne loop            ; 条件满足则跳回
```

**举例**（Q0021 的汇编分析）：

```asm
// x at %rdi
movl    $0, %eax        ; result = 0
.L2:
    movq    %rdi, %rdx  ; %rdx = x
    andl    $1, %edx    ; %edx = x & 1（取最低位）
    addq    %rdx, %rax  ; result += (x & 1)（累加最低位）
    shrq    $1, %rdi    ; x >>= 1（右移一位）
    jne     .L2         ; if(x != 0) goto .L2
    rep; ret
```

该程序的功能是**统计 x 的二进制表示中 1 的个数**（人口计数 / population count）。每次循环取最低位（`andl $1`），加到结果中，然后右移一位，直到 x 变为 0。

对应的 C 代码：
```c
long pcount_goto(unsigned long x) {
    long result = 0;
loop:
    result += x & 1;
    x >>= 1;
    if (x) goto loop;
    return result;
}
```

**初学易错点**：

1. **`shrq` 后 `jne` 判断的是右移后的结果**：`shrq` 会设置条件码，当移位后结果为 0 时 ZF=1，`jne` 检测 ZF=0（即结果不为 0）才跳转。
2. **循环变量通常需要在循环体外初始化**：如 `movl $0, %eax` 对应 `result = 0`。
3. **C 语言循环与 goto 的等价性**：编译器先将 `for`/`while` 转换为 `do-while` 或 `goto` 模式，再生成汇编。学习汇编时，用 goto 理解循环的机器级实现是最直观的方式。

### 2.7 过程调用（函数调用）与栈帧

**通俗定义**：函数调用时，需要在栈（一种后进先出的内存区域）上为每个函数分配一段临时存储空间，称为栈帧，用于存放局部变量、参数、返回地址等。x86-64 有严格的调用约定（Calling Convention）来规范这一过程。

**x86-64 过程调用规范**：

**控制流转移**：
- `call <函数地址>`：将下一条指令的地址（返回地址）压入栈中，然后跳转到函数入口
- `ret`：从栈顶弹出返回地址，跳转回去

**数据传输（参数传递）**：
- 前 6 个整型/指针参数依次放在 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9` 中
- 超过 6 个的参数通过栈传递（从右向左压栈）
- 函数返回值放在 `%rax` 中

**栈管理**：
```
       高地址
   ┌──────────────────┐
   │  ...             │
   ├──────────────────┤
   │ 第 7 个及以上参数 │  ← 调用者压入
   ├──────────────────┤
   │ 返回地址         │  ← call 指令压入
   ├──────────────────┤  ← %rsp 指向这里（栈顶）
       低地址
```

- 栈从高地址向低地址生长（压栈 `pushq` 使 `%rsp` 减小）
- 栈底在高地址，栈顶在低地址
- 被调用者负责保存 `%rbx`、`%rbp`、`%r12~%r15`（被调用者保存寄存器）
- 调用者负责保存其他寄存器（调用者保存寄存器，如 `%rax`、`%rcx`、`%rdx`、`%rsi`、`%rdi`、`%r8~%r11`）

**举例**：

```c
long func(long a, long b, long c, long d, long e, long f, long g) {
    return a + b + c + d + e + f + g;
}
```
在 x86-64 调用约定下：
- `a`~`f` 分别放入 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`
- `g` 被调用者压入栈中
- 函数内部可能需要通过 `%rsp` + 偏移量来访问栈上的参数

**初学易错点**：

1. **栈的生长方向**：初学容易搞混。`pushq %rax` 将 `%rsp` 减小 8 然后存储，所以栈是向**低地址**方向生长的。
2. **静态局部变量不在栈帧中**：函数中用 `static` 声明的静态局部变量存储在静态数据区（`.data` 或 `.bss` 段），而非栈帧中。因此 Q0008 中的错误选项 C 就是此题的关键点。
3. **`%rsp` 不能作为变址寄存器**：`%rsp` 专用于栈管理，不能出现在寻址模式的变址位置。
4. **参数的栈传递顺序**：第 7 个及以后的参数按从右向左的顺序压栈（即最右边的参数先压入，在栈顶位置）。

## 3. 典型例题

### 例题 1（来源：[Q0005]）

**题目**：

下面的全部指令执行完成后，`%bl` 寄存器中的编码是（ ）

```asm
movb $70, %al
movb $80, %bl
addb %al, %bl
```

A. 0x96
B. 0xFA
C. 0x0096
D. 0x6A

**解答**：

**第一步**：理解指令宽度。后缀 `b` 表示 byte（8 位）。`%al` 是 `%rax` 的低 8 位，`%bl` 是 `%rbx` 的低 8 位。

**第二步**：逐条执行。

- `movb $70, %al`：将立即数 70（十进制）送入 `%al`，`%al = 70`。
- `movb $80, %bl`：将立即数 80（十进制）送入 `%bl`，`%bl = 80`。
- `addb %al, %bl`：计算 `%bl = %bl + %al = 80 + 70 = 150`。

**第三步**：将结果 150（十进制）转换为十六进制。
- 150 ÷ 16 = 9 余 6 → 十六进制为 0x96。

**第四步**：8 位寄存器 `%bl` 只能存储 8 位（1 字节），0x96 = 150 < 256，没有溢出，结果正确。

因此答案为 **A. 0x96**。

**解析**：

本题考察的是基本的数据传送指令和加法运算的机器级表示。核心知识点有三个：一是 AT&T 汇编中指令后缀 `b`（8 位）、`w`（16 位）、`l`（32 位）、`q`（64 位）的含义；二是 `%al` 和 `%bl` 作为 8 位低位寄存器的使用；三是十进制到十六进制的转换。两个选项的干扰性在于：0xFA = 250（误加为 `70 + 80` 但算错），0x6A = 106（可能误用减法），0x0096 是 16 位表示（但 `%bl` 只有 8 位）。

### 例题 2（来源：[Q0022]）

**题目**：

x86-64 CPU 中寄存器 `%rax = 0x100`，`%rcx = 0x4`，内存中地址 `0x100~0x120` 处的数据如下表（小端格式）：

| 偏移量 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|--------|---|---|---|---|---|---|---|---|
| 0x100  | 06| 03| 00| 00| 0C| 08| 00| 00|
| 0x108  | FF| FF| FF| FF| CC| CC| CC| CC|
| 0x110  | 00| 00| 00| 00| 04| 00| 00| 00|
| 0x118  | 55| 55| 00| 00| 21| 20| 00| 00|

请计算以下指令执行后寄存器的值：

| 指令 | 值（十六进制） |
|------|----------------|
| `movq %rax, %rdx` | `%rdx =` ______ |
| `movq (%rax), %rdx` | `%rdx =` ______ |
| `movw 12(%rax), %dx` | `%dx =` ______ |
| `movq (%rax, %rcx, 4), %rdx` | `%rdx =` ______ |
| `movl 16(%rax, %rcx), %edx` | `%edx =` ______ |
| `lea 8(%rax, %rcx, 2), %rdx` | `%rdx =` ______ |

**解答**：

**小题 1**：`movq %rax, %rdx`

将寄存器 `%rax` 的值 0x100 直接复制到 `%rdx`。这是寄存器到寄存器的传送，不涉及内存访问。

**答案**：`%rdx = 0x100`

---

**小题 2**：`movq (%rax), %rdx`

`%rax = 0x100`，所以从内存地址 0x100 开始读取 8 字节（`q` = quad word = 8 字节）。

从表中读取地址 0x100~0x107 的连续 8 个字节：
```
地址 0x100: 06
地址 0x101: 03
地址 0x102: 00
地址 0x103: 00
地址 0x104: 0C
地址 0x105: 08
地址 0x106: 00
地址 0x107: 00
```

**小端格式解析**：最低地址的字节是数值的最低 8 位。所以这 8 个字节代表的 64 位整数为：

$$
\text{值} = 0x00\;00\;08\;0C\;00\;00\;03\;06
$$

注意小端顺序：从最高地址到最低地址读取。即字节序列从高到低为 `00 00 08 0C 00 00 03 06`。

**答案**：`%rdx = 0x0000080C00000306`

---

**小题 3**：`movw 12(%rax), %dx`

首先计算有效地址：`%rax + 12 = 0x100 + 12 = 0x10C`。

`w` 表示 word（2 字节），所以从 0x10C 读取 2 个字节。

从表中看地址 0x10C：
```
地址 0x10C: FF（偏移 0x108 + 4）
地址 0x10D: FF（偏移 0x108 + 5）
```

详细找到 0x10C：表中 0x108 行的前 8 字节是 0x108~0x10F，偏移 4~5 即 0x10C~0x10D。

小端解析 2 字节：`FF FF` → 高字节 0xFF 在高地址（0x10D），低字节 0xFF 在低地址（0x10C），所以值为 0xFFFF。

**答案**：`%dx = 0xFFFF`

---

**小题 4**：`movq (%rax, %rcx, 4), %rdx`

计算有效地址：`%rax + %rcx × 4 = 0x100 + 4 × 4 = 0x100 + 16 = 0x110`。

从地址 0x110 读取 8 字节（`q` 后缀）：

```
地址 0x110: 00
地址 0x111: 00
地址 0x112: 00
地址 0x113: 00
地址 0x114: 04
地址 0x115: 00
地址 0x116: 00
地址 0x117: 00
```

小端解析：`0x00 00 00 04 00 00 00 00`

**答案**：`%rdx = 0x0000000400000000`

---

**小题 5**：`movl 16(%rax, %rcx), %edx`

计算有效地址：`%rax + %rcx + 16 = 0x100 + 4 + 16 = 0x114`。

`l` 表示 long（4 字节），从 0x114 读取 4 字节：

```
地址 0x114: 04
地址 0x115: 00
地址 0x116: 00
地址 0x117: 00
```

小端解析：`0x00 00 00 04`

注意 `movl` 传送到 `%edx` 时，会自动将 `%rdx` 的高 32 位清零。

**答案**：`%edx = 0x00000004`

---

**小题 6**：`lea 8(%rax, %rcx, 2), %rdx`

计算有效地址（但不访问内存！）：
`%rax + %rcx × 2 + 8 = 0x100 + 4 × 2 + 8 = 0x100 + 8 + 8 = 0x110`

`lea` 指令直接将这个计算结果（地址值）存入 `%rdx`，不做内存读取。

**答案**：`%rdx = 0x110`

---

**解析**：

本题是寻址模式的经典综合题，涵盖了 **寄存器传送**（小题 1）、**间接寻址 + 小端转译**（小题 2、3、4、5）以及 **`lea` 地址计算**（小题 6）三大知识点。

关键思路总结：
1. **小端格式**一定记住：读内存时，低地址存的是数值的"低位"，需要反向组合读出真正的数值。
2. **`mov` vs `lea`**：`mov` 从内存"取值"，`lea` 只"算地址"不取内存值。
3. **不同后缀的数据宽度**：`movw` 读 2 字节，`movl` 读 4 字节，`movq` 读 8 字节。目标寄存器也要匹配对应宽度（`%dx` 是 16 位，`%edx` 是 32 位，`%rdx` 是 64 位）。
4. **寻址公式**：`Imm(%base, %index, scale)` 的完整形式计算为 `base + index × scale + Imm`。

### 例题 3（来源：[Q0012]）

**题目**：

已知函数原型 `void cond(long a, long *p)`，编译后得到的汇编代码如下，参数 `a` 和 `p` 分别存储在寄存器 `%rdi` 和 `%rsi` 中。下列 C 代码中，与汇编代码等效的是（ ）。

```asm
cond:
    testq   %rsi, %rsi
    je      .L1
    cmpq    %rdi, (%rsi)
    jge     .L1
    movq    %rdi, (%rsi)
.L1:
    ret
```

A. `void cond(long a, long *p) { if (p) { *p = a; } }`

B. `void cond(long a, long *p) { if (p && *p < a) { *p = a; } }`

C. `void cond(long a, long *p) { if (p && *p <= a) { *p = a; } }`

D. `void cond(long a, long p) { if (p && p < a) { p = a; } }`

**解答**：

**第一步**：理解参数绑定。x86-64 调用约定将第 1 个参数 `a` 放在 `%rdi`，第 2 个参数指针 `p` 放在 `%rsi`。

**第二步**：逐条分析汇编指令。

| 指令 | 解释 |
|------|------|
| `testq %rsi, %rsi` | 计算 `%rsi & %rsi`，结果与 `%rsi` 本身相同。如果 `%rsi = 0`，则 ZF=1；否则 ZF=0。<br>等价于检查 `p` 是否为 NULL（0）。 |
| `je .L1` | 如果 ZF=1（即 `%rsi = 0`，`p == NULL`），跳转到 `.L1`，跳过赋值，直接返回。 |
| `cmpq %rdi, (%rsi)` | 计算 `(%rsi) - %rdi`，即 `*p - a`，设置条件码但不保存结果。 |
| `jge .L1` | 如果 `*p - a >= 0`（即 `*p >= a`），跳转到 `.L1`，跳过赋值。 |
| `movq %rdi, (%rsi)` | 执行赋值：`*p = a`（将 `%rdi` 中的值写入 `%rsi` 指向的内存地址）。 |
| `.L1: ret` | 函数返回。 |

**第三步**：将汇编逻辑翻译为 C 代码逻辑。

```
if (p == NULL)      → 直接返回（不赋值）
if (*p >= a)        → 直接返回（不赋值）
否则（p != NULL && *p < a）→ *p = a
```

合并条件：`if (p != NULL && *p < a) { *p = a; }`

等价写法：`if (p && *p < a) { *p = a; }`（C 语言中 `p != NULL` 简写为 `p`）。

**第四步**：与选项比对。
- A 缺少 `*p < a` 的条件，错误。
- B `p && *p < a` 完全匹配，正确。
- C `*p <= a` 包含了等于的情况，而 `jge` 在 `*p >= a` 时跳转（不赋值），错误的。
- D 的参数 `p` 不是指针（`long p` 而非 `long *p`），且 `p = a` 是修改局部变量而非解引用，类型和语义均错。

**答案**：**B**

**解析**：

本题考察汇编到 C 的逆向翻译能力，核心是理解 **`test` / `cmp` + 条件跳转**的组合含义。

- `testq %rsi, %rsi` + `je`：判断寄存器是否为 0，对应 C 的 `p == NULL` 或 `!p`。
- `cmpq %rdi, (%rsi)` + `jge`：判断 `*p - a >= 0`，对应 `*p >= a` 时跳转（所以条件分支的"反面"才是赋值的条件）。这里比较容易出错：`jge` 跳过的语句块就是不满足 `*p >= a` 的情况，即 `*p < a`。
- 选项 C 的干扰性很强：它使用 `<=`（小于等于），而 `jge` 跳转的条件是"大于等于"——两个条件是对立的。`*p <= a` 时赋值的等价汇编应该是 `jg`（大于时跳转不赋值）。
- 选项 D 同时有类型错误（`long p` vs `long *p`）和语义错误（修改参数本身而非指针所指内容）。

### 例题 4（来源：[Q0021]）

**题目**：

请根据汇编指令，补全其所对应的 C 语言语句，并简述其功能。

```asm
// x at %rdi
movl    $0, %eax
.L2:
    movq    %rdi, %rdx
    andl    $1, %edx
    addq    %rdx, %rax
    shrq    $1, %rdi
    jne     .L2
    rep; ret
```

```c
long pcount_goto(unsigned long x) {
    long result = ______;
loop:
    result += ______;
    x >>= ______;
    if (x) goto loop;
    return result;
}
```

**解答**：

**第一步**：确定参数和初始化的对应关系。

- 参数 `unsigned long x` 存放在 `%rdi` 中
- `movl $0, %eax`：将 0 存入 `%eax`（`%rax` 的低 32 位，且由于 `movl` 的特性自动清零高 32 位）。这对应 C 代码中的 `result = 0`。

所以第一空：**`0`**。

**第二步**：分析循环体。

| 汇编指令 | 解释 |
|----------|------|
| `movq %rdi, %rdx` | `%rdx = %rdi`（将 `x` 复制到 `%rdx`） |
| `andl $1, %edx` | `%edx = %edx & 1`，取 `x` 的最低 1 位（如果 x 是奇数则为 1，偶数则为 0） |
| `addq %rdx, %rax` | `result += (%x & 1)`，将取出的最低位累加到结果 |
| `shrq $1, %rdi` | `x >>= 1`，将 x 右移 1 位 |

所以循环体对应 `result += (x & 1);` 和 `x >>= 1;`。

C 代码中 `result += ______;` 应填 `x & 1`（取 x 的最低位），`x >>= ______;` 应填 `1`（右移 1 位）。

**第三步**：确定函数功能。

该程序的功能是**统计 `x` 的二进制表示中 "1" 的个数**（也称为人口计数（Population Count）或汉明重量）。

每次循环：
1. 取 `x` 的最低位（`x & 1`）——如果最低位是 1 就加 1，是 0 就加 0
2. 将 `x` 右移 1 位，丢弃已经处理过的最低位
3. 重复直到 `x = 0`

例如：`x = 0b1101`（二进制），有 3 个 1，循环过程：
- 第 1 次：`x & 1 = 1`，`result = 1`，`x >>= 1 → 0b110`
- 第 2 次：`x & 1 = 0`，`result = 1`，`x >>= 1 → 0b11`
- 第 3 次：`x & 1 = 1`，`result = 2`，`x >>= 1 → 0b1`
- 第 4 次：`x & 1 = 1`，`result = 3`，`x >>= 1 → 0b0`
- `x = 0`，`jne` 不跳转，循环结束，返回 `result = 3`。

**答案**：

补全后的 C 代码：
```c
long pcount_goto(unsigned long x) {
    long result = 0;
loop:
    result += x & 1;
    x >>= 1;
    if (x) goto loop;
    return result;
}
```

函数功能：**统计无符号整数 `x` 的二进制表示中 "1" 的个数**。

**解析**：

本题综合考察循环结构的汇编表示、位运算指令和 C 语言翻译能力。

解题要点：
1. **`movl $0, %eax` 初始化 `result = 0`**：注意 `movl` 用于 32 位寄存器时自动清零高 32 位，这是 x86-64 的约定。
2. **`andl $1, %edx` 取最低位**：任何二进制数与 1 按位与，结果就是最低位的值（1 或 0）。
3. **`shrq $1, %rdi` 逻辑右移**：无符号数的右移使用逻辑右移，高位补 0。
4. **`jne .L2` 的条件**：`shrq` 指令会影响 ZF 标志位，当移位后结果为 0 时 ZF=1，`jne`（ZF=0 时跳转）就不会跳转，循环自然结束。
5. **`rep; ret`**：`rep` 前缀在 `ret` 前是 AMD 处理器的分支预测优化，不影响逻辑功能。

这是一种经典的位计数算法，时间复杂度为 $O(\text{位数})$，即对 64 位整数最多循环 64 次。

### 例题 5（来源：[Q0028]）

**题目**：

请简述 x86-64 系统中的过程调用规范。详细说明过程调用机制中的**控制流转移**、**数据传输**和**过程中数据存储管理**的具体实现方式。

**解答**：

x86-64 过程调用规范（即 System V AMD64 ABI）是一套约定，规定了函数调用前后寄存器的使用方式、参数如何传递、栈如何管理等。下面是三个核心方面的详细说明：

---

**一、控制流转移**

控制流转移通过 `call` 和 `ret` 两条指令实现：

- **`call <函数地址>`**：
  - 将下一条指令的地址（返回地址）压入栈中。
  - 然后跳转到目标函数的第一条指令开始执行。
  - 相当于组合操作：`pushq 返回地址; jmp 函数地址`。

- **`ret`**：
  - 从栈顶弹出返回地址。
  - 跳转到该地址继续执行。
  - 相当于组合操作：`popq PC`（程序计数器）。

整个调用和返回的过程是栈的"后进先出"特性的典型应用——多个函数嵌套调用时，后调用的先返回。

---

**二、数据传输（参数传递）**

参数传递遵循以下规则：

- **前 6 个整型/指针参数**依次通过特定寄存器传递：
  | 参数顺序 | 寄存器 |
  |----------|--------|
  | 第 1 个 | `%rdi` |
  | 第 2 个 | `%rsi` |
  | 第 3 个 | `%rdx` |
  | 第 4 个 | `%rcx` |
  | 第 5 个 | `%r8` |
  | 第 6 个 | `%r9` |

- **超过 6 个的参数**通过栈传递。
  - 调用者提前将超出部分的参数压入栈中。
  - 压栈顺序是从右向左（最右边的参数最先压入，在栈中位于最高地址；最左边的超出参数最后压入，在栈顶稍下方）。
  - 函数内部通过 `%rsp` 加上固定偏移量访问这些栈上的参数。

- **函数返回值**存放在 `%rax` 中。

---

**三、过程中数据存储管理（栈帧管理）**

每个函数被调用时，会在栈上分配一段区域称为**栈帧（Stack Frame）**，用于存放：

1. **返回地址**：由 `call` 指令压入，`ret` 指令弹出。
2. **被调用者保存的寄存器**：函数如果需要使用 `%rbx`、`%rbp`、`%r12~%r15`，必须先保存它们的旧值，返回前恢复。
3. **局部变量**：函数中声明的自动（非静态）局部变量。
4. **参数超出 6 个的部分**（由调用者分配）。

栈帧的分配和释放通常通过修改 `%rsp` 来实现：

- **分配栈帧**：`subq $N, %rsp`（将栈指针下移 N 字节，开辟 N 字节空间）。
- **释放栈帧**：`addq $N, %rsp`（将栈指针上移 N 字节，回收空间）或使用 `leave` 指令。
- `leave` 指令等价于 `movq %rbp, %rsp; popq %rbp`，快速恢复栈指针和基指针。

**栈区布局示意图**（高地址在上，低地址在下）：

```
        高地址
   ┌───────────────────┐
   │ 调用者的栈帧      │
   ├───────────────────┤
   │ 第 7+ 个参数      │  ← 调用者栈帧的一部分
   ├───────────────────┤
   │ 返回地址          │  ← call 指令压入
   ├───────────────────┤
   │ 保存的 %rbp       │  ← 旧基址指针
   ├───────────────────┤
   │ 局部变量          │
   ├───────────────────┤
   │ 保存的寄存器      │
   ├───────────────────┤  ← %rsp（栈顶指向这里）
        低地址
```

**寄存器保存约定**：

- **被调用者保存寄存器**（Callee-saved）：`%rbx`、`%rbp`、`%r12~%r15`。被调用函数必须保证这些寄存器在返回时与进入时相同（通过压栈保存旧值、返回前出栈恢复）。简单来说，调用者"信任"这些寄存器在函数调用后不会被破坏。
- **调用者保存寄存器**（Caller-saved）：`%rax`、`%rcx`、`%rdx`、`%rsi`、`%rdi`、`%r8~%r11`。被调用函数可以随意使用这些寄存器而不需要恢复。如果调用者在使用这些寄存器后还要继续使用其中的值，调用者必须自己在调用前保存（如压入栈中），调用后恢复。

**解析**：

本题是简答题，考察对 x86-64 过程调用约定的全面理解。

在作答时，需要从三个维度（控制流、数据传递、数据存储）系统性地展开：

1. **控制流**是最直观的——`call` 压入返回地址并跳转，`ret` 弹出返回地址并跳转回去。这是理解函数调用"怎么去、怎么回"的基础。
2. **数据传输**是初学者最容易忽略的方面。6 个寄存器参数的约定非常重要——超过 6 个才用栈传参。
3. **数据存储管理**的核心是"后进先出"的栈结构，多个函数嵌套调用时栈帧相互隔离、独立管理。

记忆方法：可以把"调用者保存 / 被调用者保存"理解为"谁干活谁负责"——函数内自由使用调用者保存寄存器（但调用者可能因此丢失数据），而被调用者保存寄存器需要函数自己保护现场。

### 自测题 1（来源：[Q0008]）

**题目**：

下列关于 x86-64 系统中栈的描述，哪一项是错误的？（ ）

A. 栈底位于高地址，栈顶位于低地址

B. 函数执行完毕，栈帧会被销毁

C. 函数中声明的静态局部变量会保存在对应的栈帧中

D. 如果函数的参数超过 6 个，则超出的部分会使用栈存储

<details>
<summary><b>点击查看提示</b></summary>

考虑"静态局部变量"（`static` 关键字修饰的局部变量）的存储位置——它和普通自动变量不同。另外从栈的生长方向判断各选项的正确性。

</details>

> [!question]- 点击查看完整解答
>
> **考查知识点**：栈的特点、栈帧管理、静态局部变量 vs 自动变量、参数传递约定。
>
> **逐项分析**：
>
> - **A（正确）**：x86-64 栈从高地址向低地址生长。栈底（最早压入的数据）在高地址，栈顶（最新压入的数据）在低地址。`push` 操作使 `%rsp` 减小。
>
> - **B（正确）**：函数返回时，通过 `addq $N, %rsp` 或 `leave; ret` 释放栈帧空间，栈帧确实会被"销毁"（栈指针恢复，但实际内存内容未被清零，只是逻辑上不再有效）。
>
> - **C（错误）**：这是本题的错误选项。用 `static` 修饰的局部变量存储在**静态数据区**（`.data` 或 `.bss` 段），其生命周期贯穿整个程序运行过程，而不是存储在栈帧中。只有非静态的自动局部变量才存储在栈帧中。
>
> - **D（正确）**：x86-64 调用约定规定前 6 个整型/指针参数通过 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9` 传递，从第 7 个参数开始通过栈传递。
>
> **答案**：**C**

### 自测题 2（来源：[Q0010]）

**题目**：

下列关于 x86-64 汇编指令控制流分支的描述中，正确的是（ ）。

A. 分为条件跳转和条件数据传输两种方式

B. 在 x86-64 汇编指令中，条件码可以直接访问，也可以使用 `setX` 一族的指令，获取某些条件码进行位运算后的结果

C. 条件数据传输，是根据条件码判断是否执行跳转进入相应的指令语句块

D. 在各分支内部计算量较大时，或各分支之间的计算存在数据依赖关系时仍然可以使用条件数据传输

<details>
<summary><b>点击查看提示</b></summary>

仔细区分"条件跳转"和"条件数据传输（conditional move）"两种实现分支的方式。条件数据传输的特点是不需要跳转（流水线友好），但在计算量大或有数据依赖时并不适用。

</details>

> [!question]- 点击查看完整解答
>
> **逐项分析**：
>
> - **A（正确）**：x86-64 实现条件分支有两种方式：一是传统的条件跳转（`je`、`jge` 等），二是条件数据传输（`cmov` 系列指令，根据条件码选择是否执行数据传送）。这个描述是正确的。
>
> - **B（错误）**：条件码（ZF、SF、OF、CF）不能直接由程序员访问（它们是 CPU 内部的状态标志位），但可以通过 `setX` 指令族（如 `sete`、`setg` 等）根据条件码的组合结果设置一个 8 位寄存器或内存字节。描述中"条件码可以直接访问"是错误的，"获取某些条件码进行位运算"的表述也不准确。
>
> - **C（错误）**：条件数据传输（`cmov`）**不涉及跳转**——它根据条件码决定是否将源操作数的值复制到目标寄存器。如果条件不满足，目标寄存器保持不变。本题干描述的是"条件跳转"而非"条件数据传输"。
>
> - **D（错误）**：条件数据传输适用于各分支**计算量小**（如简单的赋值）的场景。当分支内部计算量较大时，需要先分别计算两个分支的值再根据条件选择，这会浪费大量计算资源。当分支间存在数据依赖时，也无法使用条件数据传输来优化。
>
> **答案**：**A**

### 自测题 3（来源：[Q0018]）

**题目**：

假定汇编指令 `addl $1, (%rdi, %rax, 4)` 实现了对数组中某元素的 "+1" 操作，则寄存器 `%rdi` 和 `%rax` 中分别存放的应为 ______ 和 ______。

<details>
<summary><b>点击查看提示</b></summary>

根据寻址公式 `base + index × scale + Imm`，分析这条 `addl` 指令访问的内存在哪个位置。`(%rdi, %rax, 4)` 对应公式中的哪几部分？`scale=4` 表示什么类型的数据？

</details>

> [!question]- 点击查看完整解答
>
> **分析**：
>
> 指令 `addl $1, (%rdi, %rax, 4)` 的功能是：将内存地址 `%rdi + %rax × 4` 处的 4 字节数据加 1。
>
> 寻址模式 `(%rdi, %rax, 4)` 的完整形式是 `Imm(%base, %index, scale)` 省略了 `Imm`（偏移量为 0）：
> - 基址寄存器（base）= `%rdi`
> - 变址寄存器（index）= `%rax`
> - 比例因子（scale）= 4
>
> 有效地址 = `%rdi + %rax × 4`
>
> 题目说这条指令实现了对**数组**中某元素的 "+1" 操作，因此：
>
> - `%rdi` 应存放**数组的起始地址**（数组基地址）
> - `%rax` 应存放**数组元素的下标**（索引）
> - 比例因子 4 表示数组每个元素占 4 字节（例如 `int` 类型数组）
>
> 有效地址 = 数组首地址 + 下标 × 4（即第 `%rax` 个元素的地址）
>
> **答案**：`%rdi` 中存放**数组首地址**，`%rax` 中存放**数组下标（索引）**。
>
> **解析**：这是 x86-64 寻址模式在数组访问中的典型应用。`scale=4` 给出了数组元素大小的重要线索（4 字节 = `int` 或 `float`）。公式 `base + index × scale` 恰好对应了 C 语言中 `arr[i]` 的地址计算方式：`&arr[0] + i × sizeof(element)`。

### 自测题 4

**题目**：

（附加练习——将下面这段 C 代码的手动编译结果与汇编对应）

```c
long sum(long n) {
    long result = 0;
    for (long i = 0; i < n; i++) {
        result += i;
    }
    return result;
}
```

尝试分析：`for` 循环会被编译成什么形式的汇编代码？

<details>
<summary><b>点击查看提示</b></summary>

`for` 循环本质上可以转换为 `while` 循环再编译。关键考虑：初始化（`i=0`）、条件判断（`i<n`）、循环体、更新（`i++`）四个部分的汇编对应关系。

</details>

> [!question]- 点击查看完整解答
>
> **分析**：
>
> 编译器将 `for` 循环转换为 `goto` 模式的汇编。大致对应关系如下：
>
> ```c
> // C 原代码
> long sum(long n) {
>     long result = 0;
>     for (long i = 0; i < n; i++) {
>         result += i;
>     }
>     return result;
> }
>
> // 编译器内部转换为 goto 形式
> long sum_goto(long n) {
>     long result = 0;
>     long i = 0;
>     goto test;
> loop:
>     result += i;
>     i++;
> test:
>     if (i < n) goto loop;
>     return result;
> }
> ```
>
> **对应的汇编**（简化版本，假设参数 `n` 在 `%rdi` 中，结果在 `%rax` 中）：
>
> ```asm
> sum:
>     movq    $0, %rax        ; result = 0
>     movq    $0, %rcx        ; i = 0
>     jmp     .L2             ; 先跳到条件判断
> .L3:                        ; 循环体标签
>     addq    %rcx, %rax      ; result += i
>     addq    $1, %rcx        ; i++
> .L2:                        ; 条件判断标签
>     cmpq    %rdi, %rcx      ; 比较 i 和 n：计算 i - n
>     jl      .L3             ; 如果 i < n（有符号小于），跳回循环体
>     ret                     ; 返回 result
> ```
>
> **关键点**：
>
> 1. `for` 循环的初始化部分（`i = 0`）在循环体外执行。
> 2. 条件判断（`i < n`）在循环体之前（通过 `jmp` 先跳到判断处），这对应 C 语言中 `for` 的"先判断后执行"语义。
> 3. 更新部分（`i++`）放在循环体末尾，条件判断之前。
> 4. `jl`（有符号小于跳转）是用于有符号整数的比较。如果 `n` 和 `i` 是 `unsigned` 类型，则应使用 `jb`（无符号小于跳转）。
> 5. 这就是第 2.6 节中提到的 **`while` 模式**汇编结构。
