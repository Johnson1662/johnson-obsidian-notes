# 异常控制流 (Exceptional Control Flow, ECF)

## 控制流与异常控制流
### 控制流 (Control Flow)
处理器从启动到停机执行的指令序列。通常是平滑的（即相邻指令在内存中也相邻）。
### 异常控制流 (ECF)
为了响应系统状态的变化（如硬件定时器、网络包到达、子进程终止等），系统通过使控制流发生突变来做出反应。ECF 存在于硬件级、操作系统级和应用级。
- 硬件级：异常
- 操作系统级：进程上下文切换、信号
- 应用级：非本地跳转（Nonlocal Jumps）

## 异常 (Exceptions)
### 定义
- 异常是异常控制流的一种形式，一部分由硬件实现，一部分由操作系统实现。它将控制权从用户程序转移到操作系统内核。
### 异常表 (Exception Table)
- 处理器在检测到异常事件时，通过**异常号**索引一个跳转表（异常表），以跳转到对应的**异常处理程序**。
- 异常表初始化：在系统启动时，由操作系统分配并初始化。
### 异常处理程序 (Exception Handlers)
- 运行在内核模式下的软件程序。
- 入口地址计算：异常表基址寄存器 + (异常号 * 4/8)。
### 异常类别

| 类别  | 原因           | 同步 or 异步？ | 返回行为       | 举例                                                 |
| :-- | :----------- | :-------- | :--------- | -------------------------------------------------- |
| 中断  | 来自 I/O 设备的信号 | 异步（only）  | 总是返回到下一条指令 | 外部定时器，I/O 请求，收到一个网络套接字                             |
| 陷阱  | 有意的异常        | 同步        | 总是返回到下一条指令 | 系统调用（read、execve、fork、exit）：内核层面运行，只能用寄存器传递参数；断点调试 |
| 故障  | 潜在可恢复的错误     | 同步        | 可能返回到当前指令  | 除零、缺页、机器检查（缺页可以恢复，除法错误、一般保护错误、段错误不可恢复）             |
| 终止  | 不可恢复的错误      | 同步        | 不会返回       | 硬件错误                                               |
- **中断 (Interrupt)**: 来自处理器外部 I/O 设备的信号（如定时器中断、I/O 读写完成）。它是**异步**的。
- **陷阱 (Trap)**: **有意**的异常。主要用于**系统调用**（System Call），如 `read`, `fork`, `execve` 等，以及**断点调试**。它是**同步**的。
- **故障 (Fault)**: 由潜在可恢复的错误引起（如**缺页**、**保护违例**、**除 0**）。处理程序可能会重新执行引起故障的指令。它是**同步**的。
- **终止 (Abort)**: 不可恢复的致命错误（如**非法指令**、**奇偶校验错**）。通常导致当前程序终止。它是**同步**的。

## 进程 (Processes)
### 基本概念
- 进程是计算机科学中最深刻、最成功的抽象之一。
- **独立的逻辑控制流**: 假象——每个程序似乎独占 CPU。
- **私有的地址空间**: 假象——每个程序似乎独占内存。
### 并发的概念
- 如果两个逻辑流在时间上重叠，则称它们是并发的。
### 用户模式与内核模式
- 处理器通过**模式位**限制进程可执行的指令和可访问的地址空间。
- 内核模式可以执行任何指令并访问任何内存位置。
### 上下文切换 (Context Switch)
- 内核通过保存当前进程的上下文（寄存器、PC、栈指针等）并恢复新进程的上下文来实现进程切换。
### 进程的控制
- 获取系统调用的错误信息：通过全局变量 `errno`。
- 获取进程 ID:
    - `getpid`: 获取当前进程 PID。
    - `getppid`: 获取父进程 PID。
- 创建和终止进程:
    - 进程的状态:
        - **运行**: 正在执行（执行）或等待执行（就绪）。
        - **停止**: 被信号（如 SIGSTOP）挂起，或处于阻塞状态（如等待 I/O），直到收到信号（如 SIGCONT）或事件完成。
        - **终止**: 进程永久停止（由于 exit、main 返回或被杀死）。
    - 创建进程: `fork`
        - **一次调用，两次返回**：父进程返回子进程 PID，子进程返回 0。
        - **并发执行**：父子进程是独立的。
        - **相同但独立的地址空间**：子进程得到父进程用户级虚拟地址空间的一份副本（包括代码、数据、堆、栈、文件描述符表副本）。
        - **共享文件**：子进程继承父进程所有打开的文件描述符。
    - 终止进程: `exit(status)`。
- 回收子进程: `wait`, `waitpid`
    - 如果父进程不回收子进程，父进程结束后由 1 号进程进行回收。
    - 常驻进程需要自己回收子进程以放置内存泄漏。
- 进程休眠: `sleep` (挂起指定时间), `pause` (挂起直到收到信号)。
- 加载并运行程序: `execve`
    - 加载 ELF 文件至当前进程运行, 覆盖进程的代码、数据、堆和栈。
    - 保留 pid、文件描述符表和进程的上下文。
    - 调用成功后不返回。

## 信号 (Signals)
### 定义
- 信号是一种高层软件形式的异常控制流，通知进程系统中发生了某种事件。
### 常用信号
- `SIGINT` (2): 来自键盘的中断 (Ctrl+C)。
- `SIGTERM` (15): 终止信号。
- `SIGKILL` (9): 强制杀死信号（不能被捕获或忽略）。
- `SIGCHLD` (17): 子进程停止或终止。
- `SIGTSTP` (20): 来自终端的停止信号 (Ctrl+Z)。
- `SIGCONT` (18): 继续运行停止的进程。
### 发送信号
- **进程组**: 每个进程都属于一个进程组。
    - `getpgrp`: 获取当前进程的进程组 ID。
    - `setpgid`: 改变进程所在的进程组。
- `kill` 命令或 `kill` 系统调用发送信号.
- `alarm` 系统调用：安排在指定秒数后发送 SIGALRM.
### 接收信号
- 信号处理程序 (Signal Handler)：用户自定义的函数。
### 阻塞和解除阻塞信号
- 隐式阻塞：内核默认阻塞当前正在处理的同类型信号。
- 显式阻塞：使用 `sigprocmask`。
### 信号不排队 (Signals are not Queued)
- 信号通过将目标进程相应的信号位进行置位实现。同类型的待处理信号只会在位向量中记录一次。如果前一个信号未处理，又收到同类信号，只处理一次（**不能通过信号进行计数**）。

## 非本地跳转 (Nonlocal Jumps)
非本地跳转用于从深层嵌套的函数调用中直接返回，常用于错误处理。
- **`setjmp(env)`**：
    - 在当前位置保存栈上下文（PC、栈指针等）到 `env`。
    - **调用一次，返回多次**：直接调用返回 0；通过 `longjmp` 返回时，返回非 0 值。
- **`longjmp(env, val)`**：
    - 从 `env` 中恢复状态，并跳转回最近一次 `setjmp` 处。
    - **调用一次，永不返回**。

# 虚拟内存 (Virtual Memory, VM)

## 物理和虚拟寻址
### 物理寻址 (Physical Addressing)
- 直接使用物理地址访问。
- 无法实现真正的多任务，无法实现进程间的内存地址隔离。
- 典型设备: **MCU** (低端嵌入式系统)。
### 虚拟寻址 (Virtual Addressing)
- CPU 生成虚拟地址 (VA)，由 **MMU (内存管理单元)** 翻译成物理地址 (PA)。
- 典型设备: **MPU** (智能手机、PC、服务器)。
### VM 的核心作用
- 将虚拟地址翻译成物理地址。
- **作为缓存工具**: 高效使用内存（DRAM 缓存磁盘上的数据）。
- **作为内存管理工具**: 每个进程拥有独立的、简化的地址空间。通过引入虚拟地址与物理地址的映射可以解决三个问题：
    - 每个进程有起始地址相同的私有地址空间。
    - 进程间指令数据代码 and 状态不可互相影响。
    - 地址翻译时检测权限，对内存页界限透明，每一次内存访问都对权限进行检测。
- **作为内存保护工具**: 防止进程破坏其他进程或内核内存。

## 地址空间
### 虚拟地址空间
- 每个进程看到的私有 0 到 $2^N-1$ 的连续地址。
### 物理地址空间
- 实际物理内存的地址。
### 映射关系
- 一个物理地址可能会被多个虚拟地址空间中的地址所映射 (共享)。
- 一个虚拟地址可能被映射到一个物理地址，也可能没有对应的物理地址 (未分配)。

## 虚拟内存作为缓存的工具
### 意义
- 将内存作为下一层存储 (硬盘) 的缓存, 更有效率的使用内存。
### 页 (Page)
- VM 系统的基本单位，通常为 4KB。
- **虚拟页 (VP)**: 虚拟内存中的块。
- **物理页 (PP)**: 物理内存中的块，也叫**页帧 (Page Frame)**。
### 页表 (Page Table)
- 存放在内存中的数据结构，记录 VP 到 PP 的映射。
- **全相联**: 使用页表记录任意虚拟页到任意物理页的映射关系。
- **页表条目 (PTE)**: 包含**有效位**、**权限位**和**物理页号 (PPN)**。
    - 有效位 1: 已缓存 (虚拟地址已分配且加载到内存)。
    - 有效位 0:
        - 未分配: 虚拟地址还未被进程所申请和使用。
        - 未缓存: 虚拟地址已分配但没有加载到内存。
### 虚拟地址访问
- **页命中**: 虚拟页已缓存。
- **缺页 (Page Fault)**: 访问未缓存（有效位为 0）的 VP。
    - 触发缺页异常中断，并由操作系统进行处理。
    - **牺牲页**: 从硬盘加载新页并更新页表, 异常返回后, 重新访问虚拟地址, 进行命中时的处理。
    - 若为未分配状态, 则由操作系统程序终止当前进程运行。
### 工作集 (Working Set)
- 进程在某个时间段内频繁访问的页面集合。
- 如果物理内存小于工作集，会发生**抖动 (Thrashing)**。
- **意义**: 虚拟内存机制使得在较小物理内存下运行较大内存开销的程序成为了可能，虽然性能会因缺页而下降。
### 写策略
- 虚拟内存系统主要采用**回写 (Write-back)** 策略，而非直写 (Write-through)，以减少对磁盘的写入次数。

## 页替换算法
### 算法说明
- 当内存满时，决定哪个页面被换出（牺牲页）。现代 OS 主要采用局部替换策略。

## 简化内存管理
- **主要思想**: 每个进程有独立虚拟地址空间
    - 不同的虚拟地址空间使用不同的页表
    - 每个进程都有一个自己的页表
- **简化了内存申请**: 分配新的虚拟页
- **简化了数据指令在多进程之间共享**
    - 多个空间的虚拟页映射至一个物理页
    - 动态链接库共享
    - 共享内存
- **简化了链接**
    - 链接分配地址时不考虑考虑是否有其他进程冲突
- **简化了加载**
    - 加载器工作时只需将 ELF 代码段和数据段映射至当前进程的虚拟地址空间
    - 加载器不进行数据传输
    - 所有的数据传输都是进入进程的入口地址后, 产生的一系列缺页故障, 在故障处理程序中实现真正的数据传输
## 提供内存保护的机制
### 保护机制说明
- 在 PTE 中设置 R/W/X 和 SUP（特权）位。若违反权限，MMU 触发段错误 (SIGSEGV)。

## 地址翻译 (Address Translation)
### 页表翻译
1. **页表基址寄存器** (存放物理地址, x86 中为 CR3 寄存器)。
2. 根据虚拟页号找到页表条目地址 (**PTEA**)。
3. 根据 PTEA 内容从内存中加载页表条目。
4. 根据页表条目中的 VPN 翻译为 PPN。
### 缺页 (Page Fault)
- 页面没有映射到物理页, 引发缺页故障。
- 故障处理程序完成加载, 重新访问虚拟地址。
### TLB (翻译后备缓冲器)
- 每个虚拟地址访问会先查询内存操作, 性能低。
- 引入一个专用硬件 (TLB), 只缓存页表条目, 以 CPU 为核心。
- Intel 处理器中采用分层级进行组织: TLB -> L1 -> L2 -> 内存。
    - 第一级 TLB 分为数据表缓存和指令表缓存。
    - 第二级 TLB 为统一数据表缓存。
- **TLB 命中**: 直接从 TLB 中获取页表条目, 减少一次内存访问。
- **TLB 未命中**: 从内存中加载页表条目, 同时加载至 TLB。
### 多级页表
- **原因**:
    - 页表必须存在物理内存中。
    - 单一级页表对庞大的虚拟地址空间来说，空间开销过大。
- **解决方案**:
    - 多级页表, 大量虚拟地址未使用, 对应于这些虚拟页的页表项就不需要分配空间。
    - 只将使用的虚拟页所对应的页表分配空间, 极大减少了页表的存储空间开销。
- Intel 处理器（如 x86-64）通常采用 4 级页表。

## 传统内存管理机制: 内存分段管理 (IA-32/Linux)
### 存储地址描述
- 存储地址采用**逻辑地址**、**线性地址**和**物理地址**来进行描述。逻辑地址和线性地址是虚拟地址的两种不同表示形式。
- **逻辑地址**: 48 位，包含 16 位**段选择符**和 32 位**段内偏移量**（有效地址）。
- **线性地址**: 32 位（位数由虚拟地址空间大小决定）。
- **物理地址**: 32 位（位数由存储器总线中的地址线条数决定）。

### 1. 逻辑地址到线性地址的变换 (分段)
分段过程实现将逻辑地址转换为线性地址（早期的，现在兼容，但是不用）。

- **实模式 (Real Mode)**:
    - 早期 8086 处理器，16 位寄存器。
    - **物理访存地址 = (段寄存器 << 4) + 有效地址**。
    - 寻址空间为 1MB ($2^{20}$)。
- **保护模式 (Protected Mode)**:
    - IA-32 处理器（80386 及以后）进入保护模式。
    - **CR0 寄存器**: PE 位是开关（PE=1 为保护模式）。
    - **访存地址为逻辑地址**。

### 2. IA-32 分段机制
- **段描述符 (Segment Descriptor)**: 8 字节数据结构，描述段的属性：
    - **段基址**: 在线性地址下的基地址（32 位）。
    - **限界**: 段的总长度（20 位，配合 G 位可达 4GB）。
    - **DPL**: 段的特权级别 (0-3)。
- **段描述符表 (Descriptor Table)**: 存放在主存中的数组。
    - **全局描述符表 (GDT)**: 系统中所有任务共享。
    - **局部描述符表 (LDT)**: 进程专用的描述符（现代 Linux 已基本不用）。
    - **GDTR**: 全局描述符表寄存器，保存 GDT 的基地址和限界。
- **段选择符 (Segment Selector)**: 16 位，存放在段寄存器（CS, SS, DS, ES, GS, FS）中。
    - **Index (13位)**: 描述符在表中的索引。
    - **TI (1位)**: 0 选择 GDT，1 选择 LDT。
    - **RPL (2位)**: 请求特权级。

### 3. 地址翻译流程 (逻辑地址 -> 线性地址)
1. 通过段寄存器中的 **TI** 位决定在哪个表（GDT/LDT）查找。
2. 根据 **GDTR** 读出段描述符表的首地址。
3. 根据段选择符中的 **Index** 在表中找到对应的**段描述符**。
4. 从段描述符中读出**段基址**，与逻辑地址的**有效地址**相加，得到**线性地址**。

### 4. 存储保护 (基于环保护机制)
- **特权级 (Ring)**: 0-3 环。内核工作在 Ring 0，用户工作在 Ring 3。
- **DPL (Descriptor Privilege Level)**: 目标段的特权级。
- **CPL (Current Privilege Level)**: 当前进程的特权级（通常由 CS.DPL 决定）。
- **RPL (Requested Privilege Level)**: 请求者的特权级。
- **权限检查规则**: `target_descriptor.DPL >= max(CPL, RPL)`。

### 5. 线性地址到物理地址的变换 (分页)
- **CR0 寄存器**: PG 位控制分页（PG=1 开启）。
- **CR3 寄存器**: 保存页目录表的起始物理地址。
- **两级页表**:
    - **页目录索引 (10位)** + **页表索引 (10位)** + **页内偏移 (12位)**。
- **页表项 (PTE) 格式**:
    - **P**: 存在位。
    - **R/W**: 读写位。
    - **U/S**: 用户/系统位。
    - **D**: 脏位。
    - **高20位**: 物理页框号。

## 内存映射 (Memory Mapping)
### 映射方式
- **磁盘上的普通文件** (如：可执行文件或共享库目标文件)。
- **匿名文件** (位于交换空间中)。
	- 匿名文件是由内核创立的，包含的全部是二进制0
	- 在进程中申请内存，会在磁盘上的匿名文件中分配新的空间，在进程执行时与内存之间会发生交换
### 共享对象
- 两个进程的代码可以同时指向同一个物理地址空间。
### 私有对象
- **写时复制 (Copy-On-Write, COW)**:
- 常见于 `fork` 操作, fork 时子进程拷贝父进程所有映射 (代码, 数据, 堆, 栈)。
	- 此时子进程对应的 PTE 标记为**只读**, 内核将该页标记为写时复制。
	- 当任意进程尝试修改数据时, 触发**保护故障异常**。
	- 在保护异常程序中, 将对应页进行**复制**, 打开写权限, **重新执行写指令**, 访问新创建的页。
	- 意义：通过尽量推迟物理复制，降低进程创建开销。
### mmap 系统调用
- 显式创建内存映射。

## 动态内存分配 (Dynamic Memory Allocation)
### 分配器 (Allocator)
- **显式分配器**: `malloc` (分配), `free` (释放)。
- **隐式分配器**: Java 等语言的垃圾收集 (GC)。
- **性能指标**: 吞吐量、峰值内存利用率。
### 碎片 (Fragmentation)
- **内部碎片**: 分配块大于有效载荷（由于对齐要求或分配策略）。
- **外部碎片**: 空闲空间总量足够，但没有足够大的单一块满足请求。
### 隐式空闲链表 (Implicit Free List)
- 使用头部记录块大小 and 分配状态。
    - 有效数据前的数据对齐。
    - 包含块长度信息以连接所有块。
- **搜索空闲块**:
    - 首次适配 (First Fit): 从头开始找第一个。
    - 下次适配 (Next Fit): 从上次搜索结束处开始。
    - 最佳适配 (Best Fit): 找最小的满足要求的。
    - 最差适配 (Worst Fit): 找最大的空闲块。
- **分隔空闲块**: 分配空间小于空闲块时，将剩余部分拆分为新空闲块。
- **空闲块合并**:
    - 立即合并: 释放时立即与相邻空闲块合并。
    - 推迟合并。
    - 合并的四种情况：前空后满、前满后空、前后均满、前后均空。
### 显式空闲链表 (Explicit Free List)
- 在空闲块主体中使用指针连接（通常是双向链表），只维护空闲块列表而不是所有块。
### 分离的空闲链表 (Segregated Free List)
- 每个大小类（Size Class）都有自己的空闲链表。

## 垃圾收集 (Garbage Collection)*
### 概念说明
- 垃圾收集是隐式分配器的一种实现，自动回收不再被程序使用的内存。

## 与内存相关的错误*
### 常见错误
- 间接引用坏指针、读未初始化的内存、允许栈溢出、错位、不当使用指针等。

# 系统级 I/O

## 文件
### 文件概念
- Unix 文件就是一个字节序列。
### 文件类型
- 普通文件（文本/二进制）。
- 目录（包含其他文件信息的特殊文件）。
    - 当前目录 `.`，上一级目录 `..`。
    - 相关命令：`mkdir` (创建), `rmdir` (删除), `ls` (列出内容)。
- 套接字（用于网络通信）。
- 命名管道、符号链接、字符设备、块设备等。
### 目录层次结构
- 以 `/` (根) 开始的树状结构。

## Unix I/O
### 万物皆文件
- 所有的 I/O 设备都被模型化为文件（包括网络、磁盘、终端）。
- 标准输入 0 (STDIN_FILENO)
- 标准输出 1 (STDOUT_FILENO)
- 标准错误 2 (STDERR_FILENO)
### 基本操作
- `open`: 打开文件，返回**文件描述符 (fd)**。
- `close`: 关闭。
- `read/write`: 传输数据。注意**短计数 (Short Counts)**：实际读写的字节数少于请求的字节数（如读到文件末尾或被信号中断）。
- `lseek`: 改变当前文件游标位置。

## RIO (Robust I/O)
### RIO 简介
- CSAPP 提供的包装函数，自动处理短计数，适用于网络等不稳定场景。
### 无缓冲的输入输出
- 直接在内存 and 文件间传输数据。
### 有缓冲的输入
- 提高从文件读取文本行 and 二进制数据的效率。

## 读取文件元数据
### stat/fstat
- `stat`, `fstat`: 获取文件大小、权限、修改时间等元数据。

## 共享文件
### 内核数据结构
- **描述符表**: 进程级，指向打开文件表项。
- **打开文件表**: 系统级，包含当前文件位置、引用计数、指向 v-node 的指针。
- **v-node 表**: 系统级，包含文件类型、大小等静态元数据。
### fork 与文件共享
- `fork` 后，父子进程共享打开文件表项（即共享文件位置）。

## I/O 重定向
### 概念说明
- 控制台命令内容的重定向。
### dup2 系统调用
- 将 `newfd` 复制为 `oldfd` 的副本。常用于将 `stdout` 重定向到文件。

## 标准 I/O
### 常用函数
- `fopen`, `fclose`, `fread`, `fwrite`, `printf`, `scanf`, `fgets`, `fputs` 等。
### 缓冲机制
- **带缓冲**: 提高效率，减少系统调用。
    - 遇到 `\n` (行缓冲，如 stdout)、缓冲区满、调用 `fflush`、`exit` 或 `main` 返回时刷新缓冲区。
    - 标准输入 (stdin) 和标准输出 (stdout) 是带缓冲的。
    - 标准错误 (stderr) 通常是不带缓冲的，以确保错误信息立即显示。

## I/O 函数的选择
### 一般原则
- 尽可能使用最高级别的 I/O 函数（如标准 I/O）。
### 适用场景
- **磁盘 and 终端**: 优先使用标准 I/O。
- **信号处理**: 在信号处理函数 and 极少数需要绝对高性能的情况下使用 Unix I/O。
- **套接字 (Network)**: 访问套接字时可以使用 RIO。标准 I/O 在套接字上有限制（双向流问题）。

# 网络编程

## 客户端-服务器模型
### 基本交互
- 客户端发送请求，服务器处理并返回响应。

## 网络
### 主机视角
- 网络是一个 I/O 设备，作为数据的源 and 接收方。
### 物理角度: 地理远近组成的层次系统
- **局域网 (LAN)**: 如以太网。
    - 48 位物理地址（MAC）。
    - 数据帧：包含头（MAC 地址等）和有效载荷。
    - 桥接以太网 (Bridge Ethernet)：
        - **网桥**: 连接以太网段。
        - **集线器**: 连接主机。
- **广域网 (WAN)**: 通过**路由器**连接不同局域网。
### 路由协议
- 解决了命名机制（IP 地址）、传送机制 and 封装的思想。

## 全球 IP 因特网
### TCP/IP 协议栈
- **IP**: 提供主机到主机的不可靠传输。不可恢复。
- **TCP**: 在 IP 之上提供进程到进程、可靠、全双工、面向字节流的连接。
- **UDP**: 在 IP 之上简单扩展，提供不可靠的数据报传输。
### IP 地址
- 32 位（IPv4）或 128 位（IPv6）。使用**大端 (网络字节序)**。
- 字节序转换函数：`htonl`, `htons`, `ntohl`, `ntohs`。
- **点分十进制表示法**: IP 地址与点分十进制字符串之间的转换函数（如 `inet_pton`, `inet_ntop`）。
### 域名 (DNS)
- 域名系统，提供域名与 IP 的映射。
- 一级域名、二级域名、子域。
- `localhost` (127.0.0.1) 是回送地址。

## 套接字编程 (Sockets)
### 套接字概念
- 连接的端点。由 `IP:Port` 唯一标识。
### 常用操作
- `struct sockaddr_in`: IPv4 套接字地址结构。
- `socket`: 创建描述符。
- `connect`: 客户端发起连接。
- `bind`: 服务器将描述符绑定到本地地址和端口。
- `listen`: 将描述符转为监听状态，准备接受连接。
- `accept`: 服务器等待并接受连接，返回一个新的已连接描述符。
- `getaddrinfo / getnameinfo`: 名字与地址之间的转换，屏蔽 IPv4/IPv6 差异。
### 辅助函数 (CSAPP 实现)
- `open_clientfd`: 建立与服务器的连接。
- `open_listenfd`: 创建监听描述符。

## Web 服务器
### 基础协议
- 超文本传输协议: HTTP
- 超文本标记语言: HTML
### HTTP 协议
- 基于文本的请求-响应协议。
- **HTTP 事务**:
    - **请求**: 请求行（方法、URI、版本）、请求头。
    - **响应**: 响应行（版本、状态码、消息）、响应头、响应主体内容。
### Web 内容
- **MIME 类型**: 标识内容格式（如 `text/html`, `image/gif`）。
- **提供内容的方式**:
    - **静态服务内容**: 服务器直接读取磁盘文件返回。
    - **动态服务内容**: 服务器运行程序并返回其输出。
### URL
- 统一资源定位符。
### 动态服务内容 (CGI)*
- 将程序参数传递给服务器。
- 服务器传递参数给子进程。
- 服务器将其他信息传递给子进程。
- 子进程将输出重定向返回给客户端。

# 并发编程 (Concurrent Programming)

## 基于进程的并发
### 特点说明
- 实现简单、进程创建开销大、进程间通信难度大。

## 基于事件的并发*
### 特点说明
- I/O 多路复用 (select / epoll)。
- 手动实现控制流的交错，并发粒度不好掌握，实现复杂。

## 线程并发
### 线程执行模型
- **线程内存模型**:
    - 独立的线程上下文: ID、栈、栈指针、程序计数器、条件码、通用寄存器。
    - 共享进程上下文的剩余部分: 虚拟地址空间、打开文件的集合。
- **注意**: 每个线程的栈不受保护，其他线程可以访问，易发生变量共享。
### Pthreads 库
- `pthread_create` (创建), `pthread_exit` (终止), `pthread_join` (回收), `pthread_detach` (分离), `pthread_once` (初始化)。
### 临界资源与同步
- **共享变量**: 被多个线程引用的虚拟内存变量。
- **临界区 (Critical Section)**: 访问共享变量（临界资源）的代码段。
- **信号量 (Semaphores)**: 非负整数计数器，提供 P/V 操作。
    - **P(s)**: `s = s - 1`；若 `s < 0` 则线程挂起。
    - **V(s)**: `s = s + 1`；唤醒一个等待线程。
- **互斥锁 (Mutex)**: 二进制信号量 (0 或 1)，用于保护临界区，实现互斥。
- **计数信号量**: 用于控制同时访问某资源的线程数量（如生产者-消费者缓冲区）。

## 经典同步问题
### 生产者-消费者
- 缓冲区同步。应用案例：基于预线程化的网络服务器。
### 读者-写者
- 允许多个读者同时读，但写者必须独占访问。

## 并发中的坑
### 线程安全
- 函数在并发调用时能正确运行。
### 可重入性 (Reentrancy)
- 函数不访问共享数据（通常是线程安全的子集）。
### 竞争 (Race)
- 结果取决于线程执行的顺序。
### 死锁 (Deadlock)
- 线程互相等待对方释放资源。**预防**: 总是以相同的顺序获取锁。
