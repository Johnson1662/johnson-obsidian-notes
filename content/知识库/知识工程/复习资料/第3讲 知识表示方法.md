## 1. 语义网络（P5-P7）

语义网络：

- 用有向网络结构表示概念之间的语义关系。
- 1956 年，剑桥语言研究中心的计算语言学家 R. H. 里琴斯提出，用于自然语言机器翻译的中间语言。
- 1963 年，R. F. 西蒙斯和 S. 克莱因基于一阶谓词逻辑实现语义网络。
- 1963 年，系统开发公司的 M. 奎利安在 SYNTHEX 项目中实现语义网络。
- 1980 年代末，荷兰格罗宁根大学和特文特大学发起“知识图谱”研究项目，实际上是一种边上有约束的语义网络。
- 语义网络与后来知识图谱的概念边界逐渐模糊，2012 年谷歌推出“知识图谱”。

PPT 中的 波菲利之树：

> 已知最早的语义网络由古希腊哲学家波菲利于公元 3 世纪在亚里士多德《范畴篇》的注释中绘制。

PPT 原图：

![[assets/5aa5e4600716bcdce4768540200d5ccb2877078ae492ad5fc8ca7ddf2ca86e12.jpg]]

PPT 中的 KL-ONE 网络：

- 伍兹 1975 年提出，布拉克曼 1979 年在 KL-ONE 系统中实现。
- 描述逻辑至少包含 波菲利之树 的特征，通常还加入各种扩展。
- 角色箭头 目标端的 `/` 表示 值限制。

PPT 原图：

![[assets/d9379737ac8c4757fe05fee9650b466bbcc952fa419347996e5c2d1d6e8cc553.jpg]]

### 通俗解释

语义网络把概念画成节点，把概念之间的关系画成有向边。它适合表达“是一种”“部分-整体”“具有某属性”等关系，是知识图谱和描述逻辑的重要前身。

### 常见考法：

- 解释什么是语义网络。
- 给一组概念和关系，画语义网络。
- 问 波菲利之树 和 KL-ONE 的意义。
- 比较语义网络和知识图谱。

### 易错点 / 答题模板

> 语义网络是一种用有向图表示知识的方法，其中节点表示概念或对象，边表示概念之间的语义关系。它强调概念层次、属性关系和继承机制，是后续知识图谱和描述逻辑的重要基础。

## 2. 框架（P8-P9）

框架由 马文·明斯基 于 1974 年在论文《《知识表示框架》》中最早提出。

核心思想：

- 框架是表示常规情景（典型情景）的信息结构。
- 人类对世界的认知基于过往经验和常规情景。
- 对新事物的认识是对以往经验的分析与补充。
- 框架是一种描述对象属性的数据结构，具有槽（槽）和侧面（侧面）。

槽和侧面：

- 槽：表示某个属性。
- 侧面：表示属性的不同方面。
- 一个框架可以有任意数目的槽。
- 每个槽可以有任意数目的侧面。
- 每个侧面可以有任意数目的值。

通用形式：

| 槽名 | 侧面名 | 值 |
| --- | --- | --- |
| 槽名 A | 侧面名 A1 | 值 A11, A12, ..., A1n |
| 槽名 A | 侧面名 A2 | 值 A21, A22, ..., A2n |
| 槽名 B | 侧面名 B1 | 值 B11, B12, ..., B1n |
| 槽名 B | 侧面名 B2 | 值 B21, B22, ..., B2n |

### 示例：表示“男孩”的框架

| 槽 | 值 | 类型 |
| --- | --- | --- |
| BOY（男孩） | - | 框架名 |
| ISA | 人 | 父框架 |
| SEX | 男性 | 实例值 |
| AGE | 小于 12 岁 | 过程附件/集合约束 |
| HOME | 某一地点 | 另一框架 |
| NUM_LEGS | 默认值 = 2 | 从父框架“人”继承的默认值 |

### 示例：表示一个名为亚历克斯的男孩

| 槽 | 值 | 类型 |
| --- | --- | --- |
| ALEX | - | 框架名 |
| NAME | 亚历克斯 | 关键值 |
| ISA | 男孩 | 父框架 |
| SEX | 男性 | 继承值 |
| AGE | 需要时：用当前日期减去出生日期 | 过程附件 |
| HOME | 主街 100 号 | 实例值 |
| BIRTHDATE | 8/4/2000 | 实例值 |
| FAVORITE_FOOD | 意大利面 | 实例值 |
| CLIMBS | 树 | 实例值 |
| BODY_TYPE | 瘦而结实 | 实例值 |
| NUM_LEGS | 1 | 例外 |

PPT 说明：

- 亚历克斯是 BOY 框架的一个实例。
- `SEX` 槽从父框架继承默认值。
- `NUM_LEGS` 默认值是 2，但亚历克斯的值是 1，这是例外。
- `AGE` 槽通过 IF-NEEDED 过程附件在需要时计算。

### 通俗解释

框架像一个对象模板。父框架提供默认属性，实例可以继承默认值，也可以覆盖默认值，还可以在某些槽上挂接计算过程。

### 常见考法：

- 解释 槽、侧面、默认值、继承、过程附件。
- 给对象描述，设计框架。
- 问亚历克斯示例中哪些是继承值、默认值、例外、过程附件。

### 易错点

- 默认值可以被实例覆盖。
- IF-NEEDED 是过程附件，不是普通静态值。
- `ISA` 表示父框架或类属关系。

## 3. 产生式系统（P10-P12）

产生式系统：

- 由一组关于行为的规则组成。
- 这些规则称为产生式（产生式）。
- 用于自动规划与调度、专家系统和动作选择中的基础知识表示形式。
- 产生式由两个部分组成：
  - 感知前提 / IF 语句。
  - 动作 / THEN 语句。

触发与触发成功：

- 如果某条产生式的前提与当前世界状态相匹配，则称该产生式被触发（被触发）。
- 如果某条产生式的动作被执行，则称它触发成功（被执行）。

产生式系统通常还包括：

- 数据库 / 工作记忆（工作记忆）：维护当前状态或当前知识。
- 规则解释器（规则解释器）。

规则解释器通常执行前向链（前向链）：

- 将每条规则的条件部分 左部 与工作记忆中的当前状态匹配。
- 被触发的条件对应动作 右部 会更新工作记忆。
- 更新方式包括添加或移除数据。

停止条件：

- 用户中断前向链循环。
- 已经执行给定数量循环。
- 执行了 `halt` 操作。
- 没有任何规则前提可被满足。

### 示例：字符串反转产生式系统

PPT 使用一组产生式规则反转字符串，字符串字母表不包含 `$` 和 `*`，因为这两个符号用作标记。

规则测试按规则列表顺序进行；每条规则从左到右用滑动窗口检查输入字符串，找到匹配后用 右部 替换 左部。替换后从规则 P1 重新开始。

PPT 中规则大意：

```text
P1: $$ -> *
P2: *$ -> *
P3: *x -> x*
P4: * -> null & halt
P5: $xy -> y$x
P6: null -> $
```

字符串 `"ABC"` 的转换最终得到：

```text
ABC -> CBA
```

PPT 中展示了包含 P1-P6 的多步推导过程，核心目的是说明：

- 产生式规则可通过模式匹配和替换改变工作记忆。
- 规则顺序会影响执行流程。
- 触发后的动作会更新状态。

### 示例：OPS5 产生式规则

```text
(p Holds::Object-Ceiling
{(goal ^status active ^type holds ^objid <01>) <goal>}
{(physical-object
^id <01>
^weight light
^at <p>
^on ceiling) <object-1>}
{(physical-object ^id ladder ^at <p> ^on floor) <object-2>}
{(monkey ^on ladder ^holds NIL) <monkey>}
-(physical-object ^on <01>)
-->
(write (crlf) Grab <01> (crlf))
(modify <object1> ^on NIL)
(modify <monkey> ^holds <01>)
(modify <goal> ^status satisfied)
)
```

PPT 解释：

- 数据结构名如 `goal`、`physical-object` 出现在条件的第一个字面量。
- 字段用 `^` 标识。
- `-` 表示负条件。
- 变量绑定来自 左部 模式匹配，并在 右部 中使用。
- 工作记忆中的 `goal` 数据结构用于控制目标。
- 当猴子抓到天花板上的物体后，目标状态被设为 `satisfied`，规则不再适用。

### 通俗解释

产生式系统就是“如果条件成立，就执行动作”。它维护一个工作记忆，规则不断匹配当前状态，触发后修改状态，直到没有规则可执行或达到停止条件。

### 常见考法：

- 解释 左部、右部、工作记忆、被触发、被执行。
- 根据规则和初始状态推导执行结果。
- 解释 OPS5 中负条件、变量绑定、冲突集和目标状态更新。

### 易错点 / 答题模板

> 产生式系统由规则库、工作记忆和规则解释器组成。每条规则形如 IF 条件 THEN 动作。规则解释器将 左部 与工作记忆匹配，若匹配则触发规则，执行 右部 更新工作记忆。它常使用前向链进行推理。

## 4. 逻辑程序设计 逻辑程序设计（P13-P21）

逻辑程序设计：

- 一种编程范式（范式）。
- 通过设置答案须符合的规则来解决问题，而不是直接设置解决步骤。
- 一个逻辑程序由一组逻辑形式的句子组成，表示某个问题领域的知识。
- 通过对这些知识应用逻辑推理来执行计算。

主要逻辑程序设计语言：

- Prolog。
- ASP（答案集编程）。
- Datalog。

规则形式：

```prolog
A :- B1, ..., Bn.
```

含义：

- 要解决 `A`，需要先解决 `B1` 到 `Bn`。
- 声明式读法：A 如果 B1 且 ... 且 Bn。
- `A` 是规则头部（头实体）。
- `B1, ..., Bn` 是规则体。
- 每个 `Bi` 是文字（字面值）或条件（条件）。
- 当 `n = 0`，该规则是事实（事实）。

查询形式：

```prolog
?- B1, ..., Bn.
```

### 示例：亲属关系

```prolog
mother_child(elizabeth, charles).
father_child(charles, william).
father_child(charles, harry).

parent_child(X, Y) :-
    mother_child(X, Y).

parent_child(X, Y) :-
    father_child(X, Y).

grandparent_child(X, Y) :-
    parent_child(X, Z),
    parent_child(Z, Y).
```

查询与答案：

```prolog
?- parent_child(X, william).
X = charles
```

```prolog
?- grandparent_child(X, william).
X = elizabeth
```

```prolog
?- grandparent_child(elizabeth, Y).
Y = william;
Y = harry.
```

```prolog
?- grandparent_child(X, Y).
X = elizabeth, Y = william;
X = elizabeth, Y = harry.
```

```prolog
?- grandparent_child(william, harry).
no
```

```prolog
?- grandparent_child(elizabeth, harry).
yes
```

### 负条件与非单调逻辑

定义兄弟姐妹关系用到负条件：

```prolog
sibling(X, Y) :-
    parent_child(Z, X),
    parent_child(Z, Y),
    not(X = Y).
```

PPT 结论：

- 包含负条件的逻辑程序语言具有非单调逻辑（非单调逻辑）的知识表示能力。

### 算法 = 逻辑 + 控制

PPT 原内容：

$$
\mathrm{Algorithm}=\mathrm{Logic}+\mathrm{Control}
$$

含义：

- 逻辑程序可视为目标-子目标的反向推理过程。
- 将逻辑（知识的声明式表示）与控制（求解搜索策略）结合并实现算法。
- 同一逻辑表示可以应用不同求解策略，得到不同算法。
- 改变逻辑表示，也可在相同求解策略下生成不同算法。

两种主要问题求解策略：

| 策略 | 方向 | 应用 |
| --- | --- | --- |
| 反向推理 / 目标规约 | 目标 → 数据，自顶向下 | Prolog |
| 正向推理 正向推理 | 数据 → 目标，自底向上 | 专家系统 |

### 逻辑程序设计用于知识表示：法律例子

PPT 使用《中华人民共和国国籍法》第 4 条：

> 父母双方或一方为中国公民，本人出生在中国，具有中国国籍。

形式化例子：

```prolog
initiates(birth(Person), citizen(Person, China)) :-
    time_of(birth(Person), Time),
    place_of(birth(Person), China),
    parent_child(Another_Person, Person),
    holds(citizen(Another_Person, China), Time).
```

PPT 说明：

- 法律条文逻辑性较强，适合用逻辑程序设计形式化表达。
- 早期 AI+法律案例：英国《国籍法》被编码为逻辑程序。
- 论文《《作为逻辑程序的英国国籍法》》（1986）是 AI+法律领域里程碑。

### Datalog

Datalog：

- Prolog 的一个子集。
- 一种数据库定义语言。
- 将关系型数据库视角与逻辑程序设计结合。
- 用逻辑连结符在规则体中直接定义数据库关系。
- 适合表达递归查询。

PPT 说明：

- 关系代数或关系演算难以表达递归查询。
- 极小不动点（最小不动点算子）可以解决。
- 逻辑程序可自然表达递归关系，无需额外逻辑运算符。

Datalog 与更通用逻辑程序设计的区别：

- 只能使用常量和变量作为项。
- 所有事实都是无变量的。
- 规则受限制，自底向上执行会生成无变量的新事实。

PPT 示例：

```prolog
mother_child(elizabeth, charles).
father_child(charles, william).
father_child(charles, harry).

parent_child(X, Y) :-
    mother_child(X, Y).

parent_child(X, Y) :-
    father_child(X, Y).

ancestor_descendant(X, Y) :-
    parent_child(X, Y).

ancestor_descendant(X, Y) :-
    ancestor_descendant(X, Z),
    parent_child(Z, Y).
```

自底向上执行可推出：

```prolog
parent_child(elizabeth, charles).
parent_child(charles, william).
parent_child(charles, harry).
ancestor_descendant(elizabeth, charles).
ancestor_descendant(charles, william).
ancestor_descendant(charles, harry).
ancestor_descendant(elizabeth, william).
ancestor_descendant(elizabeth, harry).
```

### ASP：答案集编程

ASP：

- 与 Datalog 类似。
- 非图灵完备。
- 将所有子句与目标整体视为一个问题。
- 通过生成稳固模型（稳定模型）求解。

地图着色简化例子：

```prolog
country(oz).
country(iz).
adjacent(oz, iz).

colour(C, red) :-
    country(C),
    not(colour(C, green)).

colour(C, green) :-
    country(C),
    not(colour(C, red)).
```

如果不限制相邻国家颜色，有四个稳定模型：

```prolog
country(oz). country(iz). adjacent(oz, iz). colour(oz, red). colour(iz, red).
country(oz). country(iz). adjacent(oz, iz). colour(oz, green). colour(iz, green).
country(oz). country(iz). adjacent(oz, iz). colour(oz, red). colour(iz, green).
country(oz). country(iz). adjacent(oz, iz). colour(oz, green). colour(iz, red).
```

加入约束：相邻国家不能相同颜色。

```prolog
:- country(C1), country(C2), adjacent(C1, C2),
   colour(C1, X), colour(C2, X).
```

这里 `:- 规则体` 是约束，会排除 规则体 为真的模型。

剩两个解：

```prolog
country(oz). country(iz). adjacent(oz, iz). colour(oz, red). colour(iz, green).
country(oz). country(iz). adjacent(oz, iz). colour(oz, green). colour(iz, red).
```

### 通俗解释

逻辑程序设计把知识写成事实和规则，再让系统通过逻辑推理找答案。它更像“描述问题满足什么条件”，而不是写一步步算法。

### 常见考法：

- 写出规则 `A :- B1, ..., Bn` 的含义。
- 根据 Prolog 程序回答查询结果。
- 比较 正向推理 和 反向推理。
- 解释 Datalog 为什么适合递归查询。
- 解释 ASP 中约束 `:- 规则体` 的作用。

### 易错点

- Prolog 查询中的变量大写，如 `X`、`Y`。
- `not(X = Y)` 是负条件。
- ASP 中约束没有规则头，用来排除模型。

## 5. 专家系统（P22-P26）

专家系统：

- 一类具有专门知识和经验的计算机智能程序系统。
- 采用人工智能中的知识表示和知识推理技术，模拟通常由领域专家才能解决的复杂问题。

核心公式：

$$
\mathrm{ES}=\mathrm{KB}+\mathrm{IE}
$$

其中，ES 表示专家系统，KB 表示知识库，IE 表示推理机。

专家系统必须具备三要素：

1. 领域专家级知识。
2. 模拟专家思维。
3. 达到专家级水准。

PPT 原图：

![[assets/097a22cb71fbf870d033b8b142f9c3a0207a892d46a7e82cbcdcb8d328182df0.jpg]]

专家系统通常分为两个子系统：

- 知识库（知识库）：存储事实与规则。
- 推理引擎（推理引擎）：将规则应用于已知事实以推导新事实，并可包含解释和调试功能。

历史：

- 专家系统是第一批真正成功的人工智能应用系统。
- 诞生于 20 世纪 70 年代，80 年代大量涌现。
- 医学领域系统包括 MYCIN、Internist-I、CADUCEUS。
- 正式意义专家系统于 1965 年由 斯坦福启发式编程项目 提出。
- 爱德华·费根鲍姆是项目领军人物，被称为“专家系统之父”，1994 年图灵奖得主。

费根鲍姆的观点：

> 智能系统的强大之处来源于其所拥有的知识，而非其使用的形式主义或推理机制。

PPT 还提到：

- Dendral：有机分子识别。
- Mycin：传染病诊断。
- SID：用于大型产品设计。

应用类型（海耶斯-罗斯）：

| 类别 | 所解决的问题 | 示例 |
| --- | --- | --- |
| 解释 | 从传感器数据中推断情境描述 | Hearsay、PROSPECTOR |
| 预测 | 推断给定情境可能后果 | 早产风险评估 |
| 诊断 | 根据观测推断系统故障 | CADUCEUS、MYCIN、PUFF |
| 设计 | 在约束条件下配置对象 | Dendral、R1、SID |
| 规划 | 设计行动 | 自主水下航行器任务规划 |
| 监测 | 对比观测和计划，识别异常 | REACTOR |
| 调试 | 针对复杂问题提供增量式解 | SAINT、MATHLAB、MACSYMA |
| 修复 | 实施补救计划 | 有毒物泄漏危机管理 |
| 教学 | 诊断、评估并纠正学生行为 | 智能临床训练 |

## 6. 知识图谱嵌入（P4-P13）

知识图谱嵌入（KGE），也叫知识表示学习（KRL）。

定义：

> 一个基于机器学习的任务，旨在在保持语义意义（语义意义）的同时，将知识图谱中的实体和关系学习到低维向量表示中。

PPT 原图：

![[assets/e7dd09bcd6e16f07bd88ff3f36f7185e72915e4743dd54f17b390498841f854f.jpg]]

可执行的应用：

- 链接预测（链接预测）。
- 三元组分类（三元组分类）。
- 实体识别（实体识别）。
- 聚类（聚类）。
- 关系抽取（关系抽取）。

### 知识图谱形式

知识图谱由实体、关系和事实组成：

$$
G=\{E,R,F\}
$$

其中：

- $E$：实体集合。
- $R$：关系集合。
- $F$：事实集合。

一个事实表示为三元组：

$$
(h,r,t)\in F
$$

含义：

- $h$：头实体（头实体）。
- $r$：关系（关系）。
- $t$：尾实体（尾实体）。

实际应用中直接使用知识图谱的问题：

- 数据稀疏（数据稀疏），如邻接矩阵表示很稀疏。
- 高计算开销（计算效率低）。

### KGE 函数

知识图谱嵌入是一个函数：

- 将每个实体映射为给定维度的向量。
- 将每个关系也映射为给定维度的向量。
- 维度称为嵌入维度（嵌入维度）。

一个 KGE 主要由四个方面刻画：

1. 表示空间（表示空间）：实体和关系嵌入后的低维空间。
2. 打分函数（打分函数）：评价某个三元组是否合理。
3. 编码模型（编码模型）：定义实体和关系嵌入如何交互或结合。
4. 附加信息（附加信息）：用于丰富嵌入表示的额外信息。

### 嵌入过程

所有创建 KGE 的算法大体流程：

1. 将嵌入向量随机初始化。
2. 利用训练集三元组多次迭代优化向量。
3. 每次迭代从训练集中采样一个 批次。
4. 对部分三元组做 破坏，即用错误实体替换头或尾，构造假三元组。
5. 将正例三元组和破坏后的负例三元组共同训练，优化打分函数。
6. 达到停止条件后终止。

PPT 伪代码：

```text
算法：计算实体和关系嵌入
输入：
  训练集 S = {(h, r, t)}
  实体集合 E
  关系集合 R
  嵌入维度 k
输出：
  实体和关系的嵌入向量

初始化：
  随机初始化实体 e 和关系 r 的嵌入向量

while 未满足停止条件 do
  S_batch <- sample(S, b)
  for each (h, r, t) in S_batch do
    (h', r, t') <- sample(S')      // 破坏后的负例事实
    T_batch <- T_batch ∪ {((h, r, t), (h', r, t'))}
  end for
  通过最小化损失函数更新嵌入向量
end while
```

### 评估指标

用于衡量模型学得的嵌入质量。

$Q$：模型预测项排序编号的集合。

Hits@K：

$$
\text{Hits@K}=\frac{|\{q\in Q:q<K\}|}{|Q|}\in[0,1]
$$

含义：

- 正确答案出现在前 K 个预测项中的概率。
- 常用 K=10。
- 越大越好。

平均排名（MR）：

$$
MR=\frac{1}{|Q|}\sum_{q\in Q}q
$$

含义：

- 正确答案平均排名。
- 越小越好。

平均倒数排名（MRR）：

$$
MRR=\frac{1}{|Q|}\sum_{q\in Q}\frac{1}{q}\in[0,1]
$$

含义：

- 对正确答案排名取倒数再平均。
- 排名越靠前，倒数越大。
- 越大越好。

### 应用

机器学习任务：

1. 知识图谱补全（KGC）：
   - 实体预测。
   - 关系预测。
2. 三元组分类（三元组分类）：
   - 判断给定三元组真假。
   - 通常基于模型得分设置阈值。
3. 聚类（聚类）：
   - 将稀疏图谱中的相似语义实体聚到低维向量空间附近。

现实应用：

- 推荐系统：减少对大量用户反馈数据的依赖。
- 药物重定位：发现已有药物与新疾病之间的潜在联系。
- 社会网络分析。

### 通俗解释

KGE 把“符号化实体和关系”变成向量。向量可用于机器学习模型，也能通过距离、相似度、打分函数判断三元组是否可能为真。

### 常见考法：

- 写出 KGE 定义。
- 解释 $(h,r,t)$。
- 说明 KGE 的四个组成方面。
- 写出训练流程：初始化、正样本、负采样、损失优化。
- 比较 Hits@K、MR、MRR。

### 易错点

- MR 越小越好。
- Hits@K 和 MRR 越大越好。
- 破坏 是构造负例，不是修改真实图谱。

## 7. 几何模型（P15）

模型主要分类：

- 张量分解模型：如 RESCAL。
- 几何模型：如 TransE。
- 深度学习模型：如 ConvE。

几何模型：

> 该类方法把关系视作在几何空间上的变换：要得到 尾实体 的嵌入，就对 头实体 的嵌入施加某个几何变换，然后用距离函数衡量三元组可行性。

平移类（平移类）模型：

- 基于“平移不变性”思想。
- 代表模型：TransE。

### 通俗解释

几何模型把关系当作向量空间中的几何操作。对于 TransE，关系就是从头实体向量指向尾实体向量的“平移”。

### 常见考法：

- 问 KGE 模型分类。
- 解释几何模型的核心思想。
- 问 TransE 为什么属于几何模型/平移模型。

### 易错点

几何模型不是直接用图结构规则推理，而是用向量空间中的距离或变换来判断三元组合理性。

## 8. TransE 模型（P16-P20）

TransE 由博尔德斯等人于 2013 年提出。

核心思想：

$$
h+r\approx t
$$

PPT 原图：

![[assets/8dbb38c90a96b76eacc4a0521b79a1d470862549a020b09817968ff7d5b3146c.jpg]]

例子：

```text
(北京, isCapitalOf, China)
```

北京 不再只是离散符号，而是连续空间中的低维向量，例如：

```text
[0.01, 0.04, 0.8, 0.32, 0.09, 0.18]
```

向量维度无统一标准，一般取 50 到 200。

目标：

- 学得所有实体和关系的嵌入。
- 正确三元组满足 $h+r\approx t$。
- 错误三元组不满足。
- 从实体 $h$ 出发，通过“平移”关系 $r$，应到达实体 $t$ 附近。

### 打分函数 / 距离函数

TransE 将实体和关系映射到同一向量空间：

$$
h,r,t\in\mathbb{R}^d
$$

若三元组 $(h,r,t)$ 为真，则：

$$
h+r\approx t
$$

距离函数：

$$
d(h+r,t)=
\begin{cases}
\|h+r-t\|_1, & \mathrm{L1} \\
\|h+r-t\|_2, & \mathrm{L2}
\end{cases}
$$

希望：

- 正例三元组距离越小越好。
- 负例三元组距离越大越好。

### 目标函数与训练方式

PPT 原内容：

TransE 采用基于边际的损失函数（边际损失）。

训练样本：

- 正例三元组：$(h,r,t)$。
- 负例三元组：通过替换头实体或尾实体生成：

$$
(h',r,t),\qquad (h,r,t')
$$

目标函数：

$$
L=\sum_{(h,r,t)\in S}\sum_{(h',r,t')\in S'}
\left[\gamma+d(h+r,t)-d(h'+r,t')\right]_+
$$

其中：

- $S$：训练集中的正例三元组集合。
- $S'$：与正例对应的负例三元组集合。
- $\gamma$：边际，控制正例和负例之间距离差异。
- $d(\cdot)$：距离度量，L1 或 L2。
- $[x]_+=\max(0,x)$。

目标函数含义：

- 对每个正例 $(h,r,t)$，希望 $d(h+r,t)$ 足够小。
- 对对应负例，希望 $d(h'+r,t')$ 更大。
- 希望负例距离至少比正例距离大 $\gamma$。
- 如果达不到，就产生损失，驱动模型训练。

优化方法：

- 随机梯度下降（SGD）或其变体。
- 更新实体向量和关系向量。

### TransE 算法伪代码

PPT 原内容：

```text
算法 1：学习 TransE
输入：
  训练集 S = {(h, l, t)}
  实体集合 E 和关系集合 L
  边际 γ
  嵌入维度 k

1: 对每个 l ∈ L，初始化 l <- uniform(-6/sqrt(k), 6/sqrt(k))
2: 对每个 l ∈ L，归一化 l <- l / ||l||
3: 对每个实体 e ∈ E，初始化 e <- uniform(-6/sqrt(k), 6/sqrt(k))
4: loop
5:   对每个实体 e ∈ E，归一化 e <- e / ||e||
6:   S_batch <- sample(S, b)
7:   T_batch <- ∅
8:   for (h, l, t) ∈ S_batch do
9:       (h', l, t') <- sample(S'_(h,l,t))
10:      T_batch <- T_batch ∪ {((h,l,t), (h',l,t'))}
11:  end for
12:  按照下式更新嵌入向量：
     Σ [γ + d(h + l, t) - d(h' + l, t')]_+
13: end loop
```

补充说明：

- 实体和关系向量随机初始化。
- 通常使用均匀分布或正态分布。
- 对实体向量进行归一化，防止训练中范数过大。
- 学习率过大可能导致数值不稳定，过小会收敛缓慢。

### TransE 优点

PPT 原内容：

1. 模型简单、易实现。
2. 使用向量平移的直观思想。
3. 参数量少，训练速度快。
4. 是最早的平移模型，对后续平移模型有启发作用。
5. 可扩展性强，对大规模知识图谱相对容易训练。
6. 解释性较好，可直观解释实体关系。

### TransE 缺点

PPT 原内容：

难以建模复杂关系。

对称关系：

例如 `配偶`。若：

$$
h+r\approx t,\qquad t+r\approx h
$$

会迫使 $h\approx t$，导致实体难以区分。

一对多 / 多对一关系：

若：

$$
h+r\approx t_1,\qquad h+r\approx t_2
$$

则需要：

$$
t_1\approx t_2
$$

导致多个尾实体向量无法区分。

嵌入空间限制：

- 所有关系共享同一向量空间。
- 难以表达不同关系对实体的异质性影响。

### 通俗解释

TransE 把关系看成“向量平移”。如果 `(北京, 首都, 中国)` 是真，那么“北京向量 + 首都关系向量”应该接近“中国向量”。

### 常见考法：

- 写出 TransE 核心公式 $h+r\approx t$。
- 写出距离函数 L1/L2。
- 写出 边际损失。
- 解释负采样。
- 说明 TransE 优缺点，尤其是一对多、多对一、对称关系问题。

### 易错点 / 答题模板

> TransE 将实体和关系映射到同一低维向量空间。对于真实三元组 $(h,r,t)$，希望 $h+r$ 接近 $t$；对于负例，希望距离更大。训练时通过替换头或尾实体构造负样本，并使用 边际损失 让正例距离小于负例距离至少一个边际 $\gamma$。
