# Part 1：经典知识表示方法

## 一、知识表示的五大角色

### 什么是知识表示（Knowledge Representation）？

**定义**：知识表示(KR)是一种用来捕捉、存储和利用知识的符号形式

### 知识表示的五大角色（Davis, MIT AI Lab）

知识表示不仅仅是数据结构，它在系统中扮演多重角色：

#### 角色 I：代理（A Surrogate）

**概念**：知识表示是真实世界事物的替代品

**特点**：

- 用符号来代表现实中的实体、属性和关系
- 使计算机能够推理和推断现实世界的特性

**示例**：

```
"北京是中国的首都"
→ 符号表示 (Beijing, isCapitalOf, China)
→ 计算机可以基于这个符号进行推理
```

#### 角色 II：本体论承诺（A Set of Ontological Commitments）

**概念**：知识表示做出关于世界结构的基本假设

**重点**：

- 定义什么是实体、属性、关系
- 明确各类知识之间的层级关系
- 确定推理规则

**示例**：

```
医学领域的本体承诺：
- 病人、医生、病症都是不同类型的实体
- "患者患病"是一种关系
- "疾病有症状"是另一种关系
```

#### 角色 III：智能推理的碎片理论（A Fragmentary Theory of Intelligent Reasoning）

**概念**：知识表示体现了关于推理过程应该如何进行的假设

**关键点**：

- 不同表示方法对应不同的推理机制
- 表示形式影响推理的效率和准确性
- 好的表示应该使困难问题变得易处理

#### 角色 IV：高效计算的媒介（A Medium for Efficient Computation）

**概念**：知识表示应该支持高效的计算

**目标**：

- 减少计算复杂度
- 利用问题的结构特性加速推理
- 避免不必要的计算开销

#### 角色 V：人类表达的媒介（A Medium of Human Expression）

**概念**：知识表示应该易于人类理解和表达

**要求**：

- 表示形式应该直观、易读
- 便于知识的获取和维护
- 支持人机交互

## 二、语义网络（Semantic Network）

### 2.1 什么是语义网络？

**定义**：语义网络是一种用节点和边来表示知识的图形化表示方法

**基本构成**：

- **节点**：代表概念、对象或属性
- **边**：代表概念或对象之间的关系

**特点**：

- 直观易理解
- 易于可视化
- 自然反映认知结构

### 2.2 语义网络的历史发展

| 时期       | 人物/组织                        | 事件                                 | 贡献     |
| ---------- | -------------------------------- | ------------------------------------ | -------- |
| **1956年** | Cambridge Language Research Unit | R.H. Richens提出中间语言             | 奠定基础 |
| **1963年** | R.F. Simmons, S. Klein           | 系统开发公司的M. Quillian提出SYNTHEX | 早期系统 |
| **1963年** | 系统开发公司                     | 引入语义网络概念                     | 正式命名 |
| **1980年** | Groningen, Twente                | 提出"知识图"概念                     | 概念演进 |
| **2012年** | Google                           | 推出"Knowledge Graph"                | 现代应用 |

### 2.3 Porphyry的分类树

**历史背景**：

- 最古老的已知语义网络
- 由希腊哲学家Porphyry在公元3世纪创作
- 他的亚里士多德范畴论的注释中

**重要性**：

- 尽管年代久远，仍代表现代所有层级结构的核心
- 用于定义概念类型的分类体系
- 影响了现代知识表示系统

**示例** - 生物分类：

```
生物体
  ├─ 有生命
  │   ├─ 动物
  │   │   ├─ 脊椎动物
  │   │   │   ├─ 哺乳动物
  │   │   │   │   └─ 人类
  │   └─ 植物
  └─ 无生命
```

### 2.4 KL-ONE网络

**背景**：

- Woods (1975) 提出的方法
- Brachman (1979) 在名为 KL-ONE 系统中实现
- **KL-ONE** = Knowledge Language One

**核心特性**：

- 基于描述逻辑 (Description Logic)
- 包含Porphyry分类树的全部特征
- 通常添加各种扩展功能

**关键符号**：

- **v/r**：价值限制(Value Restriction)，表示在角色(role)末端的限制
- 用于约束属性值的类型

**影响**：

- 为现代本体论奠定基础
- 启发了OWL(Web Ontology Language)的发展

## 三、框架（Frame）

### 3.1 框架理论

**创立者**：Marvin Minsky (1974)
**论文**：《A Framework for Representing Knowledge》

**核心思想**：

- 人类的知识是以"框架"或"模板"的形式组织的
- 框架代表一种典型情景(stereotyped situation)
- 包含该情景的标准属性和关系

### 3.2 框架的基本结构

#### 主要成分

| 成分           | 说明            | 示例                   |
| -------------- | --------------- | ---------------------- |
| **Frame Name** | 框架名称        | "Person"（人）         |
| **Slot**       | 槽位/属性       | name, age, nationality |
| **Facet**      | 面向/属性修饰符 | default, type, range   |

#### 框架表示示例

**例1：Person框架**

```
Frame: Person
├── Slot: name
│   ├── Facet: type = String
│   ├── Facet: default = "Unknown"
│   └── Facet: comment = "Person's name"
├── Slot: age
│   ├── Facet: type = Integer
│   ├── Facet: range = 0-150
│   └── Facet: default = 0
└── Slot: nationality
    ├── Facet: type = String
    └── Facet: default = "Unknown"
```

### 3.3 框架的高级特性

#### 1. 默认值（Default Values）

**概念**：当某个槽位没有指定值时，使用默认值

```
Frame: Student
├── Slot: tuition_status
│   └── Default: "unpaid"  ← 新学生默认未交学费
└── Slot: gpa
    └── Default: 0.0
```

#### 2. 继承（Inheritance）

**概念**：子框架继承父框架的属性

```
Frame: Person
├── Slot: name
└── Slot: age

Frame: Student (is-a Person)
├── Inherits: name, age  ← 继承自Person
├── Slot: student_id
└── Slot: major
```

#### 3. 过程型附着（Procedural Attachment）

**概念**：框架中的槽位可以触发程序代码执行

**两种类型**：

| 类型           | 触发时机       | 用途           |
| -------------- | -------------- | -------------- |
| **IF-NEEDED**  | 当访问该槽位时 | 计算属性值     |
| **IF-CHANGED** | 当槽位值改变时 | 触发规则或更新 |

**示例**：

```
Frame: Account
├── Slot: balance
│   └── IF-NEEDED: compute_balance()  ← 访问时动态计算
├── Slot: interest_rate = 3.5%
│   └── IF-CHANGED: update_interest()  ← 值改变时触发
```

### 3.4 框架的优势和应用

**优势**：
✅ 直观易理解，接近人类思维
✅ 支持属性继承，避免重复
✅ 支持动态计算和规则触发
✅ 易于扩展和维护

**应用领域**：

- 语言理解
- 场景识别
- 知识库构建

## 四、生成式系统（Production System）

### 4.1 基本概念

**定义**：生成式系统是一种基于条件-行为规则的计算模型

**核心元素**：

| 元素           | 说明               | 英文             |
| -------------- | ------------------ | ---------------- |
| **规则**       | 条件-行为对        | Production       |
| **条件**       | IF部分，触发条件   | Condition/LHS    |
| **行为**       | THEN部分，执行动作 | Action/RHS       |
| **工作记忆**   | 当前事实的集合     | Working Memory   |
| **规则解释器** | 规则匹配和执行引擎 | Rule Interpreter |

### 4.2 生成式规则的结构

**标准形式**：

```
IF <条件1> AND <条件2> AND ... THEN <行为1>, <行为2>, ...
```

**具体例子**：

```
规则P1: IF 天气=下雨 AND 有伞=是
        THEN 可以出门=真, 心情=好

规则P2: IF 温度<0°C
        THEN 穿棉衣, 打开暖气
```

### 4.3 两种推理策略

#### 1. 前向链接（Forward Chaining）- 数据驱动

**原理**：从已知的事实出发，逐步应用规则推导新事实

**流程**：

```
已知事实 → 匹配规则LHS → 触发规则RHS → 新事实
         ↓
    重复上述过程，直到无新事实产生或达到目标
```

**特点**：

- 自下而上的推理
- 适合数据较多而目标不明确的情况
- 可能产生大量中间结果

**例子**：

```
已知：Alex有红头发，性格外向
规则：IF 红头发 AND 性格外向 THEN 可能来自爱尔兰

推导：Alex可能来自爱尔兰
```

#### 2. 后向链接（Backward Chaining）- 目标驱动

**原理**：从目标出发，反向寻找能够证明该目标的规则和事实

**流程**：

```
目标 → 找满足目标的规则 → 递归求解子目标
       ↓
    如果所有子目标都能满足 → 目标成立
```

**特点**：

- 自上而下的推理
- 适合目标明确、需要深度搜索的情况
- 只计算相关结果

**Prolog就使用后向链接**

### 4.4 OPS5生成式系统示例

**OPS5**是一个著名的生成式系统

**特点**：

- 支持复杂的模式匹配
- 有三种工作区：输入、工作、输出
- 支持元素插入、修改、删除

**例子：搬运问题**

```
初始状态：
  ├─ 位置A：有积木X
  ├─ 位置B：有积木Y
  └─ 目标：将X和Y都放到位置C

规则：
  P1: 如果积木在位置A且目标位置是C
      → 移动积木到C

  P2: 如果所有积木在目标位置
      → 设置goal状态为satisfied
```

### 4.5 规则的执行机制

**冲突集解决**（Conflict Set Resolution）：

当多条规则都可以在当前状态下触发时，需要决定执行顺序：

| 策略         | 说明                   | 用途             |
| ------------ | ---------------------- | ---------------- |
| **最近使用** | 优先执行最近使用的规则 | 避免重复         |
| **特异性**   | 优先执行更具体的规则   | 优先处理特殊情况 |
| **优先级**   | 根据预定优先级执行     | 控制推理顺序     |

## 五、逻辑规则编程（Logic Programming）

### 5.1 基本概念

**定义**：逻辑规则编程是一种以逻辑规则为基础的编程范式

**核心思想**：

```
算法 = 逻辑 + 控制
（指定了什么 + 怎样处理 = 完整的计算过程）
```

### 5.2 Prolog语言

**Prolog** = Programming in Logic（逻辑编程）

**基本元素**：

#### 1. 事实（Fact）

```prolog
% 事实示例
parent(john, mary).      % john是mary的父亲
citizen(mary, china).    % mary是中国公民
```

#### 2. 规则（Rule）

```prolog
% 规则的一般形式：
% Head :- Body1, Body2, ..., BodyN.
% 头 :- 体1, 体2, ..., 体N.

% 规则示例
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
% 如果X是Y的父亲，Y是Z的父亲，那么X是Z的祖父/祖母

sibling(X, Y) :- parent(Z, X), parent(Z, Y), X \= Y.
% X和Y有共同的父亲Z，且X≠Y，则X和Y是兄弟姐妹
```

#### 3. 查询（Query）

```prolog
% 查询格式：?- Goal1, Goal2, ..., GoalN.

?- parent(john, X).
% 查询：john的孩子是谁？
% 答案：X = mary

?- grandparent(john, X).
% 查询：john的孙子女是谁？
```

### 5.3 逻辑规则编程的三个方向

#### 方向 1：Prolog - 经典逻辑编程

**特点**：

- 使用后向链接（Goal Reduction）
- 从查询目标出发，反向推导
- 具有回溯(backtracking)机制

**推理过程**：

```
查询 ?- ancestor(john, tom).
→ 寻找满足ancestor的规则
→ ancestor(X,Y) :- parent(X,Y).
→ 检查 parent(john, tom) 是否为真
→ 如果失败，回溯，尝试其他规则
```

#### 方向 2：Datalog - 受限的逻辑编程

**限制**：

- 禁止在头部使用函数（即函数式编程）
- 提供最小不动点语义(Least Fixed Point)
- 保证终止性

**应用**：

- 数据库查询
- 知识库推理

```datalog
% 传递闭包示例
reachable(X, Y) :- edge(X, Y).
reachable(X, Z) :- edge(X, Y), reachable(Y, Z).

% 查询所有可达节点
?- reachable(node1, X).
```

#### 方向 3：ASP（Answer Set Programming）- 非单调逻辑

**特点**：

- 基于Datalog
- 支持非单调推理(non-monotonic logic)
- 支持"稳定模型"语义

**新特性 - 否定**：

```prolog
% 规则中可以使用否定
bird(X) :- penguin(X), \+ can_fly(X).
% X是企鹅，且企鹅不能飞

% 约束规则
:- Body.    % 如果Body为真，则产生矛盾
```

**例子：地图着色问题**

```prolog
% 使用3种颜色给地图着色
color(red). color(green). color(blue).

% 每个区域必须有一种颜色
{colored(R, C) : color(C)} = 1 :- region(R).

% 相邻区域颜色不同
:- adjacent(R1, R2), colored(R1, C), colored(R2, C).

% 寻找稳定模型（有效的着色方案）
```

### 5.4 逻辑规则编程的推理方向

| 推理方向     | 英文              | 特点                 | 用途       |
| ------------ | ----------------- | -------------------- | ---------- |
| **后向链接** | Backward Chaining | 目标驱动，从问题出发 | 查询、推理 |
| **前向链接** | Forward Chaining  | 数据驱动，从事实出发 | 知识库维护 |
| **目标规约** | Goal Reduction    | 递归分解目标         | Prolog     |
| **自下而上** | Bottom-up         | 从已知推新知         | Datalog    |

## 六、专家系统（Expert System）

### 6.1 什么是专家系统？

**定义**：专家系统是一种能够在特定领域做出像专家一样决策的计算机系统

**基本等式**：

```
专家系统 = 知识库 + 推理引擎 + 用户界面
```

**核心思想**：

- 捕获某个领域专家的知识
- 用计算机实现专家的推理过程
- 提供决策支持或自动化

### 6.2 专家系统的两大部分

#### 1. 知识库（Knowledge Base）

**包含内容**：

- 事实(facts)：该领域的基本信息
- 规则(rules)：该领域的专家知识和推理规则
- 本体(ontology)：概念的定义和分类

**例子**：

```
医疗诊断系统的知识库：
├─ 事实
│   ├─ 疾病：肺炎、感冒、哮喘
│   ├─ 症状：发烧、咳嗽、喉咙痛
│   └─ 治疗：抗生素、退烧药
├─ 规则
│   ├─ IF 发烧>38°C AND 咳嗽 THEN 可能是肺炎
│   ├─ IF 喉咙痛 AND 发烧 THEN 可能是扁桃腺炎
│   └─ ...
└─ 本体
    ├─ 症状 → 生理症状、心理症状
    └─ 治疗 → 药物治疗、手术治疗
```

#### 2. 推理引擎（Inference Engine）

**功能**：

- 匹配用户输入与知识库中的规则
- 执行推理过程
- 得出结论

**工作流程**：

```
输入用户数据
    ↓
与知识库中的规则进行匹配
    ↓
触发相关规则
    ↓
产生新的中间结论
    ↓
继续推理，直到得出最终结论
    ↓
输出结论和解释
```

### 6.3 著名专家系统案例

| 系统            | 领域     | 贡献               | 时间      |
| --------------- | -------- | ------------------ | --------- |
| **MYCIN**       | 医学诊断 | 抗生素治疗推荐     | 1970-1980 |
| **DENDRAL**     | 化学     | 质谱数据分析       | 1970-1980 |
| **Internist-I** | 医学     | 内科诊断           | 1980+     |
| **CADUCEUS**    | 医学     | 内科诊断（升级版） | 1980+     |

**MYCIN的成功**：

- 与医学专家的诊断准确率相当（80%）
- 证明了专家系统的可行性
- 启发了后续系统的开发

### 6.4 专家系统的生命周期

| 阶段         | 任务                   | 关键点             |
| ------------ | ---------------------- | ------------------ |
| **知识获取** | 从专家获取知识         | 困难、耗时         |
| **知识编码** | 将知识转化为规则       | 需要专业知识工程师 |
| **知识测试** | 用案例验证规则的正确性 | 迭代改进           |
| **系统部署** | 在实际应用中使用       | 需要维护和更新     |
| **知识维护** | 随着新知识更新规则     | 持续改进           |

### 6.5 专家系统的黄金时代

**时期**：20-80年代到90年代

**特点**：

- 大量投资专家系统开发
- 特殊硬件（Symbolics 3640）支持
- 企业和学术界的热烈追捧

**衰落原因**：

1. 知识获取困难（瓶颈问题）
2. 维护成本高
3. 适应性差
4. 机器学习兴起

### 6.6 Hayes-Roth的专家系统架构

**Hayes-Roth (1983)** 提出了10层专家系统架构：

```
第10层：系统整体
第9层：任务和推理方法
第8层：推理控制策略
第7层：知识表示
第6层：信息处理
第5层：知识组织
第4层：推理规则
第3层：事实库
第2层：数据结构
第1层：硬件基础
```

# Part 2：现代知识表示方法

## 七、知识图谱嵌入（KGE）

### 7.1 什么是知识图谱嵌入？

**定义**：知识图谱嵌入(KGE, Knowledge Graph Embedding)或知识表示学习(KRL, Knowledge Representation Learning)是将知识图谱中的实体和关系映射到低维连续空间中的方法

**基本思想**：

- 把离散的符号知识转化为连续的向量表示
- 在向量空间中保留知识图谱的语义含义
- 实现"语义相似性"的数学化

### 7.2 知识图谱的基本构成

#### 知识图谱的三要素

| 要素                 | 说明                   | 符号                      |
| -------------------- | ---------------------- | ------------------------- |
| **实体（Entity）**   | 现实世界中的对象、事物 | 如：北京、张三、中国      |
| **关系（Relation）** | 实体之间的连接         | 如：located_in、works_for |
| **事实（Fact）**     | 三元组形式的陈述       | (实体1, 关系, 实体2)      |

#### 三元组示例

```
知识图谱 = {实体, 关系, 事实}

具体例子：
(北京, 位于, 中国)
(张三, 工作于, 百度)
(百度, 创始人, 李彦宏)
(李彦宏, 毕业于, 北京大学)
```

#### 三元组的数学表示

```
三元组 = (h, r, t)
其中：
  h（head）= 头实体
  r（relation）= 关系
  t（tail）= 尾实体

例子：(北京, 位于, 中国)
  h = 北京
  r = 位于
  t = 中国
```

### 7.3 知识图谱嵌入的必要性

#### 问题 1：知识图谱的稀疏性

**现象**：

- 知识图谱中只包含实体和关系的一小部分
- 大量可能存在的三元组缺失
- 如：(张三, 认识, 李四) 这个三元组可能没有被记录

**影响**：

- 知识不完整
- 无法进行完整的推理

#### 问题 2：计算效率低

**挑战**：

- 知识图谱规模庞大（如Freebase有数百万个实体）
- 直接在符号空间进行推理计算量大
- 难以应用深度学习等现代机器学习方法

#### 解决方案：嵌入表示

**转化思路**：

```
离散符号空间 → 连续向量空间

北京 → [0.1, -0.3, 0.8, ..., 0.2]  (50-200维)
位于 → [0.05, 0.2, -0.1, ..., 0.15]
中国 → [-0.2, 0.15, 0.7, ..., 0.3]

优点：
✓ 可以使用向量运算
✓ 可以应用深度学习
✓ 计算效率高
✓ 便于相似性计算
```

### 7.4 知识图谱嵌入的四个关键要素

| 要素         | 说明               | 作用                 |
| ------------ | ------------------ | -------------------- |
| **表示空间** | 向量嵌入的维度     | 通常50-200维         |
| **评分函数** | 衡量三元组是否合理 | 决定哪些三元组是"真" |
| **编码模型** | 如何生成向量表示   | TransE、ConvE等      |
| **附加信息** | 利用其他知识       | 属性、类型、规则等   |

### 7.5 嵌入过程

#### 四步流程

**第1步：初始化**

```
随机初始化所有实体和关系的向量表示
e_i ~ N(0, 1)  for i ∈ entities
r_j ~ N(0, 1)  for j ∈ relations
```

**第2步：抽样**

```
从知识图谱中随机抽取训练三元组
- 正三元组：(h, r, t) ∈ KG
- 负三元组：通过"腐坏"操作生成

腐坏操作（Corruption）：
  将正三元组的头或尾替换为其他实体
  例：(北京, 位于, 中国)
    → 负例1: (上海, 位于, 中国)  ✓ (合理但非原三元组)
    → 负例2: (北京, 位于, 日本)   ✗ (不合理)
```

**第3步：梯度计算**

```
对每个批次(batch)：
1. 计算正三元组的评分 score(h, r, t)
2. 计算负三元组的评分 score(h', r, t')
3. 计算损失函数 L = loss(score_positive, score_negative)
4. 计算梯度 ∇L
```

**第4步：参数更新**

```
使用随机梯度下降(SGD)或其他优化器更新参数：
e_i := e_i - α * ∇L  (其中α是学习率)
```

### 7.6 嵌入模型的性能指标

#### 评价指标

| 指标                     | 英文      | 计算方式         | 含义                                          |
| ------------------------ | --------- | ---------------- | --------------------------------------------- |
| **Hits@K**               | Hits at K | 排名前K的正确率  | 如Hits@10 = 10%，表示真实三元组在前10中的概率 |
| **Mean Rank**            | MR        | 平均排名         | 真实三元组的平均排名，越低越好                |
| **Mean Reciprocal Rank** | MRR       | 排名倒数的平均值 | MRR = 平均(1/rank)，如MRR=0.5表示平均排名为2  |

#### 具体例子

```
任务：给定(北京, 位于, ?)，预测尾实体

模型的排名：
1. 中国    ✓ (正确答案)
2. 日本
3. 美国
...
10. 英国

性能指标计算：
- Hits@10 = 1 (正确答案在前10)
- Hits@1 = 0  (正确答案不在前1)
- Mean Rank = 1 (排名为1)
- MRR = 1/1 = 1.0
```

## 八、知识图谱嵌入的应用

### 8.1 三大主要应用

#### 1. 知识图谱完成（Knowledge Graph Completion, KGC）

**问题**：知识图谱中缺失大量事实

**目标**：预测缺失的三元组

**方法**：

- 利用已知三元组学习模式
- 推断新的三元组

**例子**：

```
已知：(李彦宏, 创始人, 百度)
      (张三, 工作于, 百度)
预测：(张三, 领导者, 李彦宏)  ← 通过关系传递推断
```

**应用**：补充不完整的知识库

#### 2. 三元组分类（Triple Classification）

**问题**：给定一个三元组，判断它是真还是假

**方法**：

- 计算三元组的评分
- 与阈值比较

**例子**：

```
输入三元组：(北京, 位于, 中国)
模型计算：评分 = 0.95
判定：评分 > 阈值(0.5) → 判为真

输入三元组：(北京, 位于, 日本)
模型计算：评分 = 0.1
判定：评分 < 阈值(0.5) → 判为假
```

**应用**：事实核查、虚假信息检测

#### 3. 聚类（Clustering）

**问题**：发现语义相似的实体或关系

**方法**：

- 在嵌入空间中计算相似度
- 进行聚类

**例子**：

```
实体聚类：
  簇1: {北京, 上海, 广州, ...} → 中国城市
  簇2: {华盛顿, 纽约, 洛杉矶, ...} → 美国城市
  簇3: {苹果, 谷歌, 微软, ...} → 科技公司

应用：发现概念、分类管理
```

### 8.2 高级应用领域

#### 1. 推荐系统（Recommender Systems）

**原理**：

- 将用户、物品、用户-物品交互建模为知识图谱
- 利用嵌入学习相似性
- 推荐用户感兴趣的物品

**例子**：

```
知识图谱中的三元组：
(用户A, 评分=5, 电影B)
(电影B, 类型, 科幻)
(用户A, 兴趣, 科幻)

推荐：与电影B类似的其他科幻电影
```

#### 2. 药物再利用（Drug Repurposing）

**原理**：

- 建立疾病、药物、蛋白质等的知识图谱
- 发现现有药物对新疾病的治疗潜力

**例子**：

```
已知三元组：
(药物X, 治疗, 疾病A)
(蛋白质Y, 与疾病B相关)
(药物X, 作用于, 蛋白质Y)

推断：药物X可能治疗疾病B
```

**应用**：加速新药发现，降低成本

#### 3. 社交网络分析（Social Network Analysis）

**原理**：

- 将用户和关系建模为知识图谱
- 分析用户之间的关系模式
- 发现社区结构

**例子**：

```
知识图谱：
(用户A, 关注, 用户B)
(用户B, 关注, 用户C)
(用户A, 转发, 用户C的内容)

应用：
- 发现影响力用户
- 识别社区
- 预测链接
```

## 九、嵌入模型分类

### 9.1 嵌入模型的三大类别

#### 分类维度

| 维度             | 标准                             |
| ---------------- | -------------------------------- |
| **基于模型结构** | 张量分解、几何模型、深度学习     |
| **基于表示空间** | 欧几里得空间、双曲空间、复数空间 |
| **基于评分函数** | 距离型、乘积型、神经网络型       |

### 9.2 张量分解模型（Tensor Decomposition Models）

#### RESCAL 模型

**基本思想**：

- 将知识图谱表示为三维张量
- 对张量进行分解

**数学表示**：

```
对于关系r，构建一个矩阵M_r：
  - 行：所有头实体
  - 列：所有尾实体
  - 元素：该三元组是否存在

所有M_r堆叠成三维张量 T

张量分解：T ≈ U × M_1 × U^T
其中U是实体的嵌入矩阵
```

**评分函数**：

```
score(h, r, t) = e_h^T M_r e_t

其中：
  e_h：头实体的嵌入向量
  M_r：关系的嵌入矩阵
  e_t：尾实体的嵌入向量
```

**优点**：
✓ 理论基础完善
✓ 能表示复杂关系

**缺点**：
✗ 参数量大（关系需要矩阵表示）
✗ 计算复杂度高

---

### 9.3 几何模型（Geometric Models）

#### TransE 模型（最重要）

**核心思想**：

- 将三元组关系视为向量"翻译"(translation)
- 头实体 + 关系向量 ≈ 尾实体

**数学公式**：

```
e_h + r ≈ e_t   (理想情况)

评分函数：
score(h, r, t) = ||e_h + r - e_t||_p

其中：
  ||·||_p：L1或L2范数
  p = 1 (L1范数) 或 2 (L2范数)
```

**具体例子**：

```
三元组：(北京, 位于, 中国)

向量表示：
  e_北京 = [0.01, 0.04, 0.8, 0.32, 0.09, 0.18, ...]  (50-200维)
  r_位于 = [0.2, -0.1, 0.05, ...]
  e_中国 = [0.15, -0.05, 0.9, 0.35, 0.1, 0.15, ...]

验证：
  e_北京 + r_位于 ≈ e_中国？
  [0.01+0.2, 0.04-0.1, 0.8+0.05, ...] ≈ [0.15, -0.05, 0.9, ...]？
  是的，很接近！
```

#### TransE的损失函数

**Margin Loss（间隔损失）**：

```
L = Σ_{(h,r,t)∈G} Σ_{(h',r,t')∉G} max(0, γ + d(e_h+r, e_t) - d(e_h'+r, e_t'))

其中：
  G：知识图谱中的正三元组集合
  (h',r,t')：通过腐坏生成的负三元组
  d(·)：距离函数(如L1或L2范数)
  γ：间隔(margin)参数，如1.0

直观含义：
  正三元组的距离 < 负三元组的距离 - γ
```

**损失函数的组件**：

| 组件              | 说明                           |
| ----------------- | ------------------------------ |
| `d(e_h+r, e_t)`   | 正三元组的距离（应该小）       |
| `d(e_h'+r, e_t')` | 负三元组的距离（应该大）       |
| `max(0, ...)`     | ReLU激活，只惩罚违反间隔的情况 |
| `γ`               | 间隔：保证正负三元组距离差异   |

#### TransE的训练过程

**步骤**：

```
1. 初始化实体和关系的随机向量
2. 逐个epoch循环：
   a. 对于每个批次(batch)：
      - 从知识图谱抽取正三元组
      - 通过腐坏生成负三元组
      - 计算损失函数
      - 更新梯度：
        ∇L = (e_h + r - e_t) 对正三元组梯度
            -(e_h' + r - e_t') 对负三元组梯度
   b. 使用SGD或Adam优化器更新参数
3. 重复直到收敛
```

#### TransE的变体和改进

**问题**：TransE有一些局限性

**局限1：关系对称性**

```
例如"spouse"（配偶）是对称关系：
(Alice, spouse, Bob) ↔ (Bob, spouse, Alice)

但TransE会学习：
  e_Alice + r_spouse ≈ e_Bob
  e_Bob + r_spouse ≈ e_Alice

这导致：e_Alice + r_spouse + r_spouse ≈ e_Alice
即：2 * r_spouse ≈ 0，r_spouse应该接近零向量
这与其他三元组的要求矛盾
```

**局限2：关系链接**

```
例如"位于"是可组合的：
(北京, 位于, 中国) 和 (中国, 位于, 亚洲)
应该推断出 (北京, 位于, 亚洲)

TransE假设：
  e_北京 + r_位于 ≈ e_中国
  e_中国 + r_位于 ≈ e_亚洲

但这意味着 e_北京 + 2*r_位于 ≈ e_亚洲
距离累积，容易出错
```

**改进模型**：

```
TransH：在超平面上投影关系
TransR：针对不同关系使用不同的投影空间
TransD：动态确定投影空间
```

### 9.4 深度学习模型（Deep Learning Models）

#### ConvE 模型

**思想**：使用卷积神经网络(CNN)处理嵌入

**特点**：

```
输入：
  - 头实体嵌入：e_h (1D向量)
  - 关系嵌入：r (1D向量)

处理步骤：
  1. 将向量重塑成2D张量（矩阵）
  2. 应用1D卷积操作
  3. 展平后通过MLP
  4. 输出：与所有尾实体的匹配得分
```

**优点**：
✓ 利用卷积的特征提取能力
✓ 更灵活的特征学习
✓ 性能往往更好

## 十、知识图谱的语义表示学习

### 10.1 概念理解

**定义**：利用知识图谱中的语义信息（关系层级、数据类型、本体约束、逻辑规则等）来改进嵌入学习

**目标**：

- 使嵌入不仅捕捉基本的三元组模式
- 还要融合更多语义信息
- 提高嵌入的表达能力和准确性

### 10.2 四大语义信息来源

#### 1. 关系层级结构（Relation Hierarchical Structure）

**概念**：不同关系之间存在层级关系

**例子**：

```
位置关系的层级：
  位于
    ├─ 直接位于（坐在、站在）
    ├─ 邻近位于（在...旁边）
    └─ 广泛位于（在...地区）

应用：TransRHS模型
- 母关系的嵌入应该是子关系的泛化
- 子关系表现应该保持一致
```

**TransRHS模型的优化条件**：

```
理想情况：
1. 同一类别下的关系嵌入相似
2. 不同类别的关系嵌入差异大
3. 跨层级的三元组能够继承

需要优化的情况：
1. 某些关系的嵌入与同类关系差异大
2. 某些关系不满足传递性
3. 某些关系的类型限制被破坏
```

#### 2. 数据类型属性（Data Type Attribute）

**背景**：实际知识图谱中的属性值有多种数据类型

**例子**：

```
DBpedia中的属性：
(Albert Einstein, birthDate, 1879-03-14)      ← 日期类型
(China, population, 1.4 billion)              ← 数值类型
(Tom Hanks, birthPlace, Concord, California)  ← 文本/位置类型
(Barack Obama, spouse, Michelle Obama)        ← 实体类型
```

**挑战**：

- 不同类型的属性需要不同的编码方式
- 简单的向量加法不适用于所有类型

**解决方案**：

```
双向语言模型(BiLM)编码：
  - 数值类型：用编码器将数值映射到向量
  - 日期类型：用专门的时间编码器
  - 文本类型：用预训练模型（BERT等）编码
  - 关系感知的属性值表示

利用双曲空间：
  - 双曲空间适合表示层级结构
  - 能更好地编码不同类型的信息
```

#### 3. 本体信息约束（Ontology Information Constraints）

**概念**：利用知识图谱中的类型信息和约束

**例子**：

```
类型约束：
  birthPlace关系的头实体必须是Person类型
  birthPlace关系的尾实体必须是Location类型

域和值的约束：
  spouse关系的两端都必须是Person
  locatedIn关系的头必须是Place，尾必须是Place或Country
```

**TransO模型**：

```
目标：显式建模关系并融入本体信息

特点：
1. 为不同实体类型学习不同的投影空间
2. 对关系的定义域(domain)和值域(range)施加约束
3. 保持模型的低复杂度

效果：
- 改进链接预测性能
- 提高推理的可靠性
- 减少违反类型约束的预测
```

#### 4. 逻辑规则（Logical Rules）

**概念**：利用知识工程中的逻辑规则来指导嵌入学习

**例子**：

```
对称规则：
  spouse(X, Y) ↔ spouse(Y, X)

逆关系规则：
  父亲(X, Y) ↔ 儿子(Y, X)

子关系规则：
  父亲(X, Y) → 父母(X, Y)
  祖父(X, Y) → 祖先(X, Y)
```

**统计关系模型(MLN - Markov Logic Network)**：

```
特点：
- 使用加权逻辑规则构造马尔可夫随机场
- 规则权重反映了其可靠性

工作流程：
1. 将逻辑规则编码为概率约束
2. 与嵌入模型联合训练
3. 规则权重在训练中调整
```

**变分EM算法训练**：

```
步骤：
1. 初始化嵌入和规则权重
2. E步：计算隐变量期望
3. M步：最大化似然函数
4. 迭代直到收敛

优点：
- 规则权重从数据学习
- 嵌入融合逻辑约束
- 提高可解释性
```

### 10.3 高级模型：知识超图嵌入

#### 什么是知识超图？

**定义**：超图是图的推广，其中每条边可以连接多个顶点（而不是仅两个）

**与普通三元组的区别**：

```
普通三元组（二元关系）：
  (头实体, 关系, 尾实体)
  例：(北京, 位于, 中国)

超图中的n元关系：
  (实体1, 实体2, ..., 实体n, 关系)
  例：(张三, 李四, 2023年, 结婚)  ← 4元关系
      头实体：张三、李四
      关系：结婚
      时间实体：2023年
```

#### HyConvE 模型

**创新**：使用卷积神经网络处理超图

**架构**：

```
输入：多个实体和关系
  ↓
转化为3D张量（高维表示）
  ↓
应用3D卷积操作
  ↓
降维到2D
  ↓
通过全连接层
  ↓
输出：匹配得分
```

**优点**：
✓ 能处理高阶关系
✓ 保留多个实体之间的相互作用
✓ 利用卷积的特征提取能力

#### 时间感知的超图链接预测

**动机**：现实中许多关系是时间相关的

**例子**：

```
(张三, 工作于, 百度, 2015-2020)  ← 包含时间信息
(李四, 是CEO, 公司X, 2020-现在) ← 动态关系
```

**方法**：

```
静态嵌入：表示实体和关系的不变性质
时间动态嵌入：
  - 设置时间戳的频率和权重
  - 根据时间进行动态调整
  - 学习时间演化模式
```

#### 高效的3D圆形卷积嵌入（HyCubE）

**特点**：

```
复杂语义知识：在3D圆形卷积中表示
高效性：
  - 更少的参数数量
  - 更快的计算速度
  - 端到端的高效训练

自适应结构：
  - 根据数据自动调整卷积层结构
  - 动态优化嵌入空间
```

## 十一、分布式知识图谱表示学习

### 11.1 系统瓶颈

#### 挑战 1：内存需求不断增长

**现象**：

- 知识图谱规模不断增大
- 嵌入维度也在增加（从50到200+）
- 导致内存占用剧增

**Freebase-86数据集为例**：

```
实体数量：数百万
关系数量：数千
维度：通常50-200
每个向量存储量：约50KB-200KB（根据精度）

总内存需求：GB级别甚至TB级别
```

#### 挑战 2：通信成为性能瓶颈

**现象**：

- 在分布式系统中训练大规模知识图谱嵌入
- 实体和关系的梯度需要在节点间同步
- 通信时间占比超过70%

### 11.2 优化动机

#### 关键观察

```
观察1：
  热门实体（Top-1%）的通信流量占比最高

  例如：
  - "美国"、"中国"等出现在大量三元组中
  - 这些实体的梯度频繁被同步
  - 导致通信拥堵

观察2：
  关系通信的分布也是偏斜的
  - 某些常见关系如"位于"、"属于"频繁出现
  - 这些关系的参数更新最频繁
```

#### HET-KG 系统设计

**目标**：利用热度意识缓存(Hotness-Aware Cache)减少通信

**工作流程**：

```
1. 知识图谱分割(Graph Partitioning)
   - 将知识图谱分成多个子图
   - 分配给不同的计算节点

2. 样本预加载与键嵌入表构建
   - 预先加载热点数据到缓存
   - 构建热点实体和关系的快速查找表

3. 参数拉取(Pull Parameters)
   - 节点从其他节点请求需要的参数
   - 优先从本地缓存获取热点数据

4. 迭代计算
   - 在本地执行前向传播和反向传播
   - 计算梯度

5. 梯度推送(Push Gradient)
   - 发送梯度更新到参数所有者节点

6. 键嵌入同步(Key Embedding Synchronisation)
   - 同步热点实体/关系的最新嵌入
```

**性能改进**：

```
未优化：通信时间 > 计算时间的70%
优化后：通信时间显著降低
        整体训练速度提升3-5倍
```

## 十二、LLM增强的知识表示学习

### 12.1 新方向：大语言模型(LLM)

**趋势**：将预训练的大语言模型与知识图谱嵌入结合

**目标**：利用LLM的语义理解能力改进知识表示

### 12.2 四种LLM增强方法

#### 1. BKA（基于BERT的知识增强）

**思路**：

- 使用BERT等预训练模型编码实体和关系文本
- 结合图结构学习

#### 2. KMP（知识图谱元路径）

**思路**：

- 结合元路径(meta-path)和语言模型
- 利用路径结构和语义信息

#### 3. CGSA（交叉图自注意）

**思路**：

- 使用自注意机制融合文本和图信息
- 捕捉多模态语义关系

#### 4. KG-BiLM（双向语言模型增强的KG嵌入）

**方法**：

```
输入：
  - 实体描述文本
  - 关系描述文本
  - 三元组(h, r, t)

处理流程：
  1. 使用Transformer编码器处理文本
  2. 提取文本表示
  3. 与图结构信息融合
  4. 学习增强的嵌入
```

**性能提升**：

```
在标准基准上的改进：
- WN18RR数据集：MRR提升
- FB15k-237数据集：性能显著提高
- Wikidata5M数据集：Hits@1 和 MRR指标均有改进
- FB15k-237N数据集：新的基准设立

特点：
✓ 利用文本语义信息
✓ 更好的初始化表示
✓ 减少对大规模三元组的依赖
```

### 12.3 LLM增强的优势

**相比传统方法**：

```
传统KGE：
  - 仅从三元组结构学习
  - 需要大量正负样本对
  - 冷启动问题严重

LLM增强：
  - 利用预训练的语言知识
  - 可以处理稀疏知识
  - 更好的泛化能力
  - 改进少样本学习
```

**应用前景**：

- 多模态知识图谱
- 跨语言知识融合
- 更好的可解释性

### 时间线

```
20世纪50-60年代：语义网络
  └─ 图形化表示知识

1974年：框架理论(Minsky)
  └─ 结构化知识表示

1974-1980年代：生成式系统
  └─ 规则驱动的推理

1970-1990年代：逻辑编程
  └─ Prolog、Datalog、ASP

1980-1990年代：专家系统黄金时代
  └─ MYCIN等系统应用

2000年代：本体工程兴起
  └─ OWL、RDF标准化

2010年代：知识图谱时代
  └─ Google Knowledge Graph等

2013年及之后：神经符号方法
  └─ TransE等嵌入方法
  └─ 深度学习方法(ConvE等)

2020年代：LLM融合
  └─ BERT、Transformer增强
  └─ 多模态知识融合
```
