# 第一部分：语义Web基础

## 一、万维网的演进：从文档网到数据网

### 现状：文档网 (Web of Documents)

**问题所在**：当前互联网是"人类网络"

| 特征 | 说明 | 问题 |
|------|------|------|
| **核心单位** | HTML 网页 | 为人类浏览设计 |
| **连接方式** | 超链接 (Hyperlinks) | 无语义含义 |
| **格式关注** | 展示格式（字体、加粗、颜色） | 机器无法理解内容含义 |
| **歧义性** | 例：搜索"Jaguar" | 机器无法区分：动物🐆 vs 汽车🚗 vs 系统💻 |

👉 **关键问题**：HTML 描述的是**如何显示**，而不是**是什么**。

### 愿景：数据网 (Web of Data / Semantic Web)

**机器网络**——让机器能理解数据

| 特征 | 说明 | 优势 |
|------|------|------|
| **核心单位** | 资源/事物 (Things/Entities) | 独立的语义单位 |
| **连接方式** | **有类型的链接** (Typed Links) | `isAuthorOf`, `bornIn`, `locatedIn` 等 |
| **智能推理** | 机器可自动遍历链接 | 执行跨站点的复杂任务 |
| **应用场景** | 自动旅游行程预订 | 结合多站点数据，满足所有偏好 |

👉 **核心改变**：从"展示层"升级到"数据层"，从"人读"到"机器读"。

# 第二部分：RDF与RDFS数据模型

## 一、RDF基础：三个核心概念

### 1. RDF的三要素 (RDF Terms)

RDF 使用三种类型的节点来表示知识：

#### 📌 URI（或 IRI）
- **定义**：资源的全局唯一标识符
- **格式**：`http://example.org/Beijing` 或前缀简写 `:Beijing`
- **作用**：确保全球范围内无歧义

#### 📌 Literal（字面量）
- **定义**：具体的数据值（不是URI）
- **类型**：
  - **带语言标签**：`"北京"@zh`, `"Beijing"@en`
  - **带数据类型**：`"2024-03-15"^^xsd:date`, `"100"^^xsd:integer`
- **作用**：表示数字、文本、日期等具体值

#### 📌 Blank Node（匿名节点）
- **定义**：没有全局ID的局部节点
- **用途**：当一个属性的值需要多个部分时（如地址 = 街道 + 城市 + 邮编）
- **不能作为谓语**（与URI和Literal不同）

### 2. RDF三元组 (Triple) 模型

**原子知识的表示形式**：`(Subject, Predicate, Object)`

```
数学定义：(s, p, o) ∈ (U ∪ B) × U × (U ∪ B ∪ L)
其中：
  U = URIs集合
  B = Blank Nodes集合
  L = Literals集合
```

**规则**：
- ✅ 主语：可以是 URI 或 Blank Node
- ✅ 谓语：**必须是 URI**（表示关系类型）
- ✅ 宾语：可以是 URI、Blank Node 或 Literal

### 3. 直观理解与例子

```
现实陈述             →  RDF三元组
"Alice知道Bob"      →  (:Alice, :knows, :Bob)
"Alice的年龄是25"   →  (:Alice, :age, 25)
"北京在中国"        →  (:Beijing, :locatedIn, :China)
```

## 二、Turtle语法：RDF的可读表示法

> Turtle 是最常用的RDF序列化格式，在考试和工程中都很重要。

### 1. 基础语法

#### 前缀声明
```turtle
@prefix : <http://example.org/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
```

#### 基本三元组
```turtle
# 方式1：完整写法
:Alice :knows :Bob .

# 方式2：复用主语（分号）
:Alice :knows :Bob ;
       :age 25 ;
       :hobby "Reading" .

# 方式3：复用主语和谓语（逗号）
:Alice :hobby "Reading" , "Coding" , "Hiking" .
```

### 2. 从N-Triples到Turtle的简写

**N-Triples（原始、逐行格式）**：
```nt
<http://example.org/Alice> <http://example.org/knows> <http://example.org/Bob> .
<http://example.org/Alice> <http://example.org/age> "25"^^<http://www.w3.org/2001/XMLSchema#integer> .
```

**对应的Turtle简写**：
```turtle
@prefix : <http://example.org/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

:Alice :knows :Bob ;
       :age 25 .              # 数字自动识别为xsd:integer
```

### 3. 语法简化规则速查表

| 现象 | 含义 | 效果 |
|------|------|------|
| 分号 `;` | 复用主语 | 避免重复写 `:Alice` |
| 逗号 `,` | 复用主语和谓语 | 同一谓语的多个宾语 |
| `[...]` | 匿名节点 | 创建局部节点 |
| `(...)` | RDF列表 | 有序集合 |
| `a` | `rdf:type` | 类型声明的简写 |

## 三、RDF进阶：复杂结构表示

### 1. 匿名节点 (Blank Nodes) 深度应用

**场景**：描述"Alice的住址是北京中关村"

问题：住址是一个复合结构（城市 + 街道 + 邮编），不能直接用单个URI表示。

**解决**：使用匿名节点作为中间节点

```turtle
:Alice :hasAddress [
    :city :Beijing ;
    :street "Zhongguancun" ;
    :postcode "100080"
] .

# 展开后等价于：
:Alice :hasAddress _:b1 .
_:b1 :city :Beijing .
_:b1 :street "Zhongguancun" .
_:b1 :postcode "100080" .
```

**何时使用**：
- ✅ 表示复合对象的内部结构
- ✅ 表示临时或局部的值
- ❌ 不能跨文档引用（无全局ID）
- ❌ 查询时难以追踪

### 2. RDF容器与列表

#### Bag（无序集合）
```turtle
:myBag a rdf:Bag ;
  rdf:_1 "apple" ;
  rdf:_2 "banana" ;
  rdf:_3 "cherry" .
```

#### Seq（有序集合）
```turtle
:mySeq a rdf:Seq ;
  rdf:_1 "Chapter 1" ;
  rdf:_2 "Chapter 2" ;
  rdf:_3 "Chapter 3" .
```

#### List（封闭列表 - 推荐使用）
```turtle
# 简洁写法
:myList rdf:value ( :a :b :c ) .

# 展开后的完整结构
:myList rdf:value _:l1 .
_:l1 rdf:first :a ;
     rdf:rest _:l2 .
_:l2 rdf:first :b ;
     rdf:rest _:l3 .
_:l3 rdf:first :c ;
     rdf:rest rdf:nil .
```

**选择建议**：
- 🎯 **Bag**：无序且可重复，适合标签集合
- 🎯 **Seq**：有序且可重复，适合有序清单
- 🎯 **List**：有序、封闭、结构清晰，适合大多数场景

## 四、RDF重述 (Reification)：对陈述的陈述

### 问题场景

如何表达："张三认为蒙娜丽莎在卢浮宫"

这是一个**关于陈述本身的陈述**（陈述的陈述）。

### 使用 rdf:Statement

```turtle
# 原始陈述
:Mona_Lisa :locatedIn :Louvre .

# 对陈述本身进行描述
:stmt1 a rdf:Statement ;
    rdf:subject :Mona_Lisa ;
    rdf:predicate :locatedIn ;
    rdf:object :Louvre .

# 关于陈述的断言
:ZhangSan :believes :stmt1 .
:stmt1 :confidence 0.9 .
:stmt1 :source :History_Book_2024 .
```

### ⚠️ 注意事项

- **问题**：Reification 会生成大量额外节点，显著增加数据量
- **替代方案**：
  - 使用 **Named Graphs**：为不同的陈述组提供上下文
  - 使用 **事件/观测实体**：创建轻量级中间类

```turtle
# 更轻量的替代方案：事件模式
:observation1 a :Observation ;
    :subject :Mona_Lisa ;
    :predicate :locatedIn ;
    :object :Louvre ;
    :observer :ZhangSan ;
    :confidence 0.9 .
```

## 五、RDFS：RDF的模式层

> RDFS 在RDF三元组的基础上增加**推理规则**，使机器能够自动推导新知识。

### 1. 核心推理词汇

#### rdfs:subClassOf（类的包含关系）

```turtle
:Doctor rdfs:subClassOf :Person .
:GregoryHouse rdf:type :Doctor .

# 推理结果：
# :GregoryHouse rdf:type :Person . ← 自动推导
```

**逻辑**：所有医生都是人，如果某个体是医生，那么它也是人。

#### rdfs:domain 和 rdfs:range（属性约束）

```turtle
# 定义属性的定义域和值域
:hasWife rdfs:domain :Man ;
         rdfs:range :Woman .

# 事实
:John :hasWife :Mary .

# 推理结果：
# :John rdf:type :Man .     ← 宾语来自domain
# :Mary rdf:type :Woman .   ← 宾语来自range
```

**直观理解**：
- `domain` = 这个属性的主语应该是什么类型
- `range` = 这个属性的宾语应该是什么类型

#### rdfs:subPropertyOf（属性的包含关系）

```turtle
:hasFather rdfs:subPropertyOf :hasParent .
:John :hasFather :Tom .

# 推理结果：
# :John :hasParent :Tom . ← 自动推导
```

### 2. RDFS推理规则速查表

| 规则 | 前提 | 推理结论 | 说明 |
|------|------|---------|------|
| rdfs9 | `C1 ⊑ C2` 且 `X: C1` | `X: C2` | 子类传递 |
| rdfs11 | `P1 ⊑ P2` 且 `(S,P1,O)` | `(S,P2,O)` | 子属性传递 |
| rdfs2 | `P: domain C` 且 `(S,P,O)` | `S: C` | 定义域推断 |
| rdfs3 | `P: range C` 且 `(S,P,O)` | `O: C` | 值域推断 |

### 3. 完整推理示例

```turtle
@prefix : <http://example.org/> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .

# === TBox（模式定义）===
:Doctor rdfs:subClassOf :Person .
:hasWife rdfs:domain :Man ;
         rdfs:range :Woman .
:hasSpouse rdfs:subPropertyOf :knows .

# === ABox（具体事实）===
:GregoryHouse rdf:type :Doctor .
:John :hasWife :Mary .
:Tom :hasSpouse :Jerry .

# === 推理结果 ===
# 1. 由rdfs9：:GregoryHouse rdf:type :Person .
# 2. 由rdfs2：:John rdf:type :Man .
# 3. 由rdfs3：:Mary rdf:type :Woman .
# 4. 由rdfs11：:Tom :knows :Jerry .
```

### 4. 简单模型理论 (Semantics)

**三元组的真值判定**：

在一个解释 $\mathcal{I}$ 下，三元组 $(s, p, o)$ 为**真**，当且仅当：
$$\text{映射后的对 } (s^{\mathcal{I}}, o^{\mathcal{I}}) \in p^{\mathcal{I}}$$

**直观理解**：
- 把 RDF 三元组看作一条图的边
- 在虚拟世界中检查这条边是否存在

# 第三部分：本体与描述逻辑

## 一、本体的本质 (Ontology)

### 1. 定义 (Gruber, 1993)

> **本体是概念模型的明确、形式化、共享的规范。**

分解理解：

| 特性 | 含义 | 例子 |
|------|------|------|
| **概念模型** | 对领域的抽象 | 定义"什么是车"的特征 |
| **明确** (Explicit) | 所有约束都被显式定义 | 不依赖隐含假设 |
| **形式化** (Formal) | 机器可读，有严密逻辑 | 用数学符号而非自然语言 |
| **共享** (Shared) | 达成共识，可交流 | 而非私人观点 |

### 2. 本体 vs RDFS

| 方面 | RDFS | OWL本体 |
|------|------|--------|
| **表达能力** | 基础（子类、属性） | 强大（复杂约束、推理） |
| **推理能力** | 简单推导 | 自动分类、一致性检测 |
| **应用场景** | 轻量级标注 | 企业知识管理、AI推理 |

---

## 二、描述逻辑 (Description Logic, DL)：本体的逻辑基础

> DL是OWL的数学基础，主要使用 $\mathcal{ALC}$ 语言。掌握DL是理解OWL和自动推理的关键。

### 1. DL的三个基本构成

#### 概念 (Concepts)
- **定义**：对应到类（如 `Person`, `Doctor`, `Female`）
- **集合论表示**：一个集合 $C \subseteq \Delta^{\mathcal{I}}$
- **例子**：$Person^{\mathcal{I}} = \{\text{john}, \text{mary}, \text{tom}\}$

#### 角色 (Roles)
- **定义**：对应到二元关系（如 `parentOf`, `owns`, `locatedIn`）
- **集合论表示**：一个二元有序对的集合 $R \subseteq \Delta^{\mathcal{I}} \times \Delta^{\mathcal{I}}$
- **例子**：$parentOf^{\mathcal{I}} = \{(\text{tom}, \text{john}), (\text{tom}, \text{mary})\}$

#### 概念构造算子 (Concept Constructors)
- **定义**：用来构建复杂概念的操作符
- **对应关系**：逻辑运算 ↔ 集合运算

### 2. 概念构造算子详解

**完整对照表**：

| 符号 | 逻辑含义 | 集合论定义 | 自然语言例子 |
|------|---------|----------|-----------|
| $C \sqcap D$ | 交集 (AND) | $C^{\mathcal{I}} \cap D^{\mathcal{I}}$ | 女物理学家 = 女人 ∩ 物理学家 |
| $C \sqcup D$ | 并集 (OR) | $C^{\mathcal{I}} \cup D^{\mathcal{I}}$ | 医学专业 = 医生 ∪ 律师 |
| $\neg C$ | 补集 (NOT) | $\Delta^{\mathcal{I}} \setminus C^{\mathcal{I}}$ | 不死的 = 全体 - 死者 |
| $\exists R.C$ | 存在量词 | $\{x \mid \exists y: (x,y) \in R^{\mathcal{I}} \wedge y \in C^{\mathcal{I}}\}$ | 至少养一只猫的人 |
| $\forall R.C$ | 全称量词 | $\{x \mid \forall y: (x,y) \in R^{\mathcal{I}} \rightarrow y \in C^{\mathcal{I}}\}$ | 所有孩子都是医生的人 |

### 3. 算子的直观理解与示例

#### $\exists R.C$（存在量词 / Some）

```
定义：$\exists hasChild.Doctor = 至少有一个孩子是医生的人
外延：{人物1（有医生孩子）, 人物2（有医生孩子）, ...}
```

#### $\forall R.C$（全称量词 / Only）

```
定义：$\forall hasChild.Doctor = 所有的孩子都是医生的人
外延：{人物1（所有孩子都是医生）, 人物2（所有孩子都是医生）, ...}
注意：如果一个人没有孩子，也满足这个条件（空真 vacuous truth）
```

#### 复杂组合示例

```
Female ⊓ (∃hasChild.Doctor) ⊓ (∀hasSpouse.Rich)
= 女性 且 有医生孩子 且 所有配偶都很富有
```

## 三、知识库的三层结构

### 知识库 $\mathcal{K} = \langle \mathcal{T}, \mathcal{R}, \mathcal{A} \rangle$

知识库由三个部分组成，从宏观到微观、从规则到具体。

#### 1️⃣ TBox (Terminological Box) - 概念定义层

**作用**：定义概念（类）之间的关系和约束

**包含关系**（Inclusion）：
```
Student ⊑ Person
        ↓
所有学生都是人
```

**等价关系**（Equivalence）：
```
Man ≡ Person ⊓ Male
     ↓
男人 = 人 且 男性
```

**示例TBox**：
```turtle
:Doctor ⊑ :Person .
:Surgeon ⊑ :Doctor .
:PhysicalTherapist ⊑ ¬:Doctor ⊓ :HealthProfessional .
```

#### 2️⃣ RBox (Role Box) - 关系特征层

**作用**：定义属性（角色）的特征和相互关系

**关系包含**：
```
hasFather ⊑ hasParent
        ↓
如果X是Y的父亲，则X是Y的父母
```

**关系特征**：
- **传递性** (Transitive)：如果X是Y的祖先，Y是Z的祖先，则X是Z的祖先
- **对称性** (Symmetric)：如果X和Y相识，则Y和X相识
- **反对称性** (Asymmetric)：如果X是Y的父亲，则Y不是X的父亲

**示例RBox**：
```turtle
:hasFather ⊑ :hasParent .
:ancestor rdf:type rdf:Property ;
    rdf:type owl:TransitiveProperty .
:knows rdf:type owl:SymmetricProperty .
```

#### 3️⃣ ABox (Assertional Box) - 事实断言层

**作用**：描述具体个体及其相互关系

**概念断言**（Concept Assertion）：
```
Person(john)
    ↓
约翰是一个人
```

**角色断言**（Role Assertion）：
```
hasChild(john, mary)
      ↓
约翰的孩子是玛丽
```

**示例ABox**：
```turtle
:john rdf:type :Person .
:mary rdf:type :Doctor .
:john :hasChild :mary .
:tom :knows :jerry .
```

### 三层的逻辑关系

```
TBox（规则层）  →  定义"医生是什么"
   ↓
RBox（特征层）  →  定义"父子关系的特性"
   ↓
ABox（事实层）  →  具体的个体和关系
   ↓
推理机         →  根据规则推导新事实
```

## 四、形式语义：判定真假的方式

### 1. 解释 (Interpretation)

**定义**：一个解释 $\mathcal{I}$ 由两部分组成：

- **论域** $\Delta^{\mathcal{I}}$：非空的个体集合（如 {john, mary, tom}）
- **解释函数** $\cdot^{\mathcal{I}}$：将逻辑符号映射到集合论对象

**映射规则**：
- 概念 → 论域的子集
- 角色 → 论域元素对的集合

**例子**：
```
论域 Δ^I = {john, mary, tom}

Person^I = {john, mary, tom}（三个都是人）
Doctor^I = {mary, tom}（玛丽和汤姆是医生）
hasChild^I = {(john, mary), (john, tom)}（约翰有两个孩子）
```

### 2. 满足 (Satisfaction)

**定义**：

- 一个解释 $\mathcal{I}$ **满足**一个公理，当且仅当公理在该解释下为真
- 一个解释 $\mathcal{I}$ 是知识库 $\mathcal{K}$ 的一个**模型**，如果它满足 $\mathcal{K}$ 中所有的公理
- 知识库 $\mathcal{K}$ 是**一致的**（consistent），如果它至少有一个模型；否则是**不一致的**

**公理满足的数学定义**：

| 公理类型 | 符号 | 满足条件 |
|---------|------|--------|
| 包含 | $C \sqsubseteq D$ | $C^{\mathcal{I}} \subseteq D^{\mathcal{I}}$ |
| 等价 | $C \equiv D$ | $C^{\mathcal{I}} = D^{\mathcal{I}}$ |
| 关系包含 | $R \sqsubseteq S$ | $R^{\mathcal{I}} \subseteq S^{\mathcal{I}}$ |
| 概念断言 | $C(a)$ | $a^{\mathcal{I}} \in C^{\mathcal{I}}$ |
| 角色断言 | $R(a,b)$ | $(a^{\mathcal{I}}, b^{\mathcal{I}}) \in R^{\mathcal{I}}$ |

**直观类比**：
- 解释 = 虚拟世界的配置
- 满足 = 公理在这个世界中成立
- 模型 = 与所有公理都相符的虚拟世界

# 第四部分：Tableau推理算法

## 一、推理的目标与核心思想

### 推理目标

给定知识库 $\mathcal{K}$，证明：
- 一个陈述是否被蕴含（entailed）
- 例：证明 $\mathcal{K} \models Person(john)$（约翰是人吗？）

### 核心思想

使用**反证法 (Proof by Contradiction) + 推理树 (Search Tree)**

```
目标：证明 K ⊨ C(a)

步骤1：假设相反 → 加入 ¬C(a)
步骤2：尝试找到满足所有约束的模型
步骤3：如果所有分支都产生矛盾(clash) → 无模型存在 → 原目标成立
       如果存在无矛盾分支 → 模型存在 → 原目标不成立
```

---

## 二、Tableau算法的执行步骤

### 准备阶段：公式标准化

将所有复杂的逻辑公式转化为基本形式

| 转换前 | 转换后 | 说明 |
|-------|--------|------|
| $C \sqsubseteq D$ | $\neg C \sqcup D$ | 包含转化为析取 |
| $C \sqcap D$ | 保留 | 与（交集） |
| $\neg(C \sqcup D)$ | $\neg C \sqcap \neg D$ | De Morgan律 |
| $\neg \exists R.C$ | $\forall R.\neg C$ | 量词转化 |

### 执行阶段：推理树扩展

**例子**：证明 $\mathcal{K} \models Doctor(house)$

已知：
- TBox：$Doctor \sqsubseteq Person$
- ABox：$Doctor(house)$

证明步骤：

```
初始 ABox：
┌─ house: ¬Doctor  ← 反证（假设house不是医生）

应用规则展开：
├─ Doctor ⊑ Person 变为 ¬Doctor ⊔ Person
├─ 从 house: ¬Doctor 和析取规则
│  → 必须验证 Person(house)
│
└─ 检查冲突：
   ✓ house: ¬Doctor（在ABox中）
   ✓ house: Doctor（由原TBox推导）
   ✗ 冲突！

结论：所有分支都产生矛盾 → K ⊨ Doctor(house) 成立
```

### 冲突检测 (Clash Detection)

**冲突的类型**：

1. **直接冲突**：同一个体同时包含 $A$ 和 $\neg A$
   ```
   john: Person  AND  john: ¬Person  ✗ clash
   ```

2. **空概念冲突**：个体被分配给空概念 $\perp$
   ```
   john: ⊥  ✗ clash
   ```

3. **限制冲突**：违反 `∀R.C` 或 `∃R.C` 的限制
   ```
   ∀hasChild.Doctor 但 john有个孩子不是医生  ✗ clash
   ```

### 分支与选择

当遇到 **析取** ($C \sqcup D$) 时，创建两个分支

```
初始：x: (Doctor ⊔ Lawyer)

分支1：        分支2：
x: Doctor      x: Lawyer
检查...        检查...
```

- ✅ **所有分支都冲突** → 原假设错误 → 原结论成立
- ⚠️ **至少一个分支无冲突** → 存在模型 → 原结论不成立

## 三、手工推理演练

### 示例1：简单包含关系

**知识库**：
```
TBox: Doctor ⊑ Person
ABox: Doctor(gregory_house)

目标：证明 Person(gregory_house)
```

**推理过程**：

```
Step 1: 反证 → 加入 ¬Person(gregory_house)
Step 2: 转化 Doctor ⊑ Person → ¬Doctor ⊔ Person
Step 3: 尝试满足所有约束
        - gregory_house: Doctor（已知）
        - gregory_house: ¬Person（反证假设）
        - 由包含：gregory_house: Person（推导）
Step 4: 检查冲突
        Person 和 ¬Person 同时存在 → CLASH
Step 5: 所有分支关闭 → 目标成立

结论：Person(gregory_house) ✓
```

### 示例2：量词与选择

**知识库**：
```
TBox: CatLover ⊑ ∃hasPet.Cat
ABox: CatLover(alice)

目标：证明存在某个cat
```

**推理过程**：

```
Step 1: 反证 → 假设不存在cat宠物
Step 2: alice: CatLover（已知）
Step 3: 由规则 CatLover ⊑ ∃hasPet.Cat
        → alice: ∃hasPet.Cat
Step 4: 从存在量词
        → 创建新个体 x
        → alice: hasPet(x)
        → x: Cat
Step 5: 没有冲突 → 模型存在 → 存在cat宠物

结论：通过扩展知识库，自动创建了新个体
```

## 二、描述逻辑语义（第4-5题）

### 知识点速查表

| 知识点 | 核心内容 | 考查形式 |
|--------|---------|--------|
| **解释** | 论域 + 映射函数 | 给定解释，计算概念的外延 |
| **量词** | ∃R.C / ∀R.C的集合论定义 | 判断元素是否属于量词概念 |
| **逆关系** | R⁻的定义与应用 | 给定R，推导R⁻ |
| **公理满足** | C ⊑ D 当且仅当 C^I ⊆ D^I | 验证某个解释是否满足公理 |

### 考题高频模式

#### 模式1：计算量词的外延

**题目**：已知论域 Δ^I = {1,2,3,4}，关系
```
successor^I = {(1,2), (2,3), (3,4)}
```
求 ∃successor.{3,4} 的外延

**答案**：
```
∃successor.{3,4} = {x | ∃y: (x,y)∈successor^I 且 y∈{3,4}}
                  = {1,2}（1的后继是2，2的后继是3，都在{3,4}中）
```

#### 模式2：验证公理满足性

**题目**：解释I中，
```
Positive^I = {2,3,4}（正数）
successor^I = {(1,2), (2,3), (3,4)}
```
是否满足 ∀successor⁻.Positive ⊑ Positive？

**答案**：
```
步骤1：∀successor⁻.Positive 的外延
     = {x | ∀y: (y,x)∈successor^I → y∈Positive^I}
     = {2,3,4}（每个数的前任都在Positive中）

步骤2：检查 {2,3,4} ⊆ {2,3,4}？
     → 是的 ✓

结论：满足该公理
```

## 三、Tableau推理与一致性（第6题）

### 知识点速查表

| 知识点 | 核心内容 | 应用 |
|--------|---------|------|
| **反证法** | ¬目标加入ABox | 启动Tableau推理 |
| **标准化** | C⊑D变为¬C⊔D | 转化为基本形式 |
| **展开规则** | 应用约束规则 | 逐步扩展ABox |
| **冲突检测** | 寻找A和¬A | 关闭分支 |
| **一致性** | 所有分支关闭 → 不可满足 | 判定知识库矛盾 |

### 标准化规则速查表

| 原始形式 | 标准化后 | 说明 |
|---------|---------|------|
| $C \sqsubseteq D$ | $\neg C \sqcup D$ | 包含转化为析取 |
| $\neg(C \sqcap D)$ | $\neg C \sqcup \neg D$ | De Morgan律 |
| $\neg(C \sqcup D)$ | $\neg C \sqcap \neg D$ | De Morgan律 |
| $\neg \exists R.C$ | $\forall R.\neg C$ | 量词转化 |
| $\neg \forall R.C$ | $\exists R.\neg C$ | 量词转化 |

### 考题高频模式

#### 模式：一致性检测

**题目**：检测以下知识库是否一致
```
TBox: Penguin ⊑ Bird
      Bird ⊑ Flies
      Penguin ⊑ ¬Flies
ABox: Penguin(tweety)
```

**推理过程**：

```
目标：检测ABox ∪ TBox 是否满足

初始ABox：
tweety: Penguin

应用TBox规则：
1. Penguin(tweety) + Penguin⊑Bird
   → tweety: Bird

2. Bird(tweety) + Bird⊑Flies
   → tweety: Flies

3. Penguin(tweety) + Penguin⊑¬Flies
   → tweety: ¬Flies

冲突检测：
tweety: Flies AND tweety: ¬Flies  ✗ CLASH!

所有分支都关闭 → 知识库不可满足（不一致）
```

Model base = ModelFactory.createDefaultModel();
