## 语义网概览：从 Document Web 到 Data Web

- 文档网（Web of Documents）
  - 核心：HTML 页面，供人阅读，基于超链接连接信息。
  - 问题：页面关注呈现而非语义，导致机器难以理解内容（歧义，如“Jaguar”）。

- 数据网（Web of Data / Semantic Web）的愿景
  - 核心：以实体/资源（Things/Entities）为单位，使用具有语义的链接（typed links）连接实体。
  - 优点：机器可以理解链接的意义并进行自动化推理、集成与跨站点操作（例如自动组合旅行预订数据）。

---

## 语义网技术栈（Layer Cake）

1. URI / IRI 与 Unicode：为每个实体提供全局标识与国际化支持。
2. XML / 文档格式：基础数据封装（历史遗留层）。
3. RDF（Resource Description Framework）：用三元组表示事实，是语义网的核心数据层。
4. RDFS / OWL：模式（vocabulary）与本体（ontology），用于定义类、属性、约束与复杂语义。
5. SPARQL：对图数据的查询语言（模式匹配）。
6. Logic / Proof / Trust：基于逻辑的推理、证明与可信度机制（例如数据来源验证、证明链）。

## RDF 基础：术语与三元组

- 重要术语
  - URI（或 IRI）：资源的全局标识符（例如 `http://dbpedia.org/resource/Beijing`）。
  - Literal（字面量）：带类型或语言标签的数据值（”北京”@zh, “2024-03-15”^^xsd:date）。
  - Blank node（匿名节点）：没有全局 ID 的中间节点，用于描述复合值或局部结构。

- 三元组（Triple）
  - 形式： (Subject, Predicate, Object)
  - 数学约束：谓语（Predicate）必须是 URI；主体与客体可为 URI、匿名节点或字面量（客体可以是字面量）。

---

## 常用序列化：Turtle（可读性高）

示例：基本三元组与简写用法

```turtle
@prefix : <http://example.org/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

:Alice :knows :Bob ;
       :age 25 ;
       :hobby “Reading” , “Coding” , “Hiking” .
```

说明：
- 分号 `;` 用于复用主语。
- 逗号 `,` 用于复用谓语（多个对象）。
- 数字在某些解析器会被映射为 xsd:integer。

N-Triples（最原始、逐行格式）示例：

```nt
<http://example.org/Alice> <http://example.org/knows> <http://example.org/Bob> .
```

## RDF 进阶：匿名节点、容器与列表

- 匿名节点（Blank Nodes）
  - 用途：当某个值本身有内部结构（例如地址）但不需要全局标识时使用。
  - 示例：

```turtle
:Alice :hasAddress [
  :city :Beijing ;
  :street “Zhongguancun” ;
  :postcode “100080”
] .
```

- 容器（rdf:Bag、rdf:Seq）与列表（rdf:List）
  - Bag：无序集合；Seq：有序集合；List：封闭列表，可用 `( :a :b :c )` 语法表示。

---

## RDF 的“陈述的陈述”：Reification（重述）与更好的替代方案

- Reification：把一条三元组作为一个资源来描述（使用 `rdf:Statement`, `rdf:subject`, `rdf:predicate`, `rdf:object`）。
- 示例：

```turtle
:stmt1 a rdf:Statement ;
  rdf:subject :Mona_Lisa ;
  rdf:predicate :locatedIn ;
  rdf:object :Louvre .

:ZhangSan :believes :stmt1 .
```

- 注意：reification 会生成许多额外节点，实际工程中常用更轻量的模式（如为断言创建带属性的事件/观测实体）或使用 Named Graphs 来表示声明的来源/上下文。

## RDFS：模式层与基本推理

- 关键构件
  - rdfs:subClassOf：类的包含关系（层级推理）。
  - rdfs:domain / rdfs:range：属性的域和值域，会触发类型推断。

- 例子：

```turtle
:Doctor rdfs:subClassOf :Person .
:GregoryHouse rdf:type :Doctor .
# 推理出 :GregoryHouse rdf:type :Person .

:hasWife rdfs:domain :Man ;
         rdfs:range :Woman .
:John :hasWife :Mary .
# 推理出 :John rdf:type :Man ; :Mary rdf:type :Woman .
```

- 常见 RDFS 推理规则（节选）
  - 子类传递性（subClassOf 传递）
  - 子属性传递性（subPropertyOf 传递）
  - domain/range 导出类型断言（见上例）

## 本体（Ontology）与描述逻辑（Description Logic, DL）

- 本体（Gruber 定义）：一个明确、形式化且可共享的概念模型。它把领域概念与关系用机器可读的形式规定下来（OWL 是常用的实现）。

- 描述逻辑的三要素
  - 概念（Concepts）= 类（例如 Person）
  - 角色（Roles）= 二元关系（例如 parentOf）
  - 概念构造算子（交/并/补、存在/全称等）

- 常用算子及直观含义
  - C ⊓ D（交集 / AND）
  - C ⊔ D（并集 / OR）
  - ¬C（补集 / NOT）
  - ∃R.C（存在）——存在一个通过 R 指向 C 的个体
  - ∀R.C（全称）——所有通过 R 指向的个体都属于 C

---

## 知识库结构：TBox / RBox / ABox

- TBox（Terminological Box）：概念与类的定义（模式层）。
  - 示例： Student ⊑ Person

- RBox（Role Box）：关系的性质（如传递性、对称性、角色包含）。
  - 示例： hasFather ⊑ hasParent， ancestor 为传递关系。

- ABox（Assertional Box）：具体个体与断言（实例数据）。
  - 示例： Person(john), hasChild(john, mary)

---

## 形式语义（Interpretation / Model）与一致性

- 解释（Interpretation I）由论域 Δ^I 和解释函数映射组成：将概念映射为 Δ^I 的子集、将角色映射为 Δ^I 的二元关系。
- 一个知识库有模型（存在 I 满足所有公理）则称为一致（consistent）；否则为不一致（inconsistent）。
- 公理的满足性（示例）：C ⊑ D 在解释 I 下成立当且仅当 C^I ⊆ D^I。

## Tableau 推理算法（核心：反证 + 展开规则）

- 目标：证明知识库 K 蕴含某个结论或检测 K 是否一致。
- 基本思想：对要证明的断言取反加入 ABox，使用展开规则将复杂公式分解成原子断言，构造推理树并寻找冲突（clash）。

步骤概要：
1. 将 ¬目标断言加入 ABox（反证）。
2. 反复应用展开规则（例如针对 ⊓、⊔、∃、∀ 的规则）扩展 ABox 与推理树分支。
3. 在每个分支上检查冲突（例如 x:A 与 x:¬A 同时出现）。若一分支发生冲突则关闭该分支。
4. 若所有分支均关闭，则原结论成立；若存在一个打开分支且无法继续展开，则原结论不成立。

- 常见冲突类型：
  - 同一节点同时包含 A 与 ¬A
  - 存在个体被断言属于空概念 ⊥

- 手工练习建议：
  - 在纸上构造推理树并标注每一步的展开规则与新产生的断言。
  - 练习把 TBox 公理转化为等价的公式（例如 C ⊑ D 转化为 ¬C ⊔ D），便于展开。

## 作业要点与练习建议（对应课堂作业）

1. 对于 RDF/RDFS 题（第1-3题）：
   - 熟练写出三元组并理解 domain/range 导出的类型推断。
   - 能根据 rdfs:subClassOf 做层级推导。

2. 对于描述逻辑语义题（第4-5题）：
   - 理解解释（interpretation）的结构，能判断某解释是否满足给定公理。
   - 用具体小域（例如小的有限集或自然数）手工验证算子含义。

3. 对于 Tableaux 与一致性检测（第6题）：
   - 手写推理树，逐步应用展开规则并查找 clash。
   - 练习把复杂公理拆解成基本规则后再展开 ABox。

## 常用工具与验证方法（实践指南）

- Protégé（GUI）：用于构建 OWL 本体、可视化类层次、运行内置推理机（例如 HermiT、Pellet）。
- 命令行 / 程序化验证：可用 RDF4J、Apache Jena、OWL API 等库在代码中加载 TTL/OWL 并运行推理器。

快速示例（保存为 example.ttl）

```turtle
@prefix : <http://example.org/> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .

:Doctor rdfs:subClassOf :Person .
:GregoryHouse rdf:type :Doctor .
```

在 Protégé 中打开或用 Jena/HermiT 加载后，可断言 :GregoryHouse rdf:type :Person 是否能被推理机导出。

## 结语（精要）

- RDF 提供表达事实的最小单元（三元组），RDFS/OWL 在其上增加语义与约束，使机器能够做出类型推断与逻辑推理。
- 描述逻辑与 Tableau 推理算法是理解 OWL 本体语义与自动化推理的理论基础。
- 工程实践中，要注意可伸缩性与可解释性：在使用 reification 时权衡复杂性，优先考虑 Named Graphs 或事件/观测实体模式来表示断言来源与上下文。
