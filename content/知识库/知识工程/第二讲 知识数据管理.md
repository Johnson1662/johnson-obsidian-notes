## 一、知识数据表示（RDF）

### 1.1 RDF 基础概念

#### 什么是RDF？

- **RDF** = Resource Description Framework（资源描述框架）
- **W3C标准**：是Web语义化的基础标准
- **核心理念**：用三元组（Triple）来描述任何资源和关系

#### RDF三元组结构

```
(主语, 谓语, 宾语) = (Subject, Predicate, Object)
```

**举例说明**（以电影《泰坦尼克号》为例）：

```
(James_Cameron, directs, Titanic)
→ 主语：导演詹姆斯·卡梅隆
→ 谓语：指导
→ 宾语：电影《泰坦尼克号》
```

#### RDF三元组的三种成分类型

| 成分位置        | 允许类型            | 说明                     |
| --------------- | ------------------- | ------------------------ |
| 主语(Subject)   | URI、空节点         | 必须是资源或实体         |
| 谓语(Predicate) | URI                 | 必须是属性或关系         |
| 宾语(Object)    | URI、空节点、字面值 | 可以是资源、实体或具体值 |

**具体解释**：

- **URI**（统一资源标识符）：用网址形式唯一标识资源
- **空节点**：代表不命名的资源
- **字面值**：具体的数据值，如字符串、数字、日期等

### 1.2 RDF图与RDF数据集

#### RDF图（RDF Graph）

- **定义**：一组RDF三元组的集合
- **特点**：形成一个有向图结构
- **表示方法**：G = {(s₁,p₁,o₁), (s₂,p₂,o₂), ...}

#### 泰坦尼克号电影数据的RDF图示例

**可视化图**：

```
James_Cameron ─[directs]→ Titanic ←[acts_in]─ Leonardo_DiCaprio
    ↓                         ↓                      ↓
   type: Director        type: Movie          type: Actor
   name: "James..."      label: "Titanic..."  name: "Leonardo..."
   birthDate: 1954-08-16  length: 195        birthDate: 1974-11-11
   networth: 1.79E9       budget: 2.0E8

                         ←[acts_in]─ Kate_Winslet
                                        ↓
                                   type: Actor
                                   name: "Kate..."
                                   birthDate: 1975-10-05
```

**完整的三元组集合**：

```
G = {
  (James_Cameron, rdf:type, Director),
  (James_Cameron, name, "James Cameron"),
  (James_Cameron, birthDate, 1954-08-16),
  (James_Cameron, networth, 1.79E9),
  (James_Cameron, directs, Titanic),
  (Titanic, rdf:type, Movie),
  (Titanic, label, "Titanic (1997 film)"),
  (Titanic, length, 195),
  (Titanic, budget, 2.0E8),
  (Leonardo_DiCaprio, rdf:type, Actor),
  (Leonardo_DiCaprio, name, "Leonardo DiCaprio"),
  (Leonardo_DiCaprio, birthDate, 1974-11-11),
  (Leonardo_DiCaprio, acts_in, Titanic),
  (Kate_Winslet, rdf:type, Actor),
  (Kate_Winslet, name, "Kate Winslet"),
  (Kate_Winslet, birthDate, 1975-10-05),
  (Kate_Winslet, acts_in, Titanic)
}
```

#### RDF的优势

✅ **通用性强**：可以表示任何领域的知识
✅ **互操作性好**：基于W3C标准，易于共享和集成
✅ **扩展性强**：新数据、新关系可以随时添加
✅ **查询灵活**：支持复杂的图查询

## 二、RDF扩展（RDF\*）

### 2.1 RDF的局限性

**问题**：RDF无法直接为三元组本身添加属性

**举例**：
如果演员Leonardo_DiCaprio在《泰坦尼克号》中的角色是"杰克·道森"，RDF怎么表示？

```
(Leonardo_DiCaprio, acts_in, Titanic)  ← 这个三元组本身需要一个属性：role="Jack Dawson"
```

### 2.2 RDF\*的解决方案

#### RDF Reification（对三元组的三元化）

**方法**：使用rdf:Statement将三元组转化为对象

```turtle
_:acts_in_1 rdf:type rdf:Statement .
_:acts_in_1 rdf:subject Leonardo_DiCaprio .
_:acts_in_1 rdf:predicate acts_in .
_:acts_in_1 rdf:object Titanic .
_:acts_in_1 role "Jack Dawson" .
```

**缺点**：

- 代码繁琐冗长
- 增加四倍的三元组数量
- 查询复杂困难

#### RDF\* 的新语法（推荐）

**简洁表示**：

```
<< Leonardo_DiCaprio acts_in Titanic >> role "Jack Dawson"
```

**优点**：

- 语法简洁直观
- 可以嵌套（三元组作为主宾语）
- 支持递归式元数据

### 2.3 RDF\* 的应用场景

| 场景         | 说明                   | 三元组示例                                   |
| ------------ | ---------------------- | -------------------------------------------- |
| **表演角色** | 演员在电影中扮演的角色 | `<< Actor acts_in Movie >> role "role_name"` |
| **排序信息** | 关系的排序或优先级     | `<< A knows B >> priority 5`                 |
| **时间信息** | 三元组有效的时间段     | `<< A owns B >> validFrom "2020-01-01"`      |
| **置信度**   | 数据的可信度或概率     | `<< Claim >> confidence 0.8`                 |
| **来源信息** | 数据的来源             | `<< Fact >> source "Wikipedia"`              |

## 三、三元组存储系统（Triplestore）

### 3.1 什么是Triplestore？

**定义**：专门设计用来存储和查询RDF三元组的数据库系统

**核心特性**：

- 存储RDF三元组
- 支持语义查询（SPARQL）
- 支持推理（基于OWL本体）
- 支持链接数据（Linked Data）

### 3.2 Apache Jena 简介

#### Jena是什么？

| 特性     | 说明                   |
| -------- | ---------------------- |
| **类型** | Java框架 + Triplestore |
| **用途** | 构建语义网应用         |
| **存储** | 内存或磁盘存储         |
| **查询** | SPARQL查询             |
| **推理** | OWL本体推理            |

#### Jena Fuseki 服务器

**Jena Fuseki** 是Jena的SPARQL服务器实现

**主要特性**：

- ✅ Web界面管理
- ✅ SPARQL端点
- ✅ 数据上传与下载
- ✅ 图形化查询工具

- 📊 **查询编辑器**：编写和执行SPARQL查询

- 📥 **数据下载**：导出查询结果
- 📋 **数据统计**：查看数据库统计信息
- 🔍 **简单查询**：预定义的常用查询

#### 数据格式支持

| 格式         | 说明             | 特点            |

## 四、属性图数据库

### 4.1 什么是属性图？

**定义**：一种比RDF图更灵活的图数据模型

#### 属性图的五大要素

| 要素     | 说明         | 类型                    |
| -------- | ------------ | ----------------------- |
| **V**    | 顶点集合     | 实体或对象              |
| **E**    | 边集合       | 关系或连接              |
| **Lᵥ**   | 顶点标签函数 | 给顶点标记类型          |
| **Lₑ**   | 边标签函数   | 给边标记关系类型        |
| **Attr** | 属性函数     | 给顶点/边添加键值对属性 |

#### 与RDF的区别

| 特性     | RDF图          | 属性图          |
| -------- | -------------- | --------------- |
| 主要成分 | 三元组(S,P,O)  | 顶点和边        |
| 节点标签 | 有限           | 可以有多个标签  |
| 边标签   | 同一类型       | 每条边一个标签  |
| 属性存储 | 需要额外三元组 | 直接在节点/边上 |
| 灵活性   | 相对严格       | 更灵活          |

#### 电影数据的属性图示例

**图形表示**：

```
【顶点】
v1: Director
  - name = "James Cameron"
  - birthDate = 1954-08-16
  - networth = 1.79E9

v2: Movie
  - label = "Titanic (1997 film)"
  - length = 195
  - budget = 2.0E8

v3: Actor
  - name = "Leonardo DiCaprio"
  - birthDate = 1974-11-11

v4: Actor
  - name = "Kate Winslet"
  - birthDate = 1975-10-05

【边】
e1: directs (v1 → v2)
e2: acts_in (v3 → v2, role="Jack Dawson")
e3: acts_in (v4 → v2, role="Rose DeWitt")
```

### 4.2 社交网络属性图示例

**场景描述**：一个小型社交网络

**图形结构**：

```
【用户节点】
San Zhang (中国) ─[knows]─ Si Li (中国) ─[knows]─ Bob Smith (美国)

【关系】
- San Zhang [likes] Post1: "I love Chinese food" (2018-08-22)
- Si Li [likes] Post1 (2018-09-15)
- Bob Smith [dislikes] Post2: "Blue is my favorite color" (2018-07-18)

【标签】
- San Zhang [follower] ─标签→ Chinese
```

**应用价值**：

- 📱 推荐系统（基于朋友喜好）
- 👥 社区发现（聚集相似用户）
- 🔗 关系分析（用户之间的距离）

### 6.2 SPARQL 查询语言

#### SPARQL 基础

**SPARQL** = SPARQL Protocol and RDF Query Language

- **标准历程**：
  - 2008年：SPARQL 1.0（W3C推荐）
  - 2013年：SPARQL 1.1（当前标准）
- **标准地址**：https://www.w3.org/TR/sparql11-query/

#### SPARQL 的四大查询类型

| 查询类型      | 作用         | 语法关键字  |
| ------------- | ------------ | ----------- |
| **SELECT**    | 选择返回变量 | SELECT ?var |
| **ASK**       | 检查是否存在 | ASK         |
| **CONSTRUCT** | 构造新RDF图  | CONSTRUCT   |
| **DESCRIBE**  | 描述资源     | DESCRIBE    |

#### SPARQL 查询的核心概念

**1. Triple Patterns（三元组模式）**

```sparql
?subject ?predicate ?object
```

变量用`?`前缀表示，其他为常量

**2. Basic Graph Patterns（基本图模式）**

```sparql
WHERE {
  pattern1 .
  pattern2 .
}
```

多个三元组模式用点号分隔

**3. Complex Graph Patterns（复杂图模式）**

- OPTIONAL：可选模式
- UNION：并集模式
- FILTER：过滤条件

**4. Property Paths（属性路径）**

| 操作符 | 含义       | 示例                          |
| ------ | ---------- | ----------------------------- |
| `/`    | 路径连接   | `a/b/c` 表示通过a、b、c的路径 |
| `\|`   | 路径并集   | `a\|b` 表示通过a或b的路径     |
| `*`    | Kleene闭包 | `a*` 表示0次或多次a           |
| `+`    | Kleene加   | `a+` 表示1次或多次a           |
| `^`    | 反向边     | `^a` 表示反向的a关系          |

#### SPARQL 查询示例详解

**示例 1：查询James Cameron导演的所有电影**

```sparql
SELECT ?x
WHERE {
  dbr:James_Cameron dbo:directs ?x .
}
```

**执行逻辑**：

- 查找所有满足`James_Cameron directs ?x`的三元组
- 返回所有?x的值

**预期结果**：

```
?x = Titanic
```

---

**示例 2：查询James Cameron导演的电影及其标签**

```sparql
SELECT ?x1 ?x2
WHERE {
  dbr:James_Cameron dbo:directs ?x1 .
  ?x1 rdfs:label ?x2 .
}
```

**执行逻辑**：

1. 第一行：找出`James_Cameron directs ?x1`的电影
2. 第二行：找出这些电影的标签`?x1 label ?x2`
3. 返回电影及其标签

**预期结果**：

```
?x1 = Titanic,  ?x2 = "Titanic (1997 film)"
```

---

**示例 3：查询1954年8月16日出生的导演所导演的电影**

```sparql
SELECT ?x2
WHERE {
  ?x1 dbo:directs ?x2 .
  ?x1 rdf:type dbo:Director .
  ?x1 dbo:birthDate "1954-08-16"^^xsd:date .
}
```

**执行逻辑**：

1. 第一行：找出所有导演关系
2. 第二行：确保?x1是导演类型
3. 第三行：过滤出出生日期为1954-08-16的导演
4. 返回这些导演的电影

**关键点**：

- `rdf:type`：表示"是...类型的"
- `"1954-08-16"^^xsd:date`：类型化字面值（日期类型）

---

**示例 4：复杂条件查询 - 净资产>10亿且出生于1950年后的导演所导电影中的演员**

```sparql
SELECT ?x5
WHERE {
  ?x1 rdf:type dbo:Director .
  ?x1 dbo:birthDate ?x2 .
  FILTER (?x2 >= "1950-01-01"^^xsd:date)

  ?x1 dbo:networth ?x3 .
  FILTER (?x3 > 1.0E9)

  ?x1 dbo:directs ?x4 .
  ?x5 dbo:acts_in ?x4 .
}
```

**执行逻辑**：

1. 找出所有导演
2. 检查导演的出生日期是否在1950年之后
3. 检查导演的净资产是否超过10亿
4. 找出这些导演导演的电影
5. 找出在这些电影中演出的演员

**FILTER用途**：

- 数值比较：`>`, `<`, `>=`, `<=`, `=`, `!=`
- 字符串操作：`contains()`, `strlen()`, 等
- 布尔逻辑：`&&`, `||`, `!`

---

**示例 5：路径查询 - 查询所有有"共演"关系的演员对**

```sparql
SELECT ?x1 ?x2
WHERE {
  ?x1 (dbo:acts_in / ^dbo:acts_in)* ?x2 .
  FILTER (?x1 != ?x2)
  ?x1 rdf:type dbo:Actor .
  ?x2 rdf:type dbo:Actor .
}
```

**属性路径解释**：

```
(dbo:acts_in / ^dbo:acts_in)*

acts_in：演员演出的电影
^acts_in：反向的演出关系（从电影找演员）

→ 表示：演员 → 电影 → 演员 → 电影 → ...（任意次）
→ 实现：通过共同演出的电影连接演员
```

**执行逻辑**：

1. 查找所有通过电影连接的演员对
2. 过滤掉自己与自己的配对（`?x1 != ?x2`）
3. 确保两者都是演员

**预期结果**：

```
?x1 = Leonardo_DiCaprio,  ?x2 = Kate_Winslet  (共演Titanic)
```

### 6.3 Cypher 查询语言

#### Cypher 简介

| 特性         | 说明                                     |
| ------------ | ---------------------------------------- |
| **所有者**   | Neo4j公司                                |
| **开放性**   | openCypher（https://www.opencypher.org） |
| **设计理念** | 更直观，接近自然语言                     |
| **使用场景** | Neo4j属性图数据库查询                    |

#### Cypher 基础语法

**节点与关系表示**：

| 符号            | 含义     | 示例            |
| --------------- | -------- | --------------- |
| `()`            | 节点     | `(node)`        |
| `-[ ]->`        | 有向关系 | `-[rel]->`      |
| `()--()`        | 无向关系 | 双向连接        |
| `:Label`        | 标签     | `(actor:Actor)` |
| `{prop: value}` | 属性     | `{name: "Tom"}` |

**基本操作**：

| 操作     | 语法   | 含义               |
| -------- | ------ | ------------------ |
| **匹配** | MATCH  | 查找满足模式的路径 |
| **返回** | RETURN | 返回查询结果       |
| **过滤** | WHERE  | 添加条件过滤       |
| **创建** | CREATE | 创建新节点/关系    |
| **更新** | SET    | 修改节点/关系属性  |
| **删除** | DELETE | 删除节点/关系      |

#### Cypher 与 SPARQL 对比

**例：查询James Cameron导演的电影（SPARQL示例2）**

**SPARQL 版本**：

```sparql
SELECT ?x1 ?x2
WHERE {
  dbr:James_Cameron dbo:directs ?x1 .
  ?x1 rdfs:label ?x2 .
}
```

**Cypher 版本**：

```cypher
MATCH (:Director {name: "James Cameron"})-[:directs]->(x:Movie)
RETURN x, x.label
```

**对比**：

| 特性     | SPARQL   | Cypher    |
| -------- | -------- | --------- |
| 可读性   | 数据流式 | 图形化    |
| 学习曲线 | 较陡     | 较平缓    |
| 适用场景 | RDF数据  | 属性图    |
| 性能     | 依赖存储 | Neo4j优化 |

---

**例：复杂查询 - 查询净资产>10亿且出生于1950年后的导演所导电影中的演员**

**Cypher 版本**：

```cypher
MATCH (x1:Director)-[:directs]->(:Movie)<-[:acts_in]-(x2:Actor)
WHERE x1.networth > 1.0E9 AND x1.birthDate >= date("1950-01-01")
RETURN x2
```

**Cypher 优势**：

- 模式清晰：`-[:directs]->` 直观表示"导演"关系
- 过滤简洁：WHERE子句类似SQL
- 属性访问：`x1.networth` 直接访问属性

## 📊 知识结构总结表

### 数据模型对比

| 维度         | RDF             | RDF\*           | 属性图          |
| ------------ | --------------- | --------------- | --------------- |
| **基本单位** | 三元组          | 三元组+元三元组 | 顶点+边+属性    |
| **元数据**   | 需要reification | 原生支持        | 直接存储        |
| **推理支持** | OWL本体         | 有限            | 无              |
| **查询语言** | SPARQL          | SPARQL\*        | Cypher/PGQL     |
| **典型系统** | Jena、Virtuoso  | RDF4J           | Neo4j、ArangoDB |

### 工具对比

| 工具            | 类型        | 适用场景           | 学习难度 |
| --------------- | ----------- | ------------------ | -------- |
| **Jena Fuseki** | Triplestore | 语义网、本体推理   | 中等     |
| **Neo4j**       | 图数据库    | 社交网络、推荐系统 | 低       |
| **其他**        | 混合型      | 不同应用领域       | 各异     |

## 📝 核心概念速记表

| 概念            | 定义                 | 关键特征                     |
| --------------- | -------------------- | ---------------------------- |
| **RDF**         | 资源描述框架         | (S,P,O)三元组，W3C标准       |
| **Triplestore** | 三元组存储系统       | 专门存储RDF，支持SPARQL查询  |
| **属性图**      | 带属性的有向图       | 顶点、边、属性、标签         |
| **图数据库**    | 存储和查询图的数据库 | 如Neo4j、ArangoDB            |
| **SPARQL**      | RDF查询语言          | W3C标准，1.0(2008)→1.1(2013) |
| **Cypher**      | Neo4j查询语言        | openCypher开源，更直观       |
| **RDF\***       | RDF扩展标准          | 支持三元组的元数据           |
