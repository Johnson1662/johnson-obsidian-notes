# RAG-Agent项目设计思路和学习方法

> 视频时长：14分53秒 | 发布时间：2026-03-18
> UP主：骑猪撞宝马71（985硕，前腾讯现微软）

## 一、项目背景

- 项目从去年12月开始做，初衷是帮助同学有项目投递暑期实习
- 已有不少同学用这个项目拿到暑期实习offer
- UP主本人已拿到6个offer，在面试中发现RAG是高频考点

## 二、项目设计的三个原则

### 原则1：高度面向面试

- 总结了面试官最常问的RAG知识点，全部融入项目实践
- 涵盖：切块(Chunking)、向量数据库、召回(Retrieval)、重排(Rerank)、评估等核心环节
- 之前UP主的RAG项目很简单（只有向量检索，没用数据库/BM25/召回优化），面试深入问时是减分项
- 这个项目把面试官问的所有理论点变成了真正的实践

### 原则2：RAG最完整的实战项目

- 配套任何一本RAG书籍学习都适用
- 完整串起RAG全流程：数据加载 → 切块 → 向量化 → 存储 → 检索 → 召回优化 → 重排 → 评估
- 每一部分都使用了实际策略（不是玩具代码）
- 学完这个项目 = 掌握了RAG的整体流程

### 原则3：高度可集成

- 项目由两部分组成：**MCP** + **RAG系统**
  - MCP：可以方便集成到任何客户端（Claude、Cursor等）
  - RAG系统：任何需要文档检索的业务场景都能用
- 写简历时不是"我做了个RAG项目"，而是"我在XX业务中用自研RAG系统提升了XX%准确率"
- 可扩展性强：可以从本地MCP改为远程server、Docker部署、升级为Graph RAG / Agentic RAG等

## 三、学习路线（三步走）

### 第一阶段：学Spec（约2-3周）

- 阅读项目的设计文档（Spec），非常详细，包含架构图
- 需要掌握的基础概念：
  - 什么是MCP
  - 什么是Embedding/向量化
  - 什么是分割器(Splitter)
  - 什么是BM25检索
  - 什么是重排(Rerank)
  - 什么是向量数据库
- 如果零基础直接看代码，大概率看不懂
- Spec写得非常细，细到可以让AI照着写代码

### 第二阶段：写代码（约2-3天）

- 项目被拆分为约50-60个小阶段，每个阶段只完成一件事
- 建议：
  - 不要逐行精读代码（太慢，2个月也做不完）
  - 也不要完全不管细节只看生成结果
  - **推荐做法**：看每个阶段的输入输出、核心接口、单元测试
  - 单元测试是理解代码功能的好工具
- 目标：做完后知道检索模块在哪、每个模块大概做了什么
- 有网友用2天就完成了（但理解深度有限）

### 第三阶段：面试准备（3月份开始）

- 结合项目经验准备面试
- 能够清晰讲述项目架构、技术选型、优化策略

## 四、关键RAG技术栈

从视频中提取的技术关键词：

- **分割器**：LangChain RecursiveCharacterTextSplitter
- **向量化**：Embedding模型
- **检索**：向量检索 + BM25混合检索
- **重排**：Reranker
- **数据库**：向量数据库（具体未点名）
- **评估**：RAG评估指标
- **框架**：LangChain
- **协议**：MCP (Model Context Protocol)

## 五、简历写法建议

- 不要写成"我做了个RAG-Agent项目"
- 要结合自身业务场景：
  - "在XX系统中集成了一个自研RAG系统，用于XX场景的文档检索"
  - "通过多路召回+重排策略，将检索准确率从XX%提升到XX%"
- 有真实业务数据支撑最佳

## 六、扩展方向

- 将本地MCP改为远程server（Docker部署）
- 升级为Graph RAG
- 升级为Agentic RAG
- 结合具体业务场景做垂直优化
