# 简历项目与学习路线

> 给职业生涯规划课用。7 个项目全部来自 AgentGuide 仓库真实内容，都是你还没做过、能写进简历的实战项目。按优先级排序：先打底，再拔高。

## 先记住 3 条规矩

- 所有简历 bullet 里的数字都是**占位符**（`【】`），必须自己跑出来实测再填。照抄等于编造，面试一追问就穿帮。
- 仓库定的"简历级项目"硬标准：能 clone 跑通的最小 demo + 清晰的 agent loop / 工具注册 / 上下文管理 / 权限边界 + trace + 至少 20 条 eval case + 一段复盘（为什么这么设计、替代方案、哪个机制真带来提升）。少一样都不算能写进简历。

## 优先级总览

| 顺序 | 项目 | 主攻方向 | 难度 | 耗时 | 为什么排这里 |
|:--:|:--|:--|:--:|:--:|:--|

| 4 | 旅行规划 Multi-Agent | 多 Agent / 工具编排 | ⭐⭐⭐⭐ | 2-3 周 | 展示任务分解、状态机、human-in-the-loop |

## 1. Paper Agent：论文研读与综述助手 ⭐ 首推

- **来源**：仓库蓝图 [projects/01-paper-agent/README.md](./projects/01-paper-agent/README.md)；README"项目一：自动化论文检索与分析 Agent"；外部参考 [GPT Researcher](https://github.com/assafelovic/gpt-researcher)、[STORM](https://github.com/stanford-oval/storm)
- **解决什么**：研究员找论文、读论文、写综述全靠手工，慢且容易漏引、错引。做成"给个主题就检索+精读+带证据出综述"的 Agent。
- **核心技术点**：arXiv / Semantic Scholar 检索 + PDF 解析；分层 context builder 管 query、候选论文、证据片段、草稿；每条结论保留 paper/page/section 引用；Agentic RAG 多跳检索 + rerank；幻觉控制；20 条 eval case（主题检索、单篇精读、证据引用、幻觉识别）。
- **简历 bullet 示例**（算法岗）：
  > 构建论文研读 Agent，接入 arXiv、Semantic Scholar 与 PDF 解析工具，用分层 context builder 管理检索与生成上下文；为每条综述结论保留 paper/page/section 引用，在 20 条 eval case 上统计引用准确率、幻觉率与成本，引入 query decomposition + rerank 将正确引用率从【72%】提升至【88%】，并完成 BM25 / Dense / GraphRAG 三组 baseline 对比与消融。
- **难度/耗时**：⭐⭐⭐，2-3 周。里程碑仓库已拆好：检索+综述 → PDF解析+证据 → 多源检索+对比 → 评测+复盘。
- **要补什么**：RAG 全流程（切分、混合检索、rerank）、引用溯源、LLM-as-Judge 评测。

## 2. Agent 自动化评估 Harness

- **来源**：[docs/04-interview/20-resume-guide.md](./docs/04-interview/20-resume-guide.md) 模板 3；[resources/agent/evaluation-harness.md](./resources/agent/evaluation-harness.md)；[docs/02-tech-stack/26-agent-evaluation-harness-guide.md](./docs/02-tech-stack/26-agent-evaluation-harness-guide.md)
- **解决什么**：Agent 改完"感觉变好了"没法证明。做一个离线评测流水线，让每次改动都能用数据说话。这是给后面所有项目接的通用底座。
- **核心技术点**：测试集管理 + LLM-as-Judge + 规则评分 + 回归对比；把任务完成率、工具调用正确率、成本、P95 延迟进统一报告；接入 [Promptfoo](https://github.com/promptfoo/promptfoo) / [DeepEval](https://github.com/confident-ai/deepeval) / [agentevals](https://github.com/langchain-ai/agentevals) 做轨迹诊断；PR 前自动门禁。
- **简历 bullet 示例**：
  > 设计面向工具调用 Agent 的离线评估流水线，支持测试集管理、LLM-as-Judge 与回归对比；统一报告任务完成率、工具调用正确率、平均成本和 P95 延迟，接入 CI 做质量门禁；对比 Promptfoo、DeepEval 后自研轻量脚本适配课程项目，通过持续评估定位工具参数错误、上下文污染、拒答边界不稳三类高频失败，修复后端到端通过率从【68%】升至【82%】。
- **难度/耗时**：⭐⭐⭐，1-2 周。
- **要补什么**：评测指标定义、LLM-as-Judge 的校准、失败分类。做完立即拿项目 1 当第一个试验田。

## 3. 长期记忆 Agent（Mem0 二开）

- **来源**：[resources/agent/memory.md](./resources/agent/memory.md)；开源项目 [Mem0](https://github.com/mem0ai/mem0)、[MemGPT](https://github.com/cpacker/MemGPT)、[Zep](https://github.com/getzep/zep)、[Cognee](https://github.com/topoteretes/cognee)
- **解决什么**：普通 Agent 跨会话失忆，重复问、记错、记了又召回不到。做一个有长期记忆的个人助理，对比不同记忆策略的效果和成本。
- **核心技术点**：记忆写入/更新/遗忘策略；向量+图混合存储；记忆召回与压缩；关掉 memory 的消融实验；多轮任务成功率、召回相关度、token 成本对比。
- **简历 bullet 示例**：
  > 基于 Mem0 构建跨会话长期记忆 Agent，实现记忆抽取、去重、衰减与图+向量混合召回；构建 20 条多轮对话 eval case，关闭记忆作为 baseline，记忆召回使用户偏好类任务成功率从【61%】提升至【84%】，token 消耗降低【30%】，并完成"全量存储 / 摘要压缩 / 选择性遗忘"三组策略消融。
- **难度/耗时**：⭐⭐⭐，2-3 周。
- **要补什么**：记忆架构（MemGPT 的分层思想）、向量库、消融实验设计。

## 4. 旅行规划 Multi-Agent

- **来源**：仓库蓝图 [projects/02-travel-agent/README.md](./projects/02-travel-agent/README.md)；README"项目二/五：旅行规划 Multi-Agent 系统"；框架参考 [AutoGen](https://github.com/microsoft/autogen)、[CrewAI](https://github.com/crewAIInc/crewAI)、[LangGraph](https://github.com/langchain-ai/langgraph)
- **解决什么**：旅行规划需求多、约束多（预算/天气/无障碍），单一 Agent 容易顾此失彼，且预订付款不能让 Agent 自己拍板。
- **核心技术点**：Planner / Researcher / Budgeter / Critic 多角色；状态机 + 任务队列控制协作顺序，解决循环调用和上下文膨胀；POI、地理编码、路线、天气工具组合；预算约束与冲突消解；对预订、付款、敏感凭据设 human-in-the-loop。
- **简历 bullet 示例**：
  > 基于 LangGraph 设计 Planner、Researcher、Budgeter、Critic 四类 Agent，用状态机和任务队列控制协作，接入 POI、路线、天气工具生成带预算拆分和备选方案的行程；对预订付款设 human-in-the-loop，在 50 条真实需求上评估约束满足率、路线合理性与安全合规率，工具调用成功率提升至【94%】，并通过状态机改造消除循环调用。
- **难度/耗时**：⭐⭐⭐⭐，2-3 周。
- **要补什么**：LangGraph 状态图、多 Agent 通信与终止条件、权限分级。

## 5. Web Agent：浏览器任务自动化与评测

- **来源**：仓库蓝图 [projects/03-web-agent/README.md](./projects/03-web-agent/README.md)；README"项目三：Web Agent"；评测环境 [BrowserGym](https://github.com/ServiceNow/BrowserGym)、[WebArena](https://webarena.dev/)、[OSWorld](https://github.com/xlang-ai/OSWorld)
- **解决什么**：让 Agent 自己看网页、点按钮、填表完成任务的闭环，难点在"看得懂页面 + 出错能自纠 + 结果能评测"。
- **核心技术点**：Playwright 工具封装；结构化观察层（URL、可访问性树、交互元素摘要、截图）；动作选择与自我修正；每步截图/DOM/动作 trace；本地可控测试站点 + 公开文档任务各 20 条 eval case。
- **简历 bullet 示例**：
  > 构建公开网页任务 Web Agent，封装 Playwright 工具与结构化观察层，基于 URL、可访问性树、元素摘要和截图做动作选择，加入"识别错误→分析原因→调整策略"自纠机制；设计本地测试站点 20 条 eval case，逐步记录截图与动作 trace，任务成功率达【75%】（较 baseline +【10】pp），平均步数【6.2】，高风险动作拦截率【100%】。
- **难度/耗时**：⭐⭐⭐⭐⭐，3-4 周。
- **要补什么**：多模态观察、浏览器自动化、benchmark 复现。注意安全边界，别拿真实账号乱测。

## 6. Youtu-GraphRAG 二开

- **来源**：[resources/project-catalogs/agent-harness-projects.md](./resources/project-catalogs/agent-harness-projects.md) 第 5 节；[Youtu-GraphRAG](https://github.com/TencentCloudADP/youtu-graphrag)、[Microsoft GraphRAG](https://github.com/microsoft/graphrag)
- **解决什么**：普通向量 RAG 处理多跳、需要证据链的问题很弱。GraphRAG 用图结构连接建图、检索和推理，适合做算法向的深水区项目。
- **核心技术点**：领域 graph schema 设计；建图→检索→推理链路；多跳证据召回；与向量 RAG 的对照 + 消融；索引与查询成本分析。
- **简历 bullet 示例**（算法岗）：
  > 基于 Youtu-GraphRAG 构建领域图检索问答，改造领域 graph schema 并接入自有语料；在自建 300 条多跳 QA 集上，与向量 RAG 做对照，多跳证据召回从【58%】提升至【79%】，端到端正确率提升【13】pp，完成建图策略与检索深度的消融实验，并记录索引与查询成本。
- **难度/耗时**：⭐⭐⭐⭐⭐，3-4 周。
- **要补什么**：知识图谱基础、图检索算法、消融实验。上游报告的数字不能直接写进简历，只做复现问题的起点。

## 7. 轻量 Harness 二开（OpenHarness / nanobot）

- **来源**：[resources/project-catalogs/agent-harness-projects.md](./resources/project-catalogs/agent-harness-projects.md) 第 1 节；[HKUDS/OpenHarness](https://github.com/HKUDS/OpenHarness)、[HKUDS/nanobot](https://github.com/HKUDS/nanobot)；[docs/02-tech-stack/27-agent-harness-engineering.md](./docs/02-tech-stack/27-agent-harness-engineering.md)
- **解决什么**：只会调框架不够，要证明你懂 Agent Loop、上下文压缩、工具权限、任务隔离这些底层机制。选一个轻量 Harness 精读并做一处明确二开。
- **核心技术点**：先画调用链图（模型调用→工具调用→观察回写）；上下文分层与压缩；新增一个领域工具或 Skill + 权限边界；dry-run / 人工确认；用 trace 和回归用例证明改动有效。
- **简历 bullet 示例**：
  > 精读 OpenHarness 的 Agent Loop 与上下文管理机制，为其增加【领域工具/Skill】及工具授权测试；在 20 个固定任务、相同模型和预算下与未修改版对照，端到端完成率从【70%】升至【83%】，上下文压缩使 token 开销降低【45%】，并留存失败 trace、配置诊断与回归用例。
- **难度/耗时**：⭐⭐⭐⭐，3-4 周。
- **要补什么**：Agent Harness 工程、源码阅读方法、权限与隔离设计。起点选 OpenHarness 或 nanobot，把一处机制讲透。

## 学习路线：先打底，再拔高

**阶段一 · 打底（第 1-5 周）**
1. 先做 **项目 1 Paper Agent**：它一轮就把检索、解析、引用、上下文、评测全走通，最贴你的目标岗位。
2. 同步插入 **项目 2 评估 Harness**：学会用数据说话，然后回头把项目 1 的 eval 补全。这两个做完，简历上就有第一个能追问的强项目。

**阶段二 · 补短板（第 6-11 周）**
3. **项目 3 记忆 Agent**：直接补记忆能力，和项目 1 的上下文工程形成一条主线。
4. **项目 4 旅行 Multi-Agent**：补多 Agent 编排和权限边界，让技术栈从"单 Agent"扩到"系统"。

**阶段三 · 拔高（第 12 周起，按目标岗位二选一）**
5. 冲开发岗 → **项目 5 Web Agent** 或 **项目 7 轻量 Harness 二开**。
6. 冲算法岗 → **项目 6 Youtu-GraphRAG 二开**。

**最终简历怎么组合**：一页简历放 2-3 个强项目即可。推荐"Paper Agent（RAG 主线）+ 记忆 Agent 或 Multi-Agent（能力广度）+ 一个拔高项目（深度）"。其余项目当技术博客和 demo 链接的补充，不要全堆上去。

## 每个项目交付前自查

- 数字是实测的，不是抄示例占位。
- 能讲清背景、你的动作、结果、复盘四件事。
- 能回答：为什么选这个架构、指标怎么算的、失败的 case 有哪些、数据量扩大 10 倍怎么改。
- GitHub / demo 链接能打开，clone 后按 README 跑得通。
- 技术栈分组写，不乱堆关键词；AI 辅助写的代码，简历上按真实贡献边界写，不包装成独立开发。
