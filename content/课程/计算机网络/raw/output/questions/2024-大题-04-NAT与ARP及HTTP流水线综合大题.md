# 2024-2025期末 · 压轴大题 5 (NAT表项配置、ARP空表抓包与HTTP流水线RTT计算)

> [!question] 2024-2025期末 · 压轴大题 5 (NAT表项配置、ARP空表抓包与HTTP流水线RTT计算)
> 网络拓扑：服务器 IP 为 `192.168.0.2`（内网），通过交换机接入路由器 R（内网口 IP `192.168.0.1`，外网口 IP `202.155.0.1`）；外网口经交换机连接外网主机 A（IP `202.155.0.2`）。主机 A 欲访问内网服务器的 8080 端口。
> 
> 1. 此时路由器 R 的 NAT 表项应如何配置以允许双向数据进出？
> 2. 主机 A 的 ARP 表初始为空，现在要向外发送数据包 P，说明之后的网络行为、ARP 请求与应答数据类型、源目 IP/MAC，以及 ARP 缓存条目 TTL 的作用。
> 3. 详细写出数据报通过路由器 R 时，R 左右两端口上的数据帧源目 IP 与源目 MAC 变化。
> 4. 在 HTTP/1.1 Pipelining 协议下，主机 A 请求一个包含 5 张内嵌图片的网页（图片大小忽略不计），共需要几个 RTT？
> 
> **考点**：NAT转换表, ARP过程, 路由器端口变换, HTTP-Pipeline, RTT计算 | **分值**：20分 | **关联概念**：[[04-网络层#NAT网络地址转换]]

> [!check]- 参考答案与解析（点击展开）
> **参考答案与逐步拆解**：
> 
> ### 1. NAT 端口转发配置
> - 外网主动访问内网服务，必须配置**端口映射（Port Forwarding）**：
>   - 外网访问入口：`202.155.0.1:8080`
>   - 内网转发目标：`192.168.0.2:8080`
>   - NAT 映射表项：`WAN IP 202.155.0.1 : 8080 <===> LAN IP 192.168.0.2 : 8080`
> 
> ### 2. 主机 A 的 ARP 全过程与 TTL 作用
> 1. **A 发送 ARP 请求**：
>    - 目的 IP 为默认网关 R（`202.155.0.1`）。
>    - A 发送以太网广播帧（目的 MAC: `FF-FF-FF-FF-FF-FF`），帧载荷为 ARP 请求包。
> 2. **R 响应 ARP**：
>    - 路由器 R 收到广播，识别自身 IP，向 A 单播返回 ARP 应答帧（源 MAC: R的外网口MAC，目的 MAC: A的MAC）。
> 3. **A 建立条目**：A 记录 `(202.155.0.1, R的外网口MAC)` 写入本地 ARP 缓存表。
> 4. **TTL（Time-To-Live）的作用**：
>    - ARP 表中的条目在 TTL（通常 20 分钟）过期后自动丢弃删除。
>    - 作用：适应网络设备的动态变化（如网卡热插拔、IP 重新分配、设备移动），防止过期的陈旧物理地址长期锁定导致通信黑洞。
> 
> ### 3. 路由器 R 左右两端口的 IP 与 MAC 变换
> - **数据流入 R 右端（外网口）时**：
>   - 帧头：源 MAC = A 的 MAC，目的 MAC = R 的外网口 MAC
>   - IP头：源 IP = `202.155.0.2`，目的 IP = `202.155.0.1`，目的端口 = `8080`
> - **NAT 转换后从 R 左端（内网口）发出时**：
>   - 帧头：源 MAC = R 的内网口 MAC，目的 MAC = 服务器的 MAC
>   - IP头：源 IP = `202.155.0.2`（或路由公网IP），**目的 IP 被 NAT 替换为内网服务器 IP `192.168.0.2`**，目的端口 = `8080`
> 
> ### 4. HTTP/1.1 Pipelining 请求 5 张图片的总 RTT
> 1. 建立 TCP 连接：**1 个 RTT**。
> 2. 请求并获取基础 HTML 文件：**1 个 RTT**。
> 3. 解析到 5 张图片后，客户端通过已有 TCP 连接在一个 RTT 内连续并发发出所有 5 张图片的流水线请求，并集中返回：**1 个 RTT**。
> - **总计**：$1 + 1 + 1 =$ **3 个 RTT**。
