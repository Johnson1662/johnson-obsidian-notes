# 1 概述

一句话：数据挖掘 = 从**大量的、不完全的、有噪声的、模糊的、随机的**实际应用数据中，提取**隐含的、事先不知道的、潜在有用**的信息和知识。

课件重点掌握三条：**数据挖掘的概念、数据挖掘的任务、挖掘过程。**

# 1.1 背景

| 事实                                                                                            | 结论                   |
| ----------------------------------------------------------------------------------------------- | ---------------------- |
| 信息量约每 20 个月翻一倍，数据量从 TB 到 PB                                                     | 数据收集与可获得性空前 |
| 来源：商业（Web/电商/交易/股市）、科学（遥感/生物信息/模拟）、社会与个人（新闻/相机/微信/抖音） | 数据来源极其丰富       |
| 数据库系统能高效地录入、查询、统计，但**无法发现数据中的关系和规则，无法预测未来趋势**          | 只有数据、缺少知识     |

> 我们被数据所淹没，但却渴望知识 —— 数据挖掘 = **海量数据的自动分析技术**，应运而生。

# 1.2 基本概念

## 1.2.1 数据 → 信息 → 知识 → 智慧

| 层次 | 课件定义                                                                     | 例                                         |
| ---- | ---------------------------------------------------------------------------- | ------------------------------------------ |
| 数据 | 对客观事件进行记录并可以鉴别的符号；可存储于数据库、数据仓库和其他信息资料库 | 表：TID/Items；$35,38,40,39$               |
| 信息 | 有含义、有逻辑、经过加工处理的、对决策有价值的**数据流**（具有时效性）       | 某人四天体温分别为 $35,38,40,39$ ℃         |
| 知识 | 把有关信息**关联**在一起形成的信息结构；形式为模式、关联、变化、异常等       | 事实“雪是白色的”、规则“头痛且流涕可能感冒” |
| 智慧 | 基于已有知识，针对问题用获得的信息分析、对比、演绎以找出方案的能力           | 据此判断并处理                             |

$$
\text{数据经处理加工}\to\text{信息},\quad \text{信息之间产生联系}\to\text{知识},\quad \text{串联知识发现新关系}\to\text{智慧}
$$

数据的三个要点：类型（连续型=数值；离散型=标称、二元、序数）、主要问题（**不一致、错误、缺失**）。

## 1.2.2 数据挖掘定义

定义（技术角度）：从**大量的、不完全的、有噪声的、模糊的、随机的**实际应用数据中，提取**隐含在其中的、人们事先不知道的、但又是潜在有用**的信息和知识的过程。

| 定义包含的三层含义                                         |
| ---------------------------------------------------------- |
| 数据源是真实的、海量的、含噪声的                           |
| 发现的是用户感兴趣的知识；知识要**可接受、可理解、可运用** |
| 不要求发现放之四海皆准的知识，仅支持特定的发现问题         |

与传统数据分析方法的区别（即数据的四大挑战）：

| 特点               | 说明                                                                |
| ------------------ | ------------------------------------------------------------------- |
| 海量数据           | 算法需高度可扩展，能有效处理 TB 级数据                              |
| 高维数据           | 可达数万个不同的维                                                  |
| 高度复杂、非结构化 | 文本、图像、视频、Web；时序数据；图、社会网络、多关系数据；异构数据 |
| 噪声数据           | 含误差、异常                                                        |

不是数据挖掘系统：**数据库系统、信息系统、数据统计分析系统**。数据挖掘关注更广的范围，是多学科融合；且**挖掘出的信息越是出乎意料，可能越有价值**。

| 之后           | 数据挖掘最初只是 KDD 中处理数据的一个步骤，逐渐演变成 KDD 的**同义词**             |

| 进化阶段                        | 商业问题                           | 支持技术                      | 产品特点                           |
| ------------------------------- | ---------------------------------- | ----------------------------- | ---------------------------------- |
| 数据访问（80 年代）             | 去年三月销售额是多少？             | RDBMS、SQL、ODBC              | 记录级历史性、动态数据信息         |
| 数据仓库（90 年代）             | 销售额是多少？据此可得出什么结论？ | OLAP、多维数据库、数据仓库    | 各层次回溯的、动态的数据信息       |
| 大数据分布式（00 年代）         | 如何处理海量异构数据挖掘行为规律？ | Hadoop、NoSQL、MapReduce      | 支持 PB 级海量异构数据批处理       |
| 深度学习与智能自动化（10 年代） | 如何自动识别复杂模式、精准预测？   | 深度学习、GPU、流计算、AutoML | 自动特征工程，多模态，精度大幅提升 |
| AI 原生与数据智能（20 年代）    | 如何用自然语言直接查询数据？       | 大语言模型、向量数据库、MLOps | 自然语言交互、自助式分析、智能决策 |

当前热点的三类技术：

| 方向            | 代表工作与要点                                                                                                                                                                                                                                       |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 大模型 / LDM    | 大模型从大规模数据提取知识；**LDM 结构化数据基础模型**：TabPFN-3.5（支持分类/回归/时序/异常，原生处理缺失、百万行）、LimiX-2（400M 参数，跨变量联合依赖）                                                                                            |
| AutoML / AutoFE | AutoML 自动化数据处理、模型选择、超参优化（NAS、贝叶斯优化、遗传、强化学习、元学习）；AutoGluon 集成多种模型。AutoFE 做特征选择/生成/转换，工具分三类：开源库（Featuretools/TSFresh）、商用低代码平台、一站式平台（FDL/Databricks/Snowflake）        |
| AI 数据科学代理 | 从“辅助写代码”到“自动迭代实验”：AutoGen（多智能体协作）、LangGraph（循环控制+状态管理）、Phidata、DS-STAR（“分析—顺序规划—结果验证—方案修正”循环）。**合理定位**：适合生成基线、排查报错、批量实验；数据泄漏检查、验证集设计与最终提交仍应由人工审核 |

# 1.4 挖掘过程 KDD

| 顺序 | 步骤         | 干什么                                                |
| ---- | ------------ | ----------------------------------------------------- |
| 1    | 数据清理     | 消除噪声或不一致的数据（**可能占全过程 60% 工作量**） |
| 2    | 数据集成     | 多种数据源组合到一起                                  |
| 3    | 数据选择     | 从数据库中提取与分析任务相关的数据                    |
| 4    | 数据变换     | 变换或统一成适合挖掘的形式                            |
| 5    | 挖掘算法设计 | 用智能方法提取模式（关联规则、分类、聚类、回归）      |
| 6    | 性能评估     | 按兴趣程度度量识别真正有趣的模式                      |
| 7    | 知识表示     | 向用户提供挖掘的知识                                  |

口诀：**清集选变，挖评表。** 前四步属于**数据预处理**。

| 步骤要点     | 内容                                                                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据预处理   | 包括选择（选相关数据）、净化（消除噪声冗余）、推测（推算缺值）、转换（离散↔连续）、缩减（减少数据量）；准备得好坏直接影响挖掘效率、准确度和模式有效性 |
| 挖掘算法设计 | 最为关键的一步；常用算法：关联规则、决策树、SVM、神经网络、k-means、线性回归                                                                          |
| 性能评估     | 得到的模式多为数学表达式，难以被人理解，需解释成可理解的方式呈现给用户                                                                                |
| 知识表示     | 目的是**运用**：① 看知识本身描述的关系或结果即可支持决策；② 对新数据运用知识，可能产生新问题从而需进一步优化                                          |
| 过程性质     | **需要多次循环反复**，每一步与预期目标不符都要回到前面重新调整、重新执行                                                                              |

典型数据挖掘系统的体系结构（自下而上）：数据库/数据仓库 → 服务器（数据清洗、集成、过滤）→ 知识库 → 挖掘算法 → 性能评估 → 图形用户界面。

# 1.5 主要任务

宏观两大类：

| 类型       | 定义                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| 预测性方法 | 利用已知变量的信息预测未知或未来的其它变量：$\text{解释变量}\to\text{目标变量}$ |
| 描述性方法 | 找到人类可理解的模式来描述数据                                                  |

课件给的配对关系（**记住这四组对应**）：

| 挖掘模式 | 配套话题     | 核心内容                                                                                                                                                        |
| -------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 关联分析 | 推荐系统     | 发现经常一起出现的属性-值条件元组；规则 $X\Rightarrow Y$ 表示满足 $X$ 的元组很可能满足 $Y$；用于交易数据分析、定向市场、商品目录设计                            |
| 分类     | 长尾分布     | 分析类别已知的数据集建立模型，预测类别未知的数据项；模型形式：IF-THEN 规则、决策树、神经网络。长尾：80/20 法则，80% 样本集中在 20% 的头部类别，尾部类别样本稀少 |
| 聚类分析 | 离群点分析   | 又称“同质分组”或“无监督的分类”，把数据分成簇，簇内相似、簇间远，相似性由距离函数度量。好的聚类：类内相似性尽可能大、类间相似性尽可能小                          |
| 回归     | 时间序列分析 | 与分类类似，但预测的是**连续数值**。时间序列：搜索相似序列/子序列，挖掘序列模式、周期性、趋势与偏差，对未来作估计                                               |

| 离群点                 | 说明                                                         |
| ---------------------- | ------------------------------------------------------------ |
| 定义                   | 与数据的一般行为或模型不一致的孤立数据                       |
| 常被当作噪声丢弃，但…… | 欺骗检测中恰恰通过对罕见事件做离群点分析得出结论             |
| 应用                   | 信用卡欺诈检测、移动电话欺诈检测、客户划分、医疗分析（异常） |

分类 vs 聚类（最爱考）：

| 维度     | 分类               | 聚类                 |
| -------- | ------------------ | -------------------- |
| 标签     | 有标签             | 无标签               |
| 学习方式 | 监督               | 无监督               |
| 目标     | 预测已有类别       | 自动发现群体         |
| 一句话   | 类别已知，学怎么分 | 类别未知，自己找类别 |

判断口诀：**类别 → 分类，数值 → 回归，没标签分组 → 聚类，找共同出现 → 关联分析。**

# 1.6 与其他学科的关系

数据挖掘是交叉学科，涉及数据库系统、统计学、机器学习、可视化、信息检索、高性能计算；并与深度学习、模式识别、空间数据分析、图像处理、NLP、信号处理、概率论、图论、归纳逻辑等关系密切。

| 对比       | 关系                                                                                                                                                                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 与数据库   | 数据库关注数据建模、查询语言、查询处理与优化、存储、索引与存取，处理相对结构化数据，为挖掘提供数据管理技术；数据挖掘的分析与预测能力**扩充数据库系统能力**，满足高端用户复杂分析需求                                                                                                                               |
| 与机器学习 | 数据挖掘可认为是**数据库技术与机器学习的交叉**：数据库技术管理海量数据，机器学习和统计学提供分析技术；数据挖掘独特的任务是**关联分析**                                                                                                                                                                             |
| 与统计学   | 共同点：都致力于发现数据中的结构、隐藏的内在规律。关系：统计学为算法设计提供指导思想，应用统计学评估和验证挖掘结果。不同点：统计学研究抽样样本，从小样本推测总体特征；数据挖掘从海量数据集中挖掘。统计分析预测常表现为函数关系式，数据挖掘更看重**预测结果**，很多时候不产生明确函数式，甚至不清楚哪些变量在起作用 |

# 1.8 研究热点与挑战

| 方向                   | 要点                                                                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 大语言模型 × 数据挖掘  | 语义增强的传统挖掘（用 LLM 克服符号共现的“语义脆弱性”，实现无需本体的语义泛化）；自动化 EDA；智能数据发现代理（多智能体发现数据湖中可连接的列） |
| 图基础模型与 GNN       | 面向不平衡、噪声、隐私、分布外（OOD）的鲁棒 GNN；图与 LLM 双向增强；边缘感知图学习                                                              |
| 可信与负责任的数据挖掘 | 可解释性（从“事后解释”转向内在可解释模型，量化准确率-透明度权衡）；隐私保护（PPDM：联邦学习、分割学习、差分隐私）；公平性（检测与缓解算法偏见） |
| 新兴交叉与融合         | 多模态数据挖掘（注意力+Transformer 早期融合，跨模态对齐）；数据挖掘×区块链（信任、隐私、分布式决策）；因果推断（从“预测”走向“干预”）            |
