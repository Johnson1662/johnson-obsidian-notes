# 01-命题逻辑：思维的语法与程序的骨架

嘿！很高兴看到你对离散数学产生了兴趣。如果你是一名转码选手或 CS 专业学生，恭喜你，你正在接触计算机科学最底层的"灵魂"。

很多人觉得数学枯燥，是因为它往往只给结论不给场景。但在离散数学里，每一行公式其实都是在为你的程序代码提供"合法性证明"。这一章，我们要聊的是**命题逻辑（Propositional Logic）**。它就像是思维的"语法"，教你如何把零散的直觉拼凑成严密的逻辑体系。

---

## 1. 什么是命题？（不仅仅是陈述句）

在逻辑学中，**命题（Proposition）**是一个**能够判断真假**的**陈述句**。

这个定义里有两个硬核指标：

1. **必须是陈述句**：疑问句、祈使句、感叹句统统踢出局。
2. **真值必须唯一且确定**：要么是真的（True, T），要么是假的（False, F）。不能"又真又假"，也不能"说不清道不明"。

### 举几个栗子：

- "2 是素数。" —— **是命题**（真值为 T）。
- "北京是法国的首都。" —— **是命题**（真值为 F）。
- "x > 5。" —— **不是命题**。因为 x 是个变量，在没给 x 赋值前，我们无法判断它的真假。这种含有变量的句子，我们下一章在"谓词逻辑"里专门收拾它。
- "请给我一杯咖啡。" —— **不是命题**（祈使句）。
- "这道题难吗？" —— **不是命题**（疑问句）。

### ⚠️ 逻辑的边界：自指悖论

有些句子看起来像陈述句，但逻辑学拿它没办法。最经典的就是**说谎者悖论**：

> "我正在说的这句话是谎话。"

如果你认为它是真的，那么根据内容，它就是谎话（假）；如果你认为它是假的，那它说的就是真话（真）。这种自相矛盾、真值无法确定的句子，在我们的逻辑体系里是不予讨论的。

## 2. 五大联结词：逻辑世界的"胶水"

单个命题（原子命题）的力量很小，逻辑的威力在于通过**联结词（Connectives）**把它们组合成**复合命题**。这就像你在 Python 或 Java 里写的 `if (a > 0 && b < 10)`。

左孝凌教授的教材里定义了五个最基础的联结词，我们一个一个拆开来看：

### 2.1 否定 (Negation, ¬)

**符号**：`¬p`（非 p）
**逻辑**：如果 p 是真，¬p 就是假；反之亦然。
**编程对应**：`!p` 或 `not p`。

### 2.2 合取 (Conjunction, ∧)

**符号**：`p ∧ q`（p 且 q）
**逻辑**：只有当 p 和 q **同时为真**时，结果才为真。
**生活例子**：女朋友说："只有你买了戒指 **且** 买了房子，我才嫁给你。"（少一个都不行，妥妥的 `&&` 逻辑）。

### 2.3 析取 (Disjunction, ∨)

**符号**：`p ∨ q`（p 或 q）
**逻辑**：只要 p 和 q **有一个为真**，结果就为真。
**避坑指南**：注意，这里的"或"是**相容或**（Inclusive Or）。如果 p 和 q 都为真，`p ∨ q` 也是真。这和生活中的"要么鱼死，要么网破"（异或 XOR）不太一样。

### 2.4 蕴含 (Conditional, →) —— 【重难点】

**符号**：`p → q`（如果 p，则 q）
**逻辑**：只有当 **前提 p 为真、结论 q 为假** 时，整个命题才为假。其他情况全是真！

> [!important] 承诺模型（如何理解 Vacuous Truth）
> 很多人不理解：为什么前提 p 为假时，`p → q` 竟然是真的？
>
> 想象一个程序员的承诺：**"如果明天服务器宕机 (p)，我就去公司加班 (q)。"**
>
> 1. 服务器真宕机了，你去了公司。—— **兑现承诺 (T)**
> 2. 服务器真宕机了，你在家打游戏。—— **违背承诺 (F)**
> 3. 服务器**没宕机**，但你闲着也是闲着，去公司学习了。—— **你违背承诺了吗？没有。(T)**
> 4. 服务器**没宕机**，你在家睡觉。—— **你违背承诺了吗？也没有。(T)**
>
> 在数学上，当前提 p 为假时，无论 q 是真是假，我们都称这个命题是**委婉真**（Vacuously True）。

### 2.5 等价 (Biconditional, ↔)

**符号**：`p ↔ q`（当且仅当）
**逻辑**：p 和 q 的真值**完全相同**时（同为 T 或同为 F），结果为真。
**对应**：在程序里就是 `p == q` 的布尔判断。

## 3. 命题公式与真值表：逻辑的"穷举分析"

当我们把一堆联结词和命题变量（p, q, r...）堆在一起，就形成了**命题公式**（或者叫合式公式 WFF）。

如何判断一个复杂公式在各种情况下的表现？**真值表（Truth Table）**是终极武器。

### 案例分析：分析一个复杂条件

假设我们要分析公式：`G = (p ∨ q) → ¬r`

| p   | q   | r   | p ∨ q | ¬r  | (p ∨ q) → ¬r |
| --- | --- | --- | ----- | --- | ------------ |
| T   | T   | T   | T     | F   | **F**        |
| T   | T   | F   | T     | T   | **T**        |
| T   | F   | T   | T     | F   | **F**        |
| T   | F   | F   | T     | T   | **T**        |
| F   | T   | T   | T     | F   | **F**        |
| F   | T   | F   | T     | T   | **T**        |
| F   | F   | T   | F     | F   | **T**        |
| F   | F   | F   | F     | T   | **T**        |

**分析技巧**：

1. **行数确定**：如果有 n 个变量，真值表就有 $2^n$ 行。
2. **优先级**：括号 > 否定(¬) > 合取(∧) > 析取(∨) > 蕴含(→) > 等价(↔)。

## 4. 等值演算：像做代数题一样做逻辑

在编程中，我们经常要简化 `if` 条件。比如：
`if (!(age < 18 || !hasLicense))`
这读起来太绕了！我们可以利用**等值式**进行演化。

### 核心定律（建议截图保存）：

1. **德·摩根定律 (De Morgan's Laws)**:
   - `¬(p ∧ q) ≡ ¬p ∨ ¬q`
   - `¬(p ∨ q) ≡ ¬p ∧ ¬q`
     （划重点：**取反之后，且变或，或变且**）
2. **蕴含等值式**（非常常用）：
   - `p → q ≡ ¬p ∨ q`
     （想证明 `p → q`？你可以证明"要么前提不成立，要么结论成立"）
3. **分配律**:
   - `p ∧ (q ∨ r) ≡ (p ∧ q) ∨ (p ∧ r)`
4. **吸收律**:
   - `p ∨ (p ∧ q) ≡ p`
   - `p ∧ (p ∨ q) ≡ p`

### 实战演示：简化刚才那个绕口的条件

`¬(age < 18 || !hasLicense)`

1. 令 `p = (age < 18)`, `q = hasLicense`。
2. 原式为：`¬(p ∨ ¬q)`。
3. 根据德·摩根定律：`¬p ∧ ¬(¬q)`。
4. 双重否定律：`¬p ∧ q`。
5. 翻译回人话：`(age >= 18) && hasLicense`。
   是不是清爽多了？

## 5. 范式：逻辑公式的"标准证件照"

逻辑公式可以有无数种写法，但为了方便计算机处理，我们需要**范式（Normal Forms）**。

### 5.1 主析取范式 (PDNF) —— 找"真"行

如果一个公式是由若干个**最小项**（包含所有变量的合取式）用 `∨` 连接起来的，它就是主析取范式。
**它的物理意义**：它直接告诉了你，在哪些特定的输入组合下，整个公式结果为"真"。

### 5.2 主合取范式 (PCNF) —— 找"假"行

由若干个**最大项**（包含所有变量的析取式）用 `∧` 连接。
**它的物理意义**：它规定了哪些情况是"禁区"（结果为假）。

> [!tip] 为什么要学这个？
> 在数字电路设计里，给定一个真值表需求，我们第一步就是写出它的主析取范式，然后转化为逻辑门电路。

## 6. 推理理论：从已知到未知

这是逻辑学的最高殿堂。给定一些**前提**，如何合合法地推导出**结论**？

### 常见的推理规则：

- **肯定前件 (Modus Ponens, MP)**:
  已知：`p → q` 为真，且 `p` 为真。
  结论：`q` 必然为真。
- **否定后件 (Modus Tollens, MT)**:
  已知：`p → q` 为真，且 `¬q` 为真（q 是假的）。
  结论：`¬p` 必然为真（p 必须是假的）。

## 7. 案例：如何用命题逻辑分析代码 Bug？

用户反馈说他不知道怎么分析。我们来看一个真实的场景：

**场景**：你写了一个权限校验逻辑：
`if (isAdmin || (isEditor && !isLocked))`

**Bug 表现**：一个 `isLocked` 为 true 的 `isAdmin` 用户竟然进不去后台。

**逻辑建模**：

- `p`: isAdmin
- `q`: isEditor
- `r`: isLocked
- 逻辑公式：`F = p ∨ (q ∧ ¬r)`

**分析过程**：

1. 我们期望当 `p = T` 时，无论其他值是什么，`F` 都应该是 `T`（因为管理员有最高权限）。
2. 代入 Bug 数据：`p = T, r = T`。
3. 计算：`T ∨ (q ∧ ¬T)` = `T ∨ (q ∧ F)` = `T ∨ F` = **T**。
4. **结论**：从逻辑公式看，公式结果应该是真。如果用户进不去，说明：
   - A. 代码实现写错了（比如 `&&` 写成了 `||`）。
   - B. 前提变量赋值错了（比如 `isAdmin` 没读到）。
   - C. 逻辑模型本身就不对（比如需求其实是"非锁定的管理员才能进"）。

通过这种建模，你可以把一个模糊的业务问题转化为确定的数学运算。

## 本篇小结

- **命题**：能判断真假的陈述句。
- **联结词**：¬, ∧, ∨, →, ↔。重点掌握 `p → q` 的真值。
- **等值演算**：德·摩根定律是简化逻辑的核武器。
- **范式**：公式的标准化，用于电路设计和逻辑简化。
- **推理**：从已知前提利用 MP 等规则导出结论。
