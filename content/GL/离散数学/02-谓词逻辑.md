# 02-谓词逻辑

上一章的命题逻辑有个根本局限：它只能处理"完整的句子"，无法表达"所有"和"存在"这类涉及"个体"的概念。比如：

- "所有偶数都能被2整除" —— 命题逻辑无法表达
- "存在一个素数是偶数" —— 命题逻辑也无法表达

**谓词逻辑**（Predicate Logic）解决了这个问题，它让我们能深入到"个体"和"性质"层面进行推理。这章是后续学习集合论、数据库查询、形式语言与自动机的数学基础。

## 个体与谓词：从"是什么"到"有什么性质"

**个体**（Individual）是你讨论的对象，可以是具体的人、具体的数、具体的物体。

**谓词**（Predicate）是描述个体性质或个体之间关系的词。

看例子：

- "x 是偶数" —— 这是一个谓词，记作 `E(x)`
- "x 大于 y" —— 这是一个二元谓词，记作 `G(x, y)`
- "x 是 y 的父亲" —— 二元谓词 `F(x, y)`

在编程中，方法就是谓词的天然对应：

```python
# 谓词示例
is_even(x)      # E(x): x偶数
is是_greater(x, y) # G(x, y): x > y
is_substring(s, t) # S(s, t): s是t的子串
```

## 量词：数学证明的核心工具

量词是谓词逻辑的灵魂，有两个：

### 全称量词 ∀

`∀x P(x)` 表示"对于所有x，P(x)为真"。

注意一个易错点：**全称量词的蕴含形式**。

命题"所有偶数都能被2整除"怎么写？

- ❌ 错误：`∀x (E(x) ∧ D(x))` —— 这表示"所有x既是偶数又能被2整除"
- ✅ 正确：`∀x (E(x) → D(x))` —— "对于所有x，如果x是偶数，那么x能被2整除"

为什么用蕴含？因为全称量词的管辖范围是"如果具备前件性质，则..."。这是数学证明中最重要的形式之一。

### 存在量词 ∃

`∃x P(x)` 表示"存在一个x，使得P(x)为真"。

同样注意：**存在量词的合取形式**。

命题"存在一个偶数是素数"怎么写？

- ✅ 正确：`∃x (E(x) ∧ P(x))` —— "存在一个x，x是偶数且x是素数"

### 量词的否定：深刻理解"不是所有"与"不存在"

这两个等价式至关重要，而且极易混淆：

- `¬∀x P(x) ≡ ∃x ¬P(x)` —— "不是所有x都满足P"等价于"存在x不满足P"
- `¬∃x P(x) ≡ ∀x ¬P(x)` —— "不存在x满足P"等价于"所有x都不满足P"

**记忆技巧**：量词搬家，否定内移，符号翻转。

```python
# 编程中的等价转换
# 原命题：不是所有用户都登录了
# ¬∀x Login(x) 等价于 ∃x ¬Login(x)
# 也就是说：存在一个用户没有登录

# 命题：没有免费的午餐
# ¬∃x (Free(x) ∧ Lunch(x)) 等价于 ∀x (Free(x) → ¬Lunch(x))
# 也就是说：所有免费的东西都不是午餐
```

## 谓词公式：更强大的表达能力

谓词公式由个体变量、谓词符号、量词、联结词组成。

### 自由变量与约束变量

这是令很多初学者头疼的概念：

```python
# ∀x (P(x) → Q(x))
#          ↑   这个x在量词∀管辖范围内，被"约束"了

# ∀x P(x) → Q(y)
#          ↑   这个x不在∀管辖范围内，是"自由"的
#                ↑  y也是自由的
```

**自由变量**可以理解为"还没被赋值的不确定值"；**约束变量**则已经被量词"锁定"了。

在编程中，函数参数就是自由变量，函数内部的局部变量就是被约束的：

```python
def foo(x):  # x是自由的——调用时传入
    return x > 0  # 这个x被函数体"约束"了

# ∀x: 在整个函数作用域内约束x
# x: 作为参数是自由的——调用时确定
```

## 前束范式：把所有量词提到前面

**前束范式**（Prenex Normal Form）是把所有量词都集中到公式最前面的标准形式。

转换步骤：

1. 消除蕴含（用 `p→q ≡ ¬p ∨ q`）
2. 把否定词移到量词前面（`¬∀x ≡ ∃x¬`，`¬∃x ≡ ∀x¬`）
3. 重命名约束变量避免冲突（避免 `∀x ∃x` 这种歧义）
4. 把量词提到前面

例子：把 `∀x P(x) → ∃y Q(y)` 转为前束范式

```
∀x P(x) → ∃y Q(y)
≡ ¬∀x P(x) ∨ ∃y Q(y)        (消除蕴含)
≡ ∃x ¬P(x) ∨ ∃y Q(y)        (否定内移)
≡ ∃x ∃y (¬P(x) ∨ Q(y))      (量词前提)
```

## 谓词逻辑的推理规则

谓词逻辑的推理比命题逻辑多了一些规则，但核心思想相同：

### 命名规则与替换规则

- **全称指定规则（US）**：从 `∀x P(x)` 可以推出 `P(c)`，其中c是任意个体
- **存在推广规则（EG）**：从 `P(c)` 可以推出 `∃x P(x)`

### 例子：证明"存在一个偶素数"

已知前提：

1. `∀x (E(x) → O(x))` （所有偶数都是奇数...等等，这个前提是错的，但先假设它成立用于演示）
2. `∃x E(x)` （存在一个偶数）

等等，我换一个更严谨的例子：

**证明：存在一个偶素数**

前提：

1. `∀x (P(x) → O(x))` （所有素数都是奇数...这个也不对，2是偶素数）
2. `∃x P(x)` （存在素数）

实际上，这个命题需要额外前提：

- `∃x (P(x) ∧ E(x))` （存在偶素数）

让我用更清晰的例子：

**有效论证示例**：

前提：

1. `∀x (S(x) → M(x))` （所有大学生都是成年人）
2. `S(Tom)` （Tom是大学生）

结论：`M(Tom)` （Tom是成年人）

证明：

```
1. ∀x (S(x) → M(x))      前提
2. S(Tom)                  前提
3. S(Tom) → M(Tom)        US，从(1)
4. M(Tom)                 MP，从(2)和(3)
```

### 编程中的谓词逻辑

你在写数据库查询时，谓词逻辑无处不在：

```sql
-- 找出所有订单金额大于100的用户
SELECT * FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o
    WHERE o.user_id = u.id AND o.amount > 100
)

-- 对应谓词逻辑：∃u (User(u) ∧ ∃o (Order(o) ∧ UserOf(o,u) ∧ Amount(o) > 100))
```

```python
# 列表推导式中的谓词
[x for x in items if x.is_valid()]
# ∀x (x在items中 → 如果is_valid则加入结果)
```

## 典型练习题

### 练习1：量词转换

将下列命题用谓词公式表示，并写出否定：

1. "所有程序员都会写代码"
2. "存在一个数，它既是偶数又是质数"
3. "没有免费的午餐"

**解答**：

1. `∀x (P(x) → C(x))`
   - 否定：`¬∀x (P(x) → C(x)) ≡ ∃x (P(x) ∧ ¬C(x))`
   - 意思是：存在一个程序员不会写代码

2. `∃x (E(x) ∧ P(x))`
   - 否定：`¬∃x (E(x) ∧ P(x)) ≡ ∀x (E(x) → ¬P(x))`
   - 意思是：所有偶数都不是质数

3. `¬∃x (F(x) ∧ L(x))` 或 `∀x (F(x) → ¬L(x))`
   - 否定：`¬∀x (F(x) → ¬L(x)) ≡ ∃x (F(x) ∧ L(x))`
   - 意思是：存在免费的午餐

### 练习2：推理证明

前提：

1. `∀x (H(x) → M(x))` （所有人类都是 mortal 会死的）
2. `H(Socrates)` （苏格拉底是人类）

结论：`M(Socrates)` （苏格拉底会死）

**证明**：

```
1. ∀x (H(x) → M(x))      前提
2. H(Socrates)            前提
3. H(Socrates) → M(Socrates)   US，从(1)
4. M(Socrates)           MP，从(2)和(3)
```

### 练习3：程序调试中的谓词逻辑

你有一个函数：

```python
def process_users(users):
    for user in users:
        if user.is_active and user.has_permission:
            user.send_notification()
```

用谓词逻辑分析：

- `A(u)` = user.is_active
- `P(u)` = user.has_permission
- `N(u)` = user.send_notification()

前提：`∀u ((A(u) ∧ P(u)) → N(u))`

现在假设某个用户 `u₀` 没有收到通知，但 `A(u₀) ∧ P(u₀)` 为真，请问哪里出了问题？

**分析**：

- 如果前提为真，那么对于所有 `A(u) ∧ P(u)` 为真的u，`N(u)` 应该为真
- 现在 `A(u₀) ∧ P(u₀)` 为真但 `N(u₀)` 为假
- 这意味着前提为假，或者实现违反了前提的约定
- 可能原因：代码逻辑有bug，或者前提本身不适用于这个场景

## 本篇小结

- 谓词逻辑比命题逻辑更强大，能表达"所有"和"存在"
- 全称量词 ∀ 用蕴含 `→`，存在量词 ∃ 用合取 `∧`
- 量词否定：¬∀≡∃¬，¬∃≡∀¬
- 前束范式把所有量词提到前面
- 谓词逻辑的推理规则是程序验证、形式化方法的基础
