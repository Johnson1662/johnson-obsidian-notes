# 04-重新理解Mamba：从基础到核心

有了上一章的基础，现在我们可以重新看Mamba了。这次我会把每个概念都拆解清楚。

## Mamba是什么：一句话版本

**Mamba是一种处理序列数据的神经网络架构，它用"状态传递"代替了Transformer的"注意力机制"，计算更快。**

就这么简单。接下来我们一步步拆解。

## 序列数据是什么

序列数据就是"有顺序的数据"。

- **文本**：一个个词按顺序排列
- **语音**：一帧帧声音按时间排列
- **视频**：一帧帧画面按时间排列
- **股票价格**：一天天的价格按时间排列

处理序列数据的关键是：**当前位置的输出，可能依赖于之前所有位置的信息**。

比如你读到"他打开冰箱，拿出一瓶"，下一个词很可能是"可乐"或"水"——你需要记住前面"冰箱"的信息才能预测。

## Transformer怎么处理序列

在Mamba之前，主流方法是Transformer。它的核心是**注意力机制（Attention）**。

### 注意力机制的直觉

想象你在读一篇文章，读到某个词的时候，你会"回头看"之前的词，判断哪些词和当前词有关系。

比如：

- "小明**他**很喜欢吃苹果，**他**每天都吃一个。"
- 读到第二个"他"的时候，你会"注意"到前面的"小明"，知道"他"指的是小明。

这就是注意力机制：**每个位置都要和所有其他位置"比一比"，看看有没有关系**。

### 注意力机制的问题

问题来了：**计算量太大**。

假设序列长度是N：

- 每个位置都要和其他N-1个位置比较
- 总共需要 N × N 次比较
- 这就是O(N²)的复杂度

当N=1000时，需要100万次比较。当N=10000时，需要1亿次比较。

**序列越长，计算量爆炸式增长。**

## Mamba的思路：状态传递

Mamba换了一个思路：**不回头看，而是把信息"压缩"进一个状态里，带着往前走**。

### 一个生活化的比喻

想象你在听一个故事：

**Transformer的方式**：

- 每听到新的一句话，都要"回顾"之前听过的所有句子
- 越长的故事，回顾的时间越长

**Mamba的方式**：

- 边听边总结，把关键信息记在脑子里
- 听新句子的时候，只需要看脑子里的"总结"
- 总结的大小是固定的，不会因为故事变长而变大

这就是Mamba的核心思想：**用一个固定大小的"状态"来存储历史信息**。

## 状态空间模型（SSM）详解

Mamba的核心是**状态空间模型（State Space Model，SSM）**。别被名字吓到，其实就是上面说的"状态传递"。

### 最简单的SSM

假设有一个"状态"h，它随时间更新：

$$h(t) = A \cdot h(t-1) + B \cdot x(t)$$

- **h(t)**：当前时刻的状态
- **h(t-1)**：上一时刻的状态
- **x(t)**：当前输入
- **A**：状态转移矩阵，决定历史信息怎么传递
- **B**：输入矩阵，决定当前输入怎么影响状态

用大白话说：**新状态 = 历史状态的变换 + 当前输入的变换**

### 输出怎么算

有了状态，输出就简单了：

$$y(t) = C \cdot h(t)$$

- **y(t)**：当前输出
- **C**：输出矩阵，决定怎么从状态生成输出

### 一个数值例子

假设状态h是一个数（简化版）：

- A = 0.9（历史信息保留90%）
- B = 0.5（当前输入影响50%）
- C = 1（直接输出状态）
- 初始状态h(0) = 0

输入序列：x = [1, 2, 3, 4]

计算过程：

```
h(1) = 0.9 × 0 + 0.5 × 1 = 0.5
h(2) = 0.9 × 0.5 + 0.5 × 2 = 1.45
h(3) = 0.9 × 1.45 + 0.5 × 3 = 2.805
h(4) = 0.9 × 2.805 + 0.5 × 4 = 4.5245
```

输出：y = [0.5, 1.45, 2.805, 4.5245]

看到了吗？**每个状态都"记住"了之前所有输入的信息**。

## Mamba的创新：让参数"动起来"

传统的SSM有个问题：A、B、C是固定的，对所有输入一视同仁。

Mamba的创新是：**让A、B、C根据输入动态变化**。

### 为什么需要动态参数

考虑这个例子：

- 输入："重要的信息：明天开会"
- 输入："废话废话废话废话"

对于"重要的信息"，我们希望多记住（A大一点）
对于"废话"，我们希望少记住（A小一点）

**不同输入，应该有不同的"记忆强度"。**

### Mamba怎么做

Mamba用神经网络来预测A、B、C：

```
输入 x → [神经网络] → 预测 A, B, C
```

这样，每个输入都有自己专属的A、B、C，模型可以根据内容自动调整"记忆策略"。

## 门控机制：选择性记忆

Mamba还有一个重要组件：**门控（Gating）**。

### 什么是门控

门控就是"选择性通过"。

还记得上一章说的Sigmoid函数吗？它把数字压缩到0~1之间，正好可以表示"通过比例"。

```
门控值 = Sigmoid(输入)
输出 = 原始输出 × 门控值
```

- 门控值接近1 → 全部通过
- 门控值接近0 → 几乎不通过

### Mamba里的门控

Mamba在输出阶段加了一个门控：

$$y_{out} = y_{ssm} \odot z$$

- $y_{ssm}$：SSM的输出
- $z$：门控向量（由另一个神经网络生成）
- $\odot$：逐元素乘法

**作用**：让模型自己决定哪些信息该输出，哪些该丢弃。

## 并行扫描：加速计算

SSM的计算看起来是串行的（必须算完h(t-1)才能算h(t)），这会很慢。

Mamba用了一个技巧：**并行扫描（Parallel Scan）**。

### 直觉理解

假设要计算累加和：[1, 2, 3, 4, 5, 6, 7, 8]

**串行方式**（一步步加）：

```
1 → 3 → 6 → 10 → 15 → 21 → 28 → 36
```

需要7步。

**并行方式**（两两相加，多轮）：

```
第1轮: 1+2=3, 3+4=7, 5+6=11, 7+8=15
第2轮: 3+7=10, 11+15=26
第3轮: 10+26=36
```

只需要3步！

这就是并行扫描的核心思想：**把串行计算拆成可以并行执行的多轮计算**。

### 为什么这很重要

并行扫描让Mamba可以充分利用GPU的并行能力，大大加速训练和推理。

## Mamba vs Transformer：对比总结

| 特性       | Transformer            | Mamba                  |
| ---------- | ---------------------- | ---------------------- |
| 核心机制   | 注意力机制             | 状态空间模型           |
| 处理方式   | 每个位置回头看所有位置 | 状态传递，只看当前状态 |
| 计算复杂度 | O(N²)                  | O(N)                   |
| 长序列处理 | 慢，显存爆炸           | 快，显存固定           |
| 并行性     | 训练并行，推理串行     | 训练和推理都并行       |

## 小结

这一章我们从基础概念出发，重新理解了Mamba：

1. **序列数据**：有顺序的数据，当前位置依赖历史信息
2. **Transformer的问题**：注意力机制复杂度O(N²)，长序列爆炸
3. **Mamba的思路**：用状态传递代替注意力，复杂度O(N)
4. **SSM核心**：状态 = 历史变换 + 输入变换
5. **Mamba创新**：动态参数 + 门控机制
6. **并行扫描**：让串行计算变成并行，加速训练
