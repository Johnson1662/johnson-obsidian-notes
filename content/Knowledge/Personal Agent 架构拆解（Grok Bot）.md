# Personal Agent 架构拆解（Grok Bot）

> 一句话：Personal Agent 和 Coding Agent 的架构**不一样**。Grok Bot 分三层——主 Agent、Worker、Harness；
> 两个关键设计都围绕**异步**：主 Agent 只做「理解你、派活、交付」，耗时活转后台；连上下文压缩也在后台做。
> 总结成一句：**主 Agent 永远在线，连压缩都不打扰你。**

来源：小红书「403-error」的《Personal Agent 架构拆解》（视频 95 秒，2026-10-24 抓取）。
原始素材（正文、口播稿、评论原文、画面文字）见 `raw/xhs-403-error-personal-agent-2026-10-24.md`。

## 一、三层架构

| 层 | 职责 |
|---|---|
| 主 Agent | 理解你、安排工作、交付结果 |
| Worker | 耗时的执行 |
| Harness | 保存状态、传递消息，再把主 Agent 叫醒 |

作者说这是对 **Grok Bot** 做「比较细的逆向」后得到的结构。

## 二、关键设计一：纯异步

主 Agent 只做三件事：**理解你、派活、交付**。

- **超过两轮工具调用的活，一律交给后台 Worker。**
- 派完就结束这一轮，**不等待，也不轮询**。
- Worker 做完，由 Harness 再把它唤醒。

作者说这是 **OpenClaw 最主要的创新点：转后台**（原话「OpenClaw 最主要的创新点就是这个转后台」）。

### 与 Coding Agent 的区别（作者在评论区补充）

> 主要的区别是 code agent 偏向同步，所有任务做完了再汇报，而 personal agent 全部异步。

## 三、关键设计二：压缩也是异步的

背景：压缩上下文很费时间，要把整段历史交给模型重读一遍再写成摘要。

| | 常见做法 | Grok Bot |
|---|---|---|
| 时机 | 触发时只能停下来，用户干等 | 剩余上下文**不到 10k tokens 或不到 10%** 时，在后台开始写摘要 |
| 对话 | 中断 | 照常继续 |
| 新消息 | — | 摘要期间新发的消息**接在摘要后面**，不会被旧摘要覆盖 |
| 后台 Worker | — | 不受影响 |
| 待办列表 | — | 压缩后程序直接保存的待办列表**一条都不会丢** |

## 四、一个有趣的细节：压缩 prompt 按模型定制

作者在逆向里发现，**压缩用的 prompt 是按模型分别定制的**。举例：给 OpenAI 分支时，
**把交接摘要放在最后**，贴合该模型的训练预期；Anthropic 和 xAI 也各有一套。

## 七、可以带走的三条

1. **判断一个 Agent 是「个人向」还是「编码向」，看它是同步还是异步**：做完再汇报 vs 派完就走。
2. **「转后台 + 完成时唤醒」是个人助理类 Agent 的核心机制**，不是实现细节。
3. **压缩要能被设计成后台行为**：提前在剩余额度不足时开始写摘要，让新消息接在摘要之后而不是被覆盖。
